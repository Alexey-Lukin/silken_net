## 02_01: Hardware Architecture & BOM (The Capsule)

## 🎯 Мета (Objective)

Зафіксувати апаратну архітектуру (PCBA), логіку живлення та Bill of Materials (BOM) для герметичної капсули "Солдата". Капсула повинна збирати енергію з коаксіального анкера, зберігати її в іоністорі, аналізувати звук та передавати пакети через LoRaWAN.

## ✅ Статус (Status)

- **Поточний TRL:** TRL 4 (Схемотехніка оновлена під нову фізику. Тестування BQ25570 на макетній платі завершено)
- **Оновлення (Півот):** Повністю видалено каскад LTC3108 та трансформатор 1:100. EBFC генерує >500 мВ, що перевищує поріг "холодного старту" BQ25570 (330 мВ). Це зменшує розмір плати на 40% і підвищує загальний ККД.

## 🛑 Блокери (Blockers / Needs Action)

- **Герметизація (Potting):** Необхідно підібрати епоксидний компаунд, який не зруйнує крихкі компоненти (наприклад, кварцовий резонатор LoRa-модуля) при температурному розширенні взимку (-20°C).

## ⚡ 1. Блок-схема Архітектури (System Block Diagram)

Електрони рухаються знизу (від дерева) вгору (до антени).

```
[ Титановий Анкер ]  <-- (Сліпе з'єднання / Pogo Pins)
        │
        ▼  VIN_DC (>500mV)
┌──────────────────────────────────────────────┐
│  BQ25570 (Power Management IC)               │
│  - MPPT (Maximum Power Point Tracking)       │
│  - Boost Charger (піднімає напругу до 5.5V)  │
│  - Buck Converter (стабілізує 3.3V для MCU)  │
└───────────────────┬──────────────────────────┘
                    │
                    ▼  (Накопичення: 4.14 Джоуля)
           [ Supercapacitor 0.47F / 5.5V ]
                    │
                    ▼  VDD (3.3V)
┌──────────────────────────────────────────────┐
│  STM32WLE5JC (Seeed Studio LoRa-E5)          │
│  - ARM Cortex-M4 (Обчислення mruby)          │
│  - SX1262 LoRa Radio (+22dBm TX)             │
│  - STOP2 Deep Sleep (2.1 µA)                 │
└─────────┬────────────────────────┬───────────┘
          │                        │
          ▼                        ▼
[ П'єзодиск (Акустика) ]     [ Внутрішній Термометр ]
```

## 🔋 2. Енергетичний Бюджет (Energy Budget)

Уся система спроєктована навколо стану "Нульового Лагу" — мікроконтролер спить 99.9% часу.

| Режим / Компонент | Споживання | Тривалість | Енергія (mJ) |
|------------------|-----------|-----------|-------------|
| **Deep Sleep (STOP2)** | 2.1 µA @ 3.3V | 1 година | ~25 mJ |
| **BQ25570 Quiescent** | 488 nA | 1 година | ~5 mJ |
| **LoRa TX (+14dBm)** | 120 mA @ 3.3V | ~100 ms | ~39 mJ |
| **TinyML Inference** | 12 mA @ 3.3V | ~200 ms | ~8 mJ |

**Генерація:** Навіть при слабкому метаболізмі дерева (зима/посуха), EBFC видаватиме мінімум 15-20 µW потужності. Це дає близько **54-72 mJ на годину**.

**Висновок:** Енергії вистачає на безперервний сон і **1 сеанс зв'язку (TX) щогодини**, залишаючись в абсолютному плюсі.

## 🧩 4. Апаратні Хаки (Hardware Hacks)

Замість дорогих зовнішніх датчиків використовуємо вбудовану периферію:

1. **Температура:** Вбудований у кремній STM32 датчик температури (внутрішній канал АЦП). Точність ±1°C.
2. **Акустика без живлення:** П'єзодиск приклеєний до дна капсули (контактує з металом анкера). Вібрація від бензопили генерує сплеск напруги → EXTI переривання → MCU прокидається апаратно, не витрачаючи енергію на постійне прослуховування.

## 🛠️ 5. Development Toolchain (Інструменти Розробки)

> **НОВА СЕКЦІЯ (нотатка N5, Сесія 2).** Інструменти для схемотехніки, симуляції та PCB до отримання фізичних компонентів.

### Симуляція аналогових ланцюгів

| Інструмент | Призначення | Примітки |
|-----------|------------|---------|
| **LTspice** (безкоштовний, Analog Devices) | Симуляція енергетичного каскаду: BQ25570 MPPT, заряд супераконденсатора від EBFC, струми витоку | Найкращий в своєму класі для ультранизькочастотної аналогової симуляції. Можна точно змоделювати криву заряду 0.47F від 500 мВ без ризику спалити реальні компоненти |

### Симуляція мікроконтролера

| Інструмент | Призначення | Примітки |
|-----------|------------|---------|
| **Wokwi** (хмарний) | Швидкий IoT прототип (STM32, Arduino) | Зручний для тестування логіки сенсорів та формату LoRa-пакетів до отримання плат |
| **Proteus** | Повна ко-симуляція MCU + схема | Для глибшої валідації периферії STM32 коли Wokwi недостатній |

### PCB для заводу

| Інструмент | Призначення | Примітки |
|-----------|------------|---------|
| **KiCad** (open-source) | Схема → розводка плати → Gerber export | Промисловий стандарт. Gerber-файли приймають JLCPCB, PCBWay, українські PCB-заводи. Open-source формат зберігає статус відкритого hardware — вимога для грантів Gitcoin/Giveth |

**Workflow:** KiCad схема → DRC перевірка → розводка → Gerber export → завод (JLCPCB/PCBWay або локальний UA вендор).

> ⚠️ **Послідовність:** 1. Симуляція в LTspice (верифікація енергетики) → 2. Схема в KiCad → 3. PCB layout → 4. Gerber на завод. Не починай PCB layout без верифікованої схеми.
