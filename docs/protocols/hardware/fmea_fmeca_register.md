## 0. Метод

**Шкала S/O/D — 1–10, RPN = S×O×D** (стандартна автомобільна/аерокосмічна конвенція; SilkenNet
власної шкали доти не мала — це і є названий у `00_07` «канон-борг», який ця таблиця частково
закриває, зростивши практику, а не ще один документ-визначення):

| | 1–3 | 4–6 | 7–8 | 9–10 |
|---|---|---|---|---|
| **S** (наслідок, ЯКЩО станеться) | косметичний / без впливу на функцію | деградація продуктивності / прискорена заміна | втрата основної функції ОДНОГО вузла (EBFC мертва, анкер вирвано) | **системний**: хибний slash / хибний DID / втрата 20-річної місії на класі вузлів |
| **O** (імовірність ПРИ поточному контролі) | контрольовано специфікацією + down-select, залишковий ризик = помилка виконання | design-напрям обрано, валідація не завершена | design-напрям ВІДКРИТИЙ (⚖️ не ухвалено) або залежить від поля, якого ще нема | механізм відомий, контролю НЕМАЄ |
| **D** (шанс НЕ впіймати до наслідку) | QC/ICP-MS/bench ловить на купоні чи стенді до польової фази | ловиться лише на 12-тижневому/12-місячному тесті | польова телеметрія непряма (DCI-проксі, не прямий вимірювач) | **нуль сигналу**: подія невидима жодному каналу (тиша ⊥ здоровʼя, `Tree.silent`) |

Кожен рядок несе `⚖️` там, де номер стоїть на ВІДКРИТОМУ дизайн-виборі (пряме дзеркало HW.36's
власного ⚖️-residual: severity там, де рішення ще не ухвалено, апріорі менш надійна).

## 2. Convergent AND-кластери — fault-tree-by-outcome

Плоский RPN ранжує mode'и **поодинці**. Але дві підсистеми несуть кілька kill-механізмів, **AND**-
звʼязаних на той самий 20-річний outcome — відмова БУДЬ-ЯКОГО з них вбиває підсистему, тож
ймовірність підсистемного відказу НЕ є ймовірністю найгіршого доданка, а зростає з кожним.

### 2.1 «Катод дихає 20 років» (outcome: безперервна O₂-дифузія до PTFE-GDL)

```
                    ┌─────────────────────────────┐
                    │  OUTCOME: катод задихається   │
                    │  (EBFC-потужність → 0)        │
                    └───────────────┬───────────────┘
                                     │  OR (будь-який з чотирьох вбиває)
        ┌──────────────┬────────────┼────────────────┬──────────────────┐
        │              │            │                │                  │
   [#1] Cathode-DET  [#2] Flooding [#3] Overgrowth  [CODIT-реакція,
   margin borderline (hydrophobicity (каллюс         §1 — повільна
   RPN=336           loss) RPN=315  закриває)         капсуляція за
   (не «вбиває O₂-     (вбиває       RPN=270           межами прямого
    дифузію», а         O₂-дифузію   (вбиває           FMEA-рядка, але
    вбиває СТРУМ         напряму)     O₂-дифузію)       AND-член)
    при О₂ в наявності)
```

**Чому це AND, а не незалежні ризики.** Усі чотири моди фізично атакують ОДНУ й ту саму функцію
(«O₂ доходить до каталітичного сайту катода на потрібній швидкості») з РІЗНИХ напрямків: DET —
кінетика електрон-переносу вже на межі (навіть за ідеального O₂-потоку струм малий); Flooding —
блокує сам O₂-потік дефектом мембрани; Overgrowth — блокує O₂-потік геометрично ззовні; CODIT —
блокує O₂-потік біологічною реакцією дерева на чужорідне тіло. **Жоден захист одного не рятує від
іншого.** Підсистема вже названа в самому `00_07`-пункті «вже borderline» через #1 (DET-margin) —
тобто три інші моди накладаються НЕ на здоровий запас, а на систему, де перший kill-механізм уже
зʼїв більшість margin. Практичний наслідок: коли `HW.24` (coin bake-off) обиратиме DET-важіль (рядок
#1), кандидат, що піднімає DET-margin, варто оцінювати ЯК ЗВІЛЬНЕННЯ бюджету для решти трьох
AND-членів, а не як ізольоване покращення.

### 2.2 «Анкер тримається 20 років» (outcome: механічна цілісність Zone 1↔2↔3 стику)

```
                    ┌─────────────────────────────┐
                    │  OUTCOME: анкер вирвано/       │
                    │  розгерметизовано              │
                    └───────────────┬───────────────┘
                                     │  OR
   ┌───────────┬────────────┬───────┴────────┬─────────────┬──────────────┐
   │           │             │                │              │
[#4] PEEK   [#9] Press-  [#8] O-ring/    [#10] MATE-Ø    [#11] Ti↔Au
cold-flow   fit/barb     IP68 breach     misalignment    pogo galvanic
creep       pull-out     (Sil-Pad ∥      (bayonet/       pair (Rc drift
RPN=270     RPN=180      pogo Z-stack)   lug-Z, press-   → cold-start
(seal force  (осьове      RPN=180        fit H7/s6       fail, не
падає)       утримання                   промах)         структурний,
                          падає)                          але той самий
                                                            вузол)
```

**Чому це AND.** Усі пʼять моди ділять ОДИН фізичний вузол (Zone 1↔2↔3 механічний+електричний
стик) і ОДИН спільний ресурс — **compression-вікно Z-stack** (`02_02 §3.5`), який Sil-Pad (акустика),
pogo-пружина (електрика) і O-ring (герметичність) ділять ОДНОЧАСНО. PEEK creep (#4) і press-fit creep
(#9) обидва зʼїдають contact pressure з часом — це не два незалежні 10-річні бюджети, а ОДИН
бюджет, який обидва механізми витрачають паралельно. MATE-Ø неузгодженість (#10) не є окремим
kill-механізмом у часі — вона є ПЕРЕДУМОВОЮ, яка визначає, скільки бюджету Z-stack взагалі
залишається для перших чотирьох. **Практичний наслідок:** MATE-Ø reconcile (`HW.8.8`/`HW.8.9`/
частина `HW.33`) логічно ПЕРЕДУЄ будь-якій FEA-валідації creep-бюджету (#4/#9) — рахувати 10-річний
запас на нефіксованій геометрії дає число, яке зміниться, щойно MATE-Ø зведуть.
