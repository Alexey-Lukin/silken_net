#### 🔶 Вектор 1: SPI/DMA Оптимізація — Модуль 02 (Hardware Capsule)

**Контекст: Проблема Енергетичного Блокування Процесора**

Анкери Silken Net функціонують в умовах екстремально низького енергоспоживання. Мікроконтролер STM32WLE5JC має постійно опитувати зовнішні мікросхеми: **BQ25570** (стан MPPT та `vcap`) і сенсорну периферію. Стандартний синхронний SPI-обмін **блокує CPU** на весь час транзакції — CPU простоює та марно витрачає енергію, не перебуваючи у STOP2 (2.1 мкА).

**Зв'язок з Публікаціями Ярмілка:**

Праця _«High-Speed SPI Bus Host Controller for Embedded Systems»_ (2022) та подальші дослідження апаратних SPI-експандерів (SPI-FSMC) з підтримкою **DMA (Direct Memory Access)** є прямою відповіддю на цю проблему.

**Завдання А: DMA-режим для SPI-шини STM32WLE5JC**

Впровадження DMA-режиму для SPI-шини дозволить:

1. MCU ініціює збір даних з BQ25570/сенсорів через SPI
2. MCU **негайно повертається в STOP2** (2.1 мкА) — не чекає завершення транзакції
3. DMA-контролер самостійно завантажує дані в RAM-буфер
4. Завершення DMA генерує переривання → MCU прокидається лише для обробки готових даних

```c
// Концептуальна схема (firmware/soldier/main.c — Phase 1 Enhancement):
// Поточна реалізація: блокуючий HAL_SPI_Transmit()
// Цільова реалізація після Ярмілка:
HAL_SPI_Receive_DMA(&hspi1, rx_buffer, BQ25570_REG_COUNT);
HAL_PWR_EnterSTOP2Mode(PWR_STOPENTRY_WFI);  // негайно спати
// ISR DMA_Complete: прокинутись, обробити rx_buffer
```

**Завдання Б: Запобігання Колізіям (HAL + RTOS парадигма)**

Ярмілко має досвід застосування HAL та методів RTOS для запобігання нештатним ситуаціям **множинного доступу до загальної SPI-шини**. У Silken Net на одній шині можуть конкурувати: опитування BQ25570, читання сенсора температури, TinyML inference (DMA 16 кГц аудіо). Його методологія гарантує стабільність 4-провідної системи Кельвіна при одночасному опитуванні кількох каналів без data corruption.

#### 🔶 Вектор 2: Lightweight Cryptography — Модуль 07 (Web3 Security)

**Контекст: Дилема «Безпека vs Енергія»**

Анкери Silken Net вживлені у дерева у відкритому лісі — вони фізично вразливі до перехоплення. Водночас традиційна «важка» криптографія (RSA-2048, стандартний AES з CBC-MAC) вимагає тисяч тактів процесора та занадто дорога для системи на 44 мВ. Поточна реалізація (AES-256-CBC через `HAL_CRYP_Encrypt`) захищає **тіло пакету**, але не адресує автентифікацію вузлів та integrity для Web3.

**Зв'язок з Публікаціями Ярмілка:**

Стаття _«IoT Smart Implants: Information Security and the Implementation of Lightweight Cryptography»_ (2023, співавтори: І. Розломій, С. Науменко) є **прямим науковим фундаментом** для Silken Net. Концепція «Smart Implant» у цій роботі — це буквально те, чим є гіроїдний анкер у дереві.

**Завдання А: Lightweight ECC для Автентифікації Вузлів**

Замінити або доповнити поточний AES-CBC на **ECC (Elliptic Curve Cryptography)** — алгоритм на базі еліптичних кривих, що забезпечує еквівалентний рівень захисту при на порядок меншій кількості тактів:

| Алгоритм | Рівень безпеки | Розмір ключа | Такти CPU (підпис) |
|----------|---------------|-------------|---------------------|
| RSA-2048 | 112 bit | 256 байт | ~1,000,000 |
| AES-256-CBC | симетр. | 32 байт | ~50,000 |
| **ECC (Curve25519)** | **128 bit** | **32 байт** | **~10,000** |

Curve25519 (або аналог) вкладається в енергетичний бюджет одного TX-циклу Soldier-вузла.

**Завдання Б: Криптографічне Хешування для Data Integrity (Web3)**

Розробки Ярмілка щодо застосування **хеш-методів у криптографічному аналізі потоків** забезпечать цілісність даних (Data Integrity) перед пакуванням у LoRaWAN-пакет:

```c
// Концептуальна схема (Phase 2 — після сенсорного зчитування):
// Поточно: CRC-16 (2 байти, байти 19-20 пакету) — лише error detection
// Цільово після Ярмілка: BLAKE2s або SipHash-2-4 (lightweight MAC)
//   — автентифікація відправника + integrity для peaq DID верифікації
uint8_t mac[4];
siphash24(payload, PAYLOAD_LEN, device_secret_key, mac);
memcpy(packet + MAC_OFFSET, mac, 4);
```

Цей MAC (Message Authentication Code) верифікується на боці Queen-шлюзу та Rails backend перед передачею в peaq DID pipeline (Модуль 05\_02).

#### 🔶 Вектор 3: Edge AI та Стиснення — Модуль 06 (Observability / Telemetry)

**Контекст: Мінімізація LoRa TX — Головний Пріоритет**

LoRa-передача (+22 dBm ≈ 100 мВт) — найбільш енерговитратна операція. Кожна мілісекунда TX коштує енергії, накопиченої за хвилини зарядки іоністора від EBFC. Три інструменти Ярмілка атакують цю проблему з різних боків.

**Завдання А: Арифметичне Стиснення Payload (зменшення часу TX)**

Стаття _«Transforming Big Data: A Novel Arithmetic Compression Method Based on Symbol Frequency»_ (2023) пропонує **легкий арифметичний кодек**, придатний для мікроконтролерів. Застосування до 21-байтового пакету Soldier:

- Телеметричні дані (байти 4–15: `delta_t`, `vcap`, `temp`, `acoustic`, `lorenz_z`) мають **передбачувані розподіли** (здоровий ліс → більшість значень у вузькому діапазоні «норми»)
- Арифметичний кодек стискає ці поля, потенційно скорочуючи payload з 21 до ~13–15 байт
- Кожен зекономлений байт = менше символів LoRa = коротший час TX = менше енергії

```
Орієнтовна економія:
  Поточний пакет: 21 байт → SF=7, BW=125kHz → ~56 мс TX-time
  Після стиснення: ~14 байт → ~37 мс TX-time → економія ~34% енергії TX
```

**Завдання Б: Фільтрація Нечітких Дублікатів (suppress TX взагалі)**

Стаття _«General Methodology for Detecting Fuzzy Duplicates»_ (2024) адаптується для телеметрії Soldier. Якщо вектор сенсорних показників (зокрема `delta_t` — ключовий вхід рівняння Лоренца) **є «нечітким дублікатом»** попереднього вимірювання (змінився в межах статистичної похибки), Soldier **не активує LoRa-передавач** взагалі:

```c
// Phase 2.5 — перед Phase 4 TX (firmware/soldier/main.c):
// Ярмілко: загальна методологія fuzzy duplicate detection
// Порубльов: C-реалізація fuzzy_distance() для бінарних пакетів
if (!should_transmit(current_packet, last_packet, FUZZY_THRESHOLD)) {
    goto ENTER_STOP2;  // пропустити TX, зекономити ~100 мВт × TX_duration
}
```

> **Примітка:** Ярмілко надає **методологічну базу** (загальна методологія fuzzy duplicates), Порубльов — **математичну реалізацію** функції `fuzzy_distance()` (алгоритм нечіткого порівняння бінарних векторів). Обидва внески є взаємодоповнювальними.

**Завдання В: Dependability Firmware Framework (самовідновлення після brownout)**

Стаття _«Dependability of Embedded Systems in the Industrial Internet of Things»_ (2024) дає **фреймворк відмовостійкої прошивки**. Для Silken Net це критично: EBFC може тимчасово втратити вихідну напругу (хмарність, сезонне падіння метаболізму дерева) → brownout → STM32 може зависнути у невизначеному стані.

Фреймворк Ярмілка охоплює:

- **Watchdog стратегії:** правила відновлення стану після IWDG/WWDG reset без втрати накопиченої телеметрії
- **Brownout detection:** поріг на `vcap` (наприклад, < 1.8 В) → graceful shutdown → збереження стану в RTC Backup регістрах (DR0–DR10) до глибокого STOP2
- **State recovery:** після відновлення живлення — читання DR0–DR10, відновлення контексту (mesh\_relay\_flag, last\_wakeup\_timestamp, acoustic\_events) без перезавантаження firmware-стану

```c
// Концептуальна схема brownout handler (firmware/soldier/main.c):
void HAL_PWR_PVDCallback(void) {  // Power Voltage Detector IRQ
    RTC_BKP_WriteRegister(RTC, RTC_BKP_DR0, mesh_relay_flag);
    RTC_BKP_WriteRegister(RTC, RTC_BKP_DR1, (uint32_t)last_vcap);
    // ... зберегти критичний стан ...
    HAL_PWR_EnterSTOP2Mode(PWR_STOPENTRY_WFI);  // graceful shutdown
}
```

#### 🔷 Вектор 1: Обчислювальна Геометрія — Модуль 01\_01 (Коаксіальний Гіроїд)

**Контекст:**

Центральний апаратний елемент Gaia 2.0 — монолітний **120-мм коаксіальний Ti-6Al-4V анкер**, внутрішня структура якого є **TPMS-гіроїдом (Triply Periodic Minimal Surface)** із заданою пористістю **65%**. Ця пористість є наслідком закону Gibson-Ashby:

```
E_foam / E_solid ≈ C × (ρ_foam / ρ_solid)^n   [n≈2 для відкритих TPMS, C≈1.0 для гіроїда]

При 65% пористості: ρ_foam/ρ_solid = (1 − 0.65) = 0.35
  E ≈ 1.0 × (0.35)² × 110 ГПа = 0.1225 × 110 ≈ 13.5 ГПа
Діапазон деревини Pinus sylvestris: 9–16 ГПа ✓
```

Ізоеластичність 13–15 ГПа забезпечує нульовий ефект stress-shielding. CAD-модель генерується у nTop (ліцензія очікується — BLOCKER-1 в 01\_01). Після генерації STL/STEP файлу необхідна **алгоритмічна валідація** перед відправкою на DMLS-завод (Київ/Дніпро, партія 100 шт.).

**Завдання А: Алгоритмічна Валідація STL/STEP Моделей**

Розробка Python/C++ скриптів для математичної перевірки згенерованих 3D-моделей:

- Підтвердження пористості **65% ± допустима похибка** на кожному горизонтальному зрізі гіроїда
- Топологічна цілісність сітки (відсутність «дірок», самоперетинань, вироджених полігонів)
- Коректність симетрії TPMS (тричі-периодична структура не порушена при дискретизації)
- Відповідність діаметра капілярних каналів специфікації

```
Вхід:  STL/STEP файл від nTop або Rhino+Grasshopper
Вихід: Звіт валідації (porous_fraction per slice, mesh_integrity, symmetry_score)
Інструментарій: Python (numpy, trimesh, scipy) або C++ (CGAL)
```

**Завдання Б: Розрахунок Площі Поверхні для EBFC (зв'язок з Модулем 01\_03)**

EBFC генерує струм (GOx на аноді, Laccase на катоді) пропорційно до **ефективної площі контакту** металу з ксилемним соком. Гіроїд має дворівневу шорсткість:

1. **Макрорівень:** Самі пори гіроїда (~100–500 мкм)
2. **Мікрорівень:** Протравлені ями на Ti-6Al-4V (~1–10 мкм, HF/HNO₃ травлення — Модуль 01\_02)

Методи обчислювальної геометрії точно розраховують площу `S_eff` цієї складної дворівневої поверхні з STL-моделі. Результат передається хімікам (Школа Мінаєва, Модуль 08\_01) для розрахунку точної кількості MWCNT нанотрубок та осмієвого редокс-полімеру для іммобілізації ферментів.

```
I_max = j_surface × S_eff
  де j_surface — питома густина струму (мкА/см², від Школи Мінаєва)
      S_eff    — ефективна площа поверхні (см², обчислює Порубльов)
```

**Завдання В: Оптимізація Капілярних Каналів (Відсутність «Глухих Кутів»)**

Геометрія гіроїда як мінімальна поверхня теоретично забезпечує рівномірний капілярний транспорт рідини. Проте в реальній дискретизованій STL-сітці можуть виникати локальні «кишені» — зони де сік застоюється і викликає bio-fouling (гниття, що руйнує EBFC). Порубльов застосовує алгоритми аналізу зв'язності (flood-fill / BFS по об'ємній сітці) для ідентифікації та усунення таких зон на рівні CAD-параметрів до передачі на завод.

#### 🔷 Вектор 2: Дискретна Математика та Надійність LoRa-Mesh — Модуль 07 / 03\_02

**Математичне Формулювання (Зв'язок з Дипломною Роботою)**

Дипломна робота Порубльова: _«Задача вибору варіантів при побудові систем мінімальної вартості з заданою нижньою межею надійності»_ — є **точним математичним формулюванням** архітектурної проблеми LoRa-Mesh мережі Silken Net:

| Термін дипломної роботи | Відповідник у Silken Net |
|------------------------|--------------------------|
| «Система мінімальної вартості» | Маршрут передачі пакету з мінімальними витратами енергії |
| «Вартість» | Мікровати на LoRa-TX (+22 dBm ≈ 100 мВт — найдорожча операція) |
| «Задана нижня межа надійності» | Гарантована доставка пакету телеметрії до Queen-шлюзу |
| «Варіанти» | Набір можливих маршрутів через сусідні анкери-Солдати |

**Контекст: Чому Існуюча Маршрутизація є Субоптимальною**

Поточна реалізація (`firmware/soldier/main.c`) — TTL-based multi-hop routing з PANIC\_TTL=5. Вона **не враховує поточний рівень заряду** сусідніх вузлів (`vcap` — напруга на суперконденсаторі 0.47F). Це призводить до:

- Направлення пакету через «виснажений» анкер → втрата даних
- Перевантаження популярних вузлів → failure cascade
- Відсутності балансування навантаження між рівнозначними маршрутами

**Завдання А: Математична Модель Зваженого Динамічного Графа**

```
G(V, E, W) — зважений динамічний граф:

V = {v_i}  — множина анкерів-Солдатів та Queen-шлюзів
E = {e_ij} — ребра (LoRa-зв'язок між сусідами при RSSI ≥ поріг)
W(e_ij, t) — динамічна вага ребра в момент t:

  W(e_ij, t) = α × E_tx(distance_ij)        [вартість TX у мкДж]
             + β × (1 / vcap_j(t))           [штраф за низький заряд сусіда j]
             + γ × (delta_t_j / delta_t_ref) [штраф за стрес-стан сусіда j]

  де vcap_j та delta_t_j — стан вузла j (передаються у 21-байтовому пакеті)
  Орієнтовні початкові значення коефіцієнтів (підбираються симуляцією):
    α ≈ 1.0 (базова вага TX-вартості)
    β ≈ 0.5 (штраф за низький vcap; збільшити при частих energy failures)
    γ ≈ 0.3 (штраф за стрес дерева; зменшити для пріоритету надійності над балансом)
```

**Завдання Б: Алгоритм Енергоефективної Маршрутизації**

На базі моделі — **алгоритм динамічної маршрутизації** з гарантіями надійності:

1. **Фаза побудови:** Модифікований алгоритм Дейкстри/Белмана-Форда з динамічними вагами W
2. **Фаза перебудови:** Тригер при зміні `vcap` сусіда > 20% або `delta_t` > порогу
3. **Гарантія надійності:** При недоступності основного маршруту — вибір резервного з мінімальним додатковим hop-count

**Завдання В: Аналіз Відмовостійкості (20–30% вузлів)**

Формальне доведення (математичне або Monte Carlo симуляція), що мережа **гарантовано доставить пакет** при одночасній відмові до 20–30% вузлів. Поріг 20% узгоджується зі Slashing Protocol (автоматичне спалювання SCC, якщо >20% дерев кластеру показують критичний стрес).

#### 🔷 Вектор 3: Нечіткий Пошук — Edge AI Дедуплікація Телеметрії (Модуль 03\_03)

**Контекст: LoRa TX — Найдорожча Операція**

LoRa-передача (+22 dBm) є найбільш енерговитратною операцією Soldier-вузла. Якщо показники метаболізму дерева **суттєво не змінилися** з моменту останньої передачі (знаходяться в межах «нечіткої похибки»), MCU **не вмикає LoRa-передавач** — зберігаючи критичний запас енергії в іоністорі.

**Зв'язок з Публікаціями Порубльова (2020, 2025)**

Його дослідження нечіткого пошуку та порівняння рядків (fuzzy string matching) адаптуються для порівняння векторів телеметрії:

```c
// Псевдокод для firmware/soldier/main.c (Phase 2.5 — перед Phase 4 TX):
// SENSOR_OFFSET = 4  (байти 0-3: заголовок + DID; сенсорні дані з байту 4)
// SENSOR_PAYLOAD_LEN = 12 (байти 4-15: delta_t, vcap, temp, acoustic, Lorenz)
// Повна розмітка пакету: firmware/soldier/main.c (21-байтовий формат)
bool should_transmit(uint8_t *new_pkt, uint8_t *last_pkt, uint8_t threshold) {
    uint8_t delta = fuzzy_distance(new_pkt + SENSOR_OFFSET,
                                   last_pkt + SENSOR_OFFSET,
                                   SENSOR_PAYLOAD_LEN);
    return delta > threshold; // TX лише якщо зміни суттєві
}
```

**Вимоги до алгоритму:**

- Час виконання: < 1 мс (не впливає помітно на цикл Soldier)
- RAM: < 128 байт (жорстке обмеження STM32WLE5JC)
- **Не застосовувати в PANIC-режимі** — при виявленні пилки/вогню TinyML → завжди TX
