# 02_03: BQ25570 MPPT та Нано-Менеджмент Живлення

---

## 🎯 Мета

Зафіксувати електричну схему, налаштування резистивних дільників та логіку роботи мікросхеми **BQ25570 MPPT** — єдиного менеджера живлення поточної архітектури. Документ описує конфігурацію восьми SMD-резисторів (VBAT_OV / VBAT_UV / VBAT_OK), відстежує виявлені проблеми з заводськими налаштуваннями Li-Po і встановлює цільові пороги для суперконденсатора 0.47F / 5.5V.

> **Архітектурна нотатка:** Step-up конвертер LTC3108 був **повністю виключений** із BOM під час ключового піво-ту (v2). Причина: EBFC вже генерує >500 мВ, що перевищує поріг Cold Start BQ25570 (330 мВ) — каскадний перетворювач LTC3108 більше не потрібен і видаляє 2 компоненти з плати.

Цей модуль є "травною системою" Солдата: він перетворює нестабільні мілівольти від біопаливного елемента (EBFC) на чисті 3.3V для STM32WLE5JC та LoRa-антени.

## ⚡ 1. Архітектурне Обґрунтування: Чому Спочатку Потрібен Був LTC3108?

### 1.1. Проблема Холодного Старту

Мікросхема BQ25570 — це надпотужний менеджер живлення, але вона має **фундаментальне обмеження**: для самостійного запуску (Cold Start) їй необхідна вхідна напруга не менше **330 мВ** та струм не менше 15 мкА.

Проблема: рання версія системи припускала, що EBFC на основі ксилемного потокового потенціалу генерує лише **44 мВ** (вимірювання на макеті з імітатором — резистивний дільник 3.3 кОм / 100 Ом від батарейки AA). Це в 7.5 разів менше, ніж потрібно BQ25570 для холодного старту.

### 1.2. Первісне Рішення: Каскад LTC3108 → BQ25570

Для подолання Cold-Start проблеми до системи був доданий **LTC3108** (Linear Technology / Analog Devices) — ультранизьковольтний підвищуючий конвертер, здатний стартувати від **20 мВ**:

```
Ранній прототип:
Tree Xylem (44mV)
      │
      ▼
┌─────────────┐     ┌──────────────┐     ┌─────────────┐     ┌──────────┐
│ LTC3108     │────▶│ BQ25570      │────▶│ 0.47F       │────▶│ LoRa-E5  │
│ Meissner    │     │ MPPT Manager │     │ Supercap    │     │ STM32    │
│ Oscillator  │     │ (CJMCU)      │     │ (5.5V)      │     │ WLE5JC   │
└─────────────┘     └──────────────┘     └─────────────┘     └──────────┘
  1:100 xfmr          488nA idle           4.145J @ 4.2V      2.1uA sleep
  330pF resonant       VOC sampling/16s    Energy buffer       +22dBm TX
```

LTC3108 використовував осцилятор Майснера (Meissner oscillator) на трансформаторі Coilcraft LPR6235-752SMRC (1:100) та резонансному конденсаторі 330 пФ для підняття 44 мВ до 3–5 В, достатніх для ініціалізації BQ25570.

**Недоліки каскаду LTC3108 → BQ25570:**
- +2 компоненти на платі: трансформатор (великий, дорогий) + LTC3108
- Зниження загального ККД (два каскади vs один)
- Збільшення площі плати ~40%
- Складніша збірка та налагодження

### 1.3. Архітектурний Пів'от

**Ключове відкриття:** Повноцінний EBFC Gen 2.0 на основі ферментів dgrFAD-GDH / Laccase + ZIF-nanozyme, іммобілізованих на гіроїдній поверхні Ti-6Al-4V, генерує **понад 500 мВ** — значно більше, ніж 44 мВ від простого ксилемного потокового потенціалу на металевих електродах без ферментів.

500 мВ > 330 мВ (поріг Cold-Start BQ25570) → **LTC3108 більше не потрібен!**

```
Поточна архітектура (Post-Pivot):

Tree EBFC (>500mV)
      │
      ▼  VIN_DC (>500mV, типово 500–800mV)
┌──────────────────────────────────────────────┐
│  BQ25570 (Power Management IC)               │
│  CJMCU-25570 breakout module                 │
│  - Cold Start: OK (330mV порог перекрито)    │
│  - MPPT: VOC sampling / 16s                  │
│  - Boost Charger → VSTOR (до 5.5V)          │
│  - Buck Converter → VOUT (3.3V стабілізовано)│
│  - VBAT_OK → GPIO STM32 (дозвіл пробудження)│
└───────────────────┬──────────────────────────┘
                    │
                    ▼  VSTOR (накопичення)
           [ Supercapacitor 0.47F / 5.5V ]
                    │
                    ▼  VOUT (3.3V, до 100 mA)
           [ STM32WLE5JC + SX1262 LoRa ]
```

**Результат пів'оту:**
- Видалено LTC3108, трансформатор 1:100 та резонансний конденсатор 330 пФ
- Зменшення BOM на 3 компоненти
- Зменшення площі плати ~40%
- Підвищення загального ККД (один каскад замість двох)
- Спрощення налагодження

### 1.5. Cold-Start під Навантаженням: Ризик R_int EBFC (та мітигація)

> Перенесено з колишнього BLOCKER-3 (трекінг — [`00_08 HW.13`](00_08_Action_Plan_Tracker)). Видалення LTC3108 (вище) спирається на V_OC ≥ 500 мВ — але cold-start charge pump BQ25570 тягне ≥ 15 µA, і під навантаженням V просідає за R_int.

EBFC має значний внутрішній опір (dgrFAD-GDH on Ti gyroid Gen 2.0 у синтетичному соку: R_int ≈ 5–20 кΩ). V_drop = I_load × R_int:

```
R_int = 10 кΩ → V_drop = 150 мВ → V_actual = 350 мВ (вузько над 330)
R_int = 15 кΩ → V_drop = 225 мВ → V_actual = 275 мВ ❌
R_int = 20 кΩ → V_drop = 300 мВ → V_actual = 200 мВ ❌
```

**Threshold:** charge pump ≈ R_load_eq = 350мВ/15µA = 23.3 кΩ. Умова `V_OC × R_load_eq/(R_int+R_load_eq) ≥ 330 мВ` → **R_int ≤ 12.0 кΩ** для гарантованого cold-start. Половина діапазону 5–20 кΩ провалюється → **oscillation loop** (charge pump вмикається@500мВ → просідає <330 → вимикається → відновлюється → …; supercap ніколи не сягає 1.8 В MPPT-boost).

**Мітигація (пріоритизовано):**
- **Lab (обов'язково):** виміряти R_int двома точками — V_OC та V@15µA (резистор 23.3 кΩ); R_int = (V_OC − V_loaded)·23.3/V_loaded. Запит у [`08_06`](08_06_CHMA_Biomedical_Integration).
- **A (рекоменд., якщо R_int > 12 кΩ):** серійний стек 2× EBFC → V_OC = 1.0 В → R_int_max ≤ 47.3 кΩ (comfortable). Сумісно з anchor stacking ([`01_03 §5.1`](01_03_EBFC_Enzymatic_Bio_Fuel_Cell)). +1 анкер.
- **B:** 2× анкери паралельно → R_int /2 (потребує узгоджених V_OC).
- **C:** LTC3108 cold-start preboost у **DNP footprint** (pads лишити, паяти лише для проблемних анкерів).

⚠️ До lab-перевірки R_int — **не замовляти 100 шт. PCBA без DNP-footprint LTC3108**.

## 🔌 2. Опис Пінів BQ25570

### VSTOR

**Призначення:** Підключення до суперконденсатора (накопичувач енергії).

```
VSTOR ── [0.47F / 5.5V Supercapacitor] ── GND
```

- **Діапазон:** 0V (повний розряд) до 5.5V (максимум суперконденсатора)
- **Логіка:** Boost-конвертер "перекачує" заряд з EBFC до VSTOR, поступово піднімаючи напругу від 0V
- **Захист:** VBAT_OV (Overvoltage) = 5.5V — при досягненні мікросхема зупиняє заряд
- **Firmware relevance:** `vcap_voltage` в 21-байтному пакеті (bytes 5–6) = напруга на VSTOR, виміряна ADC STM32

### VOUT

**Призначення:** Стабілізований вихід для живлення мікроконтролера та LoRa-трансивера.

```
VSTOR ──[Internal Buck]──▶ VOUT (3.3V) ──▶ STM32WLE5JC VDD
                                       ──▶ SX1262 LoRa Radio
```

- **Значення:** 3.3V (програмується резисторами ROUT1/ROUT2)
- **Максимальний струм:** 100 mA (постійний)
- **Пікове навантаження:** LoRa TX +22 dBm потребує до 118 mA → необхідний Buffer Cap (розділ 5)
- **Увімкнення:** Тільки коли VSTOR > VBAT_OK threshold (3.4V) → VBAT_OK = HIGH
- **Quiescent Current Buck:** входить до загального IQ = 488 nA (в режимі очікування)

### VBAT_OK

**Призначення:** Логічний вихід-дозволювач для пробудження STM32WLE5JC.

```
BQ25570 VBAT_OK ──▶ STM32 GPIO (EXTI або wake-up pin)
```

**Логіка спрацьовування (гістерезис):**

| Умова | Напруга VSTOR | VBAT_OK | Стан MCU |
|---|---|---|---|
| Іоністор заряджається | < 3.4V | LOW (0V) | STOP2 (глибокий сон) |
| Іоністор досяг порогу | ≥ 3.4V | HIGH (3.3V) | Дозвіл пробудження |
| Іоністор розряджається | > 3.32V | HIGH | MCU продовжує роботу |
| Іоністор критично сів | < 3.32V (~97% від 3.4V) | LOW → HIGH (гіст.) | MCU засинає (STOP2) |

**Гістерезис** (~3%, вбудований в BQ25570) запобігає швидкому перемиканню при граничній напрузі ("дрижання" / chatter).

**У Firmware:** STM32 виходить з STOP2 після апаратного переривання на піні VBAT_OK (через HAL_PWR_EnableWakeUpPin або EXTI rising edge).

## 🏗️ 3. Внутрішня Архітектура BQ25570

BQ25570 об'єднує три незалежні підсистеми в одному чіпі:

### 3.1. Cold Start Circuit (Система Холодного Старту)

**Умова активації:** VIN > 330 мВ та IIN > 15 мкА (наш EBFC: VIN ≈ 500–800 мВ → ✅)

- Спрощена "накачувальна помпа" (charge pump) з низьким пороговим струмом
- Заряджає VSTOR від 0V до ~1.8V (без MPPT, просто "накачує")
- При VSTOR ≥ 1.8V — вмикається основний Boost-конвертер (MPPT)

**Для нашої системи:** після місяців зберігання на складі або після повного розряду, достатньо буде навіть мінімального зимового EBFC-струму для запуску Cold Start.

### 3.2. Boost Charger з MPPT (Підвищуючий Зарядний Конвертер)

**Принцип роботи MPPT (Maximum Power Point Tracking):**
- Кожні **16 секунд** BQ25570 на **256 мс** від'єднує навантаження (EBFC "дихає")
- Вимірює VOC (Open Circuit Voltage) — напругу без навантаження
- Встановлює робочу точку: V_MPP = ROC_fraction × VOC
- Для нашого 50% налаштування: V_MPP = 0.5 × VOC

**Чому важливий MPPT для EBFC:** EBFC має нелінійну характеристику P-V (потужність-напруга). Без MPPT система може "пристрілятися" в неоптимальній точці і видавати в 2–3 рази менше потужності.

### 3.3. Buck Converter (Понижуючий Стабілізатор)

- **Вхід:** VSTOR (0–5.5V, нестабільна)
- **Вихід:** VOUT = 3.3V (стабілізована, до 100 mA)
- **Quiescent Current:** 488 нА (в режимі без навантаження — критично для бюджету)
- **Увімкнення:** Тільки при VSTOR > VBAT_OK threshold

## 🧮 4. Розрахунок Програмуючих Резисторів

BQ25570 програмується виключно апаратно через SMD-резистори (допуск **1%**, рекомендований розмір **0402**).

**Базова формула (V_REF = 1.21V, внутрішній опорний):**

```
V_threshold = V_REF × (1 + R_upper / R_lower)
```

### А. MPPT Sampling Fraction

**Ціль:** 65% від VOC (рекомендована початкова точка для EBFC Gen 2.0 на базі dgrFAD-GDH / Laccase+ZIF-nanozyme, див. BLOCKER-2)

> **Попередня конфігурація (50%)** наведена нижче для порівняння. Для лабораторних тестів починати з 65%.

#### 🔒 SSOT Convention — узгоджено з TI BQ25570 datasheet (SLUSBH2G, березень 2019, §8.2.3.2, Figure 42)

| Позначення | Розташування у схемі | Призначення |
|---|---|---|
| **R_OC1** | Резистор від піна **VOC_SAMP до GND** (нижнє плече) | Задає фракцію MPPT |
| **R_OC2** | Резистор від **CSTOR/VSTOR до піна VOC_SAMP** (верхнє плече) | Доповнення до RSUM |

```
MPPT_fraction = V_MPP / V_OC = R_OC1 / (R_OC1 + R_OC2)
```

> ⚠️ **Anti-Footgun:** Імена R_OC1/R_OC2 у деяких неофіційних tutorials та EE-форумах інвертовані. Якщо інженер запаяє значення за зворотньою конвенцією — **фракція стане 35% замість 65%**. Це загнало б ферментативну MPP у зону масо-транспортних обмежень (літ. Vargaftik для FAD-GDH/Laccase: P_drop до 60% при V < V_MPP). Завжди звіряти з TI datasheet Figure 42 та зведеною таблицею §5 цього документа.

**Конфігурація 65% (рекомендована для EBFC):**

| Компонент | Розташування | Значення | Допуск | Корпус |
|---|---|---|---|---|
| **R_OC1** | VOC_SAMP → GND | **10.0 MΩ** | 1% | 0402 |
| **R_OC2** | VSTOR → VOC_SAMP | **5.36 MΩ** | 1% | 0402 |
| MPPT fraction (actual) | — | 10.0 / (10.0 + 5.36) = **65.1%** | — | — |

**Перевірка за TI worked example (datasheet стор. 31):**

```
TI example: MPP = 40%, RSUM = 20 MΩ
  R_OC1 = (V_MPP/V_OC) × RSUM = 0.40 × 20 = 8.0  MΩ  ← нижній (до GND)
  R_OC2 = RSUM × (1 - V_MPP/V_OC) = 20 × 0.60 = 12.0 MΩ ← верхній (від VSTOR)
  Перевірка: 8 / (8+12) = 0.40 ✓

Наш випадок: MPP = 65%, RSUM = 15.36 MΩ
  R_OC1 = 0.65 × 15.36 = 9.98 MΩ → 10.0 MΩ standard 1%
  R_OC2 = 15.36 × 0.35 = 5.38 MΩ → 5.36 MΩ standard 1%
  Перевірка: 10 / (10+5.36) = 0.651 ✓ (65.1%)
```

**Конфігурація 50% (поточна, для порівняння/TEG):**

| Компонент | Розташування | Значення | Допуск | Корпус |
|---|---|---|---|---|
| R_OC1 | VOC_SAMP → GND | **10.0 MΩ** | 1% | 0402 |
| R_OC2 | VSTOR → VOC_SAMP | **10.0 MΩ** | 1% | 0402 |
| MPPT fraction (actual) | — | **50.0%** | — | — |

> ⚠️ **BLOCKER-2:** Фінальний коефіцієнт потребує емпіричного визначення з P-V кривою EBFC. Почати з 65%, при масо-транспортних обмеженнях знизити до 60%.

### Б. Overvoltage Protection

**Ціль:** VBAT_OV = **5.5V** (максимальна напруга суперконденсатора 0.47F/5.5V)

```
VBAT_OV = 1.21 × (1 + ROV1/ROV2) = 5.5V
1 + ROV1/ROV2 = 5.5 / 1.21 = 4.545
ROV1/ROV2 = 3.545

Вибираємо ROV2 = 4.75 MΩ (E96):
ROV1 = 3.545 × 4.75 = 16.84 MΩ → 16.9 MΩ (E96)

Перевірка: 1.21 × (1 + 16.9/4.75) = 1.21 × 4.558 = 5.515V ≈ 5.5V ✓
```

| Компонент | Значення | Допуск | Корпус |
|---|---|---|---|
| ROV1 | **16.9 MΩ** | 1% | 0402 |
| ROV2 | **4.75 MΩ** | 1% | 0402 |
| VBAT_OV (розрах.) | **5.52V** | ±55 мВ (1%) | — |

> ⚠️ **BLOCKER-1:** Ці значення потребують фізичної верифікації на CJMCU-25570 модулі. Дефолтні резистори модуля налаштовані на Li-Po (~4.2V OV), що не підходить для нашого 5.5V суперконденсатора!

### В. Undervoltage Protection

**Ціль:** VBAT_UV = **3.0V** (критичний розряд — нижче цього BQ25570 вимикає VOUT та VBAT_OK)

```
VBAT_UV = 1.21 × (1 + RUV1/RUV2) = 3.0V
1 + RUV1/RUV2 = 3.0 / 1.21 = 2.479
RUV1/RUV2 = 1.479

## 🛡️ 6. Апаратний Хак: Buffer Cap для Піку LoRa TX

**Проблема:** Buck-конвертер BQ25570 видає максимум **100 mA** постійного струму. Під час відправки пакету LoRa на максимальній потужності (+22 dBm) трансивер SX1262 споживає **118 mA** (пік ~100 мс). Різниця 18 мА може спричинити просадку напруги (Brownout) та скидання STM32.

> **⚠️ Залежить від рішення TX power у §9.** Якщо в §9 буде закріплено TX-power +14 dBm (рекомендовано для позитивного енергобалансу), то I_TX ≈ 40 mA < 100 mA buck max → **buffer cap не потрібен для brownout protection**, але залишається корисним для PSRR і фільтрації. У такому разі — 47µF 16V X7R 1210.

### 6.1. Реалістичний DC Bias Derating (виправлено)

> **⚠️ Критична правка специфікації:** Рання версія документа казала «DC bias derating для X5R: ~20% при 3.3V/6.3V» — це **сильно недооцінено**. Реальні дані з Murata GRM32 series datasheet (1210 corpus):

| Part | C@0V | C@3.3V | Derating | Eff. capacitance |
|---|---|---|---|---|
| 100µF, **6.3V**, X5R, 0603 (GRM188R60J107M) | 100 µF | ~15-25 µF | **-75 to -85%** | ❌ Brownout risk |
| 100µF, **6.3V**, X5R, 0805 | 100 µF | ~30-40 µF | -60 to -70% | ❌ Marginal |
| 100µF, **6.3V**, X5R, 1210 (GRM32ER60J107M) | 100 µF | ~45-55 µF | -45 to -55% | ⚠️ На межі |
| 100µF, **25V**, X7R, 1210 (GRM32ER70J107M) | 100 µF | ~85-90 µF | **-10 to -15%** | ✅ **Recommended** |
| 47µF, **25V**, X7R, 1210 | 47 µF | ~38-42 µF | -10 to -15% | ✅ Достатньо для +14 dBm |

**Корінь проблеми:** DC bias derating нелінійно залежить від (а) корпусу (товщина діелектрика — більший корпус = більша товщина = менший field), (б) voltage rating (25V part при 3.3V працює у 13% від номінальної напруги — мінімальний derating), (в) діелектрика (X7R стабільніший за X5R).

### 6.2. Специфікація (2 конфігурації залежно від TX power)

**Конфігурація A — TX +22 dBm (118 mA pulse):**

```
VOUT (3.3V) ──┬── [STM32WLE5JC 3V3 pin]
              │
              ├── [100 µF, 25V, X7R, 1210, low-ESR]
              │       Murata GRM32ER70J107M або аналог
              │       C_eff @ 3.3V ≈ 85 µF
              ├── [10 µF, 25V, X7R, 0805]     ← мід-частотний фільтр
              ├── [100 nF, 50V, X7R, 0402]    ← HF decoupling біля STM32 VDD pin
              │
             GND
```

ΔV during 100ms TX: ΔV = (118-100)mA × 100ms / 85µF = **21 мВ** ✓ (< 50 мВ tolerance)

**Конфігурація B — TX +14 dBm (40 mA, рекомендована, див. §9):**

```
VOUT (3.3V) ──┬── [STM32WLE5JC 3V3 pin]
              ├── [47 µF, 25V, X7R, 1210]    C_eff ≈ 40 µF
              ├── [10 µF, 25V, X7R, 0805]
              ├── [100 nF, 50V, X7R, 0402]
              │
             GND
```

При I_TX = 40 mA < 100 mA buck max → конденсатор не покриває пік, а лише фільтрує. ΔV пренебрежимо.

### 6.3. Жорсткі правила

- ✅ **MLCC X7R** (не X5R) — кращі температурна стабільність та DC bias performance
- ✅ **Voltage rating ≥ 4× робочої напруги** (для 3.3V → 25V part). Це найдешевший спосіб зменшити DC bias derating до прийнятних -15%.
- ✅ **Корпус 1210** для основного бункерного cap (більший корпус = тонший field at 3.3V)
- ❌ **6.3V parts заборонені** незалежно від корпусу — DC bias знищує половину ємності
- ❌ **Корпус 0603/0805 для основного buffer cap заборонений** — derating -65 до -85%
- ❌ **Танталові капи** — leakage 1-10 µA знищує енергобюджет (`/per §9`)

> **Чому НЕ просто 2× 47µF паралельно замість 100µF:** Це OK варіант (нижчий ESR, redundancy), але займає 2× місця на PCB і не дає виграшу в effective capacitance — два 47µF 25V X7R 1210 дають ~80 µF при 3.3V, що еквівалентно одному 100 µF 25V X7R 1210 (~85 µF). Залишити як option для high-reliability batches.

## 🔋 7. Логіка VBAT_OK: Коли Мікроконтролер Прокидається?

Сигнал `VBAT_OK` від BQ25570 — це апаратний "дозволювач" для STM32. Він реалізує принцип "Нульового Лагу": MCU не витрачає жодної енергії на опитування напруги — BQ25570 сам повідомляє коли готовий.

```
Часовий графік (типовий цикл):

0 год      0.5 год     0.75 год    1+ год
│          │           │           │
│ Холодний ▼ VSTOR     ▼ VBAT_OK   ▼ LoRa TX
│  старт   зростає     стає HIGH   цикл починається
│ (EBFC)   (0→3.4V)   (MCU BOOT)   (через 15-30 хв першого заряду)
│
└── VBAT_OK ──LOW (MCU = STOP2) ──────────────▶ HIGH ──── MCU активний
                                                       (VSTOR ≥ 3.4V)
```

**Поведінка в реальних умовах:**
- **Після монтажу (свіжий супер-кап, 0V):** BQ25570 Cold-Start → VSTOR повільно зростає → через 15–30 хвилин досягає 3.4V → VBAT_OK = HIGH → STM32 завантажується вперше
- **Нічна робота (низький EBFC-струм):** VSTOR може повільно падати → при VSTOR < 3.31V → VBAT_OK = LOW → STM32 переходить у STOP2 → зберігає стан у RTC Backup registers
- **Відновлення зранку:** Сонце прогріває ліс → EBFC-струм зростає → VSTOR знову перевищує 3.4V → VBAT_OK = HIGH → STM32 відновлює роботу

**Критичний пороговий ланцюжок:**
```
EBFC (>500mV) → BQ25570 Boost → VSTOR ≥ 3.4V → VBAT_OK HIGH
                                              → Buck ON → VOUT = 3.3V
                                              → STM32 GPIO interrupt → Wakeup from STOP2
                                              → Firmware Phase 1: SENSE
```

## ⚡ 9. Розрахунок Енергетичного Балансу (з урахуванням ККД)

> **⚠️ Критична переробка v2:** Попередня версія робила лінійний розрахунок без ККД boost+buck. Це призвело до помилкового висновку «1 TX/год = в плюсі». При реалістичних ККД система **виходила в мінус на 54 мДж/год**. Нижче — повний перерахунок з ККД per-stage та три рішення, що повертають баланс у плюс.

### 9.1. ККД BQ25570 — точні значення (TI datasheet SLVSBH2)

**Boost path (EBFC → VSTOR):**

| Робоча точка | I_IN | η_boost |
|---|---|---|
| P_EBFC=15 µW @ V_OP=325 мВ | ~46 µA | **~0.68** |
| P_EBFC=30 µW @ V_OP=325 мВ (2× площа) | ~92 µA | ~0.75 |
| P_EBFC=100 µW (winter peak) | ~300 µA | ~0.82 |

**Buck path (VSTOR=4.5V avg → VOUT=3.3V):**

| Режим | I_OUT | η_buck |
|---|---|---|
| Active TX/compute | 30–120 mA | **~0.88** |
| Idle (RTC + DMA) | ~1 µA | **~0.50** (quiescent overhead dominates) |

### 9.2. Генерація з урахуванням boost ККД

```
P_gen     = 15 µW   (typical Gen 2.0 EBFC, P_sapwood @ 15°C summer)
t         = 3600 s
E_gen_raw = 54 мДж  (raw на вході BQ25570)
η_boost   = 0.68
E_gen_supercap = 54 × 0.68 = 36.7 мДж/год  ← реальна енергія в supercap
```

### 9.3. Sleep Drain з ККД buck (low-load efficiency hit)

```
P_STM32_sleep_at_VOUT = I_STM32_STOP2 × V_OUT = 1.07 µA × 3.3 V = 3.531 µW
P_drawn_from_VSTOR    = P_STM32_sleep / η_buck_sleep = 3.531 / 0.50 = 7.06 µW

P_BQ_Q (з VSTOR безпосередньо, не через buck) = 488 nA × 4.5 V = 2.196 µW

P_total_VSTOR_drain   = 7.06 + 2.20 = 9.26 µW
E_sleep_supercap      = 9.26 × 3600 = 33.3 мДж/год  ← у 1.87× більше за лінійну оцінку!
```

### 9.4. Cost of Active Cycle з ККД buck active

```
E_active_at_VOUT:
  TinyML:       12 mA × 3.3 V × 0.2 s  = 7.92 мДж
  mruby Lorenz:  8 mA × 3.3 V × 0.15 s = 3.96 мДж
  LoRa TX@+22dBm: 118 mA × 3.3 V × 0.1 s = 38.94 мДж
  ─────────────────────────────────────
  Σ E_active_at_VOUT = 50.82 мДж/cycle

η_buck_active = 0.88
E_active_from_VSTOR = 50.82 / 0.88 = 57.75 мДж/cycle
```

### 9.5. Net Balance — поточна конфігурація (+22 dBm, 1 TX/год) ❌

```
E_net_per_hour = E_gen_supercap − E_sleep_supercap − N_TX × E_active_from_VSTOR
              = 36.7 − 33.3 − 1 × 57.75 = −54.35 мДж/год

ВИСНОВОК: система втрачає 54 мДж на кожному циклі.
Supercap розрядиться за: 7.11 Дж / 54.35 мДж = 131 цикл = 5.5 діб → reset.
```

### 9.6. Три Сценарії Виправлення

#### Сценарій A — Просто збільшити інтервал TX (не працює)
```
H = E_active / (E_gen − E_sleep) = 57.75 / (36.7 − 33.3) = 17 годин
```
17 годин між пакетами — неприйнятно для моніторингу здоров'я лісу.

#### Сценарій B — Знизити TX power з +22 до +14 dBm
SX1262 @ +14 dBm: I_TX ≈ 40 mA (datasheet, vs 118 mA @ +22 dBm).
**Trade-off:** -8 dB TX power → -8 dB link margin → знижене покриття. Компенсація: підняти SF (з SF7 на SF9-SF10) → +5 dB sensitivity на gateway, що частково компенсує. Air-time зростає (SF9 ≈ 165 ms замість 110 ms @ SF7).

```
E_TX_+14dBm = 40 mA × 3.3 V × 0.165 s = 21.78 мДж  (SF9 air-time)
E_active_at_VOUT = 7.92 + 3.96 + 21.78 = 33.66 мДж
E_active_from_VSTOR = 33.66 / 0.88 = 38.25 мДж

H = 38.25 / (36.7 − 33.3) = 11.2 години  ← все ще багато
```

#### Сценарій C — +14 dBm TX + знижений STM32 sleep current (РЕКОМЕНДОВАНО)
Зменшити sleep STM32WLE5JC з 1.07 µA до ~300 nA через RTC-backup-only mode (SRAM2 retention OFF, тільки backup registers) — це підтримується LL_PWR_EnterStop2Mode з flag `STOP2_RTC_ONLY`:

```
P_STM32_sleep_at_VOUT = 300 nA × 3.3 V = 0.99 µW
P_drawn_from_VSTOR    = 0.99 / 0.50 = 1.98 µW
P_total_VSTOR_drain   = 1.98 + 2.20 = 4.18 µW
E_sleep_supercap      = 4.18 × 3600 = 15.04 мДж/год

H = E_active / (E_gen − E_sleep) = 38.25 / (36.7 − 15.04) = 1.77 години
```
✅ **1 TX кожні 1 год 46 хв** — близько до цільового 1/год циклу, позитивний баланс +1.4 мДж/год запасу.

#### Сценарій D — +14 dBm TX + 2× площа анкера (P_gen → 30 µW) + RTC-only sleep
```
E_gen_supercap = 30 × 3600 × 0.75 = 81 мДж/год
H = 38.25 / (81 − 15.04) = 0.58 години = 35 хв
```
✅ **1 TX кожні 35 хв** — оптимально для real-time моніторингу.

### 9.8. Рішення для Архітектури

**Затверджено для v3:**
1. **TX power +14 dBm @ SF9** замість +22 dBm @ SF7 (Сценарій C). Залежить від реального link budget Queen↔Soldier — потребує польового тесту на полігоні (запит до `02_02 / 10_xx`).
2. **STM32WLE5JC STOP2 RTC-only mode** — sleep current 300 nA замість 1.07 µA (firmware change у `03_01_Firmware_Lifecycle_and_DMA`).
3. **Buffer cap §6:** 47µF 25V X7R 1210 (Конфігурація B) — достатньо для +14 dBm pulse.
4. **Цільовий цикл:** 1 TX / 1.5–2 години — `mruby BioContract` адаптивно подовжує інтервал у зимовий період.

**Roadmap до Сценарію D (TRL 6+):** Експерименти з 2× anchor configuration (`01_03 §5.1`) — паралельне з'єднання двох анкерів у одному дереві → P_gen ~30 µW → TX кожні 35 хв.

> ⚠️ **Сезонність:** P_gen = 15 µW — typical для літа. У зимовий період P_gen падає до 3–5 µW. У Сценарії C при P_gen=5 µW:
> ```
> E_gen_winter = 5 × 3600 × 0.65 (η_boost lower at lower I_IN) = 11.7 мДж/год
> Sleep тільки: 15.04 мДж/год → НЕГАТИВ навіть без TX
> ```
> → Зимовий режим: повне відключення MCU sleep current через PFET cut-off, TX лише при VSTOR ≥ 5.0V (накопичення кілька днів). Деталі — ARCH.8 "мовчання = здоров'я" та `02_05_Queen_Hardware_and_Starlink` HW.14.

### 9.9. Fauna Acoustic Overlay (ARCH.39 — поза baseline TX-циклом)

Енергобаланс §9.4–9.7 рахує **лише** baseline TX-цикл (sense → Lorenz → 1 TX). Fauna-акустичні сесії (TinyML biodiversity inference, `03_03 §10.3` / ARCH.39) — **окрема активність поверх** нього:

```
E_fauna_session ≈ 78.3 мДж     (~12 мА × 1.56 с active CPU: 156 MFCC+inference вікон, через η_buck)
E_fauna_daily   ≈ 156.6 мДж/добу (~2 сесії/добу) — × 20 від застарілої оцінки 3.3 мДж/добу
```

Це **перевищує** запас Сценарію C (+1.4 мДж/год ≈ +33.6 мДж/добу), тож fauna **не може** бути гарантованою щоденною статтею бюджету. SSOT-рішення:

1. **Opportunistic-only:** fauna-сесія запускається **лише** коли `V_cap ≥ FAUNA_VCAP_MIN_MV` — guard `Fauna_Should_Sample()` (**FW.42**). Fauna споживає **профіцит**, не baseline.
2. **Транзієнт:** пік ~12 мА × 1.56 с потребує V_cap margin над `VBAT_OK ON`, інакше brownout посеред inference (звідси guard, а не просто лічильник).
3. Baseline TX-бюджет (Сценарій C) **лишається чинним без змін** — fauna не входить у H-розрахунок інтервалу TX.

Cross-ref: ARCH.39 (`03_03 §10.3`), FW.42 (V_cap guard), ARCH.40 (монолітна 5-с сесія через SRAM2-wipe constraint).

## 🧪 10. Лабораторна Валідація (Production Breadboard, Post-Pivot)

> **Інструкція з лабораторного breadboard-тестування з реальним EBFC або його еквівалентом** — без LTC3108 і без 44 мВ-симулятора. Виробничий стенд = тільки те, що буде на PCB.

### 10.1. Compact Wiring (без LTC3108)

```
EBFC (Ti-6Al-4V anchor)  >500 мВ
       │
       ▼
┌──────────────────────┐
│ CJMCU-25570 (BQ25570 breakout, резистори перепрограмовано — §4)
│  VIN_DC ←── EBFC анод+катод
│  VSTOR  ──→ [0.47F / 5.5V Supercap, Eaton/KEMET]
│  VOUT   ──→ [STM32WLE5JC + SX1262 → LoRa-E5 mini]
│  GND    ──→ common ground rail
└──────────────────────┘
       │
       └── Buffer caps на VOUT (§6.2 Конф. B): 47µF/25V/X7R/1210 + 10µF/25V + 100nF
```

### 10.2. Альтернативне Lab-Джерело (для відсутності живого EBFC)

Замість 44 мВ-симулятора через дільник напруги — використати **програмований source-meter (Keithley 2400 або еквівалент)** у режимі «emulated EBFC»:
- V_OC = 500 мВ (program voltage source)
- Series R = 10 кΩ (симуляція R_int EBFC; за потреби — підняти до 15-20 кΩ для stress-test BLOCKER-3)
- Поведінкова крива: лінійна VR-характеристика; за потреби — Tafel-curve через Python script на SCPI

Це дозволяє відтворити cold-start loop, MPPT tracking та аналіз TX просадки **без LTC3108 у тестовому setup**, оскільки виробнича схема його не має.

### 10.3. Legacy Educational Setup

Для студентських лабораторних робіт (ЧНУ, демонстрація принципу 44мВ→3.3V) — окремий навчальний breadboard на LTC3108 + AA + Coilcraft xfmr — задокументовано в окремому додатку:

→ **[`02_03_appendix_legacy_breadboard`](02_03_appendix_legacy_breadboard)** (legacy LTC3108-based, 44 мВ симулятор, тільки для освіти)

### 10.4. Тестовий Запуск з Реальним EBFC

1. Зібрати compact wiring §10.1
2. Виміряти V_OC EBFC мультиметром (без навантаження) — має бути ≥ 500 мВ
3. Виміряти R_int за двома точками (`BLOCKER-3 §test`) — має бути ≤ 12 кΩ
4. Підключити EBFC до VIN_DC; supercap @ 0V
5. Спостерігати VSTOR через осцилограф або мультиметр: ramp up 0 → 1.8V (cold start) → 3.4V (VBAT_OK HIGH) → 5.5V (OV stop)
6. Час до першого VBAT_OK: 15–60 хв при P_gen=15 µW
7. Перевірка просадки VOUT під час TX:
   - Запустити firmware test `firmware/test/test_tx_burst.c` (1× LoRa TX @ +14 dBm)
   - Осцилограф на VOUT — ΔV має бути < 50 мВ
