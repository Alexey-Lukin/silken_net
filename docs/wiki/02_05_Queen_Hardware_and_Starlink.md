### 🔴 BLOCKER-1: STM32WLE5JC не має TCP/IP стеку — фізичний міст до Starlink відсутній

**Статус:** Відкрито. Критична архітектурна "сліпа пляма" для Phase 3 (Starlink).

**Суть проблеми:**

STM32WLE5JC — це мікроконтролер з інтегрованим LoRa (SX1262) радіомодулем. Він **не має** апаратного Ethernet MAC-контролера та **не має** WiFi-інтерфейсу. Єдиний зовнішній комунікаційний інтерфейс у поточній прошивці — `UART1`, підключений до SIM7070G через AT-команди:

```c
// firmware/queen/main.c:53
UART_HandleTypeDef huart1;  // Інтерфейс для модему SIM7070G (LTE-M / Starlink)
```

Starlink Mini (Phase 3) забезпечує підключення через **Ethernet** або **WiFi** (802.11n 2.4GHz/5GHz). Але STM32WLE5JC не може підключитися до жодного з цих інтерфейсів напряму.

**Що записано в поточному Wiki (застаріло):**

> _"Інтегрується через Ethernet/Wi-Fi міст з мікроконтролером (наприклад, через додавання ESP32-S3 як співпроцесора для TCP/IP стеку)."_

**Що є насправді у firmware:** У `firmware/queen/main.c` відсутній будь-який код для ESP32-S3 або іншого TCP/IP співпроцесора. Функція `Flush_Cache_To_Rails()` використовує **виключно** `SIM7070G` через UART:

```c
// firmware/queen/main.c:542
SIM7070_SendATCommand("AT+CCOAPNEW=\"coap://api.silkennet.com:5683\"\r\n", 1000);
```

**Висновок аудиту:** Архітектурно ESP32-S3 як WiFi/Ethernet міст для Starlink — **анонсована, але не реалізована концепція**. Для Phase 1/2 (SIM7070G LTE-M) поточна архітектура повністю функціональна. Для Phase 3 потрібен або окремий SoC з TCP/IP стеком, або перехід на модем з вбудованим Starlink-адаптером.

**Необхідна дія:**

- Прийняти архітектурне рішення: ESP32-S3 як UART-to-WiFi шлюз, або модем SIM8200G-M2 з інтегрованим WiFi, або інший підхід.
- Описати рішення в `03_02_Queen_Gateway_Firmware` та оновити апаратну схему.
- Додати прошивку ESP32-S3 або AT-команди WiFi-модему в `firmware/` перед Phase 3 деплоєм.

**Блокує:** Phase 3 Starlink інтеграція, Planetary Scale розгортання.

### 🔴 BLOCKER-2: Зимовий Енергетичний Дефіцит (Phase 3 Starlink)

**Статус:** Відкрито. Критичний ризик автономності Королеви взимку.

**Розрахунок:**

| Параметр | Phase 1/2 (SIM7070G) | Phase 3 (Starlink) |
|---|---|---|
| Споживання MCU (idle Continuous RX) | 7 мА × 3.3V = 23 мВт | 23 мВт |
| Споживання модему (idle) | ~1 мА × 3.7V = 3.7 мВт | ~1 мА (WiFi idle) |
| Пік під час TX (1×/годину, ~5 сек) | 200 мА × 3.7V = 0.74 Вт | 20–40 Вт (Starlink) |
| Тривалість TX на добу | 5 сек × 24 = 120 сек = 0.033 год | 2–3 хв × 24 = 1.2 год |
| **Добова потреба** | **~0.8–2 Вт·год/добу** | **~26–50 Вт·год/добу** |

**Бюджет сонячної панелі (50W Monocrystalline):**

| Умови | Пікова інсоляція | Вироблення |
|---|---|---|
| Літо, чисте небо | 6 год × 50W × 80% eff | 240 Вт·год/добу ✅ |
| Зима, відкрите місце | 3 год × 50W × 80% eff | 120 Вт·год/добу ✅ |
| **Зима, хвойний ліс (крони 10–15%)** | **3 год × 50W × 12.5% eff** | **18.75 Вт·год/добу** |

**Висновок (Winter Phase 3):** 18.75 Вт·год/добу генерації **vs** 26–50 Вт·год/добу споживання → щоденний дефіцит **7.25–31.25 Вт·год**.

**Батарея LiFePO4 12V/20Ah:**

- Ємність: 12V × 20Ah = 240 Вт·год. Корисна (80% DoD для LiFePO4): **192 Вт·год**.
- Автономність при дефіциті 21 Вт·год/добу (Starlink 3 хв/год): **192 / 21 ≈ 9 днів**.
- Вимога (Wiki): "витримати 14 днів суцільної хмарності" → **НЕВИКОНАНА** при Starlink.

**Необхідна дія:**

- Або збільшити батарею до 40Ah (12V × 40Ah × 80% = 384 Вт·год → 18 днів автономності).
- Або встановити дві панелі 50W або одну 100W для локацій під кронами.
- Або скоротити Starlink duty cycle до 1 хв/годину (3× менше споживання) → ~9 Вт·год/добу. При генерації 18.75 Вт·год/добу **профіцит +9.75 Вт·год навіть взимку** ✅ → батарея заряджається, Королева автономна необмежено.
- Визначити максимально прийнятний duty cycle Starlink для різних кліматичних зон і зафіксувати в SSOT.

**Блокує:** Визначення розміру акумулятора та сонячної панелі. Блокує розрахунок Unit Economics (07\_02).

### 🟡 BLOCKER-4: Пікові струми SIM7070G — BMS не специфікований

**Статус:** Відкрито. Середня серйозність.

SIM7070G (або SIM7000G) у режимі LTE-M TX може споживати імпульсно до **2A** (пікове значення при +23 dBm TX). Батарея LiFePO4 12V/20Ah технічно витримує такий струм (розрядний C-рейтинг зазвичай 1–3С = 20–60А), але:

- **BMS (Battery Management System)** не специфікований в поточному BOM. Захист від перетоку має бути ≥ 5А (з 2.5× запасом).
- **Провідники від батареї до MPPT і від MPPT до навантаження** мають витримувати пікові 2А без значного падіння напруги (AWG16 або AWG18 для L < 30 см).
- **MPPT контролер** (наприклад, Victron SmartSolar 75/10) має пропускну здатність: `75V/10А max`. Вихідний струм 10А > 2А → достатньо ✅. Але конкретна модель MPPT не зафіксована в BOM.

**Необхідна дія:**

- Зафіксувати конкретну модель BMS: мінімум 12V / 20A continuous / 50A peak.
- Зафіксувати конкретну модель MPPT: мінімум Victron SmartSolar MPPT 75/15.
- Розрахувати падіння напруги на лінії живлення до модему при 2A піковому навантаженні.

**Блокує:** Фінальний BOM, підготовка до масового виробництва.

### 🟡 BLOCKER-5: Теплове управління в IP67 корпусі

**Статус:** Відкрито. Середня серйозність.

Під час CoAP flush (1 раз/годину) або Starlink сеансу Королева генерує тепло:

- MPPT контролер: ~5% втрати → при 30W зарядному струмі = 1.5W тепловиділення.
- SIM7070G під час TX: до ~500 мВт × 5 сек (нехтовно для теплового балансу).
- Starlink Mini (Phase 3): 20–40W → ~2–4W втрат в блоці живлення 12V→Starlink DC.

**Ризики в IP67 корпусі:**

- Відсутність вентиляції → тепло не відводиться примусово.
- Влітку при прямому сонці корпус може нагрітися до 60–70°C внутрішньої температури.
- SIM7070G: робочий діапазон -40°C до +85°C ✅. STM32WLE5JC: -40°C до +85°C ✅. Але LiFePO4 зарядка при T < 0°C пошкоджує батарею → потрібен температурний захист заряду.

**Необхідна дія:**

- Розрахувати тепловий бюджет корпусу для умов +40°C зовнішньої температури.
- Додати термодатчик (NTC або DS18B20) з підключенням до GPIO STM32 або MPPT контролера.
- Реалізувати апаратний захист заряду LiFePO4 при T < 0°C (блокування BMS або логіка MPPT).

**Блокує:** Сертифікація для Polish/Ukrainian winter deployment, надійність при екстремальних температурах.

### 🟡 BLOCKER-6: Відсутність IWDG (Watchdog) у Queen прошивці

**Статус:** Відкрито. Виявлено та задокументовано в [03\_01 Firmware Lifecycle](03_01_Firmware_Lifecycle_and_DMA) (BLOCKER-5). Дублюється тут як апаратний ризик.

**`firmware/queen/main.c:791`:**

```c
void Error_Handler(void) {
  __disable_irq();
  while (1) {}  // Вічний цикл — без IWDG Queen "заморожується" назавжди
}
```

На відміну від Солдата (який має IWDG), Queen не перезавантажується автоматично при HardFault. Фізичний перезапуск вимагає відключення живлення.

**Необхідна дія (апаратна частина):** Переконатися, що MPPT контролер або BMS **не блокує** повторну подачу живлення після hard reset. У деяких BMS є захист від "коротких увімкнень" — потрібно перевірити, чи не спрацює він при перезавантаженні STM32.

**Блокує:** Автономна робота у Production режимі без людського втручання.

## 📡 2. Інтерфейси Зв'язку (Communication Interfaces)

### 2.1 STM32WLE5JC ↔ LoRa-мережа (Uplink від Солдатів)

| Параметр | Значення |
|---|---|
| Протокол | Сирий LoRa (не LoRaWAN) |
| Частота | 868.0 МГц (EU ISM, `Radio.SetChannel(868000000)`) |
| Розмір пакету | 16 байт (один AES-256 блок) |
| Режим RX | Continuous (LORA\_RX\_INFINITE) |
| ISR | `OnRxDone()` — апаратне переривання від SX1262 |
| Обробка пакету | `Process_And_Cache_Data()` → CIFO kash (50 слотів) |

**CIFO Cache (Forest Cache):**

```c
// firmware/queen/main.c:87-97
typedef struct {
    uint32_t uid;        // DID дерева (4 байти)
    uint8_t  payload[16]; // Розшифровані дані сенсора
    int8_t   rssi;       // RSSI [dBm]
    uint8_t  is_active;
} EdgeCache;

EdgeCache forest_cache[50]; // 50 × 22 байти = 1.1 KB
```

**Flush trigger:** кожні 3600 сек (+0–60 сек HRNG jitter) АБО при заповненні ≥ 45/50 слотів.

### 2.3 STM32WLE5JC ↔ Starlink Mini (Phase 3: Planetary Scale)

**⚠️ Поточний стан: архітектурно визначено, але НЕ реалізовано у firmware.**

Starlink Mini — компактний термінал LEO-супутника (Low Earth Orbit). Специфікація:

| Параметр | Starlink Mini |
|---|---|
| Живлення | DC 12–48V (рекомендовано 12V від LiFePO4) |
| Споживання | **20–40 Вт** (типово ~23 Вт при активному сеансі) |
| Підключення | Ethernet (RJ45) **або** WiFi (802.11n, 2.4/5 GHz) |
| Латентність | 25–60 мс (LEO orbit) |
| Throughput | до 100 Мбіт/с DL / 10 Мбіт/с UL |

**Проблема:** STM32WLE5JC → Starlink вимагає проміжної ланки. Два варіанти (на вибір):

**Варіант А: ESP32-S3 як WiFi-co-processor (анонсований у Wiki)**

```
STM32WLE5JC ─[UART AT]─▶ ESP32-S3 ─[WiFi 802.11n]─▶ Starlink Mini
                           (TCP/IP stack)              (WiFi AP mode)
```

- ESP32-S3: підтримує WiFi + UART. Може діяти як WiFi-to-UART шлюз.
- Drawback: ESP32-S3 споживає ~80–240 мА додатково → ~300–900 мВт.
- **Потрібна прошивка для ESP32-S3** — відсутня в `firmware/`.

**Варіант Б: Модем з інтегрованим WiFi (наприклад, SIM8200G-M2)**

```
STM32WLE5JC ─[UART AT]─▶ SIM8200G-M2 ─[WiFi]─▶ Starlink Mini
```

- SIM8200G-M2 підтримує WiFi та 5G/LTE. Один UART-інтерфейс.
- Спрощує схему, але дорожчий та складніший у програмуванні.

**⚡ Duty Cycling Starlink (рекомендована стратегія):**

```
[55 хв: Starlink OFF — STM32 накопичує дані в CIFO Cache]
[5 хв: STM32 подає 12V на Starlink → очікує з'єднання (~30-60 сек) → flush → Starlink OFF]
```

Це дозволяє живити 20-Вт Starlink від невеликої сонячної панелі (~40 Вт·год/добу при 5 хв/год duty cycle).

## 📶 5. Топологія Uplink (LoRa → Modem → Rails)

Королева не тримає постійне з'єднання з сервером. Вся телеметрія **накопичується в SRAM** і відправляється батчем — це дозволяє вмикати енергозатратний модем лише на декілька секунд на годину.

```
[Ліс: 1–5000 дерев у радіусі 3–5 км]
           │ LoRa 868 МГц
           │ 16-байтні пакети (AES-256-ECB¹)
           ▼
[STM32WLE5JC: Continuous RX]
           │
           │ 1. OnRxDone ISR → AES-ECB decrypt → Process_And_Cache_Data()
           │ 2. CIFO cache: дедуплікація + priority-aware eviction
           │ 3. 50 слотів × 21 байт = 1050 байт компактного бінарного батча
           │
[Flush trigger: 1 год або 45/50 слотів заповнені]
           │
           │ 4. HRNG генерує 128-бітний IV
           │ 5. AES-256-CBC² шифрує весь батч (формат: [IV:16][Дані:N×16])
           │ 6. AT+CCOAPNEW + AT+CCOAPSEND → SIM7070G UART
           │
           ▼
[SIM7070G: LTE-M / NB-IoT]
           │ UDP / CoAP → IP мережа
           ▼
[coap://api.silkennet.com:5683]
           │ POST /telemetry/batch/<queen_uid>
           ▼
[Rails API → TelemetryUnpackerService → PostgreSQL]
           │ (партиціоновано по місяцях)
           ▼
[Sidekiq Workers: Lorenz Attractor → Growth Points → SCC mint]
```

**URI-Path формат:** `/telemetry/batch/<queen_uid>` — ідентифікація шлюзу за `queen_uid` (а не IP) вирішує проблему динамічних IP при роботі через Starlink NAT або LTE roaming.

> ¹ **AES-256-ECB (Soldier→Queen):** Кожен LoRa-пакет — рівно один 16-байтний AES-блок, тому ECB еквівалентний CBC (дифузія між блоками не застосовна). Використовується для швидкого дешифрування в ISR. Вразливий до replay та pattern-атак — задокументовано як BLOCKER у [03_05 Hardware AES256 and Security](03_05_Hardware_AES256_and_Security).
>
> ² **AES-256-CBC (Queen→Rails):** Батч із 50+ записів шифрується CBC з унікальним HRNG IV перед кожною відправкою. Це усуває ECB-вразливість для многоблокового payload. Сервер очікує формат `[IV:16][Зашифровані дані:N×16]`.

## 🛰️ 6. Чому Starlink для Phase 3? (Planetary Scale Rationale)

Ринок вуглецевих кредитів (VCM) вимагає моніторингу Амазонки, тайги та джунглів Екваторіальної Африки — де немає вишок 4G/LTE.

| Метрика | SIM7070G (Phase 1/2) | Starlink Mini (Phase 3) |
|---|---|---|
| Покриття | Лише де є LTE мережа | Глобальне (усі континенти) |
| Пропускна здатність | 375 кбіт/с (LTE-M) | 100 Мбіт/с |
| Латентність | 50–150 мс | 25–60 мс |
| Вартість | ~$10–30/міс | ~$50/міс |
| Споживання | ~370 мВт TX burst | 20–40 Вт continuous |
| Пікові струми | до 2А | до 3А (DC 12V @ 40W) |
| Придатність | Ukraine, EU deployment | Амазонка, Тайга, Африка |

**Економіка Scale (при 5000 дерев на Королеву):**

- Вартість Starlink: $50/міс ÷ 5000 дерев = **$0.01/дерево/міс**
- Цей рівень повністю вкривається емісією SCC-токенів (~10 growth\_points/день × 30 днів = 300 GP/міс = 0.03 SCC/міс на дерево).
