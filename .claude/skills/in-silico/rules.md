# In-silico critical rules — the bodies

> **Auxiliary file of the `in-silico` skill. Read this before running or changing DFT/MD, declaring an
> anchor dimension in a script, or quoting a literature constant.** The one-line index in `SKILL.md`
> §Critical Rules is the carrier; this file is the mechanism, the incident that bought it, and its
> bounds. Edit rules HERE — the index is generated (`ruby scripts/guard_craft_index.rb --write`).
>
> **Numbering is append-only** — the numbers are cited from the tracker, canon comments and memory
> (`in-silico §Critical Rules #9`); a retired rule keeps its number and says where its content went.
> The unnumbered **Practice** paragraph belongs to #9 and travels with it.

0. 🔴 **`conda env list` in a non-interactive shell answers about ITSELF, not about the machine — ask the FILESYSTEM.** The `conda` shell function is only defined by an interactive init, so a tool-driven Bash gets a stub that reports just `base`; reading that as «the env is not installed here» is a measurement substitution. **Roster:** `ls ~/miniforge3/envs/`. **Run a script without activation:** `~/miniforge3/envs/silken_md/bin/python scripts/NN_*.py` (same for `silken_lint`, `silken_ml`, `pymol_tmp`). (Proving that a cache regeneration changed only what you meant → §When Modifying #15.)

1. **Shared lib is SSOT — every SHARED or canon-mirrored constant, every cache root and `banner()` come from `lib/` and are never redefined locally.** A coefficient private to one script's model lives in that script, named and cited there (`55`'s `ENDURANCE_OVER_YIELD`); where to change which kind → §When Modifying #2.

2. **A SMILES fix cascades — fixing one in 02-08 means rerunning ALL downstream MD that uses that ligand** (check the GAFF cache too; the ligand → MD edges are the graph in `SKILL.md`).

3. **DFT: NEVER two heavy jobs on same CPU** — cache thrashing makes both 2× slower (observed: a 92-min solo job took 190+ min alongside another). Small molecules (H₂O, lumiflavin) OK to parallelize; MD-on-GPU alongside a CPU DFT job is fine (different hardware) — the hazard is two CPU-bound DFT jobs sharing cache.

4. **No density_fit() for Os/Ce — the auto-generated aux basis for heavy metals is 3× SLOWER than standard integrals.**

5. **Open-shell transition metals can oscillate forever — `level_shift=0.3` stops UKS on Os(III), Co-Ce and Ce, but it biases the reported LUMO, so switch it on only where the SCF oscillates and then read E_total, not LUMO.** Without it the oscillation ran 60h+. `lib.dft_utils.dft_singlepoint` therefore keeps the shift OFF by default (`level_shift_open=0.0`) and rescues a non-converged SCF with SOSCF (`mf.newton()`), which converges the hard case without biasing the virtual orbitals — a cascade Δ that reads the LUMO needs exactly that.

6. **MD goes NaN at the NVT ramp unless it pre-relaxes at 10K and ramps from 50K in 10K steps** — 10K pre-relaxation (1000 steps at 10K) + start NVT from 50K + ramp step 10K (not 5K); without it about half the multi-ligand runs NaN'd, worst at high T (313K). Use `maxIterations=10000` for minimization. ⚠️ **Scope: the production pattern of `12`/`14`/`15`** (`13` and `16` pre-relax at 10 K without a ramp; `10` and `11` predate the pattern and ramp from 100 K) — **NOT the CI smoke gate**, whose iteration cap #8 forbids raising.

7. **MD trajectories are gitignored — commit only the JSON/PNG summaries** under `cache/`; `cache/runs/` (trajectories, checkpoints) and the MD binary extensions are ignored by `tools/in_silico/.gitignore`.

8. **The CI smoke MD went NaN from BOX SIZE, not RNG — shrink the box (drop disordered tails), never just re-run or raise the iteration cap.** 🔴 Seeding is not the fix: with `seed=42` on BOTH the velocity draw and the Langevin thermostat it NaN'd anyway (run 34261017635, 2026-09-08) — seeding makes a run reproducible GIVEN the positions and cannot un-clash them. ⛔ Don't raise the minimisation cap without measuring: on the oversized box the capped minimisation alone ate most of the 40-min budget, so a higher cap trades a NaN for a timeout. The measurement and the fix (the disordered N-terminal tail dropped before solvation) live in the docstring of `01_smoke_test_water_box.py`. Verify a touch locally with the exact CI env: `SILKEN_FORCE_PLATFORM=CPU SILKEN_WATER_PADDING=0.5 SILKEN_MIN_ITERATIONS=500 SILKEN_MD_STEPS=100`.

9. 🔴 **Declaring an anchor dimension: name the REFERENT, not the number — and if canon gives a RANGE, say which end you took and why.** No VALUE gate binds these scripts' literal constants to canon geometry: a pin was measured and refused (`00_07` HW.45, founder 2026-09-09), because a copy taken from a different referent carries a TRUE canon number — it breaks the BINDING, not the equality, so every pin form is green on it (ground: `00_06 §2`). The carriers are this rule and `picogk` gotcha 0a; why a gate is blind here — `guard-craft` #155. **Live instance:** `54`'s `L_ANODE_GYROID` takes the LOWER end of the canon gyroid-length range while the CEM mirror and sibling `58` take a value inside it. 🔑 **If the number is not an END, say what it IS — a worked example · a design point · a vendor figure — and whose,** and read the CLAUSE you cite, not just its address: a design point mirrored as a floor once sat in both machine halves while both had checked only the address (`52`'s `RF_ANT_TI_CLEARANCE_MIN`, now labelled OUR working floor beside the canon one). 🔴 **The referent can be wrong by AXIS while both ends are quoted correctly** — `50` compared the lattice with wood's LONGITUDINAL modulus for a part canon loads TRANSVERSELY (`01_01 §5.1`). ⚠️ A correction that lives only in a docstring and a `print()` has no machine reader — no cache field, no `CHECKS` row — so nothing reds when it rots. 🔴 **And the MIRROR of the same rule: our OWN threshold quoted as if it were an external norm.** `55`'s `INFINITE_LIFE_SF` is declared there as «the SF line this script calls infinite life», yet the tracker cited it as the bar an alloy must clear — a house constant borrowing the authority of a standard. Same axis, opposite direction: the rule above catches a canon range flattened into a floor; this catches a house constant inflated into a standard. **Practice: when a verdict turns on a threshold, say WHOSE it is in the same sentence — ours, the vendor’s, or the standard’s (and then name the standard).** Applied BEFORE the fact it looks like `55`'s weld block: the missing input stays VISIBLY missing (`WELD_KNOCKDOWN_MEASURED = None`), and both markers a vendor's value will be read against (`AS_PRINTED_DERATE` · `WROUGHT_DERATE`) are labelled OURS. 🔴 **A script's PROSE can name a quantity it never COMPUTES, and the prose is what travels** — a grep for the verdict's subject finds it richly discussed and the reader concludes the model answers it (wear in `55`, before any wear block existed). 🔑 Reflex for these scripts, whose verdict strings ride into the cache and from there into canon and the tracker: **a `verdict`/`caveats` string may state what the script MEASURED and what it DID NOT — and when it names the second, it must name it as absent, not merely discuss it.** The cheapest check before quoting a conclusion onward: grep the script for the quantity and ask whether the hits are assignments or sentences. 🔴 **A constant that declares its own subject OPEN keeps saying so after the subject is ratified** — the referent and the value can both be right and the MODALITY wrong, and downstream a soft flag reads as «this may still move». The ratification lands in CANON, never in the script, so nothing here reds: grep your constants for `ASSUMED`/`is_assumed`/«open ⚖️» after any verdict in their domain, and the `question`/`verdict`/`_note` strings for «open · not specified · assumed» too — a verdict answers the QUESTION before it moves a NUMBER. ⊕ **A derived figure has no lexical link to its cause, so the perimeter of a span fix is «what else is derived from this span», never a grep** — and a range quoted from a derived table takes both ends from the SAME row set (a bare-column minimum beside a bonded-column maximum is a row-mix).

**Practice:** every geometric constant cites either a `tools/cad/cem/*.json` field (canon-gated by `cem_canon_sync`) or a canon row; prefer importing from `tools/in_silico/lib/constants.py` over a local literal — the `D_BUS` divergence of this class was closed by ONE HOME (`D_BUS_ROD_MM`), not by a gate. A deliberately-off value carries its caveat in **every** carrier — docstring · the comment over the constant · the `caveats`/`verdict` string that rides into the cache · its `PIPELINE_STATUS` row · its `SUMMARY` section; sweep by OCCURRENCE, never by FILE. 🔴 **A constant that decomposes itself in prose reads as derived and is not** — when a span is a sum, read its terms from the manifests at runtime (as `55` does), and quote a term that has no manifest field AS a by-value crossing rather than promoting it into a CEM field, which would canonise a placeholder. A span constant is not a digit: it is the configuration every verdict in the file is about. **A categorical label derived from a sweep must say which quantifier it uses — ALL, SOME or NONE — or its else-branch will pick one for you.** **A descriptive adjective in a script comment is a claim about the part, and it needs a source exactly like a number does** («blind» for a channel the CAD cuts THROUGH changes the machining class).

10. 🔴 **A literature constant can be the right NUMBER in the wrong ROLE and of the wrong FORM — and the two errors compound silently** (`00_07` HW.5.IS). `J_MAX_25C` once held the NATIVE enzyme's current density at an OPERATING POINT where `30` needs the Michaelis-Menten ASYMPTOTE of the form we build, so under the source's own conditions the model returned half of what it was handed. The re-anchored value, its derivation and its error propagation live in the comment over `J_MAX_25C` in `tools/in_silico/lib/constants.py`. 🔑 **Three things worth carrying beyond this constant.** (a) **The route that looks authoritative can be the one that does not close:** an ABSOLUTE current from a table whose electrode area the paper never states needs a number nobody published — use it as a CONTROL instead. (b) **Propagate the uncertainty, never type it** — from the source's own error bars, and note which term dominates. (c) **Pin the RELATION, not the literals:** a derived pair moves together, so `test_cache_integrity` asserts the derivation and reds when one side moves alone. ⚖️ **The model still runs on the LAB CEILING** (the source's pH, electrode and flow, not our sap): ratified 2026-09-18 — the ceiling stays the model and the pH correction is printed BESIDE it as a bracket (`30`, from `PH_KINETICS_SYGMUND`), never folded in. Verify any correction factor against the primary BEFORE applying it, even when your own tracker carries a number — here the ratio turned out [S]-dependent, not a constant. ⛔ The bracket is an INDICATION for our electrode, not its measurement (free enzyme, small-molecule acceptor, another temperature), and the script says so in its own output. A re-anchor re-runs every consumer on the L4 line of the graph in `SKILL.md`, with the field diff of §When Modifying #15.

11. 🔴 **A part that enters a stack budget is judged on EVERY axis the envelope constrains, not on the axis the script was built for** (`00_07` HW.9, 2026-09-25). `52_z_stack_tolerance` judged the LoRa-E5 module by HEIGHT (2.5 mm, `RF_DECK_TALLEST_BOM_PART_MM`) for weeks, while its 12 × 12 mm footprint — diagonal 16.97 — never fitted the `≤ Ø15.57 − 2·t_collar` outline that the SAME script hands to HW.9 as the board ceiling. The miss cost a founder verdict (chip-down STM32WLE5CC) and it surfaced from a human reading the BOM, not from any model. 🔑 **A member admitted to a budget carries its footprint AND its height, or the verdict it drives is about half the part:** before adding a part to any `*_budget` dict, ask which OTHER envelope of the same script it must also fit. ⚠️ The same blind spot is structural for area: no script sums footprints per deck, so the first area pass lives as a hand table in `02_01 §3.5` (bodies only — a floor, not a layout), and a second pass with courtyards is an open HW.9 leg.

12. 🔴 **Two scripts that model ONE physical part describe the same hardware only if they cite the same part number — each can agree with its own document while the pair describes two different parts** (`00_07` HW.43, 2026-09-10). The pogo pin had three homes that diverged on three axes at once: the BOM said `Mill-Max 0906`, the spec `0908/0909` with an SS 316 spring, `59_contact_endurance_check` modelled BeCu C17200 with that alloy's S-N anchors, and `52_z_stack_tolerance` took a travel attributed to 0908/0909. No gate saw it, because every surface was locally consistent — the divergence exists only BETWEEN them, and it surfaced from a hand cross-read of `02_01 §3.1` ↔ `02_02 §2.2`. 🔑 **The material of a spring is not a label, it IS the S-N input,** so a mismatch here moves the fatigue verdict, not the wording. Before a script declares a part's material, travel or rate, grep the other scripts and the spec for the SAME part and name the P/N the value comes from. ⛔ **Do not reconcile the homes one by one without a choice first:** aligning each file to its neighbour cements whichever branch you touched first as if it had been ratified. The verdict HW.43 got (founder 2026-09-18) is instructive — the alloy turned out NOT to be a free variable of a catalogue part at all, so the fork moved to the axis that actually bit (travel), and that only became visible once the choice was put before the edits.
