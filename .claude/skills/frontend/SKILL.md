# Frontend (Phlex + Tailwind v4 + Turbo + Stimulus)

Navigation aid + non-obvious gotchas. The **SSOT is `04_04` + the code below** — this skill
points, it does not restate (so it can't drift). Verify a fact at its home before trusting a
summary. The view layer is **Phlex** (Ruby components, NOT ERB) on Rails 8.1, styled by
**Tailwind v4** (CSS-first `@theme`, no JS config), with **Turbo** + 8 **Stimulus** controllers.

## Gotchas Not Obvious From Docs

1. **NO `tailwind.config.js`** (Tailwind v4) — the SSOT is the **`@theme` block in `app/assets/tailwind/application.css`**. Don't create a config file; add a token to `@theme`.
2. **Raw Tailwind forbidden in SHARED components** — `bg-red-100` only in domain-specific page components; `shared/ui|iot|web3/` MUST use the semantic tokens (`bg-status-danger`, `bg-gaia-surface`, …) so the dark theme + design system stay coherent (CLAUDE.md §6).
3. **A new font-size → register it in `CUSTOM_TEXT_SCALE`** (`ApplicationComponent`) so TailwindMerge treats it as a font-size, not a text-colour (else `tokens()` mis-merges it). Current scale: `micro mini tiny compact display-sm display-md display-lg`.
4. **NO DB queries in a Phlex `initialize`** — components accept pre-loaded data only; queries belong in the controller/presenter (a query in `initialize` runs at render time → breaks caching + Turbo broadcasts).
5. **`t('.key')` autoscopes by class-name** — `Alerts::Badge#t('.heading')` → `I18n.t('alerts.badge.heading')` (the overridden base `t`, working in Phlex specs + Turbo broadcasts where there is no view context); absolute keys (`t('flash.x')`) fall back to `I18n.t`.
6. **Specs default to English** — a Ukrainian / LV / LT assertion needs an explicit `I18n.with_locale(:uk) { ... }`.
7. **Turbo `broadcast_*` runs in MODEL context** — a `broadcast_*` inside a model callback renders the component outside the request → **no `current_user` / session**. Pass everything the component needs explicitly; lean on the delegated pure helpers, not view helpers.
8. **`tokens()` is the class-builder, not string interpolation** — `tokens("base btn", active?: "ring-2")` merges via TailwindMerge so a later conflicting utility wins; hand-joined class strings don't get that conflict resolution.
9. **For live updates use `turbo_stream_from` + `Turbo::StreamsChannel.broadcast_*_to` (§8), NOT raw `ActionCable.server.broadcast`** — there is **no** consumer wiring repo-wide (`@rails/actioncable` isn't importmap-pinned, no `subscriptions.create`). ⚠️ This line used to add «`app/channels/` does not exist **at all**, so the bare `ActionCable::Connection::Base` is live and accepts anonymous sockets» — **both halves are now false** (SEC.25 Ф1, 2026-07-28): `app/channels/application_cable/connection.rb` exists, Rails picks it up automatically, and an unauthenticated socket is now `reject_unauthorized_connection`-ed. What it establishes is IDENTITY only — it never calls `stream_from`, so subscription authorization is still absent by design (`04_04 §8.1`). Raw `ActionCable.server.broadcast` broadcasts into the void; it has already shipped dead **4×** (Codex live-features, telemetry raw-hex) and never reached a browser. The working pattern is the Turbo helper — see telemetry/burn/wallet/OTA-progress for the live examples. Two corollaries: (a) before wiring a NEW `turbo_stream_from` subscription, verify the producer is on the LIVE tract (the inverse bug: subscribing to a channel fed only by a superseded worker — the SEC.20 OtaProgressBar case; the producer moved to the FW.60 poll-tract); (b) a broadcast inside a synchronous device-reply path (coap daemon) MUST be rescue-isolated — UI decoration must never kill the envelope (see `broadcast_ota_progress` / `broadcast_command_state_static`); (c) **never call a model's own inherited `broadcast_update`/`broadcast_replace`** — `Turbo::Broadcastable` is auto-mixed into every AR model and defaults to `to_partial_path`, but this repo has **no model partials at all** (`app/views/` = mailers, layouts, Phlex only), so it raises `ActionView::MissingTemplate` synchronously at the call site; always the explicit `Turbo::StreamsChannel.broadcast_*_to` with `html:` (§8.1 carries the pattern + the ARCH.67 precedent, where such a call in a money-path service truncated a batch loop and left `locked_balance` frozen). (§8.1/§8.3 list every producer and subscriber in the tree — but **do not read that as "every tract is live", and do not repeat the claim this line used to make.** It said «a COMPLETE, code-verified registry» and «no dead target survives»; a seventh dead tract surfaced the next day, and the miss was in the AXES, not in the diligence. 🔴 **A live tract has FOUR links — producer ⟷ subscriber ⟷ ROUTE ⟷ SCOPE — and a registry sweep sees only the first two.** `"geospatial_matrix"` had both: `Tree#broadcast_map_update` produces, `Dashboard::Map` subscribes, the target sits inside that very component, so every pairwise check resolved clean. It was dead anyway, because **no route rendered `Dashboard::Map` — and none ever had in the entire history of the repo** (`git log -S` on three call forms: zero); `Dashboard::Home` painted a permanent spinner where the map should be. *(Wired up 2026-07-27 — the tract is live and org-scoped now; the example stays here as the demonstration of the class.)* 🔴 **And note what the fix required, because it is the reusable half: the stream had to be org-scoped IN THE SAME CHANGE as the render.** A dead stream's name is untested by reality — nothing subscribes, so nothing leaks — and "just render the subscriber" therefore *converts a latent leak into a live one*. The name was a bare global literal carrying coordinates and DIDs; had the render landed alone, every viewer of every org would have received the whole fleet. Treat any dead tract's scope as **unverified by default**, never as "fine, since it was there". Reflex when a tract looks healthy: after pairing producer with subscriber, ask **who renders the subscriber**, and answer it from `routes.rb` + the controllers, not from the component's own file. 🔴 The sharpest lesson from that audit, because none of it was visible from the producer's own code: **a stream WITH a subscriber is still dead if the page does not render the `target`.** Three shapes shipped simultaneously — a broadcast to the bare `wallet` stream while the page subscribed to the composite `[wallet, :transactions]`; a target `transaction_{id}` while the component renders `dom_id` = `blockchain_transaction_{id}`; and `actuator_card_{id}` while `Actuators::Card` renders `actuator_{id}` — with the *same controller's* synchronous path using the correct id one file away. So verify the PAIR **and** the target, and prefer `dom_id` over a hand-written id string. Second lesson, for deletions: when a broadcast looks redundant, the reason usually isn't the one you'd write in the commit — a sibling that «does the same thing» may be throttled, or guarded on a nil association, and cover strictly less. Third, and the one that actually decides «finish or delete»: **the code cannot tell you the intent — the birth commit can.** `git log -S` on the target string separates two things that look identical in the tree: a broadcast written against a page that never existed (three of them here pointed at Phlex classes that did **not exist yet** and `NameError`d for six days, until a coverage PR created the classes to stop the failures — so the component was a cure for a crash, never a UI), versus a one-character id typo against a component that was already live. Fourth: **«no subscriber» and «too wide a stream» are different defects, and only the first is visible as deadness.** `"global_events"` was a bare unscoped string carrying insurance payouts; wiring it — the obvious «fix» — would have leaked one org's money events to every org's dashboard. Before calling a dead stream «just needs a subscriber», check whether its NAME is scoped to the entity whose data it carries. 🔴 That one was caught *before* wiring; the same shape had already SHIPPED on `"telemetry_stream"` (fixed 2026-07-27, `00_07` SEC.25) — bare global string, every gateway's telemetry, and `GET /telemetry/live` carrying no authorization beyond `authenticate_user!`, so any authenticated user of any org watched every org's `uid` + IP + raw payload live. **Why no REST/Pundit audit could ever see it: the HTTP response of that endpoint contains no tenant data at all** — chrome plus an empty placeholder — and the leak arrives over the websocket *after* subscription. So a controller-level cross-tenant review is structurally blind here, and stream scope needs its own check. ✅ **That check now exists — `spec/security/turbo_stream_scope_spec.rb` + `lib/turbo_stream_inventory.rb` (2026-07-28), mechanics and ceilings in `04_04 §8.1`.** Adding a new `turbo_stream_from` therefore goes red until you register its proof obligation, and the class of the first argument dictates which proof: AR-record → a named cross-fetch denial spec · `TurboStreams::Name.org(...)` → a two-subject name pin · `TurboStreams::Name.gateway_ota(...)` (no org token in the name, safe only transitively) → a set-equality pin. 🔴 **A string stream name written by hand is now red as a FORM, even with the right scope** — every string name comes from one home, `lib/turbo_streams/name.rb`, called by BOTH sides of the tract; before it, the four names lived in **eleven** hand-written copies across two layers (11 total, not 11 each). ⚠️ **Do not cite the three shipped "different addresses" bugs as this home's evidence — they were on the ADJACENT axis** (`transaction_{id}` vs `dom_id`, `actuator_card_{id}` vs `actuator_{id}` = target ids; `wallet` vs `[wallet, :transactions]` = record form), none of which a stream-NAME home touches. Stream-name divergence has zero shipped precedents; the home earns its keep on blast radius instead (losing `_org_` is a leak, which none of those three could cause) and on collapsing the UI.4 pair-gate to "both sides call the same function". 🔴 **And the axis with the real precedents is still un-homed: target ids hand-written on BOTH sides** (`ota_progress_{uid}` · `map_node_{id}` · `wallet_balance_frame_{id}` — one producer, *three* independent renderers · the static singletons `telemetry_feed` and `feed_placeholder`). Don't carry a site count here — the tally drifted between three homes inside one week and is only reproducible under a scope definition none of them stated; the inventory lives in `00_07` UI.4, the mechanism in `04_04 §8.3`. 🔴 **And "just use `dom_id`" is a trap I fell into and wrote down before measuring: `dom_id(record, prefix)` always splices the record's `param_key` between them**, so `dom_id(tree, :map_node)` is `"map_node_tree_42"`, NOT `"map_node_42"` (measured at runtime). It is a free swap **only** where the hand-written string already equals `"{param_key}_{id}"` with no descriptive word — `actuator_{id}`, `blockchain_transaction_{id}`, `ews_alert_{id}`. Anywhere else, adopting `dom_id` is a coordinated **rename of both sides**, not a swap; and where the id keys on a non-PK column (`ota_progress_{uid}`) `dom_id` does not apply at all. ✅ The pattern that actually works is already in the repo: `Actuators::CommandStatusFrame.dom_id(command_id)` — one shared class method called by producer AND renderer (a `TurboStreams::Name` for targets); for page-scoped singletons, a shared constant. ⚠️ Specs are a THIRD copy and each pins only ONE side, so a coordinated-but-wrong edit stays green — which is exactly the shape this axis ships bugs in. → `00_07` UI.4. On the SUBSCRIBE side the only legal sources are that home or the AR record itself (a local or a foreign method — `:indirect` — is red there; on the producer side a local holding a derived name stays normal). 🔴 And the proof FORM does not follow from the name's shape: it follows from the page's **cardinality**, which no extractor can see — a single-record page (`Gateways::Show`) and a loop over a collection (`Firmwares::Index`) share the same name class and need different proofs, so that is a declaration in the registry, never a derivation. The gate's own row for the single-record page was registered against a cross-org-404 example running `as: :json`, i.e. one that never rendered the subscription at all — measured by mutation, not by reading. The gate also now enforces corollary (c) above, so «never call the model's inherited `broadcast_*`» stopped being advice. 🔴 What it still cannot see, so keep reading for it: whether `@organization` came from the **session or a request param** (statically identical), and a subscription minted by hand instead of through the helper. Two residuals worth carrying: an org-scoped name fixes *who may subscribe now*, not *forever* — the signed stream name is a deterministic HMAC with no TTL and ActionCable never re-authorizes. ✅ The standard revocation primitive (`remote_connections…disconnect`) **was** inert — no `ApplicationCable::Connection` meant an empty `identifiers` set — and is live since 2026-07-28, at **per-device** granularity (`identified_by :current_user, :session_id`; the cookie session carries a stable `session_id`). ✅ **The token stopped being eternal on 2026-07-29 (SEC.25 Ф3): the name carries `organizations.stream_epoch`, and `Organization#rotate_stream_epoch!` abandons the address** (bump → tombstone `broadcast_refresh_to` into the *old* name → ARCH.57 trail; runbook `06_04 §5.9`). Read that narrowly, because four ceilings are load-bearing: the tombstone reaches **connected sockets only** (Solid Cable pins a new subscription to the current max, so backlog never replays — a slept tab re-subscribes to the dead name and *looks* `connected`); `:map` is deliberately **excluded** from the tombstone (morph would strip Leaflet's children while `disconnect()` never fires, killing the map for honest viewers); the epoch covers **three streams of seven** (record-form and `ota_channel_*` remain eternal); and the trigger is **manual only** — nothing in this tree mutates org membership. 🔴 **And do not reach for `expires_in:` as the cheap half of that fix — it was measured and rejected.** The verifier honours it, but the client swallows the consequence: `Subscription`'s constructor freezes the identifier (`turbo.js:5853`), `Subscriptions#reload()` on `welcome` resends the *stale* token without re-reading the DOM, and `TurboCableStreamSourceElement` defines no `rejected` callback at all — so an expired token after a laptop sleep kills live updates permanently, with no retry, no console error and no visible signal. A morph refresh does reset the clock (`observedAttributes` + `attributeChangedCallback` re-subscribe), which is exactly why an *idle* page is the victim. 🔴 **And do NOT reach for the other "obvious" fix either — this line used to call it the real one, and it is measurably not** (2026-07-28). «Authorization at `subscribe` in an owned channel, which the gem documents itself» fails twice over: `subscription_allowed?` is **not** a gem hook (two occurrences in all of turbo-rails, both inside a docblock), and the **client chooses the channel class** — `Subscriptions#add` constantizes `id_options[:channel]` from client JSON while the HMAC covers only the stream *name*, and `<turbo-cable-stream-source>` re-subscribes on any `channel` attribute change. So an owned channel is bypassed from devtools and ends up policing only honest users. Worse, its `reject` is a *tiny* silent killer: `reject()` calls `forget(subscription)`, so `reload()` never re-sends it, and the element defines no `rejected` callback — the same failure mode that got TTL rejected, now firing on the first render for any legitimate viewer whose name the resolver can't map (and nullable org chains make that an ordinary data state). The form that is immune to both is **org-epoch inside the stream name** — abandon the address rather than gate the subscriber (`04_04 §8.1`). A viewer with no organization must still fail **closed** (no subscription), which reads as a broken feature unless the empty state says why. ✅ **That half SHIPPED 2026-07-28 as acting-organization** (one org at a time for everyone; super_admin switches via `POST /organizations/:id/switch`) — canon `04_03 §3.1`. Two consequences for this file. (a) The three org-named subscriptions (`alerts/index`, `dashboard/map`, `telemetry/live_stream`) take `@organization` from the controller, so they follow acting-org automatically — but the **producers** (`ews_alert`, `tree`, `unpack_telemetry_worker`) derive it from `cluster.organization` and must NOT be switched to acting-org: **broadcast goes to the OWNER's org, subscription to the VIEWER's acting-org.** Mixing them means one tenant's alerts land in another's stream. (They load the org *record*, not `organization_id`, since SEC.25 Ф3 — the name carries `stream_epoch` and the name home stays a pure function; resolving the epoch inside it would create two branches reading it at different moments.) (b) `targeted-disconnect` is now not merely live but **used** — the switch calls it with `reconnect: false`, since the gem's default `true` would return the socket to the very same names still sitting in the un-reloaded DOM. Its ceiling is thereby demonstrated rather than theorised: it cuts sockets, it does **not** invalidate a name. 🔴 And note the boundary precisely, because the epoch (above) does **not** rescue this case: rotating on a context switch would reload every viewer of that org for one admin's hygiene, and no privilege boundary is crossed anyway (super_admin keeps legitimate access to both orgs and can switch back). So a saved token still hears the previous org after a switch — a deliberate context-hygiene compromise, not a residual bug → `04_03 §3.1`.)

10. **A user-visible enum value's home is the locale file, not `.humanize`** — resolve it through ONE shared scope constant (`TreeChronicle::TextFormatter::ALERT_TYPE_SCOPE`) that every caller reuses; two derivation sites mean a typo in one stays green forever. Locale-**invariant** values (emoji, glyphs) stay a frozen Ruby map — in YAML the parity gate would force one identical copy per catalogue locale. **The blind spot that makes this load-bearing:** `i18n-tasks missing` compares locale↔locale and is structurally blind to "the enum grew, the YAML didn't"; and `raise_on_missing_translations` does **not** cover Phlex (`ApplicationComponent#t` calls bare `I18n.t` for absolute keys, which that setting never hooks). The guard on that axis is `spec/i18n/enum_label_parity_spec.rb` — a **curated registry** of `value source → locale scope` pairs (alert_type · severity · EwsAlert#status · ActuatorCommand#status · StatusBadge::STYLES), checked **both directions** and **base-locale only** (cost then does not grow with the catalogue, and a new untranslated locale does not go red). Two non-negotiables, both learned the hard way: `I18n.exists?` **MUST** pass `fallback: false` (fallbacks are on in every env, so without it the check is vacuous for every non-base locale), and every registry row needs its own **liveness** assertion — a renamed scope must go RED, or "zero violations" quietly means "zero checks". The reverse direction is the one that matters: an **orphaned label has no symptom** (`alerts.badge.severities.high` survived in all four locales against a three-value enum). `text_formatter_parity_spec.rb` keeps only what is specific to it (icon map + the "resolves through YAML, not the humanize fallback" pin). Pattern + ceilings → `04_04 §12.14`.

🔴 **A shared status renderer keyed only by the VALUE silently merges domains that happen to share a word — and «wire the existing shared component» can therefore ship a visible lie.** `StatusBadge::STYLES` is a flat namespace over eight AASM families; `"active"` in it means **danger**, because that entry belongs to `EwsAlert` (an open alert is bad), while `Tree` / `Gateway` / `NaasContract` / `Actuator` use the same word for *healthy* and each paints it green in its own private helper. So the obvious cleanup — «N private colour maps duplicate the shared one, collapse them» — would turn a healthy tree, a live gateway and an in-force contract red. Three things generalise. **A collision like this is invisible to every parity gate**, because both sides are «present» and both are «translated»; it only shows when two owners disagree about *meaning*. **Check whether the divergence is deliberate or accidental before defending it** — I argued the private maps «encode domain semantics», and git said otherwise: `trees/index` *collapses* `removed`+`deceased` that STYLES distinguishes, two of the maps are byte-identical copy-paste, and the one real-looking divergence was born in the very commit that created the shared badge. And **check whether the collision's owner is still alive**: here it was not — the only UI rendering `EwsAlert#status` as a word went with `Alerts::Badge`, so removing the entry is dead-code deletion (27 of 33 STYLES entries render nowhere), not a product decision. Related trap on the same surface: a shared label bag also fixes **grammatical gender** for every domain at once — `ui.status.active` = masculine «активний» is right for a gateway and wrong for a tree.

**The scope belongs to the MODEL's domain, not to the component that displayed it first**, and the threshold is simple: a shared constant is needed once there are **two or more** callers (that is why severity moved `alerts.badge.severities` → `alerts.severities`, while `alerts.badge.statuses` deliberately stayed put — one caller). Worst variant of this bug class, and the one that survives review: a raw enum value interpolated into an **already-translated** sentence or aria-label — the phrase *looks* localized, so nobody re-reads it. Hunt it by grepping for a model attribute inside `t(...)`, not by grepping `.humanize`.

**A parity gate proves the labels EXIST; nothing proves they are DISTINCT.** Read an enum's label set as a *set*, in every locale, and ask which pairs must not collide. The case that produced this rule: `actuators.command_status_badge` rendered `acknowledged` and `confirmed` as **one identical word** in uk/lv/lt — while the model's own comment says `acknowledge` is the moment the valve/siren physically *starts* and `confirm` sets `completed_at`, i.e. a non-English operator of forest hardware could not tell *running* from *finished*. Both keys existed, both were translated, every gate was green: parity asks «is it present», never «must this differ from its sibling». Fixed 2026-07-27, and the axis is now held by `spec/i18n/label_distinctness_spec.rb` — a curated registry of sets that must stay distinct, which deliberately walks **every configured locale** (the base one is always green here, so a base-only check would find nothing; cost stays trivial and an untranslated new locale does not go red, since fallback serves the already-distinct base labels).

Three things about that case generalise past it. **The shared `ui.status` bag is not obliged to be distinct as a whole** — different domains may legitimately share a word — so register an explicit subset, not `enum.keys`; that is also why the fix there is *asymmetric* (`confirmed` in `ui.status` belongs to BlockchainTransaction, «confirmed by the network», while the actuator's own badge must say «finished»). **A defect can be latent**: the badge rendered in no request context at all, so users were seeing the raw English enum, which distinguishes fine — the collision only became real at the moment of wiring, which is exactly why labels ship before wiring, never after. And when borrowing a word from a sibling key, **ask what that sibling's sentence supplies that your target does not** — a Latvian past participle lifted from a phrase that names `komanda` arrives feminine into a badge that has no noun.
11. **A broadcast payload must carry NO locale-dependent prose** — the cost of a live update scales with **viewers**, never with the **locale catalogue**. `html:` is an eager argument (Phlex renders in the producer's process; `_later_` defers only delivery), and `LocaleSettable` is a `before_action` that neither Sidekiq nor `ApplicationController.renderer` runs — so a broadcast carries the producer thread's locale, non-deterministically: a controller-driven `after_update_commit` ships the *clicking* user's language to every subscriber. 🔴 **But that is only ONE of two failure classes, and the second is worse because it has no symptom.** If a component's *entire* call graph is Sidekiq, the outcome is not non-deterministic — it is a deterministic, permanent `default_locale`, i.e. its non-English translations were never reachable by anyone, ever. Nobody notices: an English-speaking reviewer sees nothing odd, `i18n-tasks` sees a *used* key, and every locale file looks healthy. Check it mechanically rather than by eye — `I18n.locale` is set from exactly three places in this tree (`LocaleSettable`'s `before_action`, `locales_controller`, `ApplicationMailer#in_locale_of`), all request- or mailer-bound, and no Sidekiq middleware touches it, so **any `t()` reachable only from `app/workers/**` is a dead translation by construction**. Before sizing such a migration, also subtract the locale-INVARIANT keys (a value byte-identical in every locale is *data*, not a translation — `04_04 §8.1а`). Per-locale stream fan-out is a **forbidden class**, not an expensive option — one render + one `solid_cable_messages` INSERT + one NOTIFY per catalogue locale, on the same Postgres instance as the money path, nearly all of it delivered to nobody. Allowed: a locale-invariant payload (class 1 — `Dashboard::MapNode` is the clean reference) or a locale-free `turbo_frame` `src` stub each client resolves in its own request (class 2 — `Wallets::BalanceFrameStub`, shipped 2026-07-27, is the worked example). ⚠️ Building a class-2 stub, note that `turbo_frame_tag` **does not work in `.call`** (the Phlex::Rails helper reaches for a view context that is `nil` outside a request — verified: `NoMethodError ... for nil`), and a broadcast renders via `.call`; use `register_element :turbo_frame` instead, and build the `src` with `Rails.application.routes.url_helpers`. → `04_04 §8.1а`, migration `00_07` I18N.2.

**The second class-2 case (`Actuators::CommandStatusFrame(Stub)`, 2026-07-27) is worth knowing because it deviates — copy a precedent BY ROLE, not wholesale.** The wallet puts `src` on the *page* frame too (lazy-loading an expensive balance); cloning that for a table of up to 20 command rows would have meant 20 GETs on first paint for data already loaded in the controller. So the page frame stays plain, and only the broadcast stub carries `src`. Two details that cost debugging time otherwise: the frame id must **differ** from the id of the component inside it (`command_status_frame_{id}` wraps `command_status_{id}`) — same id twice is a DOM duplicate, and the broadcast target must be the *frame*, since that is what holds `src`; and the stub should not be empty — an `animate-pulse` block holds the row's height while the fetch flies and stays locale-invariant, whereas the ready-made `Views::Shared::UI::Skeleton` is **not** usable here because it is localized (`t(".loading")`), i.e. it would put back exactly what class 2 removes.

12. 🔴 **A stream+target pair has exactly ONE owner — the page that renders the target — and the payload's shape belongs to that owner, not to the producer** (UI.4, 2026-07-27; canon `04_04 §8.1б`). The moment a SECOND page wants updates of the same entity is the moment pushing rendered HTML stops being legal. `EwsAlert` pushed `Alerts::Row` (a 6-column `<tr>`) into both its streams, while `Clusters::Show` keeps its alert list as a compact 3-field `<div>` panel — so an updated alert literally changed tag name mid-page while its unupdated siblings stayed `<div>`s.

**The trap is in the obvious fix, and it is worth internalising because every structural check would have blessed it.** Making the panel a real `<table>` legalises the HTML and is still wrong: the two owners need different **verbs**. The panel shows `unresolved.limit(5)`, so resolving an alert there must *remove* the row and backfill the sixth; the worklist must *replace* it with a struck-through row. A fixed HTML fragment cannot express two verbs, so "one shared row component per entity" would not have closed this class **even in principle** — a compact digest and a full worklist are different products of the same data, not one component used twice. Corollary for the repo's own instinct toward DRY: the duplication worth removing here is **semantic** (the `severity → colour` map, which had already diverged — `low` renders blue in the row and green in the panel), not structural.

**The fix that generalises: push a SIGNAL, not markup** — `Turbo::StreamsChannel.broadcast_refresh_later_to(stream)`. The owner re-runs its own query, so the verb, the filters, the pagination and the empty state all stay where they belong; and because each viewer re-renders in their own request, the payload is locale-free by construction (the surface simply leaves the §8.1а migration list). ⚠️ Two conditions. (a) `broadcast_refresh_*` is only usable with `<meta name="turbo-refresh-method" content="morph">` + `turbo-refresh-scroll: preserve` in the layout — without them it is a full Turbo visit with the scroll thrown away, worse than the bug you are fixing. (b) 🔴 **The obvious companion move — `data-turbo-permanent` on client-built state — is a trap, and it shipped here before being caught.** The reasoning feels airtight (morph preserves nodes, so mark the Leaflet canvas permanent since the server renders it empty) and it is wrong on two counts, both verifiable in `turbo.js`: the attribute fires on **any** Turbo render via `preservingPermanentElements`, not just morph; while morph itself additionally requires `action === "replace"` (`isPageRefresh`), so an ordinary nav click never triggers it. On such a visit Turbo **transplants** the node → Stimulus runs `disconnect()` → and if that controller cleans up after itself (`replaceChildren()`), it destroys the **server-rendered content nested inside that same node** along with the client's. In `Dashboard::Map` that is `#map_data_nodes`, so the map would come back empty and every later `broadcast_replace` would aim at ids that no longer exist. **Rule: never mark permanent a node the server renders data into, and read the controller's `disconnect()` before reaching for the attribute.**

🔴 **Cost note that belongs next to the fix, because the sentence «signal is cheaper» is only half true**: the unit of cost moves from a fragment to a **page**. Old path = one render + N pushes of a ready `<tr>`; new path = N full GETs by actual viewers. The §8.1а invariant still holds (only real viewers pay, so cost tracks demand not catalogue), but a signal is *not* universally cheaper than a push — which is exactly why frequency decides. And do not call such a tract «throttled» wholesale: in this repo the 5-second `should_broadcast?` guard sits **only** on the update path; the create path is bounded merely by `Turbo::ThreadDebouncer` (0.5 s **per producer thread**).

🧭 **«Nothing updates» is TWO different defects, and only one of them is visible as a dead producer.** *Nowhere* = the page never renders the `target`; *nobody* = no page subscribes to the stream. They have to be closed in order — rendering the target first, subscribing second — and a producer⟷subscriber gate sees only the latter. The `command_status` tract had both at once, which is why it survived every earlier sweep.
