# Frontend (Phlex + Tailwind v4 + Turbo + Stimulus)

Navigation aid + non-obvious gotchas. The **SSOT is `04_04` + the code below** — this skill
points, it does not restate (so it can't drift). Verify a fact at its home before trusting a
summary. The view layer is **Phlex** (Ruby components, NOT ERB) on Rails 8.1, styled by
**Tailwind v4** (CSS-first `@theme`, no JS config), with **Turbo** + a handful of **Stimulus** controllers.

## Gotchas Not Obvious From Docs

1. **NO `tailwind.config.js`** (Tailwind v4) — the SSOT is the **`@theme` block in `app/assets/tailwind/application.css`**. Don't create a config file; add a token to `@theme`. 🔴 **And know the failure mode of getting that wrong, because it is SILENT: Tailwind v4 does not complain about an unknown token — it simply emits NO class for it.** So `text-gaia-primary-text` on nine sites across six files looked like correct markup, the CSS said nothing, and the colour quietly fell through to whatever the element inherited from `<body>` — which on `bg-gaia-primary` buttons meant **1.98:1 in dark**, the only theme anyone uses. Two things make this class survive review: the markup reads as intentional (someone clearly *meant* a paired text token), and a component spec pinning `include("text-gaia-primary-text")` stays **green**, because it asserts the presence of a STRING, not the existence of a token. Gate: `spec/quality/design_token_existence_spec.rb` (every `<utility>-<gaia|status|token>-*` used in `app/views/**` must be declared in `@theme`; mutation-verified). 🔴 **NAMESPACE IS THE OTHER HALF OF THIS CLASS, and it cost seven months (2026-08-17).** «Declared in `@theme`» is not enough — the prefix decides whether Tailwind generates anything at all: colours `--color-*`, font sizes `--text-*`, families `--font-*`. Ours said `--font-size-*` / `--font-family-*` (v4 beta forms, renamed before release), so **the entire custom type scale never existed in CSS** and 448 uses of `text-micro|mini|tiny|compact` inherited root 16px. ⚠️ The families were nastier: `font-mono` **was** in the build — as Tailwind's DEFAULT stack — so 185 sites silently got system mono instead of JetBrains Mono; presence of the class proves nothing when the *value* is substituted. ⚠️ **The mirror gate could not see it: it pinned `CUSTOM_TEXT_SCALE` to `@theme` — two of our own homes — and both were wrong identically** (§Guard-craft #67). The third axis added 2026-08-17 anchors on the **built** CSS for exactly this reason. ⚠️ **The sentence that used to stand here — «it reads the source CSS, never `app/assets/builds/`, that path is gitignored so a gate keyed on it would be green on an empty set in CI» — is a MEASURED-FALSE premise:** both spec jobs enter via `.github/actions/setup-rails-test`, which runs `bin/rails tailwindcss:build`. The empty-set risk is real and is answered by a population lantern, not by refusing the anchor (§Guard-craft #68). The source-anchored colour axis stays source-anchored on its own merits — its subject is «declared», and its failure message points into `@theme`. ⚠️ **І ще одна стеля, виміряна 2026-08-11: обидва інструменти токен-шару скануть КЛАСИ, тож інлайн-`style:` із кольором їм не існує ЗА ПОБУДОВОЮ.** `gaia:lint_tokens` і цей гейт шукають `<utility>-<gaia|status|token>-*`, а `style: "color: #{...}"` не має класу взагалі — отже `--report` покаже 0 raw-хітів там, де колір зашитий, і міграція домену тихо пропустить такий сайт. ✅ **Обидва відомі сайти (`oracle_visions/forecast_card`) ЗАКРИТО 2026-08-14** разом із присудом `UI.13`; живих екземплярів у дереві **нуль** (`grep -rn 'style:.*color' app/views/` порожній), тож стеля лишається як ФОРМА класу, не як борг. 🔴 **І урок закриття варт перенесення: перевести інлайн-колір у клас довелось не заради гігієни, а тому, що без класу неможливий САМ фікс** — сигнал критичності мусив дискримінувати два стани, а інлайн-`style:` не має ані `dark:`-варіанта, ані способу нести умову. **Тобто сліпа зона інструмента й неможливість фічі — та сама властивість, побачена з двох боків.** ⚠️ Ширина смуги там свідомо лишилась інлайн: рантайм-значення у відсотках класу не має, і це законний залишок, а не пропущений сайт. ⚠️ Its ceiling is stated in its header and matters: it judges EXISTENCE, never SUITABILITY — a declared token at 1.1:1 passes, because the real fg/bg pair usually spans files (the surface comes from a parent component or `<body>`) and no static scan can see it.

✅ **That ceiling now has an instrument on the other side of it (2026-08-07), and knowing which one to reach for is the point.** `lib/silken_net/contrast.rb` (WCAG arithmetic, pure Ruby, oracles taken from WebAIM + the published W3C ACT `afw4f7` test-cases) + `spec/support/contrast_audit.rb` (browser harvester on cuprite) resolve the ACTUAL pair in the render, composite the **stack** of translucent layers, and judge each theme separately. Reach for it whenever a question is «is this colour readable», and for the static gate when it is «does this token exist». 🔴 **Three things it bought that are worth carrying, because each was a defect I nearly shipped.** (a) **Skipping to the first opaque background is wrong** — 109 sites in this tree carry a translucent surface (`bg-black/80`, `bg-gaia-surface/80`), and skipping the layer returns the panel underneath, i.e. a plausible and wrong number *in the safe direction*. Composite the stack. (b) **Tailwind v4 compiles the `/NN` alpha suffix into `color-mix(in oklab, …)`, and Chrome serialises the result IN THE INTERPOLATION SPACE** (`oklab(0.163 … / 0.8)` — measured on our own top bar). Do not write an OKLab→sRGB conversion (that is a second colour engine nobody cross-checks) and do not trust `ctx.fillStyle = css; ctx.fillStyle` — with CSS Color 4 support Chrome hands the value back in the same space. Paint one pixel and read it: the raster is always sRGB. (d) 🔴 **The instrument composites the stack of BACKGROUNDS and is blind to the alpha of the FOREGROUND — so `opacity-NN` on a text node is a hidden contrast multiplier** (`00_07` UI.3). ✅ **CLOSED 2026-08-16, and the perimeter was FIVE times the one site this entry used to name.** A sweep of all `app/views` found four live: `Alerts::Row` dimmed the entire resolved `<tr>` (16.10 → **2.46:1** light / 19.05 → 3.58 dark) · `StatusBadge` cancelled/removed (6.87 → **2.25:1** / 5.81 → 2.37) · `ForecastCard` headline (**1.70 · 2.09 · 2.12 : 1** against a 3:1 bar for `text-2xl`) · `Shared::UI::EmptyState` description (7.41 → **3.54:1** in LIGHT, 6.69 in dark — a single-theme defect half the audience never saw). 🔴 **Why it survived even though one instrument KNEW about it: «opacity-група» sits in the browser harvester's UNMEASURABLE bucket** — it honestly declined to measure such a node, and that honesty is exactly what hid the class, because a refusal does not go red and «cannot measure» reads to nobody as «there may be a defect here». **Reflex when you meet an UNMEASURABLE bucket in any of our instruments: that is a list of places to inspect by hand, not a list of things that passed.** ⚠️ **The old reflex here («put the fade on a decorative sibling») was REJECTED by measurement — do not follow it.** The alpha needed to clear the bar depends on the COLOUR (0.692 · 0.549 · 0.544 on `bg-zinc-950`) and the colour is derived at runtime, so no single value works and the shared-safe 0.70 makes the effect invisible anyway. The rule is binary: `opacity-N` never lands on a node carrying text. «Readable on hover» is not a remedy either — touch has no hover, and 1.4.3 grants no such exemption. 🔴 **And the half that would have cost more than the defect: removing the opacity can delete SEMANTICS.** On `StatusBadge` it was the ONLY thing separating «cancelled» from «draft» (identical `bg-status-neutral text-status-neutral-text`), so a naive contrast fix merges two states into one look — **and no gate says a word**, because a class gate is equally green when the opacity is simply gone. Take a non-colour discriminator already living in the same map (`line-through`, borrowed from `deceased`) and give distinguishability its OWN pin, separate from the contrast one. ⊕ Three pins in the tree were CEMENTING the defect (`alerts/row_spec` «applies reduced opacity» · `alerts/index_spec` · `contracts/index_spec` «dims cancelled») — the suite demanded it. **Carrier: `spec/quality/opacity_contrast_multiplier_spec.rb`** — exactly TWO machine exemptions (`pointer-events-none` · `disabled`), both about the LAYER itself. 🔴 **`aria_hidden` is deliberately NOT a third, and the first draft of that gate wrongly made it one — caught by the closing sweep against entry (c) above, not by a test.** 1.4.3 judges the EYE; the attribute hides from screen readers. `EmptyState` held a glyph under it at **2.32:1** in light. Decorative here is excluded by an explicit registry declaration in `contrast_audit`, never automatically. ⚠️ **The second FORM of the same multiplier — alpha on the colour itself (`text-…/NN`) — is out of scope by measurement, not by omission:** 16 sites, 15 of them the declared watermarks (`text-emerald-900/5`, deliberate 1.09:1), and the single non-watermark (`Telemetry::LogEntry`, `text-gaia-text-strong/80`) clears with room (9.28:1 light / 12.18 dark). Zero live defects, and a gate for it would be born holding fifteen exceptions — i.e. a registry. The class is real; review catches the next one. ⚠️ Its ceiling is named and cost the most: it sees a node that DECLARES text itself; opacity on a CONTAINER whose descendants carry text is statically invisible — which is precisely how `Alerts::Row` survived (no `text-` in its class expression at all). Rule home → `04_04 §3.5`. 🔴 **(e) The MIRROR of (d), and it hides behind the §3.5 exemption rather than behind an instrument: a `/NN` surface is not theme-invariant — it is theme-DEPENDENT, because it composites with whatever the page background is.** Measured 2026-08-15 on `Errors::NoOrganization`: `bg-black/80` reads as «black is black», and resolves to `rgb(49,49,49)` in light against `rgb(0,1,1)` in dark — **90× in luminance**, so text sitting on it had two different backdrops and no single value served both (`emerald-700` 2.39/3.89, `emerald-900` 1.33/2.17 — failing AA in BOTH). **Discriminator: does anything sit ON the layer.** A scrim (`backdrop:bg-black/60`) stays legal precisely because nothing does — its claim is the EFFECT, not the colour; the moment text lands on a translucent layer, the surface must be a token (`bg-gaia-surface/80` keeps the identical glass and knows about the theme). Rule home → `04_04 §3.5`. 🔴 **(f) `status-<x>` and `status-<x>-accent` are two ROLES, and the pale one is a BADGE BACKGROUND — used as a signal it hands you an invisible one.** Measured 2026-08-15: `bg-status-warning` as a glyph = **1.07:1** in light (the 403 tone of `Errors::Page`), `bg-status-info` = **1.17**, against `status-danger-accent` at **4.63/5.39**. The bar for a glyph/LED/dot/severity-border is **3:1** (1.4.11, non-text) and the pale tokens clear neither. ⚠️ **`-accent` does not exist for every family** (today: `danger`, `warning`), so "unify it onto the matching `status-*` for symmetry" is the trap, not the fix — on `Errors::Page` the raw `emerald-700` `:info` tone measured **5.14/3.78**, i.e. the only non-accent tone that is visible at all, and the tidy-looking swap would have blinded it. Add an `-accent` when a second signal site needs it, never to complete a table. Rule home → `04_04 §3.2`. ⚠️ And pin such a swap EXACTLY: `include("status-warning")` also passes on `status-warning-accent`, and `\b` is not the boundary you want — a hyphen is a non-word char, so `/\bbg-status-warning\b/` matches *inside* the accent class. Use a negative lookahead.
🔴 **Форми: причина відмови мусить бути звʼязана з ПОЛЕМ, не лише зведена згори** (WCAG 3.3.1, closed 2026-08-16). Home — `ApplicationComponent#field_error_attrs` + `#render_field_error`; `id` comes from the native `form.field_id(attr, :error)` (Rails 8.1), never derived by hand. Only forms with `model:` can do this — `form.object.errors[attribute]` does not exist on `form_with(url:)`, where the controller pushes STRINGS into `ErrorSummary` rather than fields. ⚠️ **The trap that made this look done for years: `ActionView::Base.field_error_proc` is active** and really does wrap invalid fields in `.field_with_errors` — but that class is styled NOWHERE, so the mechanism runs and emits no signal at all. Do not override the proc: it receives the finished HTML as a STRING, so adding an attribute means a regex over markup, i.e. a second renderer outside Phlex. ⊕ `field_container` yields the ARIA hash **into the block**, because the control is rendered by the caller, not the helper — `field_container(f, :x, label) { |aria| f.text_field :x, class: …, **aria }`. 🔴 **And pin it DERIVATIONALLY:** «the set of flagged fields is non-empty» stays green when the splat is lost from ONE `field_container` — the set merely shrinks. `LabelAssociation.unmarked_error_fields(fragment, record, param_key)` compares two independent sides (`record.errors` ⊥ HTML attributes) and names the field. Rule home → `04_04 §9`.

⚠️ Sibling reflex from the same pass: **a component with NO `bg-*` on its root has no known surface at all** — its text inherits `<body>`, so any ratio you compute for it is a guess. `Sessions::New` declares `bg-gaia-surface-base`; its un-migrated twin did not, and that absence — not the colours — is why an invisible heading survived review. (c) **`aria-hidden` is NOT grounds for skipping a node** — 1.4.3 is a *visual* criterion and the attribute hides from screen readers, not from the eye; decorative text (our 15 watermarks) is excluded by an explicit registry declaration, never automatically. ⚠️ And note what it is NOT: an instrument, not a gate — `00_07` UI.3. 🔴 **And the order it prescribed («fix-the-root-tokens → migrate → gate») held for the DARK theme and was INVERTED for the light one — measured 2026-08-08, both root tokens now fixed.** In the light theme a text scalar that must live both on light `gaia-*` surfaces *and* on a raw theme-invariant black panel does **not exist**: the ceiling those surfaces impose (L ≤ 0.183) sits below the floor `bg-zinc-950` imposes (L ≥ 0.187), so the feasible band is **empty** and no value can be found. Migrating those surfaces is therefore the **precondition** of the fix, not its follow-up — proved by mutation (restore one panel, the light example goes red by name while dark stays green). 🔴 **Concretely, for any contrast value in this tree the band has TWO ends, and they pull in OPPOSITE directions: light `gaia-*` surfaces push the value DARKER, raw theme-invariant black panels (`bg-black`, `bg-zinc-9xx`, `to-black` gradients) push it LIGHTER. Compute BOTH before proposing a value — a candidate that only clears the light surfaces is not a candidate.** That is not hypothetical: it is how the light half of `--gaia-text-subtle` was proven impossible, and why removing the raw panels was its *precondition* rather than its follow-up. Both halves of the pair now carry a browser carrier (`spec/features/contrast_root_tokens_spec.rb`); do not restate its numbers here — they live there.

🔴 **The class has a SECOND branch the gate cannot reach by construction, because there the missing thing is not a token but the whole UTILITY FAMILY** (UI.1/UI.3, 2026-08-07). `@tailwindcss/typography` is **not installed**, so `.prose` has **zero** occurrences in the build — and the four panels that rendered server-sanitised markdown under `prose prose-sm dark:prose-invert max-w-none` got no typography at all. The consequence is a11y, not cosmetics: Preflight ships `a { color: inherit; text-decoration: inherit }`, so a link inside rendered markdown had **no distinguishing feature whatsoever** — WCAG 1.4.1 failed in its worst form. ⚠️ `.prose` now has **zero** call sites in the tree, so the reflex below is what survives — and it fires the moment anyone reaches for a plugin utility again. The existence gate is blind here on purpose: `prose` is not a `<utility>-<gaia|status|token>-*`, so it is outside the pattern. **Reflex: before trusting any Tailwind class you did not author, `grep` the class stem in `app/assets/builds/tailwind.css` — a plugin utility, an arbitrary value, and a typo'd token all fail the same silent way, and the markup reads as intentional in all three cases.** → `00_07` UI.3. 🔴 **І з 2026-08-16 у цієї тиші є ЧЕТВЕРТА причина, якої доти не існувало: клас написано ПОЗА оголошеним периметром контенту.** `application.css` більше не успадковує дефолтний скан кореня — він оголошує `source(none)` + `@source` на `app/views`, `app/javascript` і `spec/components/previews` (UI.1: інакше продовий CSS генерувався з `bin/`, канону й навіть вендорованого mruby в `firmware/extern/**` — ~108 утиліт). **Тож греп по білду тепер відповідає на ДВА різні питання одразу — «клас не існує» ⊥ «клас існує, але його ніхто не сканує», — а вигляд у них однаковий.** Перш ніж лікувати «зниклий» клас як друкарську помилку, спитай, у якому ДЕРЕВІ він написаний; якщо це нова рендерна поверхня (ще один preview-каталог, movable ERB, мейлерний шаблон поза `app/views`), лік — рядок `@source`, а не правка класу. ⊥ Не рендерна поверхня → клас там і не потрібен. ✅ **The plugin half now has a gate (2026-08-15): `spec/quality/no_uninstalled_plugin_utilities_spec.rb`.** Its source of truth is the `@plugin` directive in `application.css` — where Tailwind v4 declares plugins — so it is a DERIVATION, not a denylist: install the plugin and the gate falls silent on its own. Today `application.css` carries `@import "tailwindcss"` and **zero** `@plugin`, i.e. no plugin utility is legal anywhere. It reads the SOURCE, never `app/assets/builds/` (gitignored → green on an empty set in CI), and it skips full-line comments so prose explaining a removal doesn't red it. 🔴 **What that gate bought, and it is the reusable half: the suite was ATTESTING the animation.** Eight examples named «renders with fade-in animation» / «renders the broadcast icon» pinned `include("animate-in")` / `include("ph-broadcast")` — presence of a STRING, never existence of a utility — and stayed green for the entire life of a feature that never rendered once (94 sites across 47 files). **A pin on a class name is not a claim about its effect**; that is the same mechanism that kept phantom `--gaia-primary-text` alive on nine sites. ⚠️ Icon FONTS (`ph ph-*`) are deliberately outside it — «the font is loaded» is a different sentence and needs its own gate (§Guard-craft #46); both live Phosphor sites were removed rather than gated.
2. **Raw Tailwind forbidden in SHARED components** — `bg-red-100` only in domain-specific page components; `shared/ui|iot|web3/` MUST use the semantic tokens (`bg-status-danger`, `bg-gaia-surface`, …) so the dark theme + design system stay coherent (CLAUDE.md §6). **HARD-gated in `docs.yml` since 2026-08-07** (`bin/rails gaia:lint_tokens`, default perimeter `app/views/shared/`). 🔴 **Read the asymmetry precisely — and note that it CHANGED on 2026-08-07, so the old reading is now wrong.** This line used to say «`04_04 §3.5` **allows** raw colours in domain page-components, so a hit under `app/views/components/` is NOT a violation». That permission is **withdrawn**: the founder's ⚖️ verdict made the light theme supported (`04_04 §1`), and §3.5's exception was narrowed to values that are **theme-invariant by intent AND declared** — the §16.4 brand-glow allowlist (`animate-ping`/`animate-pulse`/`animate-spin`) plus a value that must not flip (`backdrop:bg-black/60`, the drawer scrim). A raw surface (`bg-black`, `bg-zinc-950`) or raw text (`text-emerald-400`) on a domain page is now a **theme defect**. Note *why* the old permission was wrong rather than merely outdated: it was argued on the **REUSE** axis («these components are not re-used in different contexts») and granted on the **THEME** axis — a colour hardcoded on a single-use page is exactly as theme-dead as one in a shared component. ⚠️ The RULE is therefore stricter than the GATE's perimeter, deliberately: `gaia:lint_tokens` still defaults to `app/views/shared/**` (clean, HARD), and domain components ratchet in per-domain, each expansion preceded by its own migrate wave — measure the remainder with `LINT_SCOPE=app/views/components/ bin/rails gaia:lint_tokens`, never from a number in a doc. `app/views/layouts/` stays outside the gate pending an allowlist row for the scrim.

2a. 🔴 **The theme rides exactly ONE shaft, and since 2026-08-08 that shaft is the ENVIRONMENT — `@media screen and (prefers-color-scheme: dark)`.** There is no theme class on `<html>`, no client-side theme state, and no JS step in the chain at all: `ThemeSwitcher`, `theme_controller.js` and the FOUC script are **gone**. `@custom-variant dark (@media screen and (prefers-color-scheme: dark))` in `application.css` binds the `dark:` variant to the *same* query the semantic tokens sit under, so both halves of the shaft move together. Canon: `04_04 §1` + `§3`. ⚠️ Do not restore the class form (`&:where(.dark, .dark *)`) — with no node carrying `.dark`, it makes every raw `dark:` utility silently dead.
- 🔴 **`screen and` is load-bearing, not decoration.** Tailwind v4's default is the query *without* it, so a variant lacking `screen and` leaves `dark:` utilities dark on a printed page while the tokens go light — the same "two shafts" defect, living only in the print context and invisible to any on-screen pin.
- 🔴 **Do not try to prove the print half in a browser** — measured, not assumed: `Emulation.setEmulatedMedia` with `media: "print"` updates `matchMedia` (the composite query honestly flips to `false`) but Chrome does **not** re-style the already-rendered page, so the body keeps its dark background under a query that no longer matches. 11. **A broadcast payload must carry NO locale-dependent prose** — the cost of a live update scales with **viewers**, never with the **locale catalogue**. `html:` is an eager argument (Phlex renders in the producer's process; `_later_` defers only delivery), and `LocaleSettable` is a `before_action` that neither Sidekiq nor `ApplicationController.renderer` runs — so a broadcast carries the producer thread's locale, non-deterministically: a controller-driven `after_update_commit` ships the *clicking* user's language to every subscriber. 🔴 **But that is only ONE of two failure classes, and the second is worse because it has no symptom.** If a component's *entire* call graph is Sidekiq, the outcome is not non-deterministic — it is a deterministic, permanent `default_locale`, i.e. its non-English translations were never reachable by anyone, ever. Nobody notices: an English-speaking reviewer sees nothing odd, `i18n-tasks` sees a *used* key, and every locale file looks healthy. Check it mechanically rather than by eye — `I18n.locale` is set from exactly three places in this tree (`LocaleSettable#set_locale` — ⚠️ [I18N.3] його кличуть ДВА `before_action`: `set_locale` до автентифікації + `set_locale_from_account` після, бо Rails дедуплікує колбеки за ІМЕНЕМ фільтра й повторна реєстрація ПЕРЕСУНУЛА б єдиний виклик; точка присвоєння при цьому одна — `locales_controller`, `ApplicationMailer#in_locale_of`), all request- or mailer-bound, and no Sidekiq middleware touches it, so **any `t()` reachable only from `app/workers/**` is a dead translation by construction**. Per-locale stream fan-out is a **forbidden class**, not an expensive option — one render + one `solid_cable_messages` INSERT + one NOTIFY per catalogue locale, on the same Postgres instance as the money path, nearly all of it delivered to nobody. 12a. 🔴 **A stream+target pair has exactly ONE owner — the page that renders the target — and the payload's shape belongs to that owner, not to the producer** (UI.4, 2026-07-27; canon `04_04 §8.1б`). The moment a SECOND page wants updates of the same entity is the moment pushing rendered HTML stops being legal. `EwsAlert` pushed `Alerts::Row` (a 6-column `<tr>`) into both its streams, while `Clusters::Show` keeps its alert list as a compact 3-field `<div>` panel — so an updated alert literally changed tag name mid-page while its unupdated siblings stayed `<div>`s.

**The trap is in the obvious fix, and it is worth internalising because every structural check would have blessed it.** Making the panel a real `<table>` legalises the HTML and is still wrong: the two owners need different **verbs**. The panel shows `unresolved.limit(5)`, so resolving an alert there must *remove* the row and backfill the sixth; the worklist must *replace* it with a struck-through row. A fixed HTML fragment cannot express two verbs, so "one shared row component per entity" would not have closed this class **even in principle** — a compact digest and a full worklist are different products of the same data, not one component used twice. Corollary for the repo's own instinct toward DRY: the duplication worth removing here is **semantic** (the `severity → colour` map, which had already diverged — `low` renders blue in the row and green in the panel), not structural.

**The fix that generalises: push a SIGNAL, not markup** — `Turbo::StreamsChannel.broadcast_refresh_later_to(stream)`. The owner re-runs its own query, so the verb, the filters, the pagination and the empty state all stay where they belong; and because each viewer re-renders in their own request, the payload is locale-free by construction (the surface simply leaves the §8.1а migration list). ⚠️ Two conditions. (a) `broadcast_refresh_*` is only usable with `<meta name="turbo-refresh-method" content="morph">` + `turbo-refresh-scroll: preserve` in the layout — without them it is a full Turbo visit with the scroll thrown away, worse than the bug you are fixing. (b) 🔴 **The obvious companion move — `data-turbo-permanent` on client-built state — is a trap, and it shipped here before being caught.** The reasoning feels airtight (morph preserves nodes, so mark the Leaflet canvas permanent since the server renders it empty) and it is wrong on two counts, both verifiable in `turbo.js`: the attribute fires on **any** Turbo render via `preservingPermanentElements`, not just morph; while morph itself additionally requires `action === "replace"` (`isPageRefresh`), so an ordinary nav click never triggers it. On such a visit Turbo **transplants** the node → Stimulus runs `disconnect()` → and if that controller cleans up after itself (`replaceChildren()`), it destroys the **server-rendered content nested inside that same node** along with the client's. In `Dashboard::Map` that is `#map_data_nodes`, so the map would come back empty and every later `broadcast_replace` would aim at ids that no longer exist. **Rule: never mark permanent a node the server renders data into, and read the controller's `disconnect()` before reaching for the attribute.**

🔴 **The morph condition above is INCOMPLETE, and the missing half breaks the page silently — measured 2026-08-05, `00_07` I18N.2.** «Morph meta-tags are in the layout» says nothing about `turbo_frame`s, and on a page carrying one with `src` (lazy-load) a refresh signal **reverts the frame to its placeholder and never re-fetches it**. Живий приклад-кандидат — `reveal_controller` (`IntersectionObserver` + `unobserve` після першого показу): повернений `opacity-0` лишився б назавжди. **Питай не «чи відкотиться стан», а «ЧИ Є ХТО ЙОГО ПОВЕРНЕ»** — саме друге питання розрізняє миготіння й зниклий контент. ⛔ Гейта на це не будуй: заборона вживати такий контролер червоніла б і на правильному дротуванні (`ssot-maintenance` §Guard-craft #27/#61) — носій = застереження в ШАПЦІ контролера, там, де стоїть той, хто дротує. ⊕ **І дзеркальна половина того ж інвентаря — чесний НЕГАТИВ, що економить роботу: незасабмічені форми морф НЕ подорожчує.** Механізм лячний і справжній (`syncInputValue` робить `oldElement.value = ""` при відсутньому серверному `value`, а `ignoreActiveValue` `MorphingPageRenderer` не передає, тож стирається навіть поле під курсором) — але A/B тим самим приладом дав `morph → ""` ⊥ `replace → ""`: звичайний Turbo-візит губить незасабмічене так само. **Перш ніж лікувати «морф щось зламав», зміряй, що робить на тому ж місці ЗВИЧАЙНИЙ візит** — інакше полагодиш властивість навігації, приписавши її морфу.

## Common Tasks

- **Add a Phlex component**: `app/views/components/<domain>/<name>.rb` (`< ApplicationComponent`, `def view_template`); a reusable primitive → `app/views/shared/ui/`. **Tokens only** if shared; accept **pre-loaded data** (no DB in `initialize`); i18n via `t('.key')`. Spec per `04_06 §A`. 🔴 **Then register it, or CI reds** (`component_doc_sync`, `docs.yml`, since 2026-08-07): a row in `04_04 §6.4` (domain) or §6.1–6.3 (shared), and — for a brand-new namespace — a line in the §1 hierarchy tree. Placement rule is the §6.5 decision tree; the ONLY exempt file is `application_component.rb` itself. ⚠️ The registry writes components in **three** row forms (detailed `` `Ns::Class` `` · compressed `` `Ns` `` + leaf list under "Інші Доменні Компоненти" · **bold** in the shared sections) — match the form your section already uses, and note that the §1 tree carries **namespaces only**, never leaves (leaves have one home, §6).
- **Add a design token**: edit the `@theme` block in `app/assets/tailwind/application.css` (a `gaia-*`/`status-*`/`token-*` colour or a font-size); a **font-size ALSO → `CUSTOM_TEXT_SCALE`**; document the usage rule in `04_04 §3`.
- **Token-migration (UI.1 buildable-backlog)**: the CI gate covers `shared/` only (gotcha #2); the domain-component backlog is run **on demand** — `LINT_SCOPE=app/views/components/ bin/rails gaia:lint_tokens`. `bin/migrate-tailwind-tokens` = the safe Ruby codemod (MAPPING + PROTECTED list + dry-run) — replacement is NOT visually-neutral, so QA both themes after a run. ⚠️ This line used to say the backlog was **blocked** on a ⚖️ verdict about the three skin fractions ("is SECTOR a deliberate brand skin?"). **That verdict landed 2026-08-07 and the answer is no** — the light theme is supported, single-theme is legal only when *declared*, and §3.5 now defines the criterion (gotcha 2 above). So what remains is scope, not a decision: per-domain migrate wave → regex expansion, in that order (expanding first reds CI instantly). Plan → `00_07 UI.1`.
- **Add a Stimulus controller**: `app/javascript/controllers/<name>_controller.js` (auto-registered); wire via `data-controller` / `data-action` in the Phlex component. ⚠️ **`data-controller` мусить стояти на СПІЛЬНОМУ ПРЕДКУ всіх своїх targets** — scope контролера = елемент **+ нащадки**, тож target-сиблінг поза піддеревом не реєструється БЕЗ жодної помилки. Куплено: контролер стояв на `div` зі списком, а форма рендерилась сиблінгом того списку — `Cmd/Ctrl+Enter` був мертвий, доки `data-controller` не переїхав на секцію-предка. **Провал тихий за побудовою** (незареєстрований target не кидає), тож перевіряй не наявність атрибута, а те, що ВСІ targets лежать усередині його вузла.
- **A Turbo broadcast**: render the component with explicit data (no `current_user`, gotcha #7); use the delegated pure helpers.
- **Local-verify**: `bin/rubocop -a app/views app/javascript` ([[feedback_local_verify]]) → `COVERAGE=0 bin/rspec spec/views` (Phlex specs — wrap non-English assertions in `I18n.with_locale`) → eyeball the dark theme + `focus-visible:` rings.
