1. **DID `0x00000000` in a batch is DEAD — the Queen pulse rides the signed QATT-v2 header, so never re-add gateway metrics as a fake tree** (ARCH.54, 2026-07-03) — the old Queen-Sentinel pseudo-tree is dropped on BOTH paths (ECB and CCM): the pulse rides the SIGNED QATT-v2 envelope header (8B health block, `firmware/common/queen_attest.h`) → `UnpackTelemetryWorker#enqueue_envelope_health` → `GatewayTelemetryWorker`. Never re-add gateway metrics as a fake tree — it eats a CIFO slot, breaks the CCM stride, and health without a valid Ed25519 must not exist (masking-attack). Canon: `03_02 §7` + `06_08 §1.3`. ⊕ **[FW.59, 2026-09-08] The 8B block's `flags` byte is NOT homogeneous, so never read it as a flat bitmask:** bits 0..3 are health flags (CCM era · ring mounted · legacy drops · spoof drops — layout in `queen_attest.h`), **bit4 is BOOKED** (SEC.21 canary, enforced by a `_Static_assert` — do not take it), and bits 5..7 carry the **reset cause** (`GatewayTelemetryLog#reset_cause`). 🔴 Code `0` there means **NOT REPORTED**, never «cold start» — every pulse row older than FW.59 carries zeros, so reading `0` as a cause back-dates a verdict onto the whole history. Layout home `firmware/common/queen_attest.h`, codes `firmware/common/reset_cause.h`, prose `03_02 §7.1`.
2. **Call `log.oracle_status_fulfilled?` — the enum is declared `prefix: true`, so a bare `fulfilled?` raises NoMethodError and `== :fulfilled` (a Symbol) is silently false.**
3. **Dual computation: server Lorenz (Float) must match firmware mruby (Float) — a `to_d`/BigDecimal operand inside the Lorenz/DCI arithmetic is a bug since FW.7; the `decimal` column `z_value` and the leaf `to_s("F")` are storage, not computation.** → `CLAUDE.md §6`; home `03_04` + the header of `attractor.rb`.
4. **Queue drain is strict: `uplink` (#1) drains COMPLETELY before `alerts` (#2), so a telemetry flood delays alerts — by design.** → `CLAUDE.md §5` (order; home `04_02 §11`) · money-queue starvation — `06_08 §2.5`.
5. **TelemetryLog carries no validations by design (KENOSIS TITAN) — the bounds check runs in `TelemetryUnpackerService` BEFORE `create!` (`#valid_sensor_data?` on ECB, an inline `SAFE_*_RANGE` guard on CCM); never add validations back to the model.**
6. **Partition-aware lookups: prune through the One-Home helper picked by CARDINALITY, never hand-roll `created_at` equality, and retain only by dropping partitions** — `TelemetryLog` is RANGE-partitioned by `created_at` (monthly leaves; +1 every month, no drop/detach mechanism exists YET). ⛔ **Рядкового retention тут НЕ БУДЕ — це присуд, не прогалина** (⚖️ 2026-08-21, `00_07` ARCH.59): ретеншн робить ВИКЛЮЧНО дроп місячних партицій, будь-який `delete_all` над `telemetry_logs` — регресія, і її ловить `spec/quality/telemetry_retention_home_spec.rb`. Канон — `04_01` ⛔ CLEANUP CONSTRAINT [DOC.8]; підстава (однозначність `TelemetryArchiveBatch.retention_expired`) і історія знятого шляху — шапка спеки-носія; механізм дропу — `00_07` ARCH.70. ⚠️ **`telemetry_logs_default` is pruned or not depending on the SHAPE of the predicate** — re-measured 2026-08-07: a **closed** window (`created_at: t...t+1`) prunes to exactly **1** leaf, so the default goes too; an open lower bound (`>= cutoff`) and an unbounded query cannot prune it, and there the default is a permanent extra probe. Say which form you mean.
   **The One-Home set is three methods over two of the three models — pick by CARDINALITY, not by habit:** `TelemetryLog.partition_pruned(created_at_iso, metric_caller:)` (chainable scope) · `BlockchainTransaction.find_with_partition_pruning(id, created_at, metric_caller:)` (ONE row) · `BlockchainTransaction.where_ids_pruned(ids, span, metric_caller:)` (a SET of known ids — `span` = the `created_at` of those same rows, so the row set is unchanged; a planner hint, never a filter). Both `BlockchainTransaction` forms count their degraded path (`silkennet_blockchain_transaction_unpruned_lookups_total`). `GatewayTelemetryLog` has **no helper**, deliberately: zero id-lookups exist on it, so one would be a lever with no puller.
   🔴 **Never hand-roll the narrowing** — exact equality on `created_at` misses by construction (ISO-8601 carries seconds, the column microseconds) and that form shipped three times; on the mint path the miss is **silent** (`return unless log` → the job succeeds having done nothing). ⛔ **But a `status`-scan is NOT this class and a bound there is HARMFUL** (ARCH.52: a `:pending` row can be arbitrarily old — KYC-skip, circuit HOLD, collector accumulation and a lock timeout all leave it `:pending` cycle after cycle — so a lower bound orphans stranded funds; the lever is a partial index. ⚠️ The ground it was first ratified on, a raw `:processing→:pending` reset, no longer exists since 2026-09-22 — ARCH.62 removed it for stripping another job's claim). Rule of thumb: **a window prunes a lookup for a KNOWN row; an index prunes a set of unknown size.** The invariant now has a carrier — `spec/quality/partition_key_discipline_spec.rb` (declaration required per `.reload` and per id-lookup). Canon: `04_01` ⚡ PARTITION PRUNING INVARIANT [S6.16].
7. **«Wire = вхід GP»: the CCM frame carries the exact EMA `delta_t` the device fed into growth points, and the server recomputes GP from it statelessly** (E.63 (г), wire-rev2.1) — the CCM frame carries BOTH dT fields: raw (bytes 12..13, diagnostics/server-EMA) and `ema_delta_t_s` (bytes 20..21) = the EXACT number `metabolic_health` consumed on the device → `check_metabolic_divergence!` recomputes GP statelessly via `Attractor.expected_homeostasis_gp(ema)` (byte-identical mirror of `BioContract.metabolic_health` in `bio_contract.rb` (canon `03_04 §4.3`) — edit the formula/thresholds THERE first, mirror second, regen `lorenz_bytecode.h`). The branch is **observational** (warn+metric) until the bench calibrates `DELTA_T_FAST_S`/`DELTA_T_SLOW_S`; `ema_delta_t_s` is transient (stripped pre-persist, like `lorenz_temperature_c`/`device_z`). ECB frames carry no ema → branch honestly skips. Canon: `03_04 §4.3` + `03_01 §13.6`.

8. **`firmware_version_id` — це wire-ЗВІТ, не FK: читай через `TelemetryLog#firmware_report_*`, ніколи не джойни й не порівнюй з `BioContractFirmware.id`** (SEC.20, 2026-07-12) — post-SEC.20 семантика `[semantic:1|reverted:1|contract_id&0x3FFF]` (дзеркало `firmware/common/fw_report.h`): читай через `TelemetryLog#firmware_report_semantic?/reverted?/contract_id` (id ПО МОДУЛЮ: 14 біт на ECB-кадрі, 7 біт на CCM — vpd-байт `[reverted:1|id7]`, best-effort echo, несучий лише `reverted`; НЕ join і не пряме порівняння з `BioContractFirmware.id`); legacy-кадри (без semantic-біта) несуть C-image константу — contract-версії НЕ мають. `reverted?` → `EwsAlert firmware_reverted` (термінальний: re-issue лише версією > спаленої — 03_06 §4 bump-інваріант).

9. **TelemetryLog несе MRV-lineage сліди, і стемпнутий рядок запечатаний — мутація leaf-поля кидає raise, а нове leaf-поле вимагає `LEAF_VERSION`-bump** (ARCH.12/E.60, 2026-07-19) — mint-інтенти отримують детерміновані вікна вимірів (`Wallet` watermark-курсор → `telemetry_window_*` на tx), а pin-воркер стемпить `telemetry_logs.{archive_root, merkle_leaf}` (E.60 Фаза 1б). **Перший AR-колбек моделі**: `before_update` seal-guard — мутація `z_value`/`bio_status`/`created_at`/`tree_id` стемпнутого рядка = raise (KENOSIS недоторканий: intake = `create!` (INSERT), а `before_update` на INSERT не стріляє; oracle_status/verified_by_iotex — не leaf-поля, вільні). Leaf-формула One-Home = `05_02 §E.60` (`Mrv::TelemetryLeaf`, LEAF_VERSION). Не додавай у leaf-payload нове поле без `LEAF_VERSION`-bump.

10. **Device-event 0x57 = ОКРЕМИЙ L1-канал, не телеметрія (SEC.21, 2026-07-12)** — рідкісні security-події (canary-trip) НЕ їдуть телеметрійним трактом: окремий CoAP `PUT device/event/<uid>` → `DeviceEventWorker` (не `UnpackTelemetryWorker`). Королева підписує cleartext-конверт власним EDSK (тег `SLKN-QEVT1`, окремий від QATT2) → worker **verify gateway-origin** (`HardwareKey.ed25519_public_key_hex`, як QATT-батч), Rails LoRa-ключа НЕ торкається. Не плутай з CCM blind-courier телеметрії (там per-DID decrypt на Rails); тут — L1-підпис Королеви. Trust L1-observational, НІКОЛИ не money-path. Дім `03_05 §2.2а` + `03_02 §7а`.

11. 🔴 **OTA-mismatch у розпакувальнику СПОСТЕРЕЖНИЙ (ARCH.85): колонку-гейт тепер пише форма, тож гілка біжить, але лише логує й `fw_pending` не ставить — а перш ніж довіритись гілці, гейтованій колонкою, перелічи ПИСАЛЬНИКІВ, не читачів.** `TelemetryUnpackerService#latest_tree_firmware_id` бере `BioContractFirmware.active.where(target_hardware_type: "Tree")`, а `check_firmware_mismatch!` виходить на власний `return if latest_id.nil?`. Писальників тієї колонки в `app/` було нуль (форма завантаження слала ключ без колонки), тобто при суто-nil популяції детекція мовчить **за побудовою**, а не через дані. Наслідок сьогодні: перший типізований `Tree`-реліз дасть на кожному розбіжному аплінку лише `logger.info` «Стан НЕ змінено» (присуд нижче) — а інертна гілка, що вмикається на гарячому шляху, завжди є зміною поведінки, спричиненою сусіднім доменом. **Рефлекс: перед тим як довіритись будь-якій гілці, гейтованій значенням колонки, перелічи ПИСАЛЬНИКІВ, а не читачів** — колонка, яку ніхто не пише, робить гілку декоративною, і читацький бік при цьому виглядає справним. ✅ **ПРИСУД 2026-08-14 (ARCH.85, §🗄️): гілка лишається СПОСТЕРЕЖНОЮ, не дієвою** — вона пише `logger.info` про розбіжність і `firmware_update_status` НЕ міняє. Дієвий `update_all` **знято**, не закоментовано. Підстава — blast-radius першого прогону: тракт не біг жодного разу, тож перший запуск стався б одразу в полі, на гарячому шляху, і при хибній деривації позначив би `fw_pending` весь флот, а ретрансміту в цього стану немає (`FW.63`). ⚠️ Прапорця-перемикача свідомо НЕМА (забутий прапорець = тихо вимкнений захист, прецедент `INF.11`), тож оживлення = зняти один рядок ПІСЛЯ того, як спостереження покаже правдоподібні числа на живому флоті (сьогодні це лише `logger.info`; метрики НЕМА — заведи її першим кроком; тригер — `00_07` ARCH.59). ⊕ Заразом закрито сусідній зомбі: `deploy_globally!` не гасив БЕЗТИПНИХ предків (`where(col: X)` це SQL `= X`, а NULL не дорівнює нічому) — скіл `backend` #44.

12. 🔴 **`acoustic_events` = детекції від останнього УСПІШНОГО uplink'а (ARCH.102): накопичення легальне, `0xFE` — сентинел часу, а кавітація й пилка злиті в один лічильник — вердикту на цьому полі не будуй.** Доти на дроті було завжди 0 або 1, і бекендні пороги писались під семантику «подій за вікно», якої прошивка не мала. Фаза 2 Солдата знімала І ОБНУЛЯЛА лічильник на кожному проході `while(1)`, а три інкременти взаємовиключні (`if/else if` по зоні впевненості й класу) → максимум +1 на пробудження; тож обидва пороги `AlertDispatchService` — `insect_epidemic` (`> 50`) і `seismic_anomaly` (`>= 200`) — були недосяжні з реального заліза і стріляли лише на наших-таки сідах/HIL-профілях. Після фіксу лічильник споживає ЛИШЕ успішна передача телеметрії (віднімання знімка, не обнулення) — детекції deferred-TX-циклів (мороз) і grace-hello більше не зникають, незʼїдений залишок переживає STOP2 у DR0 — тож багатоциклове накопичення тепер легальний wire-вхід (0xFE лишається time-uncertain-сентинелом, який unpacker нейтралізує ДО DCI). 🔴 **Обидві вердикт-гілки на цьому лічильнику ЗНЯТО тим самим присудом, і підстава пережила фікс:** поріг став досяжним, а вимірювача так і немає — класу «комаха» в TinyML нема взагалі, сейсмічного каналу теж, лічильник рахує кавітацію та пилку. **Тобто «полагодити семантику» і «зробити вердикт чесним» — різні роботи, і перша другої не дає.** Вердикт-споживачів на цьому полі НУЛЬ (обидва зняті); решта читачів лише показують чи пінять його — DCI-σ (`03_04`), сентинел `0xFE`, FW.22-метрика, `AiInsight.reasoning`, IoTeX-payload (перелік: `grep -rn acoustic_events app lib --include="*.rb"`). ⛔ Не додавай нової гілки на це поле без відповіді на «а звідки ти це знаєш» → `00_07` ARCH.102 + `04_02 §2`.

14. 🔴 **Enqueue телеметрії мусить нести момент ПРИЙОМУ — інакше доба cold-derive Лоренца тихо з'їжджає на добу ОБРОБКИ** [ARCH.41, 2026-08-28]. `UnpackTelemetryWorker#perform` має ЧЕТВЕРТИЙ аргумент `received_at_iso`, який їде далі як `TelemetryUnpackerService.call(received_at:)` і читається One-Home-методом `derivation_epoch_day`. ⚠️ **Обидві опції, які здаються очевидними, ХИБНІ:** `Time.now` рухається зі спробою, а `telemetry_log.created_at` ставиться при ВСТАВЦІ, тобто на Sidekiq-ретраї він такий самий новий. Єдина величина тракту, стабільна між спробами, — момент прийому, зафіксований інтейком і серіалізований у job-аргументи. **Ціна промаху:** ретрай через межу півночі UTC дає інший `epoch_day` → інший (x₀,y₀,z₀) → категоричний DCI-мисматч на ЧЕСНОМУ дереві, і ловити його НІКОМУ: `try_time_sync_recovery` (ARCH.41-A) гейтований `!cold_start_flag`, тобто страхувальна сітка структурно відсутня рівно на cold-start, де деривація й відбувається; `-B`/`-C` стережуть НЕсинхронізований пристрій, а тут час пристрою правильний. 🔒 Аргумент ОПЦІОНАЛЬНИЙ за побудовою (`nil` = «прийом зараз», легально для bench/HIL/спек), тож його ВТРАТА на прод-сайті нічого видимого не ламає — це тримає гейт `spec/quality/telemetry_received_at_propagation_spec.rb` із ліхтарем периметра, що червоніє на НОВОМУ продовому enqueuer'і. ⛔ Додаєш enqueue-сайт — передавай `Time.current.utc.iso8601` четвертим; `lib/silken_net/load_test/**` свідомо поза периметром (bench не моделює прийом).

15. 🫁 **Soldier-pulse НЕ є окремим кадром і не потребує гілки в розпакувальнику** [SILENCE-1, ⚖️ 2026-09-04]. Кадр «я тут, але нічого не міряв» — це той самий 30B CCM-пакет із `delta_t = DELTA_T_UNKNOWN_S`, що дає на дроті пару **`status = 0, GP = 0`**, якої у ВИМІРЯНОГО гомеостазу не буває (той починається з `GP_HOMEO_MIN`) — тобто регістр оголошений даними, без нового опкоду, довжини чи прапорця. Присуд обрано **виміром** (airtime й енергія проти гілки в `Queen_Rx_Classify`, що розрізняє кадри суто за довжиною) — числа й підстава в `06_08 §1.3`. ⛔ **Тож не додавай `pulse?`-предиката й не роздвоюй шлях:** будь-яка гілка «це pulse» відтворює той самий поділ на рівні, де його немає в даних. Що ВАРТО тримати — **ТРИ** піни: pulse штампує `last_seen_at` (інакше він не розвʼязує конфаунд «мовчазне здоровʼя ↔ мертвий вузол», задля якого існує) · НЕ дає балів (інакше вузол отримує гроші за відмову міряти — рівно ціна `BASELINE_DELTA_T_S`) · **і НЕ кричить fraud**. 🔴 **Третій пін — НЕ кричить fraud:** `check_metabolic_divergence!` приймає `GP_UNMEASURED` при гомеостазі, тож оголошена пара `status = 0, GP = 0` не є порушенням смуги. Пін мусить міряти МОВЧАННЯ `TELEMETRY_FRAUD_DETECTED_TOTAL`, а не лише живість і бали; якщо файловий `before` пінить `calculate_z_from_state` поза смугою, повертай z у смугу локально, а не підганяй код під фікстуру. Дім — `06_08 §1.3`; сусідній писач-інваріант — скіл `backend` #83.

Про фізіологію він не свідчить ЗА ПОБУДОВОЮ — детермінована функція від входів, які верифікатор і так має в plaintext, тож за data-processing inequality не додає інформації понад них (`05_05 §8.1`). 🔴 **І це не теорія — так уже сталось ТРИЧІ, на трьох рівнях агрегації, щоразу з ВИМІРЯНОЮ ціною:** (1) серверна гілка `Attractor.homeostatic?` → `severe_drought` спрацьовувала на ЧЕСНИХ деревах у 1.4 % (MAX-бік, тепла погода); (2) кластерна `entropy_anomaly` давала «здорову» смугу 0.908 на лісі з НУЛЬОВОЮ біологічною різницею (⚖️ 2026-09-05 тракт знято ЦІЛКОМ — писач, сервіс, cron, gauge, Grafana й сама колонка `clusters.entropy_score`; enum-значення й локаль-ключ лишені історичними заради рендеру архівних рядків); (3) **найдорожча й знайдена ОСТАННЬОЮ — `avg_z` як ФІЧА RandomForest** у `InsightGeneratorService#calculate_stress_index` (знято 2026-09-05, дім → `00_07` E.52): через ML це не мʼякше, а ГІРШЕ, бо евристична гілка має стелю `0.6 < 0.83`, а `predict_proba` не має жодної — тоді як `stress_index` іде ПРЯМО в `BlockchainBurningService` (`slashUpTo`), Celo-виплату й страховий Trigger-1. ⛔ Тож заборона накриває не лише предикати, а й НАВЧАННЯ: `avg_z` у фіча-векторі є тим самим вердиктом, лише схованим у вагах, де його вже не видно ані грепом, ані ревʼю. Спільна причина всіх трьох — розкид Z між деревами породжений їхніми `K_seed`, які ми ПРИЗНАЧИЛИ, а не мікросередовищем. 🔑 **Дискримінатор, що ловить наступний випадок: питай не «чи прилад справний», а «про ЧИЙ предмет він свідчить» — про дерево чи про наше власне слово, сказане дереву.** ⊕ Легальний біо-гейт лишається один — ПРИСТРІЙНИЙ `bio_status` (він теж вироджений: `stress` = `z < 2.0` недосяжний за ρ-clamp, тож перил посухи сьогодні не має авто-писача, і це оголошено в `00_04 §2`). Здоровʼя мусить прийти з ПРЯМИХ вимірювачів (вологість · sap-flow · VPD · акустика) — їх у залізі ще немає, і доти чесна відповідь: «ніхто не міряв».
