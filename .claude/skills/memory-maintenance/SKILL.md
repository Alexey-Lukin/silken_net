# Memory Maintenance

Executable playbook for keeping the persistent memory (`~/.claude/projects/…/memory/`) **clean, structured, dedup'd — without amnesia**. This skill is the **HOW**; it does **not** restate the memory FORMAT (frontmatter / types / Why+How-to-apply / `[[<slug>]]` links / one-fact-per-file — that's in the system prompt), nor the live state (that's in the memories themselves).

## 📖 The method lives in one place (don't restate it here)

Full step-by-step playbook + founder's principles + the zero-loss scripts → **`.claude/prompts/memory_housekeeping.md`**. Read it before acting. Sister to `[[reference_deep_archival_prompt]]` (00_07 cement) — same "the prompt is the home, the skill just points" pattern as `ssot-maintenance`.

**Three modes:** (1) *housekeeping* (this skill + the prompt — de-cruft, structure, stale-hooks, action-items→00_07); (2) *4-way memory-sync* — a per-section pass bringing memory ↔ domain-skill ↔ canon ↔ 00_07 to one truth (ROUTE-not-restate, fix drift on BOTH surfaces, write gaps). The sync recipe (fan-out READ-ONLY agents + fable-holistic) lives in `[[project_memory_sync_program]]`; the §00–§08 cycle closed 2026-07-18. (3) **class-home consolidation** — a theme scattered as a side-note across 15–35 files, each time in a DIFFERENT vocabulary, gets one home; grep cannot find it *by construction*, so the inventory is READ-based fan-out. Built in waves, each one paying part of the previous wave's phase-2 debt; the **7-step recipe, its traps and the ledger of still-PARTIAL classes all live in `[[log_perimeter_prep]]` — read it BEFORE consolidating another**. Never keep that tally here, and no longer look for it in the tracker: DOC-T.59 carried it until 2026-08-04, when the item closed, its body was collapsed and the ID went to `§🗄️`.

### Traps before you consolidate — each one cost a wave

*(This list said «three» while carrying six, for two weeks — a header is a claim, and it drifts like any mirror. The count is deliberately absent from the header, and was re-added twice anyway; if you are about to write one, that is the drift restarting.)*

**(1) Scout counts run LOW.** A scout agent's carrier count is systematically LOW (it reads big files; most carriers are short clauses in mid-sized ones) — and it is not a model tier but a QUESTION SHAPE: on DOC-T.58 the low count came from the *adversarial*, which sampled ten examples instead of inventorying, and undercounted **tenfold**. ⚠️ **Read this WITH its mirror, or you will generalise it into "agent numbers run low" and be wrong where it costs most: the direction is set by WHAT is counted, not by who counts.** A count of what EXISTS runs low (this trap); a count of what is REDUNDANT runs HIGH — «48% of the index mirrors the tracker» re-measured at ≈8.7%, because the pass had counted the MARKER instead of the CONTENT. The two errors push opposite ways and both are cheap to believe: one under-builds homes, the other licenses cuts. → [[feedback_measurement_substitution]]

**(2) A «half-home» may be a duplicate.** "This class already has two half-homes" is often not coverage but a **duplicate** — compare their texts before believing it.

**(3) One-way strings fake homelessness.** 🔴 **A section can read as a live homeless class purely because its string is ONE-WAY.** The home was built by extraction FROM that section and cites it as provenance, but phase 2 never left a router back — so the source's reader never learns the rule already has an address, and the next pass re-derives the whole class from scratch. The systematic hole: the recipe says "in EVERY source file", and in practice it got applied to the `project_*` file while its `log_*` twin kept the rule in full. **Before declaring any theme homeless, ask whether a candidate home already cites this file — a home that cites you is a home you already have.** 🔴 **Stop hand-grepping for it: `memory_gate.sh --oneway` is the runnable form of exactly this question** (groups by the file the router must be written INTO, so one edit closes several pairs; the env lever is `MEMORY_GATE_ONEWAY_MIN`, and a bare `ONEWAY_MIN=` from the shell resolves to nothing — measured by walking into it). Its perimeter is *provenance* only — a rule-home citing a `log_*`/`project_*` source — so a clean run says nothing about peer cross-references, which are one-way by design.

**(4) Machine dedup is capped at verbatim.** 🔴 **Any machine measure of duplication in this corpus is capped at VERBATIM, and the gap is an order of magnitude.** The corpus is bilingual, so a rule written in English in the journal and in Ukrainian in its home is invisible to grep AND to shingles: on the worst offender a READ-based inventory found ~80 doubled rules where grep saw 7 and the shingle gate saw 2. Start from `--audit` to get the verbatim ones for free, then inventory by READING — never treat a green overlap as "no duplicate homes", only as "no verbatim ones". 🔴 **The same bilingualism makes a false negative the DEFAULT when you verify an index hook against its file, and there the error is expensive in the other direction — it invites you to "fix" a healthy hook.** The hook is often Ukrainian and the body English (or the reverse), so the check starts at zero hits: `READ-ONLY = ТИП агента` lives as *the brief does not constrain tools — the agent TYPE does*; `findings = кандидати` as *Agent findings are CANDIDATES*; «скоупінг має ТРИ половини» as *Scoping has THREE halves*. Two lexical traps ride along — Cyrillic case (`гейт-ПАРА` ≠ `Гейт-ПАРА`, and `grep -i` is unreliable on Cyrillic) and the apostrophe (`пʼять` ≠ `п'ять`) — plus the hook's own habit of compressing a paragraph into a LABEL, so the words genuinely differ. Measured in one pass: **8 of 10 "orphans" were false**, and twice a valid hook was nearly rewritten. **Order: root of the word → case-insensitive → BOTH languages → and only a READ gives the verdict.** Two corollaries worth carrying: after any rule/journal split, walk the target's hook, because a split leaves the index quoting clauses that have moved out; and a hook may be quoting its own file's STRUCK-THROUGH text, i.e. the file corrected itself and the index stayed on the pre-correction version.

**(5) Declare the UNIT first.** 🔴 **"Debt weight" and "what an excision returns" are different quantities, and the difference is in the SIGN — so declare the UNIT before the pass.** In a `project_*` file the debt sits in the MISSING ROUTER, not in duplicated prose: the instance is load-bearing and the generalisation is one sentence, so replacing it with a `[[string]]` costs the same or more, and the file GROWS. A phase-2 pass over `project_*` is therefore **router placement, measured by COVERAGE (inbound files), never by bytes**; only `log_*` journals, which restate rules in full, give bytes back. The tell is readable before you start — a clause shaped "instance + one sentence of rule" returns zero. Same failure at the counting level: asked without a declared unit, one inventory answered **3** and **14** for the same corpus. 🔴 **The verdict VOCABULARY needs the same care as the unit, because one verdict token can fuse two questions** (DOC-T.58): an agent marked a line CORE whose rule already stood **48 lines above in that same file** — it had seen the internal duplicate and said so, and still did not change the verdict, because «CORE» meant to it *belongs to this file* rather than *is unique within it*. Define each verdict so those two readings cannot collapse into one word.

**(6) Mechanism ⊥ frame.** 🔴 **"Does this have a home" is TWO questions, and the second decides: is the MECHANISM in the corpus ⊥ is there a FRAME over it.** A mature class can have its mechanism written verbatim (under a name the tracker never used), its gate-side half in a skill, and its remedy in another home — and still lack the frame; building a file then buys a FOURTH address, while the right move is a **dispatch** (write the frame into the best existing home + strings back). Before deciding, enumerate what is already covered — instance, mechanism, remedy, or frame — because the homeless one is almost always the frame, and grep cannot find it: grep finds instances. Corollary on debt: the phase-2 rubrics DUPLICATE/ROUTED split by whether a string exists, which silently merges "done" with a third state — **the router is there AND the restatement stayed next to it**. That state reads as the cheapest excision in the corpus and no rubric names it, so ask the third question explicitly. 🔴 **But "cheapest" is only half true, measured on all 14 of them (2026-08-04): a string cannot be lost, yet the address can be WRONG and the home INCOMPLETE.** 3 of 14 routers pointed at the wrong place (a numbered skill item when the rule sat in the unnumbered paragraph beside it; `§3` when the rule was in `§4`; the instance's home when the rule's home was a different file) — that is disinformation, not debt, and it is invisible precisely because the link resolves. And 4 of 14 restatements carried a half the home did not have, so excising as planned would have been amnesia four times over; the fix is MIGRATE-FIRST (write the missing half into the home, verify, then cut) or leave it with an explicit "this is the only copy" marker. **So this class costs the same READ as an ordinary duplicate: verify the router's TARGET and the home's COMPLETENESS, never just the presence of `[[brackets]]`.** 🔴 **And a wrong address survives even when the file KNOWS about it** (2026-08-05): a source carried a ⚠️-note forty lines BELOW the defect, stating that «the line above sends this phrase to a neighbour, not to the class home» — and it was left as a NOTE instead of a fix, so every reader of the defective line stayed unprotected, because an annotation guards only what it can reach. **Finding a wrong router obliges you to fix it in place; writing a note about it reproduces the class one level up.** Measured numbers → `log_perimeter_prep`.

**(7) An excision that TRANSLATES pays the bytes back — and looks like honest work while doing it.** 🔴 Measured 2026-08-04: shortening two English clauses and rewriting the remainder in Ukrainian produced **+40 B** across both; redoing the same two in the ORIGINAL language returned **−648 B**. Cyrillic costs 2 B/char, so the clause genuinely shrinks in characters while growing in bytes — the tell is invisible unless you measure in the unit the ceiling counts. **Keep the clause in the language it was written in**; the choice is a unit of measurement, not style. The sibling one level up: an excision's own INVENTORY costs about what the excision returns (seven cuts plus a refreshed header came to −35 B net), so **never report this work in bytes** — report how many rules stopped living in two homes.

**(8) Measure the RECEIVER's headroom, not just the source's debt.** 🔴 MIGRATE-FIRST requires writing the missing half INTO the home, and a saturated home has nowhere to put it. Measured 2026-08-04: five rule-homes sit at 35.7–36.0 kB against a 36 kB WARN, i.e. the phase-2 receivers hit the ceiling as a GROUP, not one fat outlier — one edit pushed a home past WARN mid-session and an instance had to be evicted before the migration could proceed. The lever is eviction into the `log_*` twin (what the gate's own CAP line advises), never prose dieting (~2% at the ceiling); check the twin EXISTS first. ⚠️ **The "one of the five has none" clause that stood here was STALE and is removed — its subject had been fixed by the very remedy this trap prescribes** (twins were created for the two homes lacking them, so all five criticals now have one; re-verified 2026-08-09). An instruction to do something already done is worse than a merely outdated one: it spends a pass and reads as an open hole. 🔴 **Re-measured twice since and the count moved BOTH ways, so carry neither the number nor the frame: measure the band's MEMBERSHIP, never inherit it.** (2026-08-16 it was fourteen; 2026-08-18 a fresh pass found eighteen, and three evictions took it to sixteen.) Get it with one command over `*.md` minus `log_*` minus the index, sorted by `WARN − size`; the tightest few are what decide the next wave's route. 🔴 **That reading was OVERSTATED, and it is corrected here rather than repeated: re-measured 2026-08-18, the tight band is a small minority of rule-homes while the median home has tens of kB free.** So it is not «wherever you write» — it is a NAMED QUEUE of mature, heavily-cited homes, and the practical consequence inverts: write freely almost everywhere, and plan a route only for that queue. ⚠️ The overstatement propagated by being INHERITED — a later pass echoed it while measuring something else, which is why a frame deserves the same re-measurement as a number. ⚠️ **And the twin-detector I measured that band with lied first, in exactly the class this page describes:** I looked for `log_<same stem>`, while twins are named by THEME (`log_verify_gate` for `feedback_verify_gate_exit_code`, `log_cross_ref_dig` for `feedback_exhaustive_cross_ref_dig`, `log_portfolio_surgery` for `project_portfolio_lano_surgery`) — name-matching reported «8 of 14 have no twin», measuring by the STRING (`[[log_*]]` in the body) gives **13 of 14 do**. **Ask not «does a file with the predictable name exist» but «which journal does this home POINT AT».** ✅ **The file this clause used to name — `project_money_path_orchestration`, then the only one with no `log_*` string — was split 2026-08-18** (seven instances of the `ARCH.87/88/94/96/97` classes into a new `log_money_path`; the section stayed as a header carrying only the rules, so no inbound address orphaned). It bought 306 B → 3592 B of headroom, and both curated constants had to move with it (`CORPUS_FLOOR`, `DESC_BASELINE`) — **budget that: a new twin is not free, it lands as two gate findings.** ⚠️ And the same pass found the twinless set was never a singleton — read this clause as a METHOD, not a worklist: re-derive «which homes point at no journal» by the STRING each file carries, and expect the answer to differ from the last write-up. 🔴 **And the group is not a fixed five — re-measure the BAND, never inherit its membership.** The 2026-08-09 pass found the tracker item naming four files while the critical band held five; the unnamed one was `feedback_measurement_substitution`, i.e. the home of "measurement substitution" — the receiver of every measuring wave, including the one doing the measuring. Order the work by *which home the next wave must write into*, not by which is fattest. 🔴 **Two corrections measured 2026-08-04, both about the instrument rather than the size.** (a) `WARN` is not a warning: `--audit` ends in `[ -z "$out" ]`, so a single WARN line makes the whole battery EXIT 1 — the working ceiling is the WARN, and the CAP is only where the advice changes. (b) **Before asking "where do I migrate this half", ask whether it is ONE rule at all.** A clause whose two halves belong to two different homes is cured by a PAIR of routers and needs no headroom anywhere — that is what unblocked a migration into a home with 36 B left. And when you do evict, the direction matters more than the byte count: move INSTANCES down into the journal, never the generalised rule, however verbatim the twin repeats it — a rule that lives only in a dated journal paragraph is findable only by someone who already knows the incident. 🔴 **Two more measured 2026-08-05, both about where the room actually comes from.** (a) **An excision does NOT pay for the migration — one file GREW.** `portfolio_lano` went 288 → **221 B** of headroom after four cuts, `stream_scope` gained **35 B**: a router weighs about what the sentence it replaces weighed. So "cut there first, that frees the room" is right about the ORDER and wrong about the ECONOMICS — only eviction into the `log_*` twin frees space, so never schedule a migration whose headroom depends on cutting the receiver. (b) Sibling to the "is it ONE rule" question above: **ask whether it is a MEMORY rule at all.** OPS.14's remedy sat in the queue as MIGRATE-FIRST behind a heavy prologue (evict an instance to make room) — and a READ found it already canonised in `06_07 §2` + `00_06 §3`, i.e. the half belonged to CANON by type-routing (shipped mechanism → canon), so a 171 B router closed it. One grep over `docs/` replaced a session of eviction. 🔴 **Measured again 2026-08-05 and now a pattern, not an anecdote: a THIRD of the migrate queue was not memory's.** Three of `advisory_to_hard`'s eight "homeless" halves — the recipe for promoting a gate to required — were shipped CI mechanics and went to `06_07 §2`, right beside the OPS.14 invariant that had gone there for the same reason a wave earlier. And the destination is not always canon either: of `log_subagent_craft`'s five, **two belong in SKILLS** (`memory-maintenance` traps (5) and (13a)) and one in `ssot-maintenance` §Guard-craft — a portable rule about how the WORK is done has no canon home and no memory home; its home is the playbook someone reads before doing it. **So the destination question has four answers — memory · canon · skill · prompt — and asking it costs one grep while getting it wrong costs a session of eviction from a saturated home.** 🔴 **And the WARN is a TRIGGER for that question, not only for eviction — ask it on the FIRST warning, not after two rounds of shaving** (2026-08-22). A lesson about a gate built over a workaround was written into `feedback_challenge_the_task`; the gate reported over-ceiling twice, and both times the reflex was to shorten the prose — while the correct answer was already sitting in (b) above: a portable rule about how the WORK is done belongs in the playbook (here `ssot-maintenance` §Guard-craft), not in memory. Note the asymmetry that makes this worth a line: shaving *feels* like progress because the number moves, so it hides the question instead of raising it. **Reflex: the first over-ceiling on a NEW entry reads «is this even a memory fact?»; only the second reads «where does it go inside memory».**

**(9) «All three surfaces» is FOUR — the index is one of them.** 🔴 A class was declared homeless twice, with the formula "zero hits across memory · skills · canon", while its home sat in `project_sec07_legal_campaign` **under the tracker's own literal wording** — and that same wording was a line in `MEMORY.md`, the file loaded into every single session (DOC-T.59, 2026-08-04). This is not the vocabulary trap of (3): the words matched. The index escapes the sweep because it is read as *navigation* rather than as content, so a three-surface pass walks past the one surface that is always already in context. **Before any "homeless" verdict, grep `MEMORY.md` itself** — one grep against a wave of consolidation work, and a hook is exactly the one-line pointer a class-search is looking for.

**(10) Ask whether the clause has TWO homes, not whether it has one.** 🔴 The tail of a journal was priced at ≈1.6 kB and re-measured at **≈10.1 kB** — six-fold — because the dominant form was invisible to every check run so far: the clause carries a router to the **abstract rule** (`A-2`/`A-3`/`A-10` in a rule-home) while the *same concrete instance* sits in full in a **skill that the clause never names** (`backend` #15/#1, `frontend` #12 — the gated-action actor; a bare number is a brittle address, so name the subject beside it). A router-presence check cannot see this **by construction — the address is there and it is CORRECT**; only opening the domain skill for the instance's own subject finds it. This is why phase-2 numbers keep rising instead of converging: each pass asks a sharper question of the same text ((6) asked "is the restatement still beside the router", this one asks "is there a second, undeclared home"), so **a band that measured clean is clean only against the question that pass asked** — record the QUESTION next to the number, or the next pass will read your total as the corpus's state rather than as your instrument's reach. The same session proved the mirror: a section certified an exemplar by the morning's inventory failed the evening's, unchanged. 🔴 **Measured 2026-08-05, and it turns the aside above into the main rule: the undeclared home is not a minority case.** On the `sec07_legal_campaign`+`log_sec07_legal` pair the principal home was a **skill** — `.claude/skills/legal-business/SKILL.md` holds 8 of the source's clauses verbatim and is invisible to a grep for the source's filename — and together with the other out-of-perimeter homes that is **15 of 24 excisions** the brief would never have surfaced. **So the inventory perimeter is `feedback_*` + `reference_*` + `.claude/skills/**` + `docs/`, always** — a "no home exists" verdict computed over memory files alone is wrong by construction, and it fails in the expensive direction: it schedules a MIGRATE that would write a third copy of a rule already living in a skill.

**(11) A `⊥` mark blesses the DIVERGENCE, not the missing router — it does not exempt a clause from phase 2.** Measured on `feedback_one_token_two_domains`: 4 of the 5 instances inside its ⊥ section ("deliberate divergence") were full unroutered duplicates, exactly like ordinary clauses. The mark reads as *decided, do not touch* — and that reading is correct about the CONTENT and wrong about the FORM. Same shape as the ⛔ "do not cut" list one level up: a protection is itself a claim, and it ages. 🔴 Sharpened 2026-08-05 by a ledger that contradicted ITSELF — the same block was listed both as ⛔ «router by design» and as an internal duplicate, and **both entries were right**: the block was router-shaped by design, and a restatement had moved in beside it. So a ⛔ mark protects the **FORM**, never whatever currently fills it, and the cure is neither «lift the protection» nor «ignore the diagnosis» but to make the block **more** of the thing it was protected for.

**(12) The claims that rot are almost exclusively SELF-LOCATION claims — and no sweep of the file that carries them can see it.** Measured across a 93 kB journal's every header, lead and frontmatter (2026-08-04): 10 FALSE, 5 OVERBROAD, 20 TRUE, and the split is not random. What failed: *«тут лише те, чого memory дім»* · *«дім саме тут»* · *«what lives ONLY here»* · *«стоїть ТРИЧІ дослівно»* · *«крім SEC.25»* · every ⛔ "only-here" protection (2 of 3 stale). What held at ~100 %: every `механіка → NN_NN §` delegation arrow (20+), every dated header, every named file — the only delegation failures were at *item-number* granularity inside a home (`04_06 §B.2` BP #14 vs #15), because numbers inside a home shift and section names do not. **The mechanism: a self-location claim is falsified by an edit in ANOTHER file** — a skill gains the rule, a tracker item moves to `§🗄️`, a canon section absorbs the verbs — so nothing keyed on this file can detect it, and the claim reads *fresher the longer it stands*. Cheap recurring check, one grep each: for every only-here token, grep the corpus for the claim's two rarest content tokens (a second hit means the exclusion is stale); for every «Стан → `00_07` ID», test whether that `#### ID` still sits above the `§🗄️` boundary; and inside any inventory block enforce *re-measured ⇒ struck*, since a later line that supersedes a number without striking the older one is `ssot-maintenance` §Guard-craft #31 living inside the block that documents catching #31. 🔴 **The mirror case has the OPPOSITE cure, and nothing in the file distinguishes them** (2026-08-05): a `description` promised a lesson whose words appear nowhere in the body — and both branches are live, «stale label whose subject dissolved» (cut it) versus «the LAST surviving copy» (migrate it into the body). Reconstructing the meaning from the neighbouring section would have built something plausible and wrong; what settled it in minutes was **grepping the session transcripts** (`*.jsonl`) for the phrase and taking the earliest NON-description occurrence — which still carried a word the rewrite had dropped, and the whole instance behind it. **Memory lives outside git, but the sessions that wrote it do not: a claim with no body is a lookup, not a judgement call.** 🔴 **And the class is not memory's — it is the SHAPE's, so hunt it in git too** (2026-08-08): `db/migrate/*_init_consolidated.rb` opened with *«This is THE only migration in the repository»* and kept saying so while four incrementals landed on top of it, because nothing that edits `db/migrate/` also edits that sentence. A file under review, in CI, with a gate on its directory, held a false self-description for weeks — the versioning that makes memory recoverable does nothing about a claim keyed on a file other than the one being changed. **When a git artefact describes its own population («the only», «exactly one», «all of them are here»), the fix is not to update the number but to point at the enumeration** (`ls db/migrate/`), which is the same no-volatile-counts rule one level out.

**(13) The verdict ADDRESS-vs-SCOPE is decided by the source's GENRE, so read the genre before you read the pair.** 🔴 Two agents inventorying the same class on different source files returned opposite headline verdicts — «SCOPE did not occur once» (0/25) and «~14 of 22 are SCOPE» — and both were right. What separates them is not model tier or perimeter but what the source file *is*: a **session chronicle** carries the raw instance and nothing else, so the home's rule is the only copy (→ `ADDRESS`, cured by one string); a **«Durable lessons» file** — one that writes its own conclusions under `🎓 Уроки:` / `Правило:` / `Мораль:` / `🔑` — already carries the portable imperative almost verbatim, so the rule lives twice (→ `SCOPE`, cured by excising the duplicate down to the instance). Measured verbatim on the sharpest case: «дефолт vendored-залежності перевіряй проти КОНКРЕТНОЇ версії в `extern/`… не проти памʼяті й не проти доків» stands word-for-word in both the home and the source's own `🎓 Уроки` line. 🔴 **But the marker-grep has FALSE NEGATIVES too, so it predicts the verdict and never replaces the read** (measured 2026-08-05): `project_dependabot_sweep_2026_07` returns **zero** markers while its «пастки, куплені кровʼю» section writes a bold portable imperative in every bullet — durable genre with no marker at all; mirrored on the other side, a file named `log_*` carried exactly one durable clause. And the marker COUNT is meaningless without declaring the character set — three passes over the same file returned ~20, 41 and 51 purely from different patterns. ⚠️ Deeper still: the error-axis homes are **anthologies of verbatim quotes** from their sources, so a home↔source duplicate is SYSTEMIC by design, not an anomaly — which means similarity alone never decides. The discriminator stays the second measure: does the source's copy carry a router home. **Two consequences.** (a) The two verdicts are not the same job: `ADDRESS` is additive and safe, `SCOPE` is an **excision** from a corpus outside git and needs the READ-verification bar — never batch them into one pass, and never do the `SCOPE` half at the tail of a long session. 🔴 **And the READ bar is not the whole of it: an excision needs TWO agents with OPPOSED frames, and not for reliability.** Agent #1 judged each clause against the three homes its brief named and found 2 homeless; agent #2, frame inverted, searched the whole corpus + skills + canon and found 4 — three of them generalisations whose INSTANCES had homes and whose FRAME did not. The intersection was non-empty, neither set covered the other, and the truth was the UNION. The cause is structural rather than a quality gap: the first was bounded by the perimeter its own brief handed it, the second was not. 🔴 **And that perimeter is YOURS, so a false negative arrives as your own defect wearing the agent's signature — which is why it survives review.** Measured across three verifier briefs in one night (2026-08-08): each returned a «НЕМА» that was correct inside the perimeter its brief named and wrong about the corpus — one class had its home in a file the brief simply did not list, and the answer read as a fact about the corpus because **nothing in a verdict carries the scope of the question that produced it**. A negative is the direction that LICENSES action, so re-run the narrow question yourself, corpus-wide, before acting on one. The same shape governs inherited COUNTS: a "live yield: zero" carried forward from a prior pass measured 3, and all three sat in the very file that had recorded the zero. **So for any operation whose verdict means DELETION, one agent is not «probably enough» — a single frame is systematically blind on exactly the side that erases facts.** Re-measured 2026-08-05 on the `log_subagent_craft` excision, and the second run came out **starker** than the first: the completeness frame («does the home carry every sub-claim») returned 2 blockers, the disappearance frame («what stops existing») returned 11, and they overlapped in exactly **ONE**. The costliest finding — a home whose stated ceiling was wider than its own evidence — came from the disappearance frame alone, and the completeness frame had explicitly cleared that very clause as harmless drift. Two frames, near-disjoint yields, and the one that would have been skipped as redundant is the one that caught the disinformation. (b) Grep the source for its own lesson-markers FIRST; that one grep predicts the verdict for every pair on that file, and it is cheaper than inventorying them one by one. 🔴 **But the ceiling that grep declares is not a detail — measured 2026-08-05, it hides the majority.** A full READ of THREE sources (`deploy_hole_hunt` · `money_path` · `e61`) returned **47 pairs and 13 MIGRATE-FIRST**, against a marker-directed pass that had priced the WHOLE corpus at 32 pairs and 7 MIGRATE-FIRST — same corpus, same day, and the only difference is that a marker-directed pass reads marker ZONES. **Consequence for planning rather than for counting: `SCOPE` does not fit into one session at the READ bar irreversibility demands, so never make it the tail of other work.** One finding pushes the reading cost back down: **the debt has the shape of a SECTION, not of a file** — in `deploy_hole_hunt` nearly every pair came from a single section, while the money and secrets blocks of the SAME file were already written with routing discipline (home exists → tag stands; none → plain chronicle). Ask not «is this file a debtor» but «which of its sections was written BEFORE the home existed». 🔴 **An INHERITED verdict has a perimeter of its own, and it reads more reliable than it is** (2026-08-05): a prior session's «this pair is SCOPE, not MIGRATE» had checked the clause's HEADLINE formula — which the home did carry — and never asked about its auxiliary halves, two of which lived nowhere else in the corpus; excising on the inherited verdict would have been amnesia twice over. **Give an inherited judgement the same READ you would give your own finding.** ⚠️ The mirror bites when you verify an AGENT rather than trust it: a `grep -c` returned **4** hits of the very identifiers an agent said were absent from a skill — and all four were about something else (a `\z` anchor, a CI filter), so the agent was right and the counter nearly overturned it. **Grep proves mention, never substance**, and it is most dangerous exactly when used to reject a finding, because there a false negative sounds like caution. 🔴 **Final measurement, 2026-08-05: a frame's "safe to excise" list is a set of CANDIDATES, and reading the SOURCE removes about a third of them.** Of ~31 listed positions only 9 were still excisable — the rest already had the healthy shape (tight instance + router). The frame was not wrong; it answered *"does the home carry this"*, which it did, and never asked *"does the source still restate it"* — and only the second decides whether there is anything to cut. So walk the list against the source, not against the home, and expect it to shrink.

**(14) Every instrument you write to MEASURE this corpus will strip the token that discriminates — verify by reading the top hits before you report the count.** Three times in one session, 2026-08-08, in three different hands: (a) a same-language near-duplicate run normalised `[[target]]` away, and since the target is the only thing distinguishing two otherwise-identical router sentences, it manufactured 53 pairs at Jaccard 1.00 — read the top three and the artefact was obvious; (b) an agent's cross-language detector let a compound canon-ref (`00_05§2.7`) also emit a bare number anchor (`2.7`), so 3 of its first 22 candidates cleared a "≥2 independent anchors" bar on ONE signal counted twice — it found this on itself and said so; (c) a case-insensitive substring scan for banned tokens in a publication draft reported `SMS` twice, both inside `mechanisMS`. The mechanism is not carelessness: **normalisation exists to remove noise, and in a corpus whose content IS its cross-references, the noise and the signal are the same characters.** So the reflex is not "write a better regex" — it is **never report a corpus count without reading its top hits**, because the artefact is always visible there and invisible in the total. General form of the class → [[feedback_measurement_substitution]]; the sibling about a marker count being meaningless without a declared character set is trap (13). 🔴 **The mirror failure needs a DIFFERENT reflex, because reading the top hits cannot reach it: an over-narrow pattern yields false NEGATIVES, and the misses are invisible by construction while the total stays plausible.** Measured on the map of this corpus's `⊥` sacrifices — a naive scan for the marker and its pair missed **4 of 8**, every one of them sitting inside `**bold**` or parentheses. This matters because generated maps are otherwise the corpus's one genuinely rot-proof lens (they recompute from source, so they cannot go stale) — and that is exactly why **a map lies more authoritatively than a recollection does: it looks computed.** So a lens counts as native only after its PATTERN has been READ-verified against instances you already know; until then it is a stale claim wearing a fresh timestamp.

**(17) Opposed frames do not protect against a shared READING habit — and the two costliest misses of a curation pass both arrived as a home that is not one.** Measured 2026-08-10 across four agents on two rule-homes. (a) **Two agents with deliberately inverted briefs returned the SAME false verdict**, because the divergence trap (13a) buys is in the *question*, never in how the text gets read: both judged a cited skill item by its first line and neither saw that the clause lived in an INDENTED sub-bullet of that same item — so `backend #26a` was reported WRONG-SECTION twice, and executing either report would have "fixed" a valid address. **Before accepting any WRONG-SECTION verdict, open the cited item and read to its end, sub-bullets included** — a numbered item is a block, not a line. (b) **A DERIVED artifact reads as a home, and the string points the other way.** A submission-ready paper (`docs/protocols/paper/*.md`, defensive publication) carried the frame plus four layers of a memory file near-verbatim in English, so a bilingual sweep scored it the principal home — while the paper is an extract FROM the memory, frozen for submission, and the memory is the living original that the next lesson must land in. Cutting the source toward its own excerpt is the sharpest form of "a home that cites you is not a home" (trap 3), and publication genre is the tell: **before treating any file as a home, ask whether it was written FROM the corpus.** (c) Sibling on the same pass: an agent reported a back-ticked quote as a DEAD citation (zero corpus hits under the named address) when it was alive one file away — «dead» licenses excision, «alive at a different address» licenses a one-token fix, so **re-grep a dead-citation finding across the whole perimeter before acting on it**; the direction that erases facts is the one to verify twice.

**(15) A `TO-GIT` verdict needs THREE measurements, and the third is the one that manufactures work when skipped: does git ALREADY SEND readers to the memory copy.** Measured 2026-08-08 while migrating a batch: a two-axis check («is the rule in a git file» × «is it in memory») marked a `rspec --bisect` fork-safety gotcha as a gap — and `memory_gate.sh --routes` then showed its home is cited from **four** places in git (two skills, a component skill, the housekeeping prompt). That is the router pattern working exactly as designed, not neglect, and migrating it would have written a second copy of a rule whose address was already live. **So the predicate is: absent from git ∧ present in memory ∧ NOT routed to from git.** ⚠️ The third axis does not settle it alone, because a routed FILE can still fail to carry a specific clause at the moment of action — of four migrations that same day, all four targets turned out to have no inbound router at all, but the discriminator that made them safe was checking `git show HEAD:<receiver>` for the slug, not trusting the current tree (which by then contained the routers I had just written). **Measure the receiver's pre-state, not its post-state — your own edit contaminates the instrument.** Same class one level up: the first pass of this very check counted `00_07` as a git home for four rules, when what the tracker held was *my own note describing the gap*; a queue item about a missing rule is not the rule's home, so exclude the tracker from any "does git have this" measurement.

**(16) A restatement that SENDS can still LIE — so the redundancy question has a second axis, and only the second one is dangerous.** The phase-2 criterion says a compressed restatement carrying a router is legitimate and one without is a duplicate. Measured 2026-08-08 across four files (54 clauses: 22 DUPLICATE · 12 NATIVE · 12 ROUTER · 8 PARTIAL), that criterion is **necessary and not sufficient**: three clauses routed correctly *and had drifted from what they route to*. The costliest instructed writing a gas-snapshot baseline with the pre-`00bb766e` pattern, which would have added ten foreign `testFuzz_` rows to a money-path artefact; another instructed hand-editing `db/structure.sql`, which has no `schema_migrations` row, bypasses StrongMigrations and is reverted by the next `schema:dump`. **So run redundancy and drift as two passes with different questions — «is this needed» and «is this still true» — and settle the second against the ARTEFACT, never against another document**, because two documents drift together while the artefact cannot. ⚠️ The drift pass also finds the shape a redundancy pass structurally cannot: an instruction to do something **already done** (a bullet telling you to add a check the gate has run for weeks; a tracker residual prescribing a form the shipped fix took differently). That is worse than staleness — it spends a whole pass and reads as an open hole. 🔴 **Two DEBT SHAPES, and they need opposite remedies.** *(a) «Cement the session twice»*: five of six debtor sections in one rule-file were written **the same day as the canon paragraph they duplicate**, by the session that created it — the memory is not lagging git, it is being written in parallel with git; the remedy is procedural (write the canon, then write only the send), never editorial. *(b) «The home absorbed it and the memory never shrank»*: homes 1–2.5 months older than the memory's last write; remedy is one excision per file. ✅ And the control case that validates the frame rather than the auditor: a machine-native file (local toolchain recipes) returned **zero** duplicates — **duplicate debt is a property of content that HAS a repo home, not of memory files as such**, so never price a `native:machine` file as debt. 🔴 One more, cheap and recurring: **closing a tracker item does not update the item's canon home** — OPS.19 shipped, and `06_07`, the CI inventory it points at, had no mention of the step at all. Grep the item's own canon ref before you write ✅. 🔴 **And the sharpest form aims one level up, at the PLAN rather than at a clause: an inventory that NAMES a home has usually not OPENED it.** Measured 2026-08-08 — a prior pass wrote «home = `lib/silken_net/load_test/README.md`» into the tracker for two memory sections; the README carries the first in full and the second **not at all**, its real home being the code plus a SHA-pin registry (`lib/canonical_block_pins.yml`) the memory had never heard of, i.e. git was RICHER than the copy. Excising to the named address would have been amnesia, and nothing in the plan looked wrong: the path resolves, the file exists, and one of the two claims is genuinely there — which is exactly what makes a half-right address survive. **So an address you inherit from a measurement is a hypothesis: open it and check the SPECIFIC clause before cutting to it, and expect the true home to be code comments rather than the README.**

## When to use
- Structuring / grouping `MEMORY.md` (by kind: 👤User / 🛠Feedback / 📚Reference / 📦Project, + sub-themes).
- Removing memory cruft / duplication; trimming a bloated index hook (detail belongs in the file).
- Fixing a stale index hook (drifted from its file).
- "Is every open to-do/check in memory also in 00_07?" → migrate the gaps.
- Integrity check (1:1 index↔files, no broken/orphan).

## Core principle — NO AMNESIA
**Preserve beats cleanup.** Before removing ANY content, verify it lives elsewhere (the file, git, canon, `00_07`). Improve/relocate, never delete what's valuable. When "remove cruft" conflicts with "don't lose what's needed" → keep. A well-curated memory's housekeeping is mostly **de-bloat + structure + stale-hook fixes**, not mass-deletion — say so honestly, don't manufacture deletions (the `ssot-maintenance` "don't manufacture moves" lesson, applied to memory).

## Type-routing — which surface a fact belongs to

Memory is a ROUTER, not a second copy: the absolute context is re-assembled from scratch every task (memory → skills → canon → code), so anything you would re-read from canon or code anyway is not a memory fact. Route each piece by its TYPE, **at the moment you write it** — this is a write-time question, and it is the one the index is actually consulted for.

| the fact is… | its home |
|---|---|
| operational HOW — generators, CLI recipes, code inventories | the **domain skill** |
| shipped WHAT, or a frozen decision | **canon** `NN_NN` (+ a `00_07` ID while it is still open) |
| live state · cross-domain trap · lesson · the founder's "why" | **memory** |
| a portable rule about how the WORK gets done | the **playbook** someone reads before doing it |

Two halves make this operational rather than decorative.

**Elevate, then point.** A meta-lesson recurring across domains gets ONE home and every instance points at it. The failure mode is not a missing home but a SECOND one — both links resolve, only the prose disagrees, so no gate can see it. Before building a home, ask which part is actually homeless — instance, mechanism, remedy, or FRAME — because it is nearly always the frame, and grep finds instances (trap 6).

**Routing audit.** Every `project_*` file must route somewhere real: canon, a live tracker ID, code, a skill, or an inbound string. A file routing nowhere is an episode, and an episode with no string dies whatever the index says. ⛔ **Do not rebuild the machine form of this — it was built and measured: 0 true findings against 2 false out of 55**, because the set of legitimate homes is open-ended. It stays a reading discipline on purpose. That verdict is not local to this rule: where the discriminator has a form, the yield is near zero and a carrier is cheap; where the yield is large, there is no form. Check which half you are in before proposing a gate.

**A PLAYBOOK has a trigger of its own, so audit it by asking what fires its READER — not what its title is about.** Measured 2026-08-08 on the housekeeping prompt: of 48 durable lessons only 19 were strictly `housekeeping`-scoped; the rest fired at `memory-write` · `agent-spawn` · `gate-patch` · `measure` · `big-edit` · `founder-push`, i.e. precisely at moments when that file is not loaded and nothing loads it. **A lesson stored in a playbook whose trigger it does not share is stored nowhere** — the surface looks maintained and the rule never arrives. Consequence for writing: before adding a lesson to any playbook, name the event that must interrupt someone, and put it where a reader stands at THAT event (the gate's own message text is often the strongest carrier — it is the one line that reaches the person mid-action). Consequence for the prompt specifically: `§Durable` there is now **housekeeping-scoped by construction**, and each family carries a `📤` router naming where its evicted lessons went — do not put an agent-spawn or gate-patch lesson back into it. ⚠️ Two exceptions survived the pass on purpose and both are instructive: a per-file proposal recipe that had **zero** hits anywhere else, and a classification that **two other files explicitly route INTO** the prompt for. A "home" that cites you is not a home; check the direction of the string before you cut.

**ORDER, because the debt is written in PARALLEL with git — not after it.** Measured across four files: in one rule-home **five of six** debtor sections were written the SAME DAY as the canon paragraph they duplicate, by the session that created it. So the memory is not lagging the repo and no editorial pass can fix it — both texts are produced in one sitting, and the second one is the cheap one. **Write the canon / skill / gate FIRST, verify it landed, and then write only the SEND into memory.** An excision afterwards merely removes what the procedure should never have produced, and it costs the READ bar every time. The other debt shape does need an excision, and its tell is temporal: a home one to two and a half months OLDER than the memory's last write means the home absorbed the content and the memory simply never shrank.

## The gate is the home of the mechanics — not this file, not the prompt
`.claude/hooks/memory_gate.sh` runs the whole step-1 battery (`--audit`, exit 0 = clean) **and** rides `PostToolUse` on every write into the corpus, so it fires at the moment a wall gets built rather than when someone remembers to clean. Found a new blindness class? **Patch the script** — it is live on the next write, and the separate "carry the lesson into the gate" step that failed before no longer exists. 🔴 **But that instruction was missing its other half for weeks, and the omission is expensive: the gate carries a `--selftest` battery of 40+ cases with positive AND negative controls, and it is CI-gated (`docs.yml`).** Neither this file nor the prompt said so, so a curator who obeyed the central prescription — patch the gate — would break CI without knowing why, and would not know that the norm here is to ship a patch WITH its pinning case, mutation-verified (remove the fix, prove exactly that case reds). Run it before and after every patch; a case that passes both ways is testing nothing. Beside the battery it carries **diagnostic modes that deliberately sit OUTSIDE `--audit`** (read the `case` block for the current set — naming them here is the list-by-example rot warned about below). The rule deciding which is which: a check whose live yield is a handful belongs IN the battery; one whose yield runs to dozens is a **worklist**, and folding a worklist into `--audit` makes EXIT 1 permanent, which trains the reader to skim the one stance that must stay loud. A worklist mode is therefore not a weaker gate — it is the same finding addressed to a session that has time for it. Thresholds are curated constants inside it; the corpus is outside git but the gate is not, so a bump is a visible decision.

              block is the roster, and it is short enough to read every time.

              that must stay loud.
2. INDEX=HOOKS  trim any bloated index line — but VERIFY the detail is in the file FIRST.

## Gotchas (hard-won, 2026-06-13)
- **Edit can't match a ~7000-char index line** → use a Ruby `lines[i] = …` replace with an `abort unless lines[i].include?("marker")` guard. 🔴 **For a multi-row pass the shape is a replacement TABLE, not a run of edits: every `old` must exist, so a typo MISSES safely instead of corrupting.** A substitution that silently matches nothing is the failure you want; one that matches the wrong span is the one you cannot see afterwards — which is also why the anchor must be UNIQUE, verified by counting it first, never a shared token. Then review the FULL diff rather than the changed rows: what survives this discipline is prose-mangling inside a row you did rewrite. ⚠️ The safety half is git now, not a `cp` backup (see the versioning gotcha below) — but versioning replaces the RECOVERY, never the review: a commit records the bytes, it does not notice that a sentence lost its verb.
- 🔴 **Zero-loss is a contract with a HARD set and a DECLARATION duty — and versioning repeals neither.** Hard, never thinned however routine they look: `[[strings]]` · guards and ⛔ stop-lists · open items · unique lessons · safety notes. Routine ID-examples and repeated instances may be thinned when their home is reachable — but **say what you removed**, because an honest report names the cuts, not only the keeps. Silence is the whole failure mode here: a thinned file reads exactly like a tidier version of the same file, so an undeclared cut is invisible at review time and stays invisible afterwards. ⚠️ The proof step used to be a set-diff against a `cp` backup; the corpus is versioned now, so it is `git diff` and `git show HEAD:<file>` — but the obligation did not move, it sharpened: git gives you recovery of a loss somebody NOTICED, and the declaration is the only thing that makes one noticeable.
- 🔴 **The corpus IS versioned now, and that repeals the premise most of this file was written under** (2026-08-08). `git init` at the memory dir, `main`, **local-only forever** — no remote, guarded by a `pre-push` hook that refuses, because two files carry the owner's personal circumstances and git history is permanent. Every write **made through Edit/Write** is committed automatically by `.claude/hooks/memory_git_commit.sh` (PostToolUse, subject `mem(<file>): <tool>`, body `session <id>` — so `git log -S '<phrase>'` now answers *"when did this claim enter and which session wrote it"*, which trap (12) used to answer by hand-grepping `*.jsonl`). **What this changes: irreversibility no longer sets the proof bar here.** The MIGRATE-FIRST prologue, the "two agents with OPPOSED frames before any excision" rule of trap (13a), and "preserve beats cleanup" were all priced against *unrecoverable* loss — under versioning the correct policy inverts from «when in doubt, keep» to **«when in doubt, cut and record the commit»**, which is also the only lever that ever pushed back on the growth `--weight` measures (DOC-T.62). ⚠️ **Two halves it does NOT repeal.** (a) *Reversibility is not correctness* — a wrong home is still wrong, and revert only helps a loss somebody NOTICES; the detectors that catch unnoticed loss (`corpus_floor_check`, `--audit`) carry that half and stay. (b) *CI still cannot see this corpus* — the gate remains the only enforcement point, and it fires at the write. 🔴 **(c) And the auto-commit has a hole shaped exactly like BULK curation, measured 2026-08-15: the hook rides `PostToolUse` on Edit/Write, so a batch applied through `ruby -e` in Bash — the very form this file prescribes for a long line or a replacement TABLE — writes the files and commits NOTHING.** Eight files sat uncommitted through a whole session and surfaced only on a closing `git status`. Note the shape: the heavier and more careful the pass, the more likely it evades the safety net, because the prescribed tool for a careful pass is the one the hook cannot see. **Reflex: any memory edit not made with Edit/Write ends with a manual `git -C <memory> add -A && commit` — and a closing sweep asks `git status` in the memory repo, not only in the repo.**
- 🔴 **The index ratchet is BYTE-wise, so an over-long hook is paid for in a haggling loop — write the hook short on the FIRST pass.** Measured 2026-08-09: adding one clause to an existing index line put `MEMORY.md` 146 B over its ratchet, and bringing it back cost **six** successive rewrites (146 → 105 → 50 → 39 → 13 → 3 → under), each a full edit-and-recheck cycle. Nothing was wrong with the gate — it did exactly its job — but the cost lands on the wrong side: the trimming happens *after* the thought is already phrased, when every remaining word feels load-bearing. Two consequences. (a) When a fact needs a new hook clause, draft it at roughly the length of the clause it sits beside, not at the length the idea wants. (b) Do not spend a second pass shaving a hook toward the ratchet — the policy says a new entry earns its line **by displacing one**, so at the second failed attempt the honest move is to look for the entry to evict (or to keep the detail in-file and shorten the hook to its trigger), never to keep golfing bytes.
- **Verify-before-delete** ([[feedback_verify_canon_before_delete]]) and **no-volatile-counts** ([[feedback_no_volatile_counts]]) apply to memory too (a hook must not hold drift-prone counts; trimmed detail must already live in the file).
- **De-dup is rare** — memories cross-link via `[[<slug>]]`, not restate; the big duplication is usually index-vs-file. Two distinct facts of the same kind are NOT a duplicate.
- 🔴 **«Merge + dedup» is NOT «shorten» — the founder stopped a pass mid-merge to say exactly that.** Collapsing N blocks keeps each block's CONTENT *verbatim*; what collapses is the STRUCTURE (N headers → 1 + tags) plus genuine duplicates (a recurring lesson → one shared note + a `→` pointer). **Compression is a SEPARATE operation and needs its own instruction** — a merge that quietly shortens is how a merge becomes amnesia, and the loss is invisible precisely because the result reads like a tidier version of the same thing. It lives here rather than in the housekeeping prompt because it fires at the MOMENT of the merge, and nothing routes a merger into that prompt.
- **`node_type` / `originSessionId` in the frontmatter are HARNESS-managed — do not strip them, and do not count them as yours.** A file-watcher re-stamps them on ANY write to `memory/*.md` (a Bash-only edit no longer evades it), so deleting them is wasted effort rather than damage; the direction that matters is the other one — never "clean" them out of a rewritten file expecting the change to stick, and never read their value as something this corpus decided. `format_check_one` in the gate requires only `name` + `type`, so nothing enforces any of this.
- 🔴 **Step 6A's own instrument lies by default: the corpus routes to the tracker by BARE ID, not by the literal `00_07`.** Measured 2026-08-06 — a scan for "memories carrying open-action markers with no `00_07` reference" returned four files, and **all four were false positives**: they route via `ARCH.78` · `HW.39` · `SEC.21`, which is the corpus's actual convention and a better one (an ID survives the tracker being renamed or re-sectioned). So the step-6A predicate is *"does an open item name a LIVE tracker ID"*, never *"does the file contain the string `00_07`"* — and the verification is two-step: extract the IDs, then check each against the tracker's live-vs-`§🗄️` split. ⚠️ The mirror bites on the second step too: an ID-extraction regex anchored on `^#### ID` headings and `| ID |` archive rows called **13 of 16** IDs "absent from the tracker" when they were merely referenced inline — an **81 % false-positive rate**, cured by one direct `grep -rl` per candidate. **Both halves of this check are instruments; price them before believing either.** 🔴 **And the predicate is still too weak by one question: «is the ID LIVE» does not ask «is it the RIGHT ID»** (2026-08-07). Two memory routers sent a class's state to a tracker item that was archived — and the archived item had never been about that class at all: `git show` of the commit that created it showed a different subject from birth. Nothing catches this, and the reason is worth carrying: `code_tracker_id_check` asks only whether a cited ID *has a home*, so a wrong-but-existing address passes it forever, exactly like a resolving `[[link]]` pointing at the wrong file in trap (6). The tell is cheap when you look for it — **grep the tracker for the class's own distinctive token** (here a landed byte-count) and see which `####` item actually carries it; that item is the address. Fix it in place, never annotate it, and prefer routing to the item that carries the NUMBER over the item whose title sounds related. And when a genuine ghost does surface, read it before calling it decay — all three survivors that day were **deliberate tombstones in three distinct shapes: an ID *merged* into another, an ID *renamed*, and an ID struck through beside its own deletion date** — i.e. exactly the records that make a dropped ID recoverable, and never decay. ⚠️ **The shapes are the lesson; the dead IDs themselves are deliberately NOT quoted here, and that is enforced, not stylistic** — `scripts/code_tracker_id_check.rb` scans `.claude/**` and cannot distinguish an illustrative citation from a live one, so writing a retired ID into a skill turns it into a phantom reference and reds the gate. (Learned by doing it: the very paragraph documenting that ghost IDs are legitimate created three of them.) Need the evidence? It lives in the memory files that carry those tombstones — read it there, where a dead ID is the point rather than a citation.
- **«This file has no line in `MEMORY.md`» is NOT a finding for a `log_*` journal — it is the design.** Measured 2026-08-05: **zero of ten** journals carry an index line; they are reached by `[[strings]]` alone (2–15 inbound each), which is exactly the demotion the index-vs-strings measurement prescribed. An agent that flags it as a risk is reporting the norm, so check the population before acting — the real question for a journal is whether its inbound count is healthy, not whether the index names it. 🔴 **Corollary that decides whether the split SURVIVES: create a rule-home's `log_*` twin BEFORE you need it.** The gate's whole strategy is to redirect the cheap end-of-session `append` into the journal instead of fighting it — but if the journal does not exist yet, the redirect costs a file creation, a routing decision and an index question at the exact moment the author wanted one line, and that friction is what produced every one of the four recorded rollbacks. A twin that already exists turns the prescribed move back into an `append`.
- **The prompt's own §Durable-уроки = a 6-family frame (auto-consolidate — the method applies to itself):** a new lesson gets **melted into the fitting family as a line**, NOT glued on as a fresh date-stamped paragraph (the section already bloated into a wall once and had to be refactored). New family only if it fits none (keep ≤~7); a family past ~6 lines → compress that family the same way.
