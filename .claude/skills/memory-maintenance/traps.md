# Curation traps — the bodies

> **Companion to `SKILL.md`, read ON DEMAND.** These fire when you are about to make a
> curation VERDICT — consolidate a class, price a duplicate, declare something homeless,
> report a corpus number. The one-line index in `SKILL.md` is the carrier; this file is the
> mechanism. Edit rules HERE — the index is generated (`ruby scripts/guard_craft_index.rb --write`).
>
> **Numbering is append-only:** these numbers are cited from 10 memory files and from
> `docs/00_07` (as «пастка (N)»), so a vanished number orphans its citations. The
> `floor` guard in `scripts/guard_craft_index.rb` backstops bulk loss.
> ⚠️ Those citations carry no `#`, so `skill_item_check` cannot see them — the floor is
> the ONLY protection this address space has.
>
> ⚠️ **Inline lettering is part of the address space and is NOT in the list:** several items carry
> sub-shapes as `(a)`/`(b)`/`(c)` inside their own body, and the corpus cites them that way
> («пастка (13a)», «traps (5)/(13a)»). Do not look for a numbered `13a` — open 13 and read to
> its end. Same convention as the `frontend` companion.

1. **Scout counts run LOW — and the direction is set by WHAT is counted, not by who counts.** A scout agent's carrier count is systematically LOW (it reads big files; most carriers are short clauses in mid-sized ones) — and it is not a model tier but a QUESTION SHAPE: on DOC-T.58 the low count came from the *adversarial*, which sampled ten examples instead of inventorying, and undercounted **tenfold**. ⚠️ **Read this WITH its mirror, or you will generalise it into "agent numbers run low" and be wrong where it costs most: the direction is set by WHAT is counted, not by who counts.** A count of what EXISTS runs low (this trap); a count of what is REDUNDANT runs HIGH — «48% of the index mirrors the tracker» re-measured at ≈8.7%, because the pass had counted the MARKER instead of the CONTENT. The two errors push opposite ways and both are cheap to believe: one under-builds homes, the other licenses cuts. → [[feedback_measurement_substitution]]

2. **A «half-home» may be a duplicate — compare the two texts before believing they are coverage.** "This class already has two half-homes" is often not coverage but a **duplicate** — compare their texts before believing it.

3. **One-way strings fake homelessness — a home that CITES you is a home you already have.** 🔴 **A section can read as a live homeless class purely because its string is ONE-WAY.** The home was built by extraction FROM that section and cites it as provenance, but phase 2 never left a router back — so the source's reader never learns the rule already has an address, and the next pass re-derives the whole class from scratch. The systematic hole: the recipe says "in EVERY source file", and in practice it got applied to the `project_*` file while its `log_*` twin kept the rule in full. **Before declaring any theme homeless, ask whether a candidate home already cites this file — a home that cites you is a home you already have.** 🔴 **Stop hand-grepping for it: `memory_gate.sh --oneway` is the runnable form of exactly this question** (groups by the file the router must be written INTO, so one edit closes several pairs; the env lever is `MEMORY_GATE_ONEWAY_MIN`, and a bare `ONEWAY_MIN=` from the shell resolves to nothing — measured by walking into it). Its perimeter is *provenance* only — a rule-home citing a `log_*`/`project_*` source — so a clean run says nothing about peer cross-references, which are one-way by design.

4. **Machine dedup is capped at VERBATIM, and on a bilingual corpus the gap is an order of magnitude.** 🔴 **Any machine measure of duplication in this corpus is capped at VERBATIM, and the gap is an order of magnitude.** The corpus is bilingual, so a rule written in English in the journal and in Ukrainian in its home is invisible to grep AND to shingles: on the worst offender a READ-based inventory found ~80 doubled rules where grep saw 7 and the shingle gate saw 2. Start from `--audit` to get the verbatim ones for free, then inventory by READING — never treat a green overlap as "no duplicate homes", only as "no verbatim ones". 🔴 **The same bilingualism makes a false negative the DEFAULT when you verify an index hook against its file, and there the error is expensive in the other direction — it invites you to "fix" a healthy hook.** The hook is often Ukrainian and the body English (or the reverse), so the check starts at zero hits: `READ-ONLY = ТИП агента` lives as *the brief does not constrain tools — the agent TYPE does*; `findings = кандидати` as *Agent findings are CANDIDATES*; «скоупінг має ТРИ половини» as *Scoping has THREE halves*. Two lexical traps ride along — Cyrillic case (`гейт-ПАРА` ≠ `Гейт-ПАРА`, and `grep -i` is unreliable on Cyrillic) and the apostrophe (`пʼять` ≠ `п'ять`) — plus the hook's own habit of compressing a paragraph into a LABEL, so the words genuinely differ. Measured in one pass: **8 of 10 "orphans" were false**, and twice a valid hook was nearly rewritten. **Order: root of the word → case-insensitive → BOTH languages → and only a READ gives the verdict.** Two corollaries worth carrying: after any rule/journal split, walk the target's hook, because a split leaves the index quoting clauses that have moved out; and a hook may be quoting its own file's STRUCK-THROUGH text, i.e. the file corrected itself and the index stayed on the pre-correction version.

5. **Declare the UNIT first — «debt weight» and «what an excision returns» differ in the SIGN.** 🔴 **"Debt weight" and "what an excision returns" are different quantities, and the difference is in the SIGN — so declare the UNIT before the pass.** In a `project_*` file the debt sits in the MISSING ROUTER, not in duplicated prose: the instance is load-bearing and the generalisation is one sentence, so replacing it with a `[[string]]` costs the same or more, and the file GROWS. A phase-2 pass over `project_*` is therefore **router placement, measured by COVERAGE (inbound files), never by bytes**; only `log_*` journals, which restate rules in full, give bytes back. The tell is readable before you start — a clause shaped "instance + one sentence of rule" returns zero. Same failure at the counting level: asked without a declared unit, one inventory answered **3** and **14** for the same corpus. 🔴 **The verdict VOCABULARY needs the same care as the unit, because one verdict token can fuse two questions** (DOC-T.58): an agent marked a line CORE whose rule already stood **48 lines above in that same file** — it had seen the internal duplicate and said so, and still did not change the verdict, because «CORE» meant to it *belongs to this file* rather than *is unique within it*. Define each verdict so those two readings cannot collapse into one word. 🔴 **And the sibling failure is not ambiguity but INERTIA: a verdict whose form implies no next step is where the measurement quietly stops.** «PARTIAL» / «частково» / «mostly clean» read as grounded — *I checked enough to know it is partial* — while what they actually record is that the check halted; and because nothing follows from them, nobody ever asks whether the thing is in fact a FULL home or in fact HOMELESS. Measured on the class campaign: **four of seven** classes landed on «частково», none carried 3+ IDs, so none tripped a re-measure — all of them legitimately waiting, and waiting forever. **Reflex: when you write «partial», name BOTH edges — what was verified and what was left unverified — or you have recorded the state of your own fatigue rather than the state of the subject.** Instances → memory `log_perimeter_prep`.

6. **Mechanism ⊥ frame — «does this have a home» is TWO questions, and the homeless one is almost always the FRAME.** 🔴 **"Does this have a home" is TWO questions, and the second decides: is the MECHANISM in the corpus ⊥ is there a FRAME over it.** A mature class can have its mechanism written verbatim (under a name the tracker never used), its gate-side half in a skill, and its remedy in another home — and still lack the frame; building a file then buys a FOURTH address, while the right move is a **dispatch** (write the frame into the best existing home + strings back). Before deciding, enumerate what is already covered — instance, mechanism, remedy, or frame — because the homeless one is almost always the frame, and grep cannot find it: grep finds instances. Corollary on debt: the phase-2 rubrics DUPLICATE/ROUTED split by whether a string exists, which silently merges "done" with a third state — **the router is there AND the restatement stayed next to it**. That state reads as the cheapest excision in the corpus and no rubric names it, so ask the third question explicitly. 🔴 **But "cheapest" is only half true, measured on all 14 of them (2026-08-04): a string cannot be lost, yet the address can be WRONG and the home INCOMPLETE.** 3 of 14 routers pointed at the wrong place (a numbered skill item when the rule sat in the unnumbered paragraph beside it; `§3` when the rule was in `§4`; the instance's home when the rule's home was a different file) — that is disinformation, not debt, and it is invisible precisely because the link resolves. And 4 of 14 restatements carried a half the home did not have, so excising as planned would have been amnesia four times over; the fix is MIGRATE-FIRST (write the missing half into the home, verify, then cut) or leave it with an explicit "this is the only copy" marker. **So this class costs the same READ as an ordinary duplicate: verify the router's TARGET and the home's COMPLETENESS, never just the presence of `[[brackets]]`.** 🔴 **And a wrong address survives even when the file KNOWS about it** (2026-08-05): a source carried a ⚠️-note forty lines BELOW the defect, stating that «the line above sends this phrase to a neighbour, not to the class home» — and it was left as a NOTE instead of a fix, so every reader of the defective line stayed unprotected, because an annotation guards only what it can reach. **Finding a wrong router obliges you to fix it in place; writing a note about it reproduces the class one level up.** Measured numbers → `log_perimeter_prep`.

7. **An excision that TRANSLATES pays the bytes back — and looks like honest work while doing it.** 🔴 Measured 2026-08-04: shortening two English clauses and rewriting the remainder in Ukrainian produced **+40 B** across both; redoing the same two in the ORIGINAL language returned **−648 B**. Cyrillic costs 2 B/char, so the clause genuinely shrinks in characters while growing in bytes — the tell is invisible unless you measure in the unit the ceiling counts. **Keep the clause in the language it was written in**; the choice is a unit of measurement, not style. The sibling one level up: an excision's own INVENTORY costs about what the excision returns (seven cuts plus a refreshed header came to −35 B net), so **never report this work in bytes** — report how many rules stopped living in two homes.

8. **Measure the RECEIVER's headroom, not just the source's debt.** 🔴 MIGRATE-FIRST requires writing the missing half INTO the home, and a saturated home has nowhere to put it. Measured 2026-08-04: five rule-homes sit at 35.7–36.0 kB against a 36 kB WARN, i.e. the phase-2 receivers hit the ceiling as a GROUP, not one fat outlier — one edit pushed a home past WARN mid-session and an instance had to be evicted before the migration could proceed. The lever is eviction into the `log_*` twin (what the gate's own CAP line advises), never prose dieting (~2% at the ceiling); check the twin EXISTS first. ⚠️ **The "one of the five has none" clause that stood here was STALE and is removed — its subject had been fixed by the very remedy this trap prescribes** (twins were created for the two homes lacking them, so all five criticals now have one; re-verified 2026-08-09). An instruction to do something already done is worse than a merely outdated one: it spends a pass and reads as an open hole. 🔴 **Re-measured twice since and the count moved BOTH ways, so carry neither the number nor the frame: measure the band's MEMBERSHIP, never inherit it.** (2026-08-16 it was fourteen; 2026-08-18 a fresh pass found eighteen, and three evictions took it to sixteen.) Get it with one command over `*.md` minus `log_*` minus the index, sorted by `WARN − size`; the tightest few are what decide the next wave's route. 🔴 **That reading was OVERSTATED, and it is corrected here rather than repeated: re-measured 2026-08-18, the tight band is a small minority of rule-homes while the median home has tens of kB free.** So it is not «wherever you write» — it is a NAMED QUEUE of mature, heavily-cited homes, and the practical consequence inverts: write freely almost everywhere, and plan a route only for that queue. ⚠️ The overstatement propagated by being INHERITED — a later pass echoed it while measuring something else, which is why a frame deserves the same re-measurement as a number. ⚠️ **And the twin-detector I measured that band with lied first, in exactly the class this page describes:** I looked for `log_<same stem>`, while twins are named by THEME (`log_verify_gate` for `feedback_verify_gate_exit_code`, `log_cross_ref_dig` for `feedback_exhaustive_cross_ref_dig`, `log_portfolio_surgery` for `project_portfolio_lano_surgery`) — name-matching reported «8 of 14 have no twin», measuring by the STRING (`[[log_*]]` in the body) gives **13 of 14 do**. **Ask not «does a file with the predictable name exist» but «which journal does this home POINT AT».** ✅ **The file this clause used to name — `project_money_path_orchestration`, then the only one with no `log_*` string — was split 2026-08-18** (seven instances of the `ARCH.87/88/94/96/97` classes into a new `log_money_path`; the section stayed as a header carrying only the rules, so no inbound address orphaned). It bought 306 B → 3592 B of headroom, and both curated constants had to move with it (`CORPUS_FLOOR`, `DESC_BASELINE`) — **budget that: a new twin is not free, it lands as two gate findings.** ⚠️ And the same pass found the twinless set was never a singleton — read this clause as a METHOD, not a worklist: re-derive «which homes point at no journal» by the STRING each file carries, and expect the answer to differ from the last write-up. 🔴 **And the group is not a fixed five — re-measure the BAND, never inherit its membership.** The 2026-08-09 pass found the tracker item naming four files while the critical band held five; the unnamed one was `feedback_measurement_substitution`, i.e. the home of "measurement substitution" — the receiver of every measuring wave, including the one doing the measuring. Order the work by *which home the next wave must write into*, not by which is fattest. 🔴 **Two corrections measured 2026-08-04, both about the instrument rather than the size.** (a) `WARN` is not a warning: `--audit` ends in `[ -z "$out" ]`, so a single WARN line makes the whole battery EXIT 1 — the working ceiling is the WARN, and the CAP is only where the advice changes. (b) **Before asking "where do I migrate this half", ask whether it is ONE rule at all.** A clause whose two halves belong to two different homes is cured by a PAIR of routers and needs no headroom anywhere — that is what unblocked a migration into a home with 36 B left. And when you do evict, the direction matters more than the byte count: move INSTANCES down into the journal, never the generalised rule, however verbatim the twin repeats it — a rule that lives only in a dated journal paragraph is findable only by someone who already knows the incident. 🔴 **Two more measured 2026-08-05, both about where the room actually comes from.** (a) **An excision does NOT pay for the migration — one file GREW.** `portfolio_lano` went 288 → **221 B** of headroom after four cuts, `stream_scope` gained **35 B**: a router weighs about what the sentence it replaces weighed. So "cut there first, that frees the room" is right about the ORDER and wrong about the ECONOMICS — only eviction into the `log_*` twin frees space, so never schedule a migration whose headroom depends on cutting the receiver. (b) Sibling to the "is it ONE rule" question above: **ask whether it is a MEMORY rule at all.** OPS.14's remedy sat in the queue as MIGRATE-FIRST behind a heavy prologue (evict an instance to make room) — and a READ found it already canonised in `06_07 §2` + `00_06 §3`, i.e. the half belonged to CANON by type-routing (shipped mechanism → canon), so a 171 B router closed it. One grep over `docs/` replaced a session of eviction. 🔴 **Measured again 2026-08-05 and now a pattern, not an anecdote: a THIRD of the migrate queue was not memory's.** Three of `advisory_to_hard`'s eight "homeless" halves — the recipe for promoting a gate to required — were shipped CI mechanics and went to `06_07 §2`, right beside the OPS.14 invariant that had gone there for the same reason a wave earlier. And the destination is not always canon either: of `log_subagent_craft`'s five, **two belong in SKILLS** (`memory-maintenance` traps (5) and (13a)) and one in `ssot-maintenance` §Guard-craft — a portable rule about how the WORK is done has no canon home and no memory home; its home is the playbook someone reads before doing it. **So the destination question has four answers — memory · canon · skill · prompt — and asking it costs one grep while getting it wrong costs a session of eviction from a saturated home.** 🔴 **And the WARN is a TRIGGER for that question, not only for eviction — ask it on the FIRST warning, not after two rounds of shaving** (2026-08-22). A lesson about a gate built over a workaround was written into `feedback_challenge_the_task`; the gate reported over-ceiling twice, and both times the reflex was to shorten the prose — while the correct answer was already sitting in (b) above: a portable rule about how the WORK is done belongs in the playbook (here `ssot-maintenance` §Guard-craft), not in memory. Note the asymmetry that makes this worth a line: shaving *feels* like progress because the number moves, so it hides the question instead of raising it. **Reflex: the first over-ceiling on a NEW entry reads «is this even a memory fact?»; only the second reads «where does it go inside memory».**

9. **«All three surfaces» is FOUR — the index is one of them.** 🔴 A class was declared homeless twice, with the formula "zero hits across memory · skills · canon", while its home sat in `project_sec07_legal_campaign` **under the tracker's own literal wording** — and that same wording was a line in `MEMORY.md`, the file loaded into every single session (DOC-T.59, 2026-08-04). This is not the vocabulary trap of (3): the words matched. The index escapes the sweep because it is read as *navigation* rather than as content, so a three-surface pass walks past the one surface that is always already in context. **Before any "homeless" verdict, grep `MEMORY.md` itself** — one grep against a wave of consolidation work, and a hook is exactly the one-line pointer a class-search is looking for.

10. **Ask whether the clause has TWO homes, not whether it has one.** 🔴 The tail of a journal was priced at ≈1.6 kB and re-measured at **≈10.1 kB** — six-fold — because the dominant form was invisible to every check run so far: the clause carries a router to the **abstract rule** (`A-2`/`A-3`/`A-10` in a rule-home) while the *same concrete instance* sits in full in a **skill that the clause never names** (`backend` #15/#1, `frontend` #12 — the gated-action actor; a bare number is a brittle address, so name the subject beside it). A router-presence check cannot see this **by construction — the address is there and it is CORRECT**; only opening the domain skill for the instance's own subject finds it. This is why phase-2 numbers keep rising instead of converging: each pass asks a sharper question of the same text ((6) asked "is the restatement still beside the router", this one asks "is there a second, undeclared home"), so **a band that measured clean is clean only against the question that pass asked** — record the QUESTION next to the number, or the next pass will read your total as the corpus's state rather than as your instrument's reach. The same session proved the mirror: a section certified an exemplar by the morning's inventory failed the evening's, unchanged. 🔴 **Measured 2026-08-05, and it turns the aside above into the main rule: the undeclared home is not a minority case.** On the `sec07_legal_campaign`+`log_sec07_legal` pair the principal home was a **skill** — `.claude/skills/legal-business/SKILL.md` holds 8 of the source's clauses verbatim and is invisible to a grep for the source's filename — and together with the other out-of-perimeter homes that is **15 of 24 excisions** the brief would never have surfaced. **So the inventory perimeter is `feedback_*` + `reference_*` + `.claude/skills/**` + `docs/`, always** — a "no home exists" verdict computed over memory files alone is wrong by construction, and it fails in the expensive direction: it schedules a MIGRATE that would write a third copy of a rule already living in a skill.

11. **A `⊥` mark blesses the DIVERGENCE, not the missing router — it does not exempt a clause from phase 2.** Measured on `feedback_one_token_two_domains`: 4 of the 5 instances inside its ⊥ section ("deliberate divergence") were full unroutered duplicates, exactly like ordinary clauses. The mark reads as *decided, do not touch* — and that reading is correct about the CONTENT and wrong about the FORM. Same shape as the ⛔ "do not cut" list one level up: a protection is itself a claim, and it ages. 🔴 Sharpened 2026-08-05 by a ledger that contradicted ITSELF — the same block was listed both as ⛔ «router by design» and as an internal duplicate, and **both entries were right**: the block was router-shaped by design, and a restatement had moved in beside it. So a ⛔ mark protects the **FORM**, never whatever currently fills it, and the cure is neither «lift the protection» nor «ignore the diagnosis» but to make the block **more** of the thing it was protected for.

12. **The claims that rot are almost exclusively SELF-LOCATION claims — and no sweep of the file that carries them can see it.** Measured across a 93 kB journal's every header, lead and frontmatter (2026-08-04): 10 FALSE, 5 OVERBROAD, 20 TRUE, and the split is not random. What failed: *«тут лише те, чого memory дім»* · *«дім саме тут»* · *«what lives ONLY here»* · *«стоїть ТРИЧІ дослівно»* · *«крім SEC.25»* · every ⛔ "only-here" protection (2 of 3 stale). What held at ~100 %: every `механіка → NN_NN §` delegation arrow (20+), every dated header, every named file — the only delegation failures were at *item-number* granularity inside a home (`04_06 §B.2` BP #14 vs #15), because numbers inside a home shift and section names do not. **The mechanism: a self-location claim is falsified by an edit in ANOTHER file** — a skill gains the rule, a tracker item moves to `§🗄️`, a canon section absorbs the verbs — so nothing keyed on this file can detect it, and the claim reads *fresher the longer it stands*. Cheap recurring check, one grep each: for every only-here token, grep the corpus for the claim's two rarest content tokens (a second hit means the exclusion is stale); for every «Стан → `00_07` ID», test whether that `#### ID` still sits above the `§🗄️` boundary; and inside any inventory block enforce *re-measured ⇒ struck*, since a later line that supersedes a number without striking the older one is `ssot-maintenance` §Guard-craft #31 living inside the block that documents catching #31. 🔴 **The mirror case has the OPPOSITE cure, and nothing in the file distinguishes them** (2026-08-05): a `description` promised a lesson whose words appear nowhere in the body — and both branches are live, «stale label whose subject dissolved» (cut it) versus «the LAST surviving copy» (migrate it into the body). Reconstructing the meaning from the neighbouring section would have built something plausible and wrong; what settled it in minutes was **grepping the session transcripts** (`*.jsonl`) for the phrase and taking the earliest NON-description occurrence — which still carried a word the rewrite had dropped, and the whole instance behind it. **Memory lives outside git, but the sessions that wrote it do not: a claim with no body is a lookup, not a judgement call.** 🔴 **And the class is not memory's — it is the SHAPE's, so hunt it in git too** (2026-08-08): `db/migrate/*_init_consolidated.rb` opened with *«This is THE only migration in the repository»* and kept saying so while four incrementals landed on top of it, because nothing that edits `db/migrate/` also edits that sentence. A file under review, in CI, with a gate on its directory, held a false self-description for weeks — the versioning that makes memory recoverable does nothing about a claim keyed on a file other than the one being changed. **When a git artefact describes its own population («the only», «exactly one», «all of them are here»), the fix is not to update the number but to point at the enumeration** (`ls db/migrate/`), which is the same no-volatile-counts rule one level out.

13. **The verdict ADDRESS-vs-SCOPE is decided by the source's GENRE, so read the genre before you read the pair.** 🔴 Two agents inventorying the same class on different source files returned opposite headline verdicts — «SCOPE did not occur once» (0/25) and «~14 of 22 are SCOPE» — and both were right. What separates them is not model tier or perimeter but what the source file *is*: a **session chronicle** carries the raw instance and nothing else, so the home's rule is the only copy (→ `ADDRESS`, cured by one string); a **«Durable lessons» file** — one that writes its own conclusions under `🎓 Уроки:` / `Правило:` / `Мораль:` / `🔑` — already carries the portable imperative almost verbatim, so the rule lives twice (→ `SCOPE`, cured by excising the duplicate down to the instance). Measured verbatim on the sharpest case: «дефолт vendored-залежності перевіряй проти КОНКРЕТНОЇ версії в `extern/`… не проти памʼяті й не проти доків» stands word-for-word in both the home and the source's own `🎓 Уроки` line. 🔴 **But the marker-grep has FALSE NEGATIVES too, so it predicts the verdict and never replaces the read** (measured 2026-08-05): `project_dependabot_sweep_2026_07` returns **zero** markers while its «пастки, куплені кровʼю» section writes a bold portable imperative in every bullet — durable genre with no marker at all; mirrored on the other side, a file named `log_*` carried exactly one durable clause. And the marker COUNT is meaningless without declaring the character set — three passes over the same file returned ~20, 41 and 51 purely from different patterns. ⚠️ Deeper still: the error-axis homes are **anthologies of verbatim quotes** from their sources, so a home↔source duplicate is SYSTEMIC by design, not an anomaly — which means similarity alone never decides. The discriminator stays the second measure: does the source's copy carry a router home. **Two consequences.** (a) The two verdicts are not the same job: `ADDRESS` is additive and safe, `SCOPE` is an **excision** from a corpus outside git and needs the READ-verification bar — never batch them into one pass, and never do the `SCOPE` half at the tail of a long session. 🔴 **And the READ bar is not the whole of it: an excision needs TWO agents with OPPOSED frames, and not for reliability.** Agent #1 judged each clause against the three homes its brief named and found 2 homeless; agent #2, frame inverted, searched the whole corpus + skills + canon and found 4 — three of them generalisations whose INSTANCES had homes and whose FRAME did not. The intersection was non-empty, neither set covered the other, and the truth was the UNION. The cause is structural rather than a quality gap: the first was bounded by the perimeter its own brief handed it, the second was not. 🔴 **And that perimeter is YOURS, so a false negative arrives as your own defect wearing the agent's signature — which is why it survives review.** Measured across three verifier briefs in one night (2026-08-08): each returned a «НЕМА» that was correct inside the perimeter its brief named and wrong about the corpus — one class had its home in a file the brief simply did not list, and the answer read as a fact about the corpus because **nothing in a verdict carries the scope of the question that produced it**. A negative is the direction that LICENSES action, so re-run the narrow question yourself, corpus-wide, before acting on one. The same shape governs inherited COUNTS: a "live yield: zero" carried forward from a prior pass measured 3, and all three sat in the very file that had recorded the zero. **So for any operation whose verdict means DELETION, one agent is not «probably enough» — a single frame is systematically blind on exactly the side that erases facts.** Re-measured 2026-08-05 on the `log_subagent_craft` excision, and the second run came out **starker** than the first: the completeness frame («does the home carry every sub-claim») returned 2 blockers, the disappearance frame («what stops existing») returned 11, and they overlapped in exactly **ONE**. The costliest finding — a home whose stated ceiling was wider than its own evidence — came from the disappearance frame alone, and the completeness frame had explicitly cleared that very clause as harmless drift. Two frames, near-disjoint yields, and the one that would have been skipped as redundant is the one that caught the disinformation. (b) Grep the source for its own lesson-markers FIRST; that one grep predicts the verdict for every pair on that file, and it is cheaper than inventorying them one by one. 🔴 **But the ceiling that grep declares is not a detail — measured 2026-08-05, it hides the majority.** A full READ of THREE sources (`deploy_hole_hunt` · `money_path` · `e61`) returned **47 pairs and 13 MIGRATE-FIRST**, against a marker-directed pass that had priced the WHOLE corpus at 32 pairs and 7 MIGRATE-FIRST — same corpus, same day, and the only difference is that a marker-directed pass reads marker ZONES. **Consequence for planning rather than for counting: `SCOPE` does not fit into one session at the READ bar irreversibility demands, so never make it the tail of other work.** One finding pushes the reading cost back down: **the debt has the shape of a SECTION, not of a file** — in `deploy_hole_hunt` nearly every pair came from a single section, while the money and secrets blocks of the SAME file were already written with routing discipline (home exists → tag stands; none → plain chronicle). Ask not «is this file a debtor» but «which of its sections was written BEFORE the home existed». 🔴 **An INHERITED verdict has a perimeter of its own, and it reads more reliable than it is** (2026-08-05): a prior session's «this pair is SCOPE, not MIGRATE» had checked the clause's HEADLINE formula — which the home did carry — and never asked about its auxiliary halves, two of which lived nowhere else in the corpus; excising on the inherited verdict would have been amnesia twice over. **Give an inherited judgement the same READ you would give your own finding.** ⚠️ The mirror bites when you verify an AGENT rather than trust it: a `grep -c` returned **4** hits of the very identifiers an agent said were absent from a skill — and all four were about something else (a `\z` anchor, a CI filter), so the agent was right and the counter nearly overturned it. **Grep proves mention, never substance**, and it is most dangerous exactly when used to reject a finding, because there a false negative sounds like caution. 🔴 **Final measurement, 2026-08-05: a frame's "safe to excise" list is a set of CANDIDATES, and reading the SOURCE removes about a third of them.** Of ~31 listed positions only 9 were still excisable — the rest already had the healthy shape (tight instance + router). The frame was not wrong; it answered *"does the home carry this"*, which it did, and never asked *"does the source still restate it"* — and only the second decides whether there is anything to cut. 14. **Every instrument you write to MEASURE this corpus will strip the token that discriminates — verify by reading the top hits before you report the count.** Three times in one session, 2026-08-08, in three different hands: (a) a same-language near-duplicate run normalised `[[target]]` away, and since the target is the only thing distinguishing two otherwise-identical router sentences, it manufactured 53 pairs at Jaccard 1.00 — read the top three and the artefact was obvious; (b) an agent's cross-language detector let a compound canon-ref (`00_05§2.7`) also emit a bare number anchor (`2.7`), so 3 of its first 22 candidates cleared a "≥2 independent anchors" bar on ONE signal counted twice — it found this on itself and said so; (c) a case-insensitive substring scan for banned tokens in a publication draft reported `SMS` twice, both inside `mechanisMS`. The mechanism is not carelessness: **normalisation exists to remove noise, and in a corpus whose content IS its cross-references, the noise and the signal are the same characters.** So the reflex is not "write a better regex" — it is **never report a corpus count without reading its top hits**, because the artefact is always visible there and invisible in the total. General form of the class → [[feedback_measurement_substitution]]; the sibling about a marker count being meaningless without a declared character set is trap (13). 🔴 **And the practice half, which is about WHEN you speak rather than how you measure** (founder frame, 2026-08-22, Gelassenheit): a number becomes a position to defend the moment it is said aloud, so **state whether its top hits are read AT THE SAME TIME as the number** — «53, top hits unread» and «41, read» are different claims, and only the second is a measurement. Measured on the curator in one session: the instrument lied SIX times, each time plausibly — an eaten emoji prefix, a window truncated at the dot inside an ID, `стан` matching inside «інстанс», a `cd` that made every canon doc look deleted, a rename that created a FRESH collision, and ugrep choking on Cyrillic context. None was a crash; all produced a credible figure. 🔴 **The mirror failure needs a DIFFERENT reflex, because reading the top hits cannot reach it: an over-narrow pattern yields false NEGATIVES, and the misses are invisible by construction while the total stays plausible.** Measured on the map of this corpus's `⊥` sacrifices — a naive scan for the marker and its pair missed **4 of 8**, every one of them sitting inside `**bold**` or parentheses. This matters because generated maps are otherwise the corpus's one genuinely rot-proof lens (they recompute from source, so they cannot go stale) — and that is exactly why **a map lies more authoritatively than a recollection does: it looks computed.** So a lens counts as native only after its PATTERN has been READ-verified against instances you already know; until then it is a stale claim wearing a fresh timestamp.

15. **A `TO-GIT` verdict needs THREE measurements, and the third is the one that manufactures work when skipped: does git ALREADY SEND readers to the memory copy.** Measured 2026-08-08 while migrating a batch: a two-axis check («is the rule in a git file» × «is it in memory») marked a `rspec --bisect` fork-safety gotcha as a gap — and `memory_gate.sh --routes` then showed its home is cited from **four** places in git (two skills, a component skill, the housekeeping prompt). That is the router pattern working exactly as designed, not neglect, and migrating it would have written a second copy of a rule whose address was already live. **So the predicate is: absent from git ∧ present in memory ∧ NOT routed to from git.** ⚠️ The third axis does not settle it alone, because a routed FILE can still fail to carry a specific clause at the moment of action — of four migrations that same day, all four targets turned out to have no inbound router at all, but the discriminator that made them safe was checking `git show HEAD:<receiver>` for the slug, not trusting the current tree (which by then contained the routers I had just written). **Measure the receiver's pre-state, not its post-state — your own edit contaminates the instrument.** Same class one level up: the first pass of this very check counted `00_07` as a git home for four rules, when what the tracker held was *my own note describing the gap*; a queue item about a missing rule is not the rule's home, so exclude the tracker from any "does git have this" measurement.

16. **A restatement that SENDS can still LIE — so the redundancy question has a second axis, and only the second one is dangerous.** The phase-2 criterion says a compressed restatement carrying a router is legitimate and one without is a duplicate. Measured 2026-08-08 across four files (54 clauses: 22 DUPLICATE · 12 NATIVE · 12 ROUTER · 8 PARTIAL), that criterion is **necessary and not sufficient**: three clauses routed correctly *and had drifted from what they route to*. The costliest instructed writing a gas-snapshot baseline with the pre-`00bb766e` pattern, which would have added ten foreign `testFuzz_` rows to a money-path artefact; another instructed hand-editing `db/structure.sql`, which has no `schema_migrations` row, bypasses StrongMigrations and is reverted by the next `schema:dump`. **So run redundancy and drift as two passes with different questions — «is this needed» and «is this still true» — and settle the second against the ARTEFACT, never against another document**, because two documents drift together while the artefact cannot. ⚠️ The drift pass also finds the shape a redundancy pass structurally cannot: an instruction to do something **already done** (a bullet telling you to add a check the gate has run for weeks; a tracker residual prescribing a form the shipped fix took differently). That is worse than staleness — it spends a whole pass and reads as an open hole. 🔴 **Two DEBT SHAPES, and they need opposite remedies.** *(a) «Cement the session twice»*: five of six debtor sections in one rule-file were written **the same day as the canon paragraph they duplicate**, by the session that created it — the memory is not lagging git, it is being written in parallel with git; the remedy is procedural (write the canon, then write only the send), never editorial. *(b) «The home absorbed it and the memory never shrank»*: homes 1–2.5 months older than the memory's last write; remedy is one excision per file. ✅ And the control case that validates the frame rather than the auditor: a machine-native file (local toolchain recipes) returned **zero** duplicates — **duplicate debt is a property of content that HAS a repo home, not of memory files as such**, so never price a `native:machine` file as debt. 🔴 One more, cheap and recurring: **closing a tracker item does not update the item's canon home** — OPS.19 shipped, and `06_07`, the CI inventory it points at, had no mention of the step at all. Grep the item's own canon ref before you write ✅. 🔴 **And the sharpest form aims one level up, at the PLAN rather than at a clause: an inventory that NAMES a home has usually not OPENED it.** Measured 2026-08-08 — a prior pass wrote «home = `lib/silken_net/load_test/README.md`» into the tracker for two memory sections; the README carries the first in full and the second **not at all**, its real home being the code plus a SHA-pin registry (`lib/canonical_block_pins.yml`) the memory had never heard of, i.e. git was RICHER than the copy. Excising to the named address would have been amnesia, and nothing in the plan looked wrong: the path resolves, the file exists, and one of the two claims is genuinely there — which is exactly what makes a half-right address survive. **So an address you inherit from a measurement is a hypothesis: open it and check the SPECIFIC clause before cutting to it, and expect the true home to be code comments rather than the README.**

17. **Opposed frames do not protect against a shared READING habit — and the two costliest misses of a curation pass both arrived as a home that is not one.** Measured 2026-08-10 across four agents on two rule-homes. (a) **Two agents with deliberately inverted briefs returned the SAME false verdict**, because the divergence trap (13a) buys is in the *question*, never in how the text gets read: both judged a cited skill item by its first line and neither saw that the clause lived in an INDENTED sub-bullet of that same item — so `backend #26a` was reported WRONG-SECTION twice, and executing either report would have "fixed" a valid address. **Before accepting any WRONG-SECTION verdict, open the cited item and read to its end, sub-bullets included** — a numbered item is a block, not a line. 18. **Editing memory through `Bash` bypasses BOTH of its carriers silently — the growth gate and the auto-commit are hooked on `Edit|Write`, and nothing announces their absence.** Measured 2026-08-27 while syncing seven memory files with `python3` heredocs: no ceiling WARN fired on any of them (one file had ~600 B of headroom), and the memory repo accumulated seven uncommitted files while its log kept showing the usual per-edit `mem(<file>): Edit` commits from earlier in the same session — so the history looked continuous while a whole sweep sat outside it. The matcher is literally `"Edit|Write"` in `.claude/settings.json`; a `sed`/`python` write is not a tool call it can see.
    🔑 **The general shape, and it is not about memory: a carrier bound to a TOOL is bound to a HABIT, and the moment you switch tools for good reasons (batch edits, exact-string assertions, avoiding a read-before-edit round-trip) the carrier stops without a sound.** Silence from a hook is indistinguishable from approval by that hook.
    ⚠️ **Reflex, cheap and sufficient:** after any memory edit made outside `Edit`/`Write`, run `bash .claude/hooks/memory_gate.sh --audit` and `git -C <memory> status` by hand — the two things the hooks would have done. ⊕ And when the sweep is deliberate, one grouped commit beats seven `mem(): Edit` ones: the message can carry WHY each line moved, which the per-edit form structurally cannot.
