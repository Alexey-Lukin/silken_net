# Guard-craft — ways a gate cannot see its own surface

> **Auxiliary file of the `ssot-maintenance` skill. Read this when you are building,
> hardening or DEBUGGING a gate — and also when writing a spec, doing a mass delete,
> narrowing a rule, running a campaign, or shipping anything a human executes by hand:
> roughly half of these fire outside gate-work.** `SKILL.md` carries only the generated
> one-line index of these items; this file is the source, and the index is regenerated
> from it (`ruby scripts/guard_craft_index.rb --write`). Edit rules HERE, never in the
> index — a hand-edited index is a second home, and #31 is what that costs.
>
> ⚠️ This file is the heaviest artifact in the practice — price it with
> `memory_gate.sh --weight` or `wc -c`, never from a number written here: this very
> sentence carried «~80 kB» while the file had grown past 100. "One Read away" is
> honest about the address, not about the
> cost: opening it is a multi-call read. That is the trade — the reflex arrives
> automatically in every session, the evidence is deliberately not free.

(`§Guard-craft #N`). Numbering is append-only — `10a` exists because insertion happens

1. **Decorative — the gate's INPUT sits outside the workflow's `changes:` filter, so it only ever fires on somebody else's PR** — its INPUT sits outside the workflow's `changes:` filter, so it only ever fires on somebody else's PR (the `bio_contract.rb` hole; `.claude/**` repeated it later on a different gate). **Reflex: input ⊆ trigger-filter?** `guard_registry_sync` CHECK D now enforces this for pinned sources and mirror trees — but it is scoped to those, not to every guard tree.

🔴 **Measured again 2026-08-19, on a gate written the same day by someone who had just read this item — so record what did NOT protect: knowing the rule.** A new Rails spec (`font_delivery_spec`) guards «the font family we name first must actually ship»; its inputs are `app/assets/**` *and* the vendored `vendor/assets/fonts/**`. The `test` job runs on the `ruby` filter, and `vendor/assets/**` belongs to `js` — so deleting a woff2 skips the job the gate lives in, i.e. the gate was blind on **exactly its own class** («declaration stands, file gone»). Note the two things that make this survive: the gate is green locally (the filter is a CI concept, invisible to `bin/rspec`), and its subject genuinely lives in TWO trees, so the half that is inside the filter makes the perimeter look right. ⚠️ **And no meta-guard covers it:** `workflow_gate_perimeter` classifies WORKFLOWS into required/advisory buckets and never asks whether a gate's input triggers its own job — read its header before assuming otherwise. **Reflex, sharpened: when a gate reads from more than one TREE, list the trees and check each against the job's filter separately — a gate whose subject spans trees is the shape where a partial match reads as coverage.** Found by the closing sweep, not by the rule.
2. **A whole GENRE outside every linter's namespace — «Стаття N» headings; a genre exempt BY DESIGN is where drift is densest, so a green `docs_check` ≠ correctness there** — "Стаття N" headings; `08_03` carried `§1.1–§1.5` pointing at subsections that never existed, green for years. A genre exempt **by design** (`manifest.md`) is where drift is densest. Measured blind to named-article (H3) headings: `Tracker::Dashboard` · `code_tracker_id_check` · `DocsToc` — so a green `docs_check` ≠ correctness there, and a manual re-grep is mandatory. ⚠️ Note the mirror, because it bounds the claim: `§`-refs those same gates DO validate (mutation-proved — `§99`/`§4` → HARD), so the blindness is **genre**-shaped, not reference-shaped.
3. **A noisy advisory is functionally OFF — and a semantic gate that does not name its CEILING in the script header turns green into «not checked»** — functionally off. Fix by narrowing the scope to one unit of work and grouping output (one line per file, detail behind `--verbose`), and by **naming the ceiling in the script header**: a semantic gate must declare what it cannot see, or green reads as "not checked". ⊕ **The mirror case, and it is the one that outlives its reason: an `advisory` label that has become STALE CAUTION at zero noise** (moved here from the `00_06 §3` `magic-marker` row, 2026-08-10 — its only home). That guard is a deterministic byte-packing check, FP-free *by construction* (it needs a quoted four-letter name adjacent to an ASCII-range hex, scoped to `/magic/i`), and it had sat advisory with zero residual hits — the caution was inherited from the era before the design ruled false positives out, and nothing re-examines a label once it is written. So the audit is two-directional: a **noisy** advisory is off and must be narrowed, but a **silent** one is usually a promotion nobody proposed. **Reflex: for every advisory in the registry, ask which of the two it is — measure its live hit-count, then ask whether the design still admits the FP class the label was hedging against.**
4. **Blind to its own prose — a gate sees its DATA, never what it SAYS about itself, so its header comment can contradict its own constant indefinitely.** `workflow_gate_perimeter` read the workflows and its own Ruby constant, so its header comment could contradict that constant ("all eight" on line 6 vs "flip-pending" on line 10) and live that way until a prose-check was added. A gate sees data; it does not see what it says about itself.
5. **It under-implements the contract it declares.** Worse than #4, because the prose is *right* and the code is a subset. `stale_who` stated its contract as a UNION in three homes (rake comment, spec comment, §3 row) and implemented one direction — it caught meta OVERSTATING and was structurally blind to meta UNDERSTATING, the costlier half (the meta-line is the scan layer, so a pure-👤 meta over machine work reads as "nothing here for me"). **Reflex: read what the gate SAYS it enforces, then check each direction of that sentence separately.** A bidirectional word — *union*, *parity*, *symmetric*, *round-trip*, *1:1* — is a promise of ≥2 checks; count them. ⚠️ **And counting them is not enough — check each direction's DOMAIN too** (DOC-T.55, 2026-07-31). The tracker's WHO pair looked complete: one gate for understating, one for overstating, both shipped. But the overstate half reads literally `include?("🤖")`, so of the three executor glyphs it guards exactly one — a meta-line advertising a `⚖️` verdict nobody is waiting for passes green forever. I found it by walking into it: an item of mine carried a stale `⚖️` for a day while `tracker:check` said clean. So the question after "how many directions?" is **"over what SET does each direction range?"** — a check that covers one member of an enum reads, from its name and its green run, exactly like one that covers all of them. ✅ **CLOSED 2026-08-05 (`stale_who`), and closing it bought three things the diagnosis had not predicted.** (a) The enum was only HALF the hole: the same guard exited on `open.empty?`, so the EMPTY SET satisfied it trivially — a finished item kept a full WHO axis over nothing at all. Two blindnesses in one predicate, and the item's own title named only the first. (b) **The remedy the tracker prescribed was UNBUILDABLE as written** — it said such an item "must carry an EMPTY WHO axis", but `WHO_CANON` in the sibling guard has no empty member, so a gate written from that sentence would have ordered a state its neighbour HARD-rejects. This is the inverted root one paragraph down, aimed at a tracker item instead of canon prose: **construct the prescribed end-state and check that the rest of the system accepts it, before implementing the sentence.** The buildable form came from the legend instead — `🌿`/`⚫` mean the WHO names a FUTURE executor, every other STAGE means the union is genuinely empty. (c) The guard's own spec carried an example named *"stays silent on an item with no open residuals at all"* — i.e. #12's shape, a pin asserting the defect AS the intent, sitting inside the very gate whose contract it contradicted. ⚠️ And the honest ceiling got materially WORSE with the widening, which is worth stating because nobody re-measures an exemption after changing its scope: the item-wide exemptions (`🔗`-led / glyph-less residual) now silence **27 of 29** literal hits, since an undetermined executor backs ANY glyph and therefore cannot be narrowed per-glyph. Measure what an exemption costs AFTER you widen what it guards, not before. ⊕ **And never quote the YIELD of a half-built gate — it is understated, and the understatement is invisible in the number itself** (moved here from the `00_06 §3` row, 2026-08-10, which was its only home). The corpus figure for the understate axis was measured with the SHIPPED guard against a pre-fix tracker; the first, broken version had reported fewer, because its own two bugs silenced part of its own catch. A catch-count is evidence about the GATE that produced it before it is evidence about the corpus, so a figure quoted from a run predating the fix describes neither. **Reflex: tie every catch-count to the gate VERSION that produced it, and re-measure after any change to the gate itself — otherwise a number about your instrument travels as a number about the world.** 🔴 **Inverted root, and the more expensive one: the CANON PROSE is the under-implementation, and a gate transcribed from it faithfully inherits the hole** (the PR auto-labeler gate, 2026-07-29 — **both the gate and its canon section were removed 2026-08-09 with the Projects/Shape-Up layer, so this example lives only in git; the lesson does not**). The canon prose had carried the mitigation as "an `all:` wrapper is mandatory wherever negative globs appear" — true, load-bearing, and strictly weaker than the invariant: it blesses a negative sharing one `changed-files` with a positive (OR *inside* the AND-wrapper) and an `all:` holding the negative block alone, both of which stick the label to every PR. The gate that finally held was written from a *derived* rule (expand to a disjunction of conjunctions; every branch carrying a negative must carry a positive), not from the sentence. **Reflex: when translating a prose rule into a gate, first construct counter-examples AGAINST THE PROSE — if one passes the sentence and still exhibits the disease, the canon is the defect and must be tightened in the same commit.** A remediated bug whose fix is recorded as a *form* ("wrap it in `all:`") rather than a *property* is where this hides.

🔴 **Sharpest variant: the gate's own DATA contradicts its declared taxonomy, and nothing compares the two** (SEC.25 scope gate, found 2026-07-28 — one day after shipping it). The gate's header prescribes a proof FORM per class (`unscoped_interpolation` → set-equality pin); its registry then pointed that row at a cross-org-404 example running `as: :json`, which never renders the subscription at all. So the row was of the wrong form *from birth*, which is strictly worse than the ceiling the header honestly admits ("pins the example's NAME, not its provingness" — that one describes an example *hollowed out later*). The gate can only grep the example's name, so nothing can catch this but reading. **Reflex: for any gate whose registry declares a per-row proof KIND, re-read each row's proof and ask "is this actually of the kind the row claims?" — a registry is data, and data drifts from the prose above it exactly like a mirror does.** Corollary that made it costly: it was found only because a *different* stale-mirror sweep dragged me through that row; no sweep was looking for it.

6. **It compares a HOMOGENEOUS pair and is blind to the seam between LAYERS** (I18N.1, 2026-07-26). The most reassuring gates compare like with like — locale↔locale, doc↔doc, workflow↔workflow — and a green run gets read as "this whole surface is fine". `i18n-tasks missing` compares every locale to every other and is structurally incapable of noticing that the *model's enum* grew while the YAML stood still: a display enum reached 14 values while the formatter knew 9, green the whole way. The sibling shape is worse — the pair that **no** gate compares: broadcast producers vs `turbo_stream_from` subscribers both live in the repo, nobody compares them, and eight producers were shipping into streams with zero listeners. **Reflex: name the two sets a gate compares, then ask which OTHER set this artifact must agree with — and whether anything checks that pair.** The cross-layer gate is usually a cheap spec (`Model.enum.keys` vs the locale file), not a linter. Corollary for such a spec: check the **base** locale only — cost then does not grow with the catalogue, and a newly-added, still-untranslated locale does not turn it red.

7. **A config mask switches the gate OFF, and the comment above it justifies a DIFFERENT problem** (I18N.1, 2026-07-26). `ignore_inconsistent_interpolations: ['*']` meant the CI step `i18n-tasks check-consistent-interpolations` could never fail — a green line in every build, checking nothing. The comment above it explained the mask with "UK has pluralisation forms en does not need", which is about the set of **keys**, not about `%{}` **variables**: a true sentence excusing an unrelated setting, which is exactly why nobody re-read it. It let a real bug through — a locale value carrying literal `#id` where every other locale had `#%{id}`. **Two reflexes.** (a) For every ignore/exempt/skip entry in a gate's config, ask *what would fail if I deleted this line* — here the answer was "nothing", the corpus was already clean and the mask was pure cost. (b) Read the justification against the setting, not against the code: a plausible sentence is not evidence that it describes THIS knob. A `'*'`-shaped exemption is never a tuning — it is a disabled gate wearing a config's clothes.

8. **It checks EXISTENCE where the real defect is SCOPE** (UI.4, 2026-07-27). A gate that pairs producers with subscribers answers "is anyone listening?" — and reads as covering the whole surface. It is structurally blind to "listening is fine, the channel is too wide": `"global_events"` was a bare unscoped stream carrying insurance payouts, and the fix the existence-gate would have blessed (add a subscriber) was precisely the cross-tenant leak. Note the adjacent gate did not help — the repo's cross-tenant item covers REST/Pundit, not stream names, so at the time *both* gates were green on the hole. *(The scope axis got its own gate on 2026-07-28 — `spec/security/turbo_stream_scope_spec.rb`; the example stays as the demonstration of the CLASS, and the general point survives: a gate owning one axis over a pairing silently launders the others.)* **Reflex: for every gate that pairs A with B, ask whether the pairing can be CORRECT and still wrong — usually the second axis is scope, quantity, or ordering, and it needs its own check, not a wider first one.**

9. **A guard's own extraction regex silently under-collects, and the guard's ceiling section says nothing about it** (I18N.2, measured 2026-07-27). `broadcast_payload_invariance_spec` anchors on a multi-line call shape, so a single-line `broadcast_*_to(...)` does not exist for it — verified: 1 of 2 calls seen in one file. Harmless for *that* gate (the missed call carries no payload), which is exactly why it survived: **an extraction bug shows no symptom while the missed items happen to be innocent.** The bill arrives when the same machinery is reused for a gate where completeness is the point. Reflex: before reusing an extractor, measure it against a hand count on one real file; and prefer AST (`Ripper`) over regex the moment a second consumer appears. 
🔴 **Sharpest form, and the tell is counter-intuitive: the DATA is polymorphic, so every successive fix to the extractor returns a DIFFERENT confident number — and none of them is "now it's right"** (UI.12, 2026-08-07). One hand-maintained registry wrote its subject in **three** row forms (a detailed code-span, a compressed one-row-per-namespace with the leaves in the *second* cell, and a **bold** variant in a neighbouring section). Reading form A alone said "35 undocumented"; teaching it form B said 5; form C moved a third surface again. The tracker item that ordered the gate had shipped the first number as fact, named six components as its evidence — **all six were in the registry, one of them added four days before the measurement** — and prescribed a "1:1 check like the neighbouring surfaces", which in the naive shape would have opened with ~30 false positives. **Reflex: when a re-measurement changes the answer, do NOT record the new number — record that you have not yet enumerated the FORMS. Ask "how many ways can this artifact spell one entry?" and pin one example of each in the spec, because a parser blind to a form is silent, and silence reads exactly like health.** ⚠️ And the second half is a decision, not a parser fix: if the same subject is enumerated in TWO places (here a table and an ASCII tree), gating both doubles the rot surface — collapse the weaker one to a ROUTER and gate it at a granularity it can actually hold (#31).

🔴 **And when you do write that AST extractor, expect the blindness to live in IT rather than in the gate's logic — three separate holes surfaced in one, each only after the gate was already green** (SEC.25 scope gate, 2026-07-28). (a) A node kind that *looks* like a record is not one: `var_ref` covers both `@wallet` and a local holding a string, so the classifier marked an interpolated local as a record — i.e. it **over-stated** the site's safety, the worst direction for anything that dispatches obligations. Found by measuring the extractor against a hand count, not by reading it. (b) **Any name pattern is wrong in both directions**: `broadcast_\w*_to` missed the gem's non-`_to` forms (which broadcast to the record's *own* stream — a stream with no name and no registry row), while `broadcast_\w+` swept in the app's own private helpers sharing the prefix (more numerous than the gem calls themselves — and the exact tally proved unreproducible on any basis a year later, which is its own lesson about writing one down). The durable fix is to stop patterning: derive the set from the library at runtime (`Turbo::Streams::Broadcasts` ∪ `Turbo::Broadcastable`), which also survives a gem upgrade untouched. (c) **The argument-less call form is a different AST node** — `broadcast_refresh` with no parens is `:vcall`, not `:command`/`:method_add_arg` — so the walker was blind to precisely the most idiomatic spelling of the thing the gate forbade, and the mutation *landed green*. Reflex for any AST walker: enumerate the call shapes explicitly (`foo(a)` · `foo a` · `X.foo(a)` · `X.foo a` · `foo` · `X.foo`) and write a unit example per shape — the paren-less and receiver-less ones are the pair everyone forgets. **(d) A THIRD shape surfaced the next day, in the same walker, found the same way — by probing, not reading** (2026-07-28): when the *nested* call is paren-less (`f X.m a, b`), it swallows the argument list into itself, so the OUTER call's args node arrives as a **bare array of arg nodes** with no `:args_add_block` wrapper — the only shape the arg extractor recognised. Result: `:absent`, i.e. "this call has no first argument", on a call that visibly has one. Note the meta-pattern across all three: each hole was in the *shape of the surrounding syntax*, none was in the walker's logic, and every one of them was invisible to reading and instant under a probe that enumerates spellings. So the reflex is not "read the walker carefully" — it is **write the probe table first**. Corollary on coverage: when such a walker's defensive branches sit uncovered, the honest fix is usually **deletion, not tests** — collapsing five duplicated emit paths into one and dropping genuinely unreachable guards moved branch coverage 97.81% → 98.16%, because the branches were dead rather than untested.


🔴 **Sharpest instance measured 2026-08-15, and the under-collection is TOTAL rather than partial: a NESTED bracket inside a link label makes the whole link invisible to every `\[([^\]]*)\]\(` guard in the family.** The class excludes `]`, so it stops at the *inner* closer, no `](` follows, and the match never happens — a forbidden label form sat unflagged on a money-path page for months. ⚠️ The mirror bites the other way, and it is why a WIDER character class is the wrong fix: starting the capture at the FIRST `[` makes a bold prose marker that merely wraps a link donate its outer text as the label, producing a confident FALSE accusation. One shape hides a real violation, the mirror invents one, and both come from the same lazy delimiter. Sub-reflex of the enumerate-the-FORMS rule above: **parse a markdown label by walking back from `](` to the MATCHING `[`, never by a character class — and return nil on an unbalanced walk, so an odd bracket makes the link invisible rather than mis-attributed, which is the safe direction for a gate that accuses.**
10. **It announces its own failure LOUDLY — and exits 0** (I18N.1, 2026-07-27). `i18n-tasks missing` could not resolve relative keys in the mailer templates (`relative_roots` knew only `app/views/components`), printed `Cannot resolve relative key ".heading"` — and returned **success**. The surface went unscanned, the build stayed green, and the diagnosis sat in output nobody reads, precisely because the exit code says everything is fine. This is worse than the silent shapes above: those at least do not assert health. **Reflex: for any gate that can print ERROR/WARN, check whether that affects its exit code** — if not, grep its output in CI or treat the step as inert. ⚠️ **And re-measure before you inherit that verdict: this very entry cited `check-normalized` as a gate that "already must" be grepped, and by 2026-08-13 that was false** — the gem had grown `:exit1 unless non_normalized.empty?`, so the wrapper was both stale AND unreachable (`run:` is `bash -e`, so the assignment aborted the step first), while five other homes went on teaching that its exit code is worthless (I18N.4). A grep-the-output workaround is a **dated** claim about a third-party tool: it pins a sentence in someone else's English, and nothing goes red when the tool starts behaving. Give every such workaround a re-measure date, and prefer the exit code the moment it discriminates. Corollary: a gate's *coverage* can shrink without its *verdict* changing, so a green step proves nothing about what it actually looked at.

10a. 🔴 **The gate must skip its own documentation — and that necessary skip leaves the HUMAN measurement permanently poisoned** (TEST.10, 2026-08-03). Any gate that scans the corpus for a forbidden *form* will also match the prose explaining a past violation, so it has to ignore comment lines or it reds on its own write-up. That skip is correct and it is also a hole: the ad-hoc `grep` a person runs to size the class keeps counting those comments forever. Measured: 9 hits = **6 live code + 3 prose**, so a third of the tracker's number was our own explanations — and the item's scope was overstated three revisions in a row because of it. Note the failure is not in the gate (it was right) but in the *manual* instrument beside it. **Reflex: whenever a gate skips comments, write the counting recipe next to it — «split code from prose in every measurement of this class» — because no automation will ever cover the hand-grep, and the durable fix for the prose itself is to PARAPHRASE the old form rather than quote it.** Sibling of #4/#5: there a gate is blind to what it says about itself; here it is deliberately blind, and the blindness migrates into the human's count.

11. **The spec pins that the call HAPPENED, never where it POINTED** (UI.4, 2026-07-27). Every spec on the broadcast surface asserted `have_received(:broadcast_replace_to)` with no argument matcher — so a producer aiming at `actuator_card_{id}` while the component rendered `actuator_{id}` stayed green for months. The assertion was *true*; it simply never touched the only thing capable of being wrong. **Reflex: when a call's correctness lives in an ARGUMENT — a DOM id, a stream name, a queue, a target path — assert the argument (`hash_including(target: …)`), not the bare invocation.** Generalises past specs: where the failure mode is silent (nothing raises, nothing logs), "it ran" and "it worked" are different claims, and only the first is cheap to assert — so cheapness is exactly what makes the useless one attractive.

🔴 **And the argument pin has its OWN blind half, one level down: it attests the CALL SHAPE and says nothing about whether the value survives the callee — because every call-site spec stubs the callee** (PERF.1, 2026-08-07, found by adversarial review after the suite went green). A new kwarg was pinned at five call sites with `kind_of(Time)` / `all(be_a(Time))`, all green — while one caller passed a **bare** timestamp into a helper doing `Kernel#Array(span)`, which answers `to_a` on `Time` with a ten-element decomposition (`[sec,min,hour,mday,mon,year,wday,yday,isdst,zone]`), so `.min` raised on the `isdst` boolean. Every internal insurance payout would have failed. The pins could not see it *by construction*: `allow(Service).to receive(:call)` means the value never reaches the code that breaks on it, and the model spec that WOULD have caught it covered Array, Range, `nil` and all-nil — every shape except the one the only scalar caller uses. **Two reflexes.** (a) When you add a parameter, write ONE example that carries a real value END-TO-END (no stub on the receiver) — an argument matcher plus a stubbed callee is a claim about the caller alone. (b) Enumerate the parameter's **input shapes from the CALL SITES**, not from your own imagination of the type: here five callers passed a collection and one passed a scalar, and the scalar was the untested one precisely because it was the odd one out. ⚠️ Sibling on the API side: prefer `Array.wrap` to `Kernel#Array` for anything that may be a scalar — `Kernel#Array` calls `to_a`, and several core objects (`Time`, `Hash`, `Struct`) answer it destructively.

12. **The spec computes its expectation with the SAME broken transform as the code** (I18N.1, 2026-07-26). A mailer spec asserted the subject by calling `alert.alert_type.humanize` — exactly what the code did — so the assertion was a tautology that could never fail, and the fact that the label never went through the locale file stayed invisible. Sibling shape in the same sweep: a spec riding a *fabricated* enum value (`"Thermal Anomaly"`, not in the enum) exercised only the fail-open branch and never the production path. **Reflex: an expectation must be an INDEPENDENT statement of the wanted result — a literal, or a value fetched from the other side of the contract — never a re-run of the logic under test.** 🔴 **Sharpest sub-shape, and it recurred three times in one campaign: the spec does not merely fail to see the defect — it NAMES the defect as the intended behaviour.** Three specs called `manual_review` an "unknown/unrecognized status" and pinned the fallback style, i.e. they asserted that a double-spend guard renders invisible on the money path; a sidebar-badge spec stubbed the very scope whose absence was the cross-tenant leak and asserted the stub's own number; and two cache-invalidation specs wrote *and* read the same dead key the code deleted, so code and pin drifted together and the pair stayed self-consistently green. In all three the assertion was true, the name was plausible, and mutation was useless — the mutant matched the pin. **Reflex: when a spec's name contains a synonym for "unknown / default / fallback / legacy", open the value it is describing and ask whether that value is actually a documented state of the system** — if it is, the spec is cementing a bug, not covering one. And when a spec must change to accommodate a fix, treat it as a hypothesis about what it was really testing: 24 red specs were the *evidence* the migration worked, and two of them turned out to have been asserting the bug.

13. **«Closed» for one caller is not closed for the CLASS** (I18N.1, 2026-07-26). `alert_type` was recorded as done once the shared formatter resolved it — then three separate bypasses surfaced (`clusters/show` raw enum, `dashboard/event_row` raw value interpolated into a *translated* sentence, `alert_mailer` `.humanize`). Each caller had reached the value by its own path, so fixing the shared method proved nothing about them. **Reflex: after fixing a shared derivation, grep for the SOURCE (the model attribute), not for the fixed symbol** — the bypasses by definition do not mention it. The inverse case is worth the same alertness: sometimes the code drifted against a canon that was already right (`render_auth_page`'s `title:` default existed in code while `04_04 §1` had long documented the signature without it), so «doc is stale» is a hypothesis, not a default.

14. **It pairs A with B and never asks whether EITHER is reachable** (UI.4, 2026-07-27, found the day after the sweep that declared the surface clean). *(The tract itself was wired up later the same day — the example below is kept in the past tense as a demonstration of the CLASS, not as live state.)* A producer⟷subscriber check answers "do both ends exist"; it cannot answer "does anyone ever arrive at them". `"geospatial_matrix"` passed every pairwise test — producer present, subscriber present, target rendered inside that very subscriber — and is dead, because **no route renders the subscriber, and none ever did in the whole history of the repo**. Note what makes this class expensive: the *manual* audit that preceded the gate made the same omission and then wrote its confidence into two canon homes and a skill («a COMPLETE, code-verified registry», «no dead target survives»), so the false claim outlived the check that produced it. **Reflex: for a gate over a graph of references, the endpoints are not the perimeter — reachability is. Ask what would have to be TRUE for a passing pair to still be inert, and check that separately (here: `routes.rb` + controllers, not the component's own file).** Sibling reading for #8: existence, scope, and reachability are three axes over one pairing, and a gate that owns one silently launders the other two.

15. **It checks that a pairing EXISTS and cannot ask who OWNS the shape flowing through it** (UI.4, 2026-07-27, the same afternoon). The fourth axis after existence/reachability/scope, and the one that finally explains why the earlier three kept finding half-fixes. A stream+target pair has exactly one owner — the page that renders the target — and any gate that merely confirms "producer aims at a target that exists" will bless a producer pushing a fragment shaped for a *different* owner: here `EwsAlert` pushed a 6-column `<tr>` into both a real `<tbody>` and a compact `<div>` panel, so an updated row changed its own tag mid-page. **The trap for the fixer is sharper than the bug**: making the container a table would satisfy every structural check and still be wrong, because the two owners need different *verbs* — the digest panel must `remove` a resolved alert and backfill the next one, the worklist must `replace` it with a struck-through row, and a fixed HTML fragment cannot express two verbs at all. **Reflex: when one entity feeds two surfaces, stop asking "does the payload fit" and ask "whose shape is this, and does the other owner need a different OPERATION?" If yes, the payload must become a signal (`broadcast_refresh_*_to`) rather than markup** — which also happens to dissolve the locale problem, since each viewer then re-renders in their own request. Generalises past Turbo: any push-based channel that ships a rendered artifact to more than one consumer has this defect latent.

16. **The assertion runs in the one locale where the fix and the bug produce IDENTICAL output** (I18N.1, 2026-07-27). Specs default to the base locale, and in a base locale a label very often *equals its own token* (`confirmed: confirmed`, `active: active`). So `expect(html).to include("confirmed")` is green whether the component resolved the label through the locale file or printed the raw enum — the example cannot express the defect it was written for, and no mutation reveals this because the mutation changes nothing observable. **Reflex: an i18n assertion belongs in a NON-base locale, where the label and the token differ; and add the negative half (`not_to match(/>\s*active\s*</)`) so a regression to the raw value goes red.** Generalises past i18n to every identity-shaped transform: if `f(x) == x` for your fixture, the fixture proves nothing about `f`.

17. **The pinned CSS class exists elsewhere on the same page, so the example passes through a NEIGHBOUR** (I18N.1, 2026-07-27). A spec named "highlights failed command status with danger accent" asserted `text-status-danger-accent` — which is the hover/focus class of the card's OFF *button*, not the status. It would have stayed green with the status not rendered at all, and it survived a rewrite of the very code it claimed to cover. Worse, the obvious replacement repeated the mistake: `bg-red-900` is also used by that card's own `offline` LED. **Reflex: before pinning a class/id/string, `grep -c` it in the file under test — a pin is only a pin if it is UNIQUE to the element under test.** Sibling of #11 (assert the argument, not the invocation): here the assertion touched the right page but the wrong element, which is the same failure wearing different clothes.

18. **The session that hunts stale mirrors leaves its own** (UI.4/I18N.2, 2026-07-27). Two commit messages in one session boasted about «lists that lied» and «mirrors that outlived the fact» — and that same session left a registry row asserting a producer that no longer exists, plus an item tail in the present tense about defects it had closed 11 minutes earlier. Both survived **three** subsequent doc-commits that edited the very same files, one of them three lines away. **The mechanism is specific, not carelessness: you sweep the thing you are changing, and a registry row is not what you are changing — it is what DESCRIBES what you changed.** Reflex: after editing behaviour, grep the artifact for the *old* behaviour's vocabulary (`prepend`, the old target id, the old method name), not for the item you were working on. A gate cannot help here — `tracker:check` and `docs:check_refs` both stayed green, because the row is well-formed and every link resolves; only the CLAIM is false.

19. **The idempotency spec is vacuous because the first run removed the subject from the scan scope** (ARCH.58, 2026-07-27). A self-healing sweeper scans a *symptom* (`Actuator.active`) and then *cures* it. Two specs named "does not create a second STOP on the next pass" and "does not duplicate the alert on the next pass" both passed — and would have passed with **both dedup guards deleted**, because after pass 1 the actuator is `idle` and pass 2 never looks at it. The assertion was true; it simply never reached the code it named. Note how convincing the shape is: it reads exactly like a real idempotency test, it is the same shape used for sweepers that *don't* cure (where the subject persists and the test is genuine), and a mutation of the guard leaves it green — so mutation-testing alone does not expose it either; only asking *"which of my two runs actually enters the branch?"* does. **Reflex: for any worker that removes its own trigger condition, an idempotency spec must RE-CREATE the precondition between runs (`re_stick`), or it asserts nothing.** Generalises to every cure-the-symptom job — reconcilers, migrators, backfills, retry-drainers: the second invocation is a no-op by construction, which is precisely why it proves nothing about the guard you wrote for it.

20. **The fix silently invalidates the spec that guarded the thing it fixed** (ARCH.58, 2026-07-27, found by a *third* adversarial round aimed at the *fixes*). Round two found a real defect: a sweeper's recovery step burned its own predicate fuel before a fallible tail, so a crash could leave a row invisible forever. The fix — wrapping the step in a transaction — was correct, and it also moved every `after_commit` callback to *after* the whole set commits. One existing spec (`"STOP bypasses the readiness gate on a still-active actuator"`) had been meaningful precisely because the callback fired while the actuator was still active; post-fix it fires after the actuator is already idle, so the gate would pass **without the bypass** and the spec stopped killing its mutant — while keeping a name that describes a world that no longer exists. **The general shape: changing WHEN something runs retroactively changes what every timing-dependent assertion is actually testing, and nothing goes red to tell you.** Transaction boundaries, `after_commit`→`after_save`, moving work into or out of a job, adding a lock — all have this property. **Reflex: after any change to ordering/atomicity, re-run the mutation for the guards that live in that window — not the whole suite, which stays green by construction.** Corollary on review economics: the round aimed at the *fixes* yielded more than the round aimed at the original work, because fixes are written under time pressure, against a freshly-changed model, by someone who has stopped looking for new classes.

21. **A scoping fix has THREE halves — the query, the CACHE KEY, and whoever DELETES that key — and mutating only the query proves one of them** (SEC.16 sidebar badge, 2026-07-28; the third half bought separately on the Oracle forecast cache). The third is the quiet one: when tenant-isolation renamed the key, only the *reader* moved to the scoped name, while three invalidators kept deleting the pre-scope name — so after the very event the invalidation existed for, the stale value survived its full TTL. **A rename orphans its invalidators silently, and nothing goes red**: the deleters still run, still succeed, and still delete a key nobody writes. 🔴 **And the reason it stayed open is worth as much as the bug: the tracker item had declared this axis CLOSED** («the sidebar badge was the ONLY org-blind key, no work remains») **because the inventory behind that claim had read only the READERS** — one half of the surface, presented as the whole of it. So the completeness claim was false in the direction nobody checks, and the fix's own scope argument inherited it. Reflex: after renaming any cache key, grep the OLD name and confirm every deleter moved with it; the fix is one home (a class method that both sides call) rather than three call sites agreeing by hand. A helper computed a tenant-scoped count under a **shared** cache key. Fixing the query alone still leaks: the first viewer to warm the cache serves their number to every other tenant for the TTL. The two halves are independent defects with independent mutations, and a fix verified by one mutation reads as fully verified. **Reflex: for any per-tenant (or per-user, per-locale, per-role) cached value, mutate the KEY as its own experiment** — and note the assertion that catches it must call the helper for tenant A *before* tenant B, since a key-collision defect is invisible unless something is already cached. Generalises to every memoization boundary: `Rails.cache`, `@ivar` on a long-lived object, an HTTP `Cache-Control` header, a CDN key, a Sidekiq-side memo. The sibling reading is #12: the spec that made this invisible for as long as it existed stubbed `EwsAlert.unresolved` and asserted the stub's own value, so the scope could not be expressed by the example at all.

22. **Premises that apply identically to both branches cannot rank the branches** (SEC.25 gate design, 2026-07-28). Five runtime-measured facts about a signed capability token (deterministic, transparent-but-unforgeable, verified without user context, no TTL, no connection identity) were all true — and every one of them held equally for both classes the gate was meant to distinguish. Building a *ranking* on them, and concluding the prescribed classifier was inverted, was therefore an invented bridge over correct measurements: the honest test was empirical (every leak the repo had actually shipped sat on one side) and structural (one side — an AR-record stream — inherits an existing, separately-audited enforcement layer of scoped finds + Pundit + foreign-404 specs; a bare string inherits nothing, **and its failure is UNBOUNDED rather than scoped to one entity**, which is what makes the asymmetry worth a rule). **Reflex: after measuring, ask which of your facts DISCRIMINATES — a premise shared by both options is background, not evidence.** Corollary about form: the classifier survived as a **dispatcher** (which proof obligation each site owes) rather than as the check itself, and in that role it immediately surfaced a money-path hole the replacement design would never have looked at. So when an item prescribes a "cheap first step", attacking it as if it claimed to be the whole gate is a strawman — read what the item says its own scope is before overriding it.

23. **A one-home refactor BLINDS the gate that keyed on the value's literal shape — and the fix is to key on the CENTRALIZER, not to widen the shape** (SEC.25, 2026-07-28). The scope gate classified a stream name by the AST shape of the literal (`scoped_string` = has an `_org_` token, `unscoped_interpolation` = doesn't). Moving name derivation into one home — the right fix for the real defect, 11 hand-written copies of 4 names across 2 layers — turns every one of those arguments into a method call, i.e. `:indirect`: **two distinct proof obligations collapse into one opaque class, and the gate stops being able to see a class CHANGE, the worst event on that axis.** Widening the shape-matcher is the trap (you cannot pattern-match "this string was built correctly"). The answer is that the *method name on the blessed receiver* becomes the class (`Name.org` → one obligation, `Name.gateway_ota` → another), which is strictly more robust than shape-matching and, as a bonus, immune to the call-shape blindnesses in #9. **Reflex: before centralizing any value a gate inspects, ask what that gate keys on — and move both in one commit.** The general form: any DRY refactor of a value under surveillance must relocate the surveillance to the new single point of truth, or it silently converts a specific check into a generic one.

🔴 **Sharper sub-shape, because the victim need not exist yet: a one-home refactor also blinds gates that are still only PLANNED, and there is nothing to notice it on** (SEC.25/UI.4, 2026-07-30). The tracker had carried, for weeks, "the producer⟷subscriber pair reduces to a set comparison — the AST extractor already exists, no new machinery". Measured before writing a line: after names moved into the home, `arg_pattern` is `nil` on **all 20 sites**, so the pair would have compared argument *classes*, not addresses. The shipped gate had compensated by keying on the method name; the unbuilt one had nothing to compensate with, and no red run could ever have told us — a plan cannot go green or red. **Reflex: when you centralize a value, also grep the BACKLOG for gates described against its old shape, and re-measure their premise before implementing them.** Corollary that decided this case: the honest test of a proposed symmetric check is *"list the shipped defects and name the SHAPE each had"* — here 7 of 12 were "the producer addresses the stream opaquely" (a method parameter, a `||` chain, bare `self`), i.e. an axis of FORM, and only 1 was "two sets diverged". A pair-gate is attractive because it is symmetric and easy to describe, not because defects take that shape.

24. **A machine-derivable attribute stands in for the human-only one that actually decides** (SEC.25, 2026-07-28). The gate derives a name's CLASS from its shape, and prescribes the proof FORM from the class. But the form that is actually required follows from the **page's cardinality**: a single-record page whose stream name interpolates that record's own attribute is safe transitively (the org-scoped `find` runs before format dispatch), while a page looping over a collection needs set-equality, because there the defect looks like an *extra* stream rather than a missing own one. Cardinality is not visible to any extractor — so the taxonomy had silently conflated two cases under one class. **Reflex: for every derived classification a gate makes, name the thing that REALLY determines the required proof, and check whether the derivation can see it. If it cannot, the class must be a DECLARATION in the registry with the reason written next to it — never an inference.** Sibling of #8: three axes over one pairing, and a machine can only see the ones it can parse.

25. **A new example can be vacuous because the method under test is STUBBED elsewhere in its own file — and the neighbouring example's odd-looking setup line is the tell** (SEC.25, 2026-07-28). I added an example calling `alert.send(:broadcast_alert_update)` and asserted the resulting broadcast; it reported "received: 0 times" while a runtime probe showed every precondition healthy. Cause: the spec file stubs that method globally, so `send` hit the stub and executed nothing. The sibling example three lines above carried `allow_any_instance_of(described_class).to receive(:broadcast_alert_update).and_call_original` — which I had read as ceremony. It was the precondition. **Reflex: before writing an example that invokes a method directly, grep the file for that method's name in `allow`/`expect ... to receive` — and treat any `and_call_original` in a neighbour as a warning sign, not boilerplate.** The dangerous direction is the *silent* one: had my assertion been a negative (`not_to have_received`), the stub would have made it pass forever, and nothing — not mutation, not coverage — would have said so. Sibling of #19: both are examples that never reach the code they name.

26. **Citing the wrong precedents is the same failure as inventing a mechanism, one level up: the EVIDENCE is borrowed rather than the reasoning** (SEC.25, 2026-07-28). Justifying a one-home refactor, I wrote into five separate homes that it removes "the class this repo caught three times". All three catches were real, all three were the *adjacent* axis (target DOM ids and record-form streams); the surface I had just centralized had **zero** shipped precedents. Nothing in the sentence was invented — the bugs happened, the duplication was real — yet the bridge between them was false, and it made a defensible change look battle-proven. Two consequences worth internalising: the honest justification is usually narrower and still sufficient (here: blast radius — losing the tenant token is a *leak*, which none of the cited bugs could cause), and **the cited-but-unfixed axis is a finding in itself** — those five hand-written target ids were still there, un-homed and un-gated, precisely because attention went to the surface that had no precedent. **Reflex: when you reach for "this class has bitten us before", open each incident and check it is the same MECHANISM, not the same feeling.**

27. 🔴 **A gate whose bypass is CHEAP and whose miss is SILENT is aimed at the wrong population — it has NEGATIVE expected value, not merely low** (SEC.25 Ф1, 2026-07-28, killed at design stage before a line was written). The plan was subscribe-time authorization in an owned ActionCable channel. Two measurements ended it. (a) **The client picks which channel class handles its subscription** — `Subscriptions#add` constantizes `id_options[:channel]` from client JSON, checking only descent from `Channel::Base`, while the signature covers the stream *name* alone; the stream-source element even keeps `channel` in `observedAttributes` and re-subscribes itself. So the adversary edits one attribute and lands on the unguarded default, and the gate polices only people who were never the threat. (b) **Its `reject` is invisible and irreversible** — `reject()` calls `forget(subscription)`, so the client never re-sends it, and no `rejected` callback exists. Hence the *only* population it can actually affect is legitimate viewers whose case the resolver fails to map — and that was not an edge case, since four of five org-resolution chains end in NULLABLE columns. **Two reflexes.** First, for any fail-closed control, name **who it fires on** and **who can step around it**; if those are different people, the control is theatre with a victim. Second, "fail-closed" is only safe when failure is *loud* — a silent fail-closed is an outage scheduled for later, and the honest comparison is against the hole it bounds, not against zero. **Third, and this item is the rule's only home: when a plan prescribes a mitigation, measure the MITIGATION's own failure mode, not only its benefit — a stopgap can cost more than the hole it bounds.** Here the mitigation's failure mode was strictly worse than the leak it addressed, and the form that survived (abandon the address — rotate an epoch inside the name) is immune to both halves because it needs no per-subscriber verdict at all. The SIBLING phase bought the same rule twice over, and name it precisely — it was **Ф0**, not this item's Ф1: its two prescribed halves were TTL on the signed name (mechanism → canon `04_04 §8.1`, lever (в)) and a render-time assert (tautological *and* unreachable for the component harness). Both died on their own failure modes, while what shipped — one home for stream names, 11 hand-written copies → 0 — was never in the plan at all. ⚠️ This sentence used to cite the rule as «§Mutation-verify's», where it has never appeared: a router pointing inside its own skill can be as dead as one pointing out of it, and nothing greps it.

**Two traps specific to writing the second half** (both shipped, both caught by adversarial review the same day — the session's real yield):
- **Your exemption may rest on a premise your own code refutes.** The reverse-axis guard exempted three-executor items as "physically unsatisfiable in two slots" — while the `⚖️ ⊂ 👤` line three lines below collapsed the triple onto a legal pair. The exemption silenced the gate on ~12% of the corpus, including three instances of the exact pathology it was written for: **the fix legalised the disease it diagnosed.** Before writing `next if …`, construct the case you are excusing and run it.
- **Match on the LEADING token, never `include?` over the line.** A residual tagged `👤` may *cite* closed machine work in prose ("§5.3 вже 🤖-verified"); an `include?` scan reads that as open 🤖 and the "fix" writes a phantom claim into the meta-line — manufacturing the very drift the sibling gate guards. Both gates carried the defect, so they blinded each other and both stayed green. Anchor first, then count.

28. 🔴 **The subject runs BEFORE the layer you would compare it against — so its own spec is structurally incapable of going red** (SEC.29, 2026-08-01). `Rack::Attack` sits in the middleware stack *ahead of the router*, so `rack_attack_spec` gets its 429 even for a path that no longer exists. Every one of its examples is therefore honest about the counter and silent about the target: a throttle rule can drift off a live route, off a verb, or off half its own declared surface, and the suite stays green forever. Two real drifts were sitting there — a `post?` check on a route registered as PATCH (the only step that actually *changes* a password), and an `==` path compare that missed `/auth/m2m_token/refresh`, i.e. the rule covered half of what its own comment says it protects. **Reflex: for any component that executes before the thing it references, its own spec cannot be the gate — you need a second spec that asks the OTHER layer** (here: `recognize_path` against the router). And name the axis precisely: one example proves the PATH is alive, a different one proves the RULE fires on it; the first stayed green through both defects.

    🔴 **And the gate I wrote for exactly this failed at exactly this — it compared the registry to the ROUTER and never to the RULE.** Its `verbs:` column was hand-written prose that nothing verified, so on the founding defect (path alive, rule reading the wrong verb) it would have been green, and one registry row was *already* lying about its rule on the day it was born. The fix is to call the subject directly — `Rack::Attack.throttles[name].block.call(request)` — which turns the column from a declaration into a measurement, and the founding-class mutation now goes red. ⚠️ The probe itself needed measuring first: the block returns `request.ip` as its discriminator, so a `Rack::MockRequest` without `REMOTE_ADDR` reads as "matches nothing" for *every* rule — a probe that is false-green in both directions. **Reflex: when a registry declares a property of some other artifact, ask what compares the two — and if the answer is "a human wrote it down", the gate is documentation with a test-suite's reputation.**

    🔴 **And it came back a third time, one layer deeper: the gate's own DEFAULT silently narrowed the very axis the registry left open** (ARCH.77, 2026-08-01, caught by an adversarial pass — not by the suite). The registry says `verbs: nil` meaning *"this rule does not discriminate on verb, so check them all"*; the example generator read `(config[:verbs] || %w[GET])` and checked **GET alone**. Consequence: of the five paths under the one rule that spans both routing circuits, the two POST-only ones produced **zero examples** — so deleting the load-bearing `(?:/api/v1)?` group from the rule's regex left the entire suite green (mutation-verified). Worse, the registry comment three lines above asserted the opposite in prose ("both addresses listed explicitly … no example would have gone red otherwise"), i.e. the gate shipped with a **written promise its own default made empty**. The fix is to derive the verbs from the router (`recognize_path` per candidate verb) rather than from a literal default, which turned 40 examples into 42 — and the two new ones are exactly the missing POSTs. **Reflex: `nil` in a registry means "unspecified", and every `||` that fills it is a policy decision — read each default and ask which member of the set it silently drops. A default that narrows is indistinguishable from a check that passes.** 🔴 **Sibling of the same family, and the cheapest to walk into: the set is empty because it was gathered from ONE root when there are TWO** (SEC.30, 2026-08-03). A new gate asserted "no controller outside the machine registry drops CSRF" by iterating `ApplicationController.descendants` — but `Api::V1::BaseController` inherits `ActionController::Base` **directly**, so the app's entire API tree was outside the enumeration: the example checked nothing and was green forever (mutation-verified: dropping CSRF on a real controller did not turn it red). Note the timing — this was written **an hour after** documenting "a gate over an empty set is green forever" in canon, which is the point: knowing the rule does not protect you at the moment of writing; only the mutation does. **Two reflexes: enumerate from every root an inheritance tree actually has (`grep -c 'class .* < '` beats intuition), and put a floor-assert on the population itself (`expect(set.size).to be > N`) — a gate whose subject can silently become empty needs a lantern on its own measurement.** 🔴 **Third reflex, and it is the mirror of the two above: a runtime-enumerated population contains the FRAMEWORK's own members, and a gate written from the item's wording indicts them forever** (SEC.27, 2026-08-12). Asked to require a declaration on every Active-Storage attachment, the honest population is `attachment_reflections` at runtime — and it returns **five vendor attachments with no validations at all** (ActionText ×2, ActiveStorage ×2, ActionMailbox), against our four. A gate shipped on that set is permanently red on code we do not own, which is the fastest way to get it deleted (#46b). **The discriminator must be PROVENANCE, not a name prefix**: `Object.const_source_location(model.name)` under `app/models` answers "is this ours" structurally, while a `%w[ActionText:: ActiveStorage::]` denylist is a hand-written mirror that rots on the next engine you mount. ⊕ And the same measurement paid twice: narrowing a SHARED framework default (`variable_content_types`) required checking who else consumes it — heic/heif had to stay, because a neighbouring attachment renders `variant(:thumb)` from iPhone photos, so the "obvious" narrowing would have broken a live evidence tract. 🔴 **Third form, and the population-lantern does NOT catch it: the set is healthy, but the THRESHOLD sits above the metric's maximum** (DOC-T.59, 2026-08-04). `memory_gate.sh`'s duplicate-home check compared whole-file 6-gram overlap against an absolute floor of 120; measured across all **6441** pairs of the live corpus the maximum is **72**, so the floor stood at 167% of the physical maximum and could not fire on any corpus state — a duplication detector that had never once been capable of reporting a duplicate, while two known duplicates measured 63 and 20. A `size > N` lantern stays green here: 6441 pairs is a healthy population, and nothing about the subject is empty. The tell is **dimensional** — an absolute floor over a whole-FILE measure asks a question about volume, while the defect is one paragraph: 60 duplicated words cannot reach 120 shared 6-grams no matter how many times they are copied. **Reflex: for any threshold gate, plot the metric's DISTRIBUTION over the whole population ONCE and stand the threshold next to the observed maximum — if no real case reaches it, the gate is not strict, it is dead. And check the unit: a scale-free measure (a coefficient over the smaller subject) keeps meaning as the corpus grows; an absolute count silently stops meaning anything.**

🔴 **Fourth round on that same gate, and it moved the lesson twice — first sideways, then deeper** (SEC.31, 2026-08-04). (a) **The missing root was the CHEAPEST of its defects.** The same predicate read `_process_action_callbacks.map(&:filter).include?(:verify_authenticity_token)` — i.e. it measured the callback's NAME. `skip_callback` with a condition does not remove the callback; it substitutes a conditional twin carrying **the same symbol**, so four distinct ways to drop CSRF (`only:` · `except:` · a scoped `skip_before_action` · `with: :null_session`) all read as "guard present", and the example asserting that a partially-exempted controller *keeps* its guard was a tautology that could never go red. A missing member is visible by counting; a predicate measuring the wrong PROPERTY is not, because every count it produces is correct. **Reflex: after asking "is every member in the set?", ask "does the predicate measure the thing the sentence claims?" — and prove it by mutating each way the property can be broken, not just the one you had in mind.** (b) **The first fix stopped one level short, and the shape of that shortfall is the general lesson:** distinguishing *conditional vs unconditional* is a verdict about the FORM of the exemption, while what matters is its EXTENT — so the full inversion (`only:` pointed at the cookie-reachable action instead of the machine one) stayed green, being just as "conditional" as the correct spelling. The honest measure was behavioural (`ActionFilter#match?` against a probe instance), and the registry had to declare the exact action list rather than a `:partial` label. Structural introspection would have failed anyway: `only:` files the filter under `@unless`, `except:` under `@if`.

🔴 **And the companion lesson, which cost more than the original defect: replacing a weak lantern with a TAUTOLOGY is a regression, and "independent source" is a claim requiring proof** (same session). Told that a size threshold guards collapse rather than completeness, I replaced `set.size > N` with a cross-check against the router — which reads as the textbook fix and was empty **by construction**: a routed controller is a `Metal` descendant by dispatch, and both sides ran through the same origin filter, so the difference could never be non-empty. Net effect: the threshold *did* catch a total collapse, and its replacement did not. Caught only by an adversarial pass that broke the filter deliberately and watched the lantern stay green. **Reflex: before calling a source independent, name the assumption each side shares — and verify by BREAKING the shared component and confirming the check goes red. A completeness check must key on something the derivation cannot influence** (here: the file system, not the router). Sibling of the "what could make this pass that is not my code?" rule, inverted: here the danger was what could make it pass that IS my code. Note the meta-pattern across all three rounds of this same gate: the declaration was wrong (round 1), then the comparison target was wrong (round 2), then the *filler for the unstated* was wrong (round 3) — each time the gate was green and each time a human sentence nearby claimed coverage.

    Two corollaries earned the same day. **(a) The form of the fix can be impossible for reasons that have nothing to do with the fix.** The obvious repair — derive the paths from `Rails.application.routes.url_helpers` into one home — cannot run in an initializer: `load_config_initializers` is an Engine-group initializer and routes are drawn in `set_routes_reloader_hook` (Finisher), while the lazy route set is enabled only under `Rails.env.local?`. So the constant would resolve fine in dev/test and raise on production boot — a defect that *no test run can surface*. Check the framework's load order before promising a "single home". **(b) A curated registry needs a completeness check, or it becomes the blindness it was written to cure**: pair the registry with `expect(Rack::Attack.throttles.keys).to match_array(REGISTRY.keys)` so a newly added rule cannot enter the codebase unwatched. Mutation-verify that half separately — rename one key and confirm it goes red.

29. 🔴 **Mass deletion leaves SEMANTIC tails that every link-checker blesses — the ID still resolves, so the gate stays green while the prose lies** (`08_03` module dissolution, 2026-07-23…24). Deleting whole sections or files is the operation `docs:check_refs` is weakest against, because it validates *references* and never the sentences built around them. Four shapes, all shipped, none gate-visible: **(a) range prose** — `§9–§15` survives the deletion of `§13–§15`, since the auto-ToC rewrites headings and never touches a sentence; **(b) vocabulary orphan** — a term whose *definition* lived only in the deleted home (`WP1–WP9`, defined in `07_03 §7`) stays in use elsewhere with nothing defining it; **(c) archive node** — archiving an ID with N inbound refs leaves every "do X for [ID]" semantically stale even though the archive row resolves, so a high-inbound ID (one carried 10) means N rewrites, not one; **(d) bare `§X` outside a code span** — `file_section_dangling_refs` is digit-led (`NN_NN §X`) by construction, so a naked `(North-Star §0.1)` orphaned by deleting `§0` is invisible to it; **(e) a RE-POINTED reference whose DESCRIPTION stayed with the old target** — the sharpest of the five, because nothing dangles: dissolving a page rewrites the *link* to a live successor and leaves the *sentence* describing the page that no longer exists. Measured 2026-08-10 on the `00_02` dissolution — the Read-First list ended up naming `00_03` **twice**, the first entry advertising content (`Intent-First`, `AI Pipeline`) that the very same commit had cut as dead, while the `Validation Gate` it promised had moved to `00_06 §5` and the `00_06` entry never mentioned it. Sibling of #50 (which is about the gate's PREDICATE) — this one is about its PERIMETER, and the two fail in the same silence. 🔴 **Re-measured 2026-08-15, and the 08-10 fix was itself an instance: widening a gate FOR a tree does not mean the gate can READ that tree, and the two live proofs were in the two guards that had just been widened.** (a) `link_label_target_mismatch` gained `.github/**` + root `*.md` — and a file one directory down can only write `](../docs/NN_NN…)`, the one dialect the pattern did not admit; the live lie sat in `pull_request_template.md`, the very file that sends contributors to read the registry. (b) `section_ref_after_doclink` already CARRIED `(?:\.\./)*`, added expressly for `docs/protocols/**` — but that subtree writes the extension in every href, and without `(?:\.md)?` the group never closed, so the guard reached exactly zero of the files it was widened for; the flip surfaced 16 violations that had been green since the widening. **Reflex: after widening a gate FOR a tree, open that tree and read ONE real line before believing the perimeter — a dialect check costs a single `grep -m1`, while a perimeter that cannot match its own target reports coverage it does not have.** ⊕ And the same session found the PREDICATE half of this pair alive too: the guard skips any label carrying no `NN_NN` token, so a label naming a *different kind* of document (`` [`CLAUDE.md §6`](00_06_…) ``) is unverifiable by construction — a gap #50 owns, listed here because the two were found in one read and a reader who fixes only the perimeter will believe the class closed.

52. 🔴 **Mutation-verify a gate in BOTH directions — «it reds on the defect» is only half the proof, and the missing half is where an over-broad gate hides** (ARCH.89, 2026-08-11). A gate that only ever goes red on the bug is indistinguishable from one that goes red on the bug's *legitimate neighbours* too, and nobody discovers that until it blocks honest work — at which point the cheapest response is to weaken it. **So pair every RED mutation with a GREEN one on the nearest lawful form.** Worked example: the gate forbids a bare `decimal` column in a Phlex block, and the four mutations were `remove .to_f` → RED · **`.round(2)` → RED** (on BigDecimal that returns BigDecimal, so it is NOT a cure) · **`.round` with no args → GREEN** (returns Integer, so it IS) · `alias_attribute` name → RED. The two middle ones carry the whole design: without the first the gate misses a real defect wearing a cure's clothes, without the second it is over-broad and its own header would be lying. 🔴 **And the GREEN half needs a sharper probe than «a new lawful pair»: use the domain's most common RESERVED value, because that is what crosses the boundary first** (UI.11, 2026-08-11). A frame-target gate proved not-over-broad against a freshly written legitimate pair — and still false-positived on `_top`, Turbo's documented «break out of the frame» directive, for which an element with that id must NEVER exist. Nobody used it that day, so the band was green and the hole was invisible; the first person to write it CORRECTLY would have met a red gate on correct code, and the cheapest response to an over-broad gate is to weaken it. **So when you enumerate GREEN probes, ask what the underlying tool reserves — sentinel values, wildcards, `_self`/`_top`/`*`/`0` — and make the exemption an EXACT match with its own pin** (measured: `_top` green, look-alike `_topmost` still red). 🔴 **And the GREEN half is not always ENUMERABLE in advance — sometimes the domain's most common lawful value is a STRUCTURAL by-product nobody would think to list** (ARCH.89 root fix, 2026-08-12). Both probes above assume you can name the lawful neighbours by reading (a fresh legitimate pair; a reserved sentinel like `_top`). Here the guard was a runtime one — raise on any type the renderer drops silently — and the RED half proved instantly. The GREEN half could not be reasoned out at all: the most frequent lawful value turned out to be **the return value of the block itself**, because `div { rows.each … }` yields the collection, and on an empty collection the buffer has not moved, so the renderer asks about it. Nothing in the domain vocabulary suggests "a collection is not a value here" — the suite said it, by turning **105 legitimate examples red** on the first run. **Reflex: when a gate fires at RUNTIME rather than over text, do not ship it on a reasoned GREEN half — run it over the whole suite once and read the failures as a QUESTION ("which lawful shape did I not know about?"), not as a worklist.** The tell that you are in this case: the guard's subject is produced by the framework (a block's return, an implicit `nil`, a `to_s` fallback) rather than written by a human — nobody wrote that value, so nobody can list it. ⊕ Sibling on the input side: derive the gate's SETS from the runtime (`columns_hash`, `attribute_aliases`), never from a hand-written list — a hand-copied member list is a mirror and it rots on the first schema change (same rule as the label-distinctness registry). ⚠️ And an invariant spec like this takes **no** `00_06 §3` row — its home is the canon section it protects plus its own header; check with `guard_registry_sync` rather than inferring.

53. 🔴 **A carve-out registry gates the PRESENCE of its `back:` condition, never its TRUTH — so an expired exemption looks identical to a live one, and the reader is the only check that exists** (UI.11, 2026-08-11). Our registries (`browser_contour_registry`, and now the frame-target gate) require each exception to declare `why` (the grounds) and `back` (the event after which it must go). That was itself a hardening — the earlier form measured only the LENGTH of the justification (SEC.31). But the second field is a *prediction*, and nothing evaluates it: the row stays green whether or not the event has happened. Measured here by nearly getting it backwards — I read «`SimulationWorker` appears» as already fired and was about to treat a valid carve-out as stale debt; `ls app/workers/` settled it in one command. **So when you meet a `back:` condition, EVALUATE it before acting on the row in either direction** — a fired one licenses work the registry still forbids, and an unfired one gets mistaken for rot. ⊕ The reflex generalises past registries: any field whose content is a *future* event is unverified by construction, and its cheapest check is usually one shell command — run it rather than reasoning from the prose around it. 🔴 **A `back:` condition has a THIRD outcome the item did not name, and it is the one that actually happened here (2026-08-15): not fired, not pending — made MOOT.** The frame-target carve-out predicted «the UI.7 verdict, before any edit to this target»; the verdict, when it came, deleted the whole feature, so the exemption did not expire — its SUBJECT stopped existing. Both registry rows and their live example went with it, and this item's worked example is now historical (kept because the lesson is unchanged). Two consequences worth carrying. (a) When a row's file disappears, a registry that only checks `presence` never notices — the `browser_contour_json_spec` catches exactly this with an explicit «registry does not rot» example (`ALL.keys - actual`), and the frame-target gate has **no** such example, so its stale rows would have sat there green forever; if you build a carve-out registry, build that staleness half in the same commit. (b) An emptied registry turns its own «every exception carries why+back» example **vacuous** — green over nothing. Do not quietly leave it: the fix shipped here was to declare the vacuum in the example's NAME, so a reader cannot mistake the zero for coverage.

54. 🔴 **A guard installed in a BOOTSTRAP file covers only the processes that LOAD that file — and the colliding party is usually the one that loads a different one** (TEST.12, 2026-08-11). The suite's concurrent-run guard lives in `config.before(:suite)` inside `rails_helper.rb`, and its header honestly names three ceilings (silent in CI · Redis-keyed while Postgres is shared · blind to a run that started milliseconds earlier). It does not name the one that actually fired: `spec/lib/docs_*_spec.rb` require **`spec_helper` only** (pure units, no Rails), so the Docs band — which runs them via `COVERAGE=0 bin/rspec` — never reaches the hook at all. The guard is not weak here; it is **absent**, and absence looks exactly like consent. 🔴 **Two halves generalise, and the second is the one that fooled me.** (a) *Ask which bootstrap path the OTHER process takes* — `rails_helper` ⊥ `spec_helper`, full app-boot ⊥ `:environment`-less rake, web process ⊥ worker ⊥ console: a guard in an initializer, a `before(:suite)`, or a middleware is scoped to its own boot path, never to «the project». (b) *Name the shared RESOURCE before concluding «safe»*: I reasoned, correctly, that the band boots no Rails and therefore cannot contend for Postgres or Redis — and that was true about the wrong resource. What they share is SimpleCov's cached resultset — the dotfile SimpleCov keeps under the coverage output directory — which **every** rspec writes, because `COVERAGE=0` disables the GATE and not the report. (Spelling that artifact's path here would itself trip `claude_prose_path_refs`, since it is gitignored and absent until a run produces it — shape #29's teaching-citation-becomes-a-claim, met while writing this very item.) So a correct argument about one resource licensed a collision on another. ⚠️ Diagnostic signature worth carrying, since the symptom reads as «I broke coverage» rather than «something else ran»: `0 failures` together with `EXIT=2` and *every* group at 0.0 % — a genuine floor breach moves ONE group by tenths. Remedy is deleting that cached resultset and re-running the suite alone. Sibling of #43/#44 (two stances of one gate) with the axis moved one level down: there the two stances both existed and diverged, here the second stance never instantiates the guard.

55. 🔴 **Before building a gate, look for the record that this class was ALREADY measured and the gate ALREADY refused — and look for it in the ARTEFACT's header, because that is where such a verdict tends to live** (TEST.12 axis D, 2026-08-12). I spent half an hour writing a Prism parser to size a class, then designed a narrow gate for it, and only afterwards found `scripts/spec_claim_audit.rb` — an existing instrument for exactly that class whose header already carried **both** conclusions I was re-deriving: a HARD gate here is impossible by construction (the matchers are individually appropriate; the defect is semantic), and a corpus-wide advisory report was *measured and rejected* because ~282 candidates at roughly half precision get read zero times. **Two things generalise.** (a) *A design verdict is not only a tracker item or a memory line* — the cheapest home for "we tried this and refused it" is the header of the tool that replaced it, and nobody greps headers. So before writing an instrument or a gate, `grep` `scripts/` and the neighbouring gates' headers for the class's vocabulary; the answer is often a paragraph away from where you were about to add a second opinion. (b) *Building a parallel instrument is itself a measurement substitution* — four independent parsers over one class returned four different numbers, each honest about a different FORM of assertion, and the tool's own header says the count may be taken from it alone precisely because that had already gone wrong three times. ⊕ The mirror worth keeping: the tool's declared ceilings are a shortcut to the class's real depth — its ceiling "two examples with byte-identical bodies are not sought" was, in this pass, a live instance found by hand.

57. 🔴 **A gate over DECLARATIONS makes the whole class look covered — while the oldest member is usually the one whose behaviour nothing has ever tested** (SEC.27, 2026-08-12). Closing a "nobody declared X" class, the natural instrument is a gate asserting the declaration EXISTS on every member; it goes green across the set and reads as "class closed". It is not: **"the declaration is present" and "the declaration works" are different claims**, and the gate is blind to the second BY CONSTRUCTION. The asymmetry that follows is the trap, and it is self-inflicted — you write behavioural pins for the members you just fixed, because they are in your hands, and the pre-existing member inherits nothing. Measured here: two newly-validated attachments got a pass/reject pair each, while `MaintenanceRecord#photos` — the oldest, and the one guarding the D-MRV evidence base — had **zero** behavioural pins after years, and a mutation proved it (weakening its validator reddened nothing until pins were written). **Reflex: after adding a declaration-gate, ask which member existed BEFORE the gate, and mutate ITS mechanism — that is where the untested behaviour lives.** ⊕ Sibling framing worth keeping: the axis is "new ⊥ old", not "A ⊥ B", so the usual fork-detector (memory `feedback_exhaustive_cross_ref_dig` B-1, "one branch has the guard, check the other") only fires if you read your own diff as one branch of the fork.

56. 🔴 **Deleting a REDUNDANT test is not the same act as deleting a dead branch, and it needs THREE independent measurements plus a fourth pass nobody's brief asks for** (TEST.12 axis D, 2026-08-12; 22 examples removed). A dead branch is settled by an invariant; a redundant example is settled by nothing — "it has a successor" is a claim, and the three cheap ways it goes wrong are disjoint. **(1) Verify the pairs MECHANICALLY**: for every deletion, the claimed successor must exist at its address AND assert something beyond a status code — otherwise you are trading one vacuum for another, and the pairing report reads identically either way. **(2) Zero-loss set-diff over the WHOLE corpus of examples**, not the touched files: before-set minus after-set must equal exactly the intended drops, and — the half that matters — **nothing may APPEAR**; that is the only cheap way to catch a neighbour clipped by an off-by-one range. **(3) Coverage before and after.** If it does not move by a single line, the deleted set covered nothing of its own, and that is a measurement rather than an argument; if it moves, you have found a path the pairing missed. ⚠️ **None of the three sees RESIDUE, and three different instruments found three different residues in one pass**: `rubocop` gave two now-empty `describe` blocks, an adversarial agent gave an orphaned `let!` fixture (invisible to lint because `RSpec/LetSetup` is disabled repo-wide), and only a human read found two survivors that needed a PIN rather than deletion. **So budget a fourth pass — lint the touched files, and give the DISAPPEARANCE frame to someone who is not you** (§the two-frame rule: the curator can hold completeness, never disappearance). 🔑 **And before any of it, ask whether the "layer" you are cutting is a layer at all.** Here `spec/integration/` turned out to be a DIRECTORY, not a tier — rspec-rails maps `spec/(requests|integration|api)` to one and the same `type: :request`, so those examples shared the middleware stack, the hooks and the tier of the very files that superseded them. That single fact predicted the zero coverage delta before it was measured. **Ask not "how is this layer different by intent" but "what does the framework DO with this directory".** ⊥ The SIBLING act — removing a dead code BRANCH, the one an invariant does settle — is a different discipline with a different home: memory `feedback_dead_code_refactor` (taxonomy + canon `04_06 §B.4`). Do not merge the two: what makes that one cheap is precisely the thing this one lacks.

58. 🔴 **A boot guard is usually blind to the very placeholder that exists to make it fail loudly — because `REQUIRED_SECRET_NOT_SET` is neither blank nor the sentinel, and a presence-shaped predicate reads it as a real value** (ARCH.60, 2026-08-14). Our deploy manifests carry that string ~105 times as a visible "fill this in" marker, and the convention works only for guards that happen to check something else too: the AR-encryption guard rejects it *by accident*, because it measures LENGTH and the placeholder is 24 chars against a floor of 32. A new mail-transport guard checking "non-blank ∧ not the scaffold default" therefore passed on a manifest whose every mail variable was still a placeholder — I shipped that predicate, then met it two edits later when adding the placeholder rows myself. **The fix is not to special-case the string** — that is a second home for a convention nobody would think to update — **it is to check the value's SHAPE**, which is what `Security::Web3NetworkGuard` already does one file over (its address-format check rejects the placeholder as a side effect, and its message says so out loud). An address needs `@`; a hostname cannot contain `_`. Shape-checking is strictly stronger: the same predicate also catches a mispaste, a truncation and a `changeme`. **Two reflexes.** (a) *When you write a presence-shaped guard, enumerate the values your own deploy surfaces will legitimately contain before real provisioning* — placeholder, empty string, the framework's default, the scaffold value — and check the predicate against each; three of those four look "set". (b) *Then make the MESSAGE distinguish them*: "unset" and "set to a placeholder" are different operator actions, and telling a deployer their variable is missing when it is present-but-unusable sends them to the wrong file. ⊕ Mirror worth carrying past guards: the same blindness afflicts any *validation* whose only question is presence — a `validates :x, presence: true` on a column a seed fills with a placeholder is green forever. ⚠️ And the guard's arrival creates obligations elsewhere that no gate enforces: a boot dependency must be walked across **every deploy surface** (Kamal clear+secret · secrets file · each deploy workflow · every SDL service in every manifest · the terraform variable + template map) **and every PROCESS that loads the environment** — here two of them, a web-only staging leg with no Sidekiq and a UDP daemon that boots all initializers, would have been newly un-bootable for a capability neither can exercise. Sibling of #54, which is the same question asked of a *bootstrap file* rather than of a *variable*.

59. 🔴 **A shrink-list exemption has TWO ways to die, and the obvious check catches only one — the other leaves an expired exemption actively PROTECTING the regression it was meant to track** (I18N.2, 2026-08-14). The gate had the right instinct: a curated list that only shrinks, with an example asserting no dead entry. But "dead" was computed as `pending - live_producers`, i.e. it fires when the *producer* disappears. The second death is the one the list exists for: the component **migrates and becomes clean**. Nothing noticed, because the entry still resolves to a live producer — so the row stayed green, and any `t()` re-added to that component would have passed, since being on the list is exactly what waives the check. **An exemption whose grounds expired is not decorative; it is a hole shaped like the original defect.** Fix is one example: for each exemption, re-derive its GROUNDS and fail if they no longer hold (`pending.select { |c| source(c).scan(/\bt\(/).none? }`). ⊕ This is #53 with the crucial difference stated: there the condition was a *future event* (`back:`) and unverifiable by construction, so the reader was the only check; here the condition is **mechanically re-derivable**, and leaving it to the eye had no justification — so the rule sharpens to: *when you write a carve-out, ask whether its grounds are computable, and if they are, gate them.* 🔴 **And mutation-verify such a gate in THREE directions, because the middle one is what proves it is not simply always-red:** defect + no exemption → RED · defect + exemption → **GREEN** (the exemption legitimately waives) · clean + exemption → RED. Skipping the middle probe would leave "the gate reds on my mutation" indistinguishable from "the gate reds on everything", which is how an over-broad gate gets weakened later instead of trusted. ⚠️ Note the tell that sent me looking: closing the last item on the list made the list EMPTY, and an empty curated list is the moment to ask what its checks now assert — several of them become vacuous, and one of them (this one) turned out to have been vacuous all along for a whole class of entry.

61. 🔴 **Чи є ПОРОЖНЯ МНОЖИНА для гейта провалом чи метою — вирішує ФОРМУ доказу його живості, і переплутати їх означає або вічнозелену декорацію, або гейт, що забороняє власний успіх** (UI.7, 2026-08-15). Дві протилежні конструкції, і в цьому репо вони стояли поруч. Гейт над **ВЛАСТИВІСТЮ** населення («кожна рукописна форма несе токен») мусить мати підмет: нуль форм = нуль перевірок, тож він потребує явного `has subjects`-прикладу — і той **чесно впав** у мить, коли остання рукописна форма зникла, надрукувавши «правило втратило підмет, зніми гейт». Гейт-**ЗАБОРОНА** («рукописних форм немає») навпаки: порожня множина Є метою, тож `has subjects` заборонив би успіх, і живість несе САМОПЕРЕВІРКА ДЕТЕКТОРА (позитивний ⊥ негативний контроль) плюс пін, що glob узагалі бачить дерево. **Reflex: перш ніж писати гейт, спитай, як має виглядати перемога — і якщо це порожня множина, доводь живість детектором, а не популяцією; якщо ні, дай гейту приклад, який скаже тобі, коли він доробив.** ⊕ Наслідок для наступності: щойно заборона зазеленіла, гейт над властивістю став другим домом однієї осі — його знімають, а не лишають «про всяк випадок».

62. 🔴 **Пиши гейт ПЕРШИМ і прожени його ЧЕРВОНИМ по всьому периметру — тоді перехід у зелене доводить РОБОТА, а не твоя правка гейта** (UI.7, 2026-08-15). Звичний порядок зворотний: спершу міграція, тоді сторож «щоб не поверталось», — і в ньому неможливо відрізнити «гейт ловить клас» від «гейт написано під уже прибраний стан». Тут гейт стартував червоним зі списком **11 сайтів із точними рядками**, той список і став планом роботи, а зелений колір наприкінці був вимірюванням, не твердженням. **Три побічні вигоди, кожна виміряна:** (1) повідомлення про помилку довелось написати ДО того, як я знав розв'язок кожного сайту, тож воно вийшло про ЛІК, а не про порушення; (2) червоний список дав ЧЕСНИЙ периметр — трекерне число «15 сайтів в 11 файлах» було стале, реально 11 у 8; (3) жодної спокуси послабити умову, бо кожне послаблення одразу читалося б як шахрайство із власним планом. **Reflex: якщо збираєшся робити кампанію, першим комітом роби її вимірювач — і не май права його редагувати, доки не закінчиш.**

63. 🔴 **«Прибрано/гейтовано на користь X» вимагає доказу, що X ПРАЦЮЄ — виміряного живим трактом, а не запланованого; найдорожча форма — зняти РОБОЧИЙ механізм тим самим комітом, на слово про наступника** (UI.2 + два ADR того ж шару, 2026-07-27…08-15; сам шар зрізано 2026-08-15 — урок пережив носія). Куплено ТРИЧІ на одному шарі, і кожен раз інакше. **(а)** Optimistic-UI прибрали «на користь Turbo Stream broadcast» — насправді воркер слав сирий `ActionCable.server.broadcast` (не Turbo) у топік, якого ніхто не слухав, і навіть імʼя каналу було не те: наступника НЕ ІСНУВАЛО, а робочий фолбек видалили в тому ж коміті на силі обіцянки. **(б)** ADR два з половиною місяці ніс гейт присутності у ВЛАСНОМУ ЗАГОЛОВКУ («шле лише онлайн-спостерігачам → O(active_users)») — а `git log -S` на обох писачах Redis-сета порожній за всю історію репо: гейт не «прибрали», його **ніколи не дротували**, і описаний у самому сервісі «Stimulus heartbeat» не мав ні контролера, ні маршруту. **(в)** Компонент, знятий «як дубль готового наступника», сам виявився не готовим попри заяву сусіда. **Три рефлекси.** (1) Видаляючи A «бо є X», **відкрий X і доведи його ЖИВИМ** — продюсер + споживач + маршрут + скоуп, а не імʼя в докстрінгу; слово «заплановано» в обґрунтуванні зносу = стоп-токен. (2) Git-негатив («викликачів не було ніколи») доказовий **лише в парі з позитивним контролем** на сусідньому символі — інакше він міряє твій grep, а не історію. (3) Дзеркальний борг: щойно X доведено мертвим, канон мусить перестати описувати його теперішнім часом **у тому ж коміті** — виправлення прози не чекає на присуд про долю механізму.

64. 🪦 **Зрізавши щось, НЕ пояснюй його відсутність — переказ власного зрізу сам є дрейфовою поверхнею, і він народжується десятками за одну кампанію** (Codex-зріз 2026-08-15; клас ратифіковано ще на У-ВЕЙ 2026-08-09, спрацював УТРЕТЄ). Прибираючи підсистему, ти сотні разів проходиш повз речення, яке щойно стало напівправдою — і рефлекс дописати «(пішов зі зрізом шару X, ДАТА)» здається чесністю. Виміряно: за одну кампанію я лишив **25** таких нот у каноні, скілах і коді; founder зрізав їх усі, як зрізав мої ж надгробки двічі до того. **Підстава не стилістична: канон каже, що Є, а історію тримає git** — надгробок нічого не тримає, але кожна наступна правка мусить лишати його правдивим, тобто він додає поверхню обслуговування рівно там, де ти щойно її зменшував. 🔴 **Розрізняй ТРИ речі, бо зовні вони однакові.** (1) *Наратив про зняття з датою* → геть завжди. (2) *Факт відсутності, що МІНЯЄ ДІЮ* («спільного хелпера для цього НЕМА — заводь, коли зʼявиться друга така поверхня») → лишається, бо без нього читач піде шукати неіснуючий символ; але без дати й без переказу того, хто його вбив. (3) *Урок, чий інстанс помер* → лишається завжди, інстанс де-іменовується («засновковий сайт», «одна таблиця кулдауну»), а не викидається разом із прикладом. **Reflex: закриваючи кампанію, грепни власний діф на дату цієї сесії поруч зі словом зрізаної підсистеми — це і буде перелік твоїх надгробків.** ⚠️ Два свідомі винятки, інакше правило зʼїдає потрібне: **сам трекер-пункт**, що описує зріз (він його предмет), і **`✅ ЗАКРИТО`-записи** — запис про виконану роботу не є переказом реструктуризації. ⊕ Сиблінг однією поверхою нижче, з ВЛАСНОЮ механікою: цитата на видалений ШЛЯХ у прозі `.claude/**` мусить нести `†` на закривному бектику — там надгробок навпаки ОБОВʼЯЗКОВИЙ, бо інакше `DEADPATH` тримає найгучніший стенс вічно червоним (механіка → `00_06 §3`).

65. 🔴 **A mutation that PASSES is ambiguous, and the reflex reading is the wrong one: before concluding "the pin doesn't discriminate", check that the thing you mutated is even IN the set the pin judges** (UI.3, 2026-08-16). Wiring per-field `aria-invalid` across three forms, I proved the derivational pin by deleting the `**aria` splat from one `field_container` — and the suite stayed green. The honest-looking conclusion was that the pin was weak. It was not: the field I picked (`:labor_hours`) is **valid in that fixture**, so `field_error_attrs` returns `{}` there and removing the splat changes nothing in the rendered markup. One question to the model (`MaintenanceRecord.new.tap(&:valid?).errors.attribute_names`) named the four attributes that actually carry errors; re-running the same mutation on one of THOSE went red by name (`[:action_type]`). **Reflex: a mutation target must be measured, not guessed — ask the source of truth which members are in the failing state before you edit anything, because a no-op mutation and a blind gate are indistinguishable from the green bar.** ⚠️ The asymmetry is what makes this expensive: a false RED gets investigated immediately (something broke), while a false GREEN gets *written down* as a property of the gate — so this error class ships, and it ships inside the very paragraph that claims the gate was verified.

66. 🔴 **A runtime probe can be structurally incapable of seeing the class it was built for — and its zero reads exactly like a clean tree** (UI.3, 2026-08-16). `Clusters::Show#initialize` issued a DB query five lines below its own comment forbidding one. Two probes, both plausible, both blind: **(a)** a static scan of `initialize` bodies for AR chains (`.where` · `.order` · `.first`) returns **zero** across `app/views`, because the query hides behind a DOMAIN method (`Cluster#active_contract`) and calling a domain method is syntactically indistinguishable from reading an attribute; **(b)** a runtime subscription to `sql.active_record` wrapped around `component_class.new` in the shared spec helper ran across all 1639 component examples and also returned **zero** — not because the tree is clean, but because component fixtures are **unpersisted**, and `Cluster.new.active_contract` issues 0 queries against 1 on a saved record (measured both ways). **Reflex: before reporting a probe's zero, re-introduce the KNOWN defect and confirm the probe names it — and when it doesn't, the useful output is not "clean" but "this instrument cannot see this class on this tier".** ⚠️ The tier itself is the tell: a lazy-association defect is observable only where the subject came from the database, so unit-tier fixtures suppress exactly the signal the probe exists to catch. ⊕ Sibling of #65 (a mutation that passes because the target was outside the judged set) — same asymmetry: the false green gets written down as a property of the tree.

67. 🔴 **A gate that pins two of OUR OWN homes to each other proves AGREEMENT, never correctness — and it is structurally blind to both sides being wrong the same way** (UI.3, 2026-08-17). `design_token_existence_spec` held set-equality between `ApplicationComponent::CUSTOM_TEXT_SCALE` and the `--font-size-*` keys in `@theme`, mutation-verified in both directions, green for seven months. Both sides named the same thing, and the thing did not exist: Tailwind v4 takes font sizes from `--text-*`, so every declaration under the beta-era `--font-size-*` prefix emitted a plain custom property and generated **no utility, silently**. 448 uses of `text-micro|mini|tiny|compact` inherited root 16px instead of 8–11px. The mirror could not see it because a mirror has no third point: consistency between two artifacts you control is a property of your discipline, not of the world. 🔴 **Reflex: for any cross-artifact gate, name the EXTERNAL anchor — the framework's own output, the server's API, the wire — and if the answer is "there isn't one", that is the finding.** Here the anchor was the built CSS: Tailwind emits an `@theme` variable to `:root` only when something was generated from it, so `--text-<name>:` present in the build *is* «the utility exists». ⚠️ Judge only what is USED: a design scale may legitimately offer more positions than the tree consumes, and `display-md`/`display-lg` at zero uses are correctly absent — conflating «unusable» with «unused» turns one gate into two (#46a).

68. 🔴 **A declared ceiling can encode an UNVERIFIED PREMISE about the environment — and because a ceiling reads as rigor, nobody ever re-measures it** (UI.3, 2026-08-17). Two gate headers and the tracker all carried the same sentence: «the build lives in `.gitignore`, so CI may not have it at all — a gate anchored there would be green on an empty set, exactly the class it exists to catch». The reasoning is sound, the danger is real, and the premise is false: both spec jobs enter through `./.github/actions/setup-rails-test`, whose «Build Tailwind CSS» step runs `bin/rails tailwindcss:build`. The build is always present when those examples run. This is worse than a missing ceiling, because a wrong ceiling is *load-bearing*: it did not merely fail to warn, it **argued the only external anchor away**, and #67 above is the seven-month bill. ⚠️ The empty-set risk it named was genuine — the correct answer was a population lantern (file exists ⊕ carries a core utility), not refusal of the anchor. **Reflex: a ceiling that says «we cannot do X because the environment lacks Y» is a claim about the environment — go read the workflow, not the ceiling. Ceilings age exactly like the absence-justifications in #-note «X is impossible», and for the same reason: they are read as reference, never as claim.**
🔴 **Second shape, and it needs a DIFFERENT reflex, because here the ceiling is TRUE about its own subject and false only as the RULE it states** (ARCH.84, 2026-08-17). Canon `04_01` carried, under the `Tree` card: «coverage is needed only where trees SUM — the single such consumer is the emission forecast». About that card's own column (`latest_stress_index`, per-tree) the sentence is correct. But what a reader carries away is the **generalisation**, and the generalisation excluded the biggest AVERAGE in the system — the cluster-level daily insight, whose consumers are the commercial `backing_asset.cluster_health`, a real Celo payout and the immutable IPFS evidence. An average depends on coverage no less than a sum, and it argues its case *better*, because it reads as a property of the whole. ⚠️ Two things make this shape survive longer than #68's first: (a) the ceiling sits in **canon prose next to a neighbouring card**, not in a gate header, so nobody hunting «why is there no gate here» ever reaches it; (b) it is unfalsifiable from the inside — you can only disprove it by measuring the very site it excludes. **Reflex: when a ceiling states a RULE («X is needed only when Y»), do not check whether it is true of the card it stands on — enumerate the OTHER members of the class it just excluded, and measure one.**

69. 🔴 **A locally-generated artifact can SHADOW the file under test, so the lane grades a snapshot instead of the tree — and unlike the loud form, this one is green** (UI.3, 2026-08-17). A leftover `public/assets/.manifest.json` flips Propshaft to its Static resolver; the canon already documented the *loud* symptom (every browser example fails at login, misreading as broken auth) and prescribed `assets:precompile` as the fix. The silent symptom was absent and cost more: examples **pass** while the browser is served a three-day-old digest of the CSS, so a fix verified by grepping the fresh build never reaches the page, and the instrument reddens on already-correct code. ⚠️ The prescribed remedy is also the wrong one for this half — refreshing the manifest keeps the local lane on a resolver CI does not use, and goes stale again at the next CSS edit; removing the directory is what matches CI. **Reflex: when a measurement disagrees with a change you just made, ask which ARTIFACT the harness actually loaded before you doubt the change** — and note that a gitignored shadow is invisible to every CI gate by construction, so this class can only ever be caught locally.

70. 🔴 **A class closed by MIGRATION is closed for the FILES someone edited, never for the SURFACE — the CARRIER's perimeter is a separate measurement from the FIX's** (three domains in one night, 2026-08-18). A migration touches the files it touches; the pin stays where it was written, and the tracker records the class as done. Measured: the label⟷control carrier stood on **3 form specs out of 10**, so breaking `for=` on the largest form in the tree left the suite GREEN · the "a sweeper must give the zero a voice" fix had reached **1 worker of 3** · wiring an enum label covered two display screens while the third site — the INPUT surface — kept rendering the raw token. **Cheap measurement: mutate a RANDOM member of the class, never the member you just fixed** — green there is the report about the carrier's reach. ⚠️ The quietest form is a record saying «mutation-verified», where the mutation was a ONE-OFF during the migration rather than a standing example: both read identically afterwards, and only the second survives the next edit. ⊕ Sibling of #57 (a declaration-gate makes the whole class look covered while the OLDEST member is untested) — there the untested member predates the gate, here it is simply outside the files the migration walked; and of #35, whose half-fix frame this sharpens with the instrument.

71. 🔴 **A registry entry can name a SUBJECT THAT DOES NOT EXIST — and every field-shaped check passes, because they interrogate the entry, never the tree** (UI.3, 2026-08-18). Building the contrast-contour registry I declared a decoration exemption keyed on `[data-contrast-decoration]`; the tree contains **zero** nodes with that attribute — the real watermarks are identified by a colour class. The entry had a substantive `why`, a live `back`, correct shape, and it exempted **nothing**: an aspirational declaration is strictly worse than a missing one, because it reads as coverage. Note the sibling it is NOT: #53 is about an exemption whose REASON has expired — semantic, and only a reader can judge it. This one is about the exemption's SUBJECT, and it is **mechanically checkable**, which is exactly why leaving it to the reader is a choice rather than a limit. **Reflex: for every registry keyed on a selector, a class token, a path, a constant or an ID, add the axis «does this subject resolve in the tree» — one grep per entry — and if the registry cannot check it, say so in its ceiling instead of implying it does.** ⊕ The generalisation that makes it worth a number: a registry is TWO claims stacked — *this thing exists* and *it is exempt for reason X* — and the gate almost always inherits only the second, because the second is the one the author was thinking about.
