### Mutation-verify: the pitfalls

- `git checkout` also reverts an UNCOMMITTED fix → mutate with a `cp`-backup (`cp f "$T/f.bak"` → mutate → run → `cp` back) or a reverse `Edit`, never a checkout. ⚠️ **Це більше не порада: з 2026-08-28 хук `bash_verify_guard.sh` (блок D) ЗАБОРОНЯЄ `git checkout` по файлу з незакоміченими рядками** — п'ять рецидивів довели, що попередження для незворотної дії носієм не є (воно приходить разом із результатом уже виконаної команди). Заборона не вбиває легітимний відкат, вона вимагає ОГОЛОШЕНОГО наміру: додай токен `discard-dirty` у команду (коментаря досить) або візьми `cp` того самого шляху в ТІЙ САМІЙ команді.
- **A money-path constant is its own hazard**: editing `GAMMA` tripped the permission classifier, and rightly — an interrupted session would have left the tree broken. Make the pin engine a **pure function** and mutate **in memory**.
- A mutation that fails to apply, or breaks syntax, proves **nothing** — check that it landed (and that the file still parses) before reading the result.
- 🔴 **A mutation can land, parse, mean exactly what you wrote — and still prove nothing, because it hits a line the ASSERTION does not read** (DOC-T.59, 2026-08-04). Verifying a new self-test battery, three of four mutations came back "not caught", which reads as four holes. Only one was: two had edited a *neighbouring* sentence of the same message while the case grepped a different phrase, and the third prefixed the target string (`XX-OVERRIDE`) where the case greps a SUBSTRING, so the match survived the break. The tell is cheap and was skipped: after mutating, grep the mutant for **the exact token the assertion looks for** — not for your edit. **Reflex: a mutation is aimed at an ASSERTION, not at a file; state which line goes red before running it, and prefer deleting the asserted token over decorating it.** Sibling of the "it landed" bullet below — there the edit missed the file, here it missed the assertion, and both return the same comfortable green.
- 🔴 **Asserting an absence plus asserting the wrong branch does NOT cover a fork — the healthy branch needs its own pin** (DOC-T.59, 2026-08-04). A gate learned to tell "compression" from "eviction" by a derived reach count. Two cases guarded it: one rejected the wrong advice, one expected the eviction message. Breaking the discriminator to a constant `0` left **both green** — the reject passes because the wrong advice is now never emitted, the expect passes because the wrong branch now fires always — while the gate had become a permanent false accusation. **Reflex: for any discriminator, pin BOTH outcomes positively; a negative assertion pairs with the branch it denies, never with the branch it protects.**
- 🔴 **A gate with two stances needs the battery run against BOTH — testing only the audit stance leaves the moment of action unguarded** (DOC-T.59, 2026-08-04). Fifteen cases and three mutation runs all invoked `--audit`; the PostToolUse path — the one this gate exists as, and the only one that fires while a wall is being built — had zero coverage, so removing a check from the write battery kept the suite green. This is the UNSTRUNG lesson one level up: a check living in one stance is *absent* from the other. **Reflex: enumerate the entry points, then require at least one case per entry point — the cheap one is a fixture piped through the real contract (stdin JSON), not a refactor.**
- 🔴 **A self-test fixture that reads an ENVIRONMENT default passes at home and silently disarms elsewhere — and it disarms in the direction that looks like health** (DOC-T.60, 2026-08-04). A new case built its fixture by copying the resolver from `$REPO`, whose default is a hard-coded developer path; on the CI runner that path does not exist, so the fixture came up without a resolver, the check returned 0 for lack of an engine, and **only the positive case failed while the negative stayed green** — the exact signature of "the detector switched off", not "the detector is wrong". Read that asymmetry as a diagnosis: one-sided failure across environments means the machinery is missing, not mistaken. **Reflex: a fixture must derive every path it needs from something that travels with the code — the script's own location — never from a configurable default, because the default is exactly what differs between the machine where you prove it and the machine where it runs.** Verify by re-running the OLD code with that default pointed at nothing: if it reproduces the remote failure byte for byte, the diagnosis is confirmed rather than plausible.
- 🔴 **A mutation can land, parse, AND mean something other than what you wrote — so "it landed" is not the check; "what does it evaluate to" is** (SEC.25 Ф3, 2026-07-29). To prove a stream name's epoch suffix was load-bearing I neutered it as `#{'' && epoch}` — and in Ruby the empty string is **truthy**, so the expression returned `epoch` and the name went from `..._org_5_e1` to `..._org_51`. The epoch was still in the name; only the separator died. Seven examples went red (they pin the literal), the one end-to-end example that pins the *mechanism* stayed green, and the obvious reading — "that pin is vacuous" — was exactly backwards: the pin was fine, the mutation was. Note why the usual safeguards all passed: the file changed, `ruby -c` was OK, and the suite went red. **Reflex: for any mutation more clever than deleting a term, print or reason out the mutated VALUE once** (`..._org_51` would have shown it instantly), and prefer the dumbest possible mutation — drop the term entirely rather than short-circuit it. Sibling of the fixture-collision bullet below: there the mutation was semantically right and the data made it a no-op; here the data was fine and the mutation was wrong.
- 🔴 **A mutation can be semantically RIGHT and still prove the opposite, because the object under it is memoized — and the failure direction is FALSE-POSITIVE, i.e. "the lever works"** (SEC.25, 2026-07-30). To show that rotating `Turbo.signed_stream_verifier_key` invalidates every issued stream name, I reassigned the key in-process and re-verified a name: it still verified, which reads as "rotation does nothing". Cause: `Turbo.signed_stream_verifier` is `@signed_stream_verifier ||=`, so the verifier was built once and the new key never reached it. The honest measurement is **two separate processes**, and it returned `nil` as designed. Note which way this cuts — had I been *confirming* rather than *doubting*, the same experiment would have "proved" the lever fine while it was inert. **Reflex: for anything read through a memo, a cache, a connection pool, a class-level `||=`, or a config frozen at boot, mutate by starting a NEW process — never by assignment.** Sibling of the bullet above: there the mutation was wrong and the data fine; here the mutation was fine and the *object* stale.
- 🔴 **A mutation that LANDS can still be a no-op, because the fixtures make the wrong value equal the right one** (SEC.25, 2026-07-27). To prove a request-spec really pinned *whose* organization, I swapped `current_user.organization` → `Organization.first` — and the suite stayed green. Not because the pin was weak in shape, but because the spec's own `let` ordering created the user's org **first**, so the two expressions were literally the same record. A single-subject spec cannot distinguish "the right one" from "the first one", "the only one", or "the last created one"; the fix is a **second subject that must get a different answer** (two users in two orgs), after which the same mutation goes red. **Reflex: when the thing under test is a SELECTION, the mutation must be to a plausible WRONG selection — and the fixture has to make wrong ≠ right.** Corollary: a mutation surviving is a claim about the spec, so investigate it; treating green-under-mutation as "close enough" is how a pin that pins nothing gets committed with a comment saying it pins something.
- 🔴 **The mirror of "a spec that cannot fail": a pin constructed so it can never PASS — and it looks like a real regression** (SEC.25, 2026-07-31). A fresh cross-tenant pin asserted `not_to include(foreign_wallet.crypto_public_address.to_s)`. That record's address is `nil`, `nil.to_s` is `""`, and `include("")` is true for every string — so the example failed on a correctly-behaving app, and the obvious reading ("the fix is missing") was exactly backwards. Note the shape: the emptiness came from the *fixture path*, not the assertion — the wallet is built by a `Tree` callback rather than the factory, so the attribute the pin keyed on was never populated. **Reflex: any negative assertion on a value read off a record must first prove that value is non-blank** — `expect(x).to be_present` before `not_to include(x)` — and when a brand-new pin goes red, suspect the pin before the code, because a pin has never been mutation-verified yet while the code usually has.
- 🔴 **Planting the guard's state BY HAND verifies the branch and says nothing about the TRIGGER — and it is exactly wrong when the guard's state lives in a resource the subject clears itself** (TEST.8, 2026-08-03). A concurrency guard stamped an owner key into Redis at `before(:suite)`; both branches mutation-verified green (live pid → block, dead pid → silence) and three homes recorded "mutation-proved". But the suite's own `flushdb` runs on that same DB **before every example**, so the key never survived the first one: the detection window was not "the whole run" but a sub-second overlap of two starts. The mechanism (`raise`) was flawless; the trigger was dead — and no hand-planted mutation can see that, because planting the state *is* the thing that never happens on its own. One probe during a real run returned `nil` and killed the claim in a second. **Reflex: when a guard persists state anywhere the tested process also writes, verify with a LIVE competitor, never with planted state — and ask separately "who else writes to this store between the stamp and the read?"** Generalises past test harnesses: any watchdog whose heartbeat lives in a cache the watched process flushes, any lock in a table the job truncates, any marker file under a directory the build cleans.
- 🔴 **The oracle names a value the implementation can never emit — so ONE pin is vacuous in BOTH directions at once, permanently red on one side and permanently green-on-empty on the other** (UI.1, 2026-08-07). Proving a `dark:`-variant fix, I asserted `getComputedStyle(el).boxShadow == "none"`. In Tailwind v4 `shadow-none` does not set `box-shadow: none` — it sets `--tw-shadow: 0 0 #0000` and leaves `box-shadow` a five-`var()` composite, so the computed string is *always* a long list of `rgba(0,0,0,0) …`. Hence `to eq("none")` could not pass and `not_to eq("none")` could not fail: the symmetric pair looked like thorough coverage while one half was noise and the other a false green — and the false green is the one that ran first and "passed". Note what did NOT catch it: the failing half looked like an honest red for the real defect, which is precisely the cover story. **Reflex: before writing an equality oracle, print the value once from the running system — an oracle is a claim about the implementation's OUTPUT vocabulary, and a plausible literal (`"none"`, `"0px"`, `"transparent"`, `""`) is where that claim is usually wrong.** Sibling of #12: there the expectation re-ran the logic under test; here it names a value outside the logic's range entirely.
- 🔴 **When an example manipulates the environment out-of-band, it must assert the manipulation TOOK EFFECT — otherwise it measures a consequence while never proving its own precondition** (UI.1, 2026-08-07). A browser example emulated the OS colour scheme via CDP (`Emulation.setEmulatedMedia`) and then asserted what the CSS did about it. Had the CDP call silently no-op'd — wrong param shape, a page object recreated by navigation, a driver upgrade — the example would have been green on an empty set, i.e. attesting exactly the class it existed to catch. One line fixed it: assert `window.matchMedia('(prefers-color-scheme: dark)').matches` equals what was emulated, *before* reading the consequence. **Reflex: every out-of-band precondition — CDP/`Emulation.*`, an ENV var, a feature flag, a frozen clock, a stubbed geolocation, a seeded cache — needs its own positive assertion inside the example. "I set it up in `before`" is a claim about the setup code, not about the running system.** This is the mutation-verify analogue of the population-lantern (#28): a lantern on the *environment* rather than on the subject set.
- 🔴 **Коли перевіряєш МІСЦЕ виклику, мутація мусить ПЕРЕМІЩАТИ, а не ДОДАВАТИ — інакше вона міряє ідемпотентність і червонить ШИРШЕ, ніж має** (ARCH.59, 2026-08-16). Щоб довести, що enqueue стоїть після коміту, я вставив другий виклик усередину транзакції, лишивши оригінал зовні — і дістав **4 падіння замість 1**, бо три з них були про ПОДВІЙНИЙ enqueue, а не про його розташування. ⚠️ Помилка тішить: ширший червоний читається як «клас добре застережений», тож перевіряти його не хочеться. Чиста форма — ПЕРЕНЕСТИ рядок; вона дала RED рівно×1 поіменно. **Рефлекс: назви властивість, яку міряє мутація — наявність, КІЛЬКІСТЬ чи МІСЦЕ. Для місця легальна рівно одна операція, і це переміщення; додавання копії перевіряє ідемпотентність, тобто зовсім інше твердження.**
- **Verify by EXIT CODE after every batch**, never by `| tail` (a cut-off FAILED header reads green).

### Triaging a phantom tracker-ID — most are NOT ex-items

`code_tracker_id_check` flags an ID cited in code/docs with no `00_07` home, and its own hint («give the ID a §🗄️ row if it deserves one») reads like an instruction to add rows. **Measured 2026-08-06 on six phantoms: exactly ONE deserved a row.** Dig each one's fate with `git log -G'<ID>\b'` on the tracker before writing anything — and note that a bare `git log -S` is a literal *substring* search, so a two-digit family member also matches every three-digit sibling; the word boundary is not optional. 🔴 **Write the surviving phantoms into this file and you red the gate — it scans `.claude/**` and cannot tell an illustrative citation from a live one.** (Learned twice in one hour: the paragraph documenting that trap was itself written with the tokens in it.) Hence the five shapes below carry **no ID literals** — the shapes are the lesson, and the concrete instances live in the memory files and in git:

- **A regex artifact, never an ID.** One came from prose naming a subsystem after the item number with a hyphen; the extractor stopped at the first lowercase letter and invented an ID out of the word's first initial. Adding a row would canonise the gate's own parsing bug.
- **A phantom the commit REMOVED.** Another is cited only in a CHANGELOG line that describes deleting a phantom reference — the release note *is* the record of its death.
- **A row that already existed and was deliberately deleted.** One HAD an archive row; a dedup commit removed it because the content merged into a sibling that is itself archived. Re-adding undoes a deliberate merge — so check `git log -G` for a *removed* `| ID |` line before concluding it never had a home.
- **Retracted content.** One was cut together with a claim the founder ordered removed everywhere. A tombstone row re-creates a hook back to the retraction; leave that record in memory, where a strikethrough plus its deletion date is self-limiting.
- **A corrected mis-attribution.** One was never an item at all — a reference assigned to the wrong number and later corrected to a live sibling.

The one that DID qualify (`E.51`) had the full shape: a real item, a real successor, and a citation in a file we cannot edit (release-please-generated `CHANGELOG.md`). Its row records **both** of its lives — the ID carried two unrelated tracks in sequence, so a single «renamed → X» would have been half the truth. Precedent form is already in the table (`E.5` merged into `ARCH.2`). ⚠️ And the advisory list is not a to-do: the gate marks CHANGELOG advisory-only *because* it is generated, so a permanently non-empty advisory tail is the designed state, not debt.

1. **Decorative — the gate's INPUT sits outside the workflow's `changes:` filter, so it only ever fires on somebody else's PR** — its INPUT sits outside the workflow's `changes:` filter, so it only ever fires on somebody else's PR (the `bio_contract.rb` hole; `.claude/**` repeated it later on a different gate). **Reflex: input ⊆ trigger-filter?** `guard_registry_sync` CHECK D now enforces this for pinned sources and mirror trees — but it is scoped to those, not to every guard tree.

🔴 **Measured again 2026-08-19, on a gate written the same day by someone who had just read this item — so record what did NOT protect: knowing the rule.** A new Rails spec (`font_delivery_spec`) guards «the font family we name first must actually ship»; its inputs are `app/assets/**` *and* the vendored `vendor/assets/fonts/**`. The `test` job runs on the `ruby` filter, and `vendor/assets/**` belongs to `js` — so deleting a woff2 skips the job the gate lives in, i.e. the gate was blind on **exactly its own class** («declaration stands, file gone»). Note the two things that make this survive: the gate is green locally (the filter is a CI concept, invisible to `bin/rspec`), and its subject genuinely lives in TWO trees, so the half that is inside the filter makes the perimeter look right. ⚠️ **And no meta-guard covers it:** `workflow_gate_perimeter` classifies WORKFLOWS into required/advisory buckets and never asks whether a gate's input triggers its own job — read its header before assuming otherwise. **Reflex, sharpened: when a gate reads from more than one TREE, list the trees and check each against the job's filter separately — a gate whose subject spans trees is the shape where a partial match reads as coverage.** Found by the closing sweep, not by the rule.
2. **A whole GENRE outside every linter's namespace — «Стаття N» headings; a genre exempt BY DESIGN is where drift is densest, so a green `docs_check` ≠ correctness there** — "Стаття N" headings; `08_03` carried `§1.1–§1.5` pointing at subsections that never existed, green for years. A genre exempt **by design** (`manifest.md`) is where drift is densest. Measured blind to named-article (H3) headings: `Tracker::Dashboard` · `code_tracker_id_check` · `DocsToc` — so a green `docs_check` ≠ correctness there, and a manual re-grep is mandatory. ⚠️ Note the mirror, because it bounds the claim: `§`-refs those same gates DO validate (mutation-proved — `§99`/`§4` → HARD), so the blindness is **genre**-shaped, not reference-shaped.
3. **A noisy advisory is functionally OFF — and a semantic gate that does not name its CEILING in the script header turns green into «not checked»** — functionally off. Fix by narrowing the scope to one unit of work and grouping output (one line per file, detail behind `--verbose`), and by **naming the ceiling in the script header**: a semantic gate must declare what it cannot see, or green reads as "not checked". ⊕ **The mirror case, and it is the one that outlives its reason: an `advisory` label that has become STALE CAUTION at zero noise** (moved here from the `00_06 §3` `magic-marker` row, 2026-08-10 — its only home). That guard is a deterministic byte-packing check, FP-free *by construction* (it needs a quoted four-letter name adjacent to an ASCII-range hex, scoped to `/magic/i`), and it had sat advisory with zero residual hits — the caution was inherited from the era before the design ruled false positives out, and nothing re-examines a label once it is written. So the audit is two-directional: a **noisy** advisory is off and must be narrowed, but a **silent** one is usually a promotion nobody proposed. **Reflex: for every advisory in the registry, ask which of the two it is — measure its live hit-count, then ask whether the design still admits the FP class the label was hedging against.**
4. **Blind to its own prose — a gate sees its DATA, never what it SAYS about itself, so its header comment can contradict its own constant indefinitely.** `workflow_gate_perimeter` read the workflows and its own Ruby constant, so its header comment could contradict that constant ("all eight" on line 6 vs "flip-pending" on line 10) and live that way until a prose-check was added. A gate sees data; it does not see what it says about itself.
5. **It under-implements the contract it declares.** Worse than #4, because the prose is *right* and the code is a subset. `stale_who` stated its contract as a UNION in three homes (rake comment, spec comment, §3 row) and implemented one direction — it caught meta OVERSTATING and was structurally blind to meta UNDERSTATING, the costlier half (the meta-line is the scan layer, so a pure-👤 meta over machine work reads as "nothing here for me"). **Reflex: read what the gate SAYS it enforces, then check each direction of that sentence separately.** A bidirectional word — *union*, *parity*, *symmetric*, *round-trip*, *1:1* — is a promise of ≥2 checks; count them. ⚠️ **And counting them is not enough — check each direction's DOMAIN too** (DOC-T.55, 2026-07-31). The tracker's WHO pair looked complete: one gate for understating, one for overstating, both shipped. But the overstate half reads literally `include?("🤖")`, so of the three executor glyphs it guards exactly one — a meta-line advertising a `⚖️` verdict nobody is waiting for passes green forever. I found it by walking into it: an item of mine carried a stale `⚖️` for a day while `tracker:check` said clean. So the question after "how many directions?" is **"over what SET does each direction range?"** — a check that covers one member of an enum reads, from its name and its green run, exactly like one that covers all of them. ✅ **CLOSED 2026-08-05 (`stale_who`), and closing it bought three things the diagnosis had not predicted.** (a) The enum was only HALF the hole: the same guard exited on `open.empty?`, so the EMPTY SET satisfied it trivially — a finished item kept a full WHO axis over nothing at all. Two blindnesses in one predicate, and the item's own title named only the first. (b) **The remedy the tracker prescribed was UNBUILDABLE as written** — it said such an item "must carry an EMPTY WHO axis", but `WHO_CANON` in the sibling guard has no empty member, so a gate written from that sentence would have ordered a state its neighbour HARD-rejects. This is the inverted root one paragraph down, aimed at a tracker item instead of canon prose: **construct the prescribed end-state and check that the rest of the system accepts it, before implementing the sentence.** The buildable form came from the legend instead — `🌿`/`⚫` mean the WHO names a FUTURE executor, every other STAGE means the union is genuinely empty. (c) The guard's own spec carried an example named *"stays silent on an item with no open residuals at all"* — i.e. #12's shape, a pin asserting the defect AS the intent, sitting inside the very gate whose contract it contradicted. ⚠️ And the honest ceiling got materially WORSE with the widening, which is worth stating because nobody re-measures an exemption after changing its scope: the item-wide exemptions (`🔗`-led / glyph-less residual) now silence **27 of 29** literal hits, since an undetermined executor backs ANY glyph and therefore cannot be narrowed per-glyph. Measure what an exemption costs AFTER you widen what it guards, not before. ⊕ **And never quote the YIELD of a half-built gate — it is understated, and the understatement is invisible in the number itself** (moved here from the `00_06 §3` row, 2026-08-10, which was its only home). The corpus figure for the understate axis was measured with the SHIPPED guard against a pre-fix tracker; the first, broken version had reported fewer, because its own two bugs silenced part of its own catch. A catch-count is evidence about the GATE that produced it before it is evidence about the corpus, so a figure quoted from a run predating the fix describes neither. **Reflex: tie every catch-count to the gate VERSION that produced it, and re-measure after any change to the gate itself — otherwise a number about your instrument travels as a number about the world.** 🔴 **Inverted root, and the more expensive one: the CANON PROSE is the under-implementation, and a gate transcribed from it faithfully inherits the hole** (the PR auto-labeler gate, 2026-07-29 — **both the gate and its canon section were removed 2026-08-09 with the Projects/Shape-Up layer, so this example lives only in git; the lesson does not**). The canon prose had carried the mitigation as "an `all:` wrapper is mandatory wherever negative globs appear" — true, load-bearing, and strictly weaker than the invariant: it blesses a negative sharing one `changed-files` with a positive (OR *inside* the AND-wrapper) and an `all:` holding the negative block alone, both of which stick the label to every PR. The gate that finally held was written from a *derived* rule (expand to a disjunction of conjunctions; every branch carrying a negative must carry a positive), not from the sentence. **Reflex: when translating a prose rule into a gate, first construct counter-examples AGAINST THE PROSE — if one passes the sentence and still exhibits the disease, the canon is the defect and must be tightened in the same commit.** A remediated bug whose fix is recorded as a *form* ("wrap it in `all:`") rather than a *property* is where this hides. 🔴 **THIRD AXIS, and it is neither a direction nor an enum domain: the contract's noun is a CLASS and the implementation ENUMERATES ITS MEMBERS** (`gaia:lint_tokens`, 2026-08-19). The message reads "no raw Tailwind **colour utilities** detected" — a claim over an open-ended category — while the regex listed five neutral families out of twenty-two, four carriers out of fifteen, `white` under `text-` but not `black`, emerald cut to `400…900`, and hex-or-`rgb(` but not the 148 named CSS colours. No bidirectional word to count, no enum to range over: just a category named in prose and a subset shipped in code, where **every member added later reads as a widening rather than as a repair**, which is why it survived two prior widenings that each closed one member and left the class open. **Tell, and it is cheap: look for a MEMBER ADJACENT TO A COVERED ONE.** Here `shadow-[0_0_8px_red]` sat one line below `shadow-[0_0_5px_#10b981]` in the same `case`, same carrier, same role — one red, one silent, discriminated purely by NOTATION. An adjacency like that is not a missing rule; it is the class boundary made visible, and it says the enumeration is the defect. ⚠️ **Two traps in the repair.** (a) The arithmetic is not the verdict — "666 seen vs 268 missed" prices the hole and proves nothing about whether the HARD perimeter is at risk; only injecting six missed families into that perimeter and watching `✓ EXIT=0` does. (b) **The cost of widening was written into the tracker as a PREREQUISITE and had been dead for months**: "every regex widening needs its own migrate wave, else CI reds instantly" was true while the default scope was the dirty tree and false the day the scope flipped to the clean one — the item conflated **perimeter** (adds FILES, costs a migration) with **dialect** (same files, costs whatever the new form hits inside the current scope, here zero). **Reflex when a gate widening looks expensive: ask what SET OF FILES it adds; if none, it is a dialect and it is free.** Sibling on the doc side: the `00_06 §3` row for this gate correctly routed to the script header as the one home for the dialect list — and restated the list beside the router anyway, which is the copy that rotted (it still declared the gate blind to gradients four days after they were closed). The enumeration belongs in exactly one place and the registry's job is to point at it.

🔴 **Sharpest variant: the gate's own DATA contradicts its declared taxonomy, and nothing compares the two** (SEC.25 scope gate, found 2026-07-28 — one day after shipping it). 6. **It compares a HOMOGENEOUS pair and is blind to the seam between LAYERS** (I18N.1, 2026-07-26). Corollary for such a spec: check the **base** locale only — cost then does not grow with the catalogue, and a newly-added, still-untranslated locale does not turn it red.

7. **A config mask switches the gate OFF, and the comment above it justifies a DIFFERENT problem** (I18N.1, 2026-07-26). `ignore_inconsistent_interpolations: ['*']` meant the CI step `i18n-tasks check-consistent-interpolations` could never fail — a green line in every build, checking nothing. (b) Read the justification against the setting, not against the code: a plausible sentence is not evidence that it describes THIS knob. A `'*'`-shaped exemption is never a tuning — it is a disabled gate wearing a config's clothes.

8. **It checks EXISTENCE where the real defect is SCOPE** (UI.4, 2026-07-27). A gate that pairs producers with subscribers answers "is anyone listening?" — and reads as covering the whole surface. 9. **A guard's own extraction regex silently under-collects, and the guard's ceiling section says nothing about it** (I18N.2, measured 2026-07-27). `broadcast_payload_invariance_spec` anchors on a multi-line call shape, so a single-line `broadcast_*_to(...)` does not exist for it — verified: 1 of 2 calls seen in one file. Harmless for *that* gate (the missed call carries no payload), which is exactly why it survived: **an extraction bug shows no symptom while the missed items happen to be innocent.** The bill arrives when the same machinery is reused for a gate where completeness is the point. Reflex: before reusing an extractor, measure it against a hand count on one real file; and prefer AST (`Ripper`) over regex the moment a second consumer appears. 
🔴 **Sharpest form, and the tell is counter-intuitive: the DATA is polymorphic, so every successive fix to the extractor returns a DIFFERENT confident number — and none of them is "now it's right"** (UI.12, 2026-08-07). One hand-maintained registry wrote its subject in **three** row forms (a detailed code-span, a compressed one-row-per-namespace with the leaves in the *second* cell, and a **bold** variant in a neighbouring section). Reading form A alone said "35 undocumented"; teaching it form B said 5; form C moved a third surface again. Ask "how many ways can this artifact spell one entry?" and pin one example of each in the spec, because a parser blind to a form is silent, and silence reads exactly like health.** ⚠️ And the second half is a decision, not a parser fix: if the same subject is enumerated in TWO places (here a table and an ASCII tree), gating both doubles the rot surface — collapse the weaker one to a ROUTER and gate it at a granularity it can actually hold (#31).

🔴 **And when you do write that AST extractor, expect the blindness to live in IT rather than in the gate's logic — three separate holes surfaced in one, each only after the gate was already green** (SEC.25 scope gate, 2026-07-28). (a) A node kind that *looks* like a record is not one: `var_ref` covers both `@wallet` and a local holding a string, so the classifier marked an interpolated local as a record — i.e. it **over-stated** the site's safety, the worst direction for anything that dispatches obligations. Found by measuring the extractor against a hand count, not by reading it. (b) **Any name pattern is wrong in both directions**: `broadcast_\w*_to` missed the gem's non-`_to` forms (which broadcast to the record's *own* stream — a stream with no name and no registry row), while `broadcast_\w+` swept in the app's own private helpers sharing the prefix (more numerous than the gem calls themselves — and the exact tally proved unreproducible on any basis a year later, which is its own lesson about writing one down). The durable fix is to stop patterning: derive the set from the library at runtime (`Turbo::Streams::Broadcasts` ∪ `Turbo::Broadcastable`), which also survives a gem upgrade untouched. (c) **The argument-less call form is a different AST node** — `broadcast_refresh` with no parens is `:vcall`, not `:command`/`:method_add_arg` — so the walker was blind to precisely the most idiomatic spelling of the thing the gate forbade, and the mutation *landed green*. Reflex for any AST walker: enumerate the call shapes explicitly (`foo(a)` · `foo a` · `X.foo(a)` · `X.foo a` · `foo` · `X.foo`) and write a unit example per shape — the paren-less and receiver-less ones are the pair everyone forgets. **(d) A THIRD shape surfaced the next day, in the same walker, found the same way — by probing, not reading** (2026-07-28): when the *nested* call is paren-less (`f X.m a, b`), it swallows the argument list into itself, so the OUTER call's args node arrives as a **bare array of arg nodes** with no `:args_add_block` wrapper — the only shape the arg extractor recognised. Result: `:absent`, i.e. "this call has no first argument", on a call that visibly has one. Note the meta-pattern across all three: each hole was in the *shape of the surrounding syntax*, none was in the walker's logic, and every one of them was invisible to reading and instant under a probe that enumerates spellings. So the reflex is not "read the walker carefully" — it is **write the probe table first**. Corollary on coverage: when such a walker's defensive branches sit uncovered, the honest fix is usually **deletion, not tests** — collapsing five duplicated emit paths into one and dropping genuinely unreachable guards moved branch coverage 97.81% → 98.16%, because the branches were dead rather than untested.


🔴 **Sharpest instance measured 2026-08-15, and the under-collection is TOTAL rather than partial: a NESTED bracket inside a link label makes the whole link invisible to every `\[([^\]]*)\]\(` guard in the family.** The class excludes `]`, so it stops at the *inner* closer, no `](` follows, and the match never happens — a forbidden label form sat unflagged on a money-path page for months. ⚠️ The mirror bites the other way, and it is why a WIDER character class is the wrong fix: starting the capture at the FIRST `[` makes a bold prose marker that merely wraps a link donate its outer text as the label, producing a confident FALSE accusation. One shape hides a real violation, the mirror invents one, and both come from the same lazy delimiter. Sub-reflex of the enumerate-the-FORMS rule above: **parse a markdown label by walking back from `](` to the MATCHING `[`, never by a character class — and return nil on an unbalanced walk, so an odd bracket makes the link invisible rather than mis-attributed, which is the safe direction for a gate that accuses.**
10. **It announces its own failure LOUDLY — and exits 0** (I18N.1, 2026-07-27). `i18n-tasks missing` could not resolve relative keys in the mailer templates (`relative_roots` knew only `app/views/components`), printed `Cannot resolve relative key ".heading"` — and returned **success**. The surface went unscanned, the build stayed green, and the diagnosis sat in output nobody reads, precisely because the exit code says everything is fine. This is worse than the silent shapes above: those at least do not assert health. **Reflex: for any gate that can print ERROR/WARN, check whether that affects its exit code** — if not, grep its output in CI or treat the step as inert. ⚠️ **And re-measure before you inherit that verdict: this very entry cited `check-normalized` as a gate that "already must" be grepped, and by 2026-08-13 that was false** — the gem had grown `:exit1 unless non_normalized.empty?`, so the wrapper was both stale AND unreachable (`run:` is `bash -e`, so the assignment aborted the step first), while five other homes went on teaching that its exit code is worthless (I18N.4). A grep-the-output workaround is a **dated** claim about a third-party tool: it pins a sentence in someone else's English, and nothing goes red when the tool starts behaving. Give every such workaround a re-measure date, and prefer the exit code the moment it discriminates. Corollary: a gate's *coverage* can shrink without its *verdict* changing, so a green step proves nothing about what it actually looked at.

10a. 🔴 **The gate must skip its own documentation — and that necessary skip leaves the HUMAN measurement permanently poisoned** (TEST.10, 2026-08-03). 11. **The spec pins that the call HAPPENED, never where it POINTED** (UI.4, 2026-07-27). Every spec on the broadcast surface asserted `have_received(:broadcast_replace_to)` with no argument matcher — so a producer aiming at `actuator_card_{id}` while the component rendered `actuator_{id}` stayed green for months. The assertion was *true*; it simply never touched the only thing capable of being wrong. **Reflex: when a call's correctness lives in an ARGUMENT — a DOM id, a stream name, a queue, a target path — assert the argument (`hash_including(target: …)`), not the bare invocation.** Generalises past specs: where the failure mode is silent (nothing raises, nothing logs), "it ran" and "it worked" are different claims, and only the first is cheap to assert — so cheapness is exactly what makes the useless one attractive.

🔴 **And the argument pin has its OWN blind half, one level down: it attests the CALL SHAPE and says nothing about whether the value survives the callee — because every call-site spec stubs the callee** (PERF.1, 2026-08-07, found by adversarial review after the suite went green). A new kwarg was pinned at five call sites with `kind_of(Time)` / `all(be_a(Time))`, all green — while one caller passed a **bare** timestamp into a helper doing `Kernel#Array(span)`, which answers `to_a` on `Time` with a ten-element decomposition (`[sec,min,hour,mday,mon,year,wday,yday,isdst,zone]`), so `.min` raised on the `isdst` boolean. Every internal insurance payout would have failed. The pins could not see it *by construction*: `allow(Service).to receive(:call)` means the value never reaches the code that breaks on it, and the model spec that WOULD have caught it covered Array, Range, `nil` and all-nil — every shape except the one the only scalar caller uses. **Two reflexes.** (a) When you add a parameter, write ONE example that carries a real value END-TO-END (no stub on the receiver) — an argument matcher plus a stubbed callee is a claim about the caller alone. (b) Enumerate the parameter's **input shapes from the CALL SITES**, not from your own imagination of the type: here five callers passed a collection and one passed a scalar, and the scalar was the untested one precisely because it was the odd one out. ⚠️ Sibling on the API side: prefer `Array.wrap` to `Kernel#Array` for anything that may be a scalar — `Kernel#Array` calls `to_a`, and several core objects (`Time`, `Hash`, `Struct`) answer it destructively.

12. **The spec computes its expectation with the SAME broken transform as the code** (I18N.1, 2026-07-26). A mailer spec asserted the subject by calling `alert.alert_type.humanize` — exactly what the code did — so the assertion was a tautology that could never fail, and the fact that the label never went through the locale file stayed invisible. Sibling shape in the same sweep: a spec riding a *fabricated* enum value (`"Thermal Anomaly"`, not in the enum) exercised only the fail-open branch and never the production path. **Reflex: an expectation must be an INDEPENDENT statement of the wanted result — a literal, or a value fetched from the other side of the contract — never a re-run of the logic under test.** 🔴 **Sharpest sub-shape, and it recurred three times in one campaign: the spec does not merely fail to see the defect — it NAMES the defect as the intended behaviour.** Three specs called `manual_review` an "unknown/unrecognized status" and pinned the fallback style, i.e. they asserted that a double-spend guard renders invisible on the money path; a sidebar-badge spec stubbed the very scope whose absence was the cross-tenant leak and asserted the stub's own number; and two cache-invalidation specs wrote *and* read the same dead key the code deleted, so code and pin drifted together and the pair stayed self-consistently green. In all three the assertion was true, the name was plausible, and mutation was useless — the mutant matched the pin. **Reflex: when a spec's name contains a synonym for "unknown / default / fallback / legacy", open the value it is describing and ask whether that value is actually a documented state of the system** — if it is, the spec is cementing a bug, not covering one. And when a spec must change to accommodate a fix, treat it as a hypothesis about what it was really testing: 24 red specs were the *evidence* the migration worked, and two of them turned out to have been asserting the bug.

13. **«Closed» for one caller is not closed for the CLASS** (I18N.1, 2026-07-26). `alert_type` was recorded as done once the shared formatter resolved it — then three separate bypasses surfaced (`clusters/show` raw enum, `dashboard/event_row` raw value interpolated into a *translated* sentence, `alert_mailer` `.humanize`). The inverse case is worth the same alertness: sometimes the code drifted against a canon that was already right (`render_auth_page`'s `title:` default existed in code while `04_04 §1` had long documented the signature without it), so «doc is stale» is a hypothesis, not a default.

14. **It pairs A with B and never asks whether EITHER is reachable** (UI.4, 2026-07-27, found the day after the sweep that declared the surface clean). *(The tract itself was wired up later the same day — the example below is kept in the past tense as a demonstration of the CLASS, not as live state.)* A producer⟷subscriber check answers "do both ends exist"; it cannot answer "does anyone ever arrive at them". `"geospatial_matrix"` passed every pairwise test — producer present, subscriber present, target rendered inside that very subscriber — and is dead, because **no route renders the subscriber, and none ever did in the whole history of the repo**. Ask what would have to be TRUE for a passing pair to still be inert, and check that separately (here: `routes.rb` + controllers, not the component's own file).** Sibling reading for #8: existence, scope, and reachability are three axes over one pairing, and a gate that owns one silently launders the other two.

15. **It checks that a pairing EXISTS and cannot ask who OWNS the shape flowing through it** (UI.4, 2026-07-27, the same afternoon). The fourth axis after existence/reachability/scope, and the one that finally explains why the earlier three kept finding half-fixes. A stream+target pair has exactly one owner — the page that renders the target — and any gate that merely confirms "producer aims at a target that exists" will bless a producer pushing a fragment shaped for a *different* owner: here `EwsAlert` pushed a 6-column `<tr>` into both a real `<tbody>` and a compact `<div>` panel, so an updated row changed its own tag mid-page. **The trap for the fixer is sharper than the bug**: making the container a table would satisfy every structural check and still be wrong, because the two owners need different *verbs* — the digest panel must `remove` a resolved alert and backfill the next one, the worklist must `replace` it with a struck-through row, and a fixed HTML fragment cannot express two verbs at all. **Reflex: when one entity feeds two surfaces, stop asking "does the payload fit" and ask "whose shape is this, and does the other owner need a different OPERATION?" If yes, the payload must become a signal (`broadcast_refresh_*_to`) rather than markup** — which also happens to dissolve the locale problem, since each viewer then re-renders in their own request. Generalises past Turbo: any push-based channel that ships a rendered artifact to more than one consumer has this defect latent.

16. **The assertion runs in the one locale where the fix and the bug produce IDENTICAL output** (I18N.1, 2026-07-27). Specs default to the base locale, and in a base locale a label very often *equals its own token* (`confirmed: confirmed`, `active: active`). So `expect(html).to include("confirmed")` is green whether the component resolved the label through the locale file or printed the raw enum — the example cannot express the defect it was written for, and no mutation reveals this because the mutation changes nothing observable. **Reflex: an i18n assertion belongs in a NON-base locale, where the label and the token differ; and add the negative half (`not_to match(/>\s*active\s*</)`) so a regression to the raw value goes red.** Generalises past i18n to every identity-shaped transform: if `f(x) == x` for your fixture, the fixture proves nothing about `f`.

17. **The pinned CSS class exists elsewhere on the same page, so the example passes through a NEIGHBOUR** (I18N.1, 2026-07-27). A spec named "highlights failed command status with danger accent" asserted `text-status-danger-accent` — which is the hover/focus class of the card's OFF *button*, not the status. It would have stayed green with the status not rendered at all, and it survived a rewrite of the very code it claimed to cover. 18. **The session that hunts stale mirrors leaves its own** (UI.4/I18N.2, 2026-07-27). Two commit messages in one session boasted about «lists that lied» and «mirrors that outlived the fact» — and that same session left a registry row asserting a producer that no longer exists, plus an item tail in the present tense about defects it had closed 11 minutes earlier. Both survived **three** subsequent doc-commits that edited the very same files, one of them three lines away. **The mechanism is specific, not carelessness: you sweep the thing you are changing, and a registry row is not what you are changing — it is what DESCRIBES what you changed.** Reflex: after editing behaviour, grep the artifact for the *old* behaviour's vocabulary (`prepend`, the old target id, the old method name), not for the item you were working on. 19. **The idempotency spec is vacuous because the first run removed the subject from the scan scope** (ARCH.58, 2026-07-27). A self-healing sweeper scans a *symptom* (`Actuator.active`) and then *cures* it. Two specs named "does not create a second STOP on the next pass" and "does not duplicate the alert on the next pass" both passed — and would have passed with **both dedup guards deleted**, because after pass 1 the actuator is `idle` and pass 2 never looks at it. The assertion was true; it simply never reached the code it named. Note how convincing the shape is: it reads exactly like a real idempotency test, it is the same shape used for sweepers that *don't* cure (where the subject persists and the test is genuine), and a mutation of the guard leaves it green — so mutation-testing alone does not expose it either; only asking *"which of my two runs actually enters the branch?"* does. **Reflex: for any worker that removes its own trigger condition, an idempotency spec must RE-CREATE the precondition between runs (`re_stick`), or it asserts nothing.** Generalises to every cure-the-symptom job — reconcilers, migrators, backfills, retry-drainers: the second invocation is a no-op by construction, which is precisely why it proves nothing about the guard you wrote for it.

20. **The fix silently invalidates the spec that guarded the thing it fixed** (ARCH.58, 2026-07-27, found by a *third* adversarial round aimed at the *fixes*). Round two found a real defect: a sweeper's recovery step burned its own predicate fuel before a fallible tail, so a crash could leave a row invisible forever. The fix — wrapping the step in a transaction — was correct, and it also moved every `after_commit` callback to *after* the whole set commits. One existing spec (`"STOP bypasses the readiness gate on a still-active actuator"`) had been meaningful precisely because the callback fired while the actuator was still active; post-fix it fires after the actuator is already idle, so the gate would pass **without the bypass** and the spec stopped killing its mutant — while keeping a name that describes a world that no longer exists. **The general shape: changing WHEN something runs retroactively changes what every timing-dependent assertion is actually testing, and nothing goes red to tell you.** Transaction boundaries, `after_commit`→`after_save`, moving work into or out of a job, adding a lock — all have this property. **Reflex: after any change to ordering/atomicity, re-run the mutation for the guards that live in that window — not the whole suite, which stays green by construction.** Corollary on review economics: the round aimed at the *fixes* yielded more than the round aimed at the original work, because fixes are written under time pressure, against a freshly-changed model, by someone who has stopped looking for new classes.

21. **A scoping fix has THREE halves — the query, the CACHE KEY, and whoever DELETES that key — and mutating only the query proves one of them** (SEC.16 sidebar badge, 2026-07-28; the third half bought separately on the Oracle forecast cache). The third is the quiet one: when tenant-isolation renamed the key, only the *reader* moved to the scoped name, while three invalidators kept deleting the pre-scope name — so after the very event the invalidation existed for, the stale value survived its full TTL. **A rename orphans its invalidators silently, and nothing goes red**: the deleters still run, still succeed, and still delete a key nobody writes. 🔴 **And the reason it stayed open is worth as much as the bug: the tracker item had declared this axis CLOSED** («the sidebar badge was the ONLY org-blind key, no work remains») **because the inventory behind that claim had read only the READERS** — one half of the surface, presented as the whole of it. So the completeness claim was false in the direction nobody checks, and the fix's own scope argument inherited it. Reflex: after renaming any cache key, grep the OLD name and confirm every deleter moved with it; the fix is one home (a class method that both sides call) rather than three call sites agreeing by hand. A helper computed a tenant-scoped count under a **shared** cache key. Fixing the query alone still leaks: the first viewer to warm the cache serves their number to every other tenant for the TTL. 22. **Premises that apply identically to both branches cannot rank the branches** (SEC.25 gate design, 2026-07-28). 23. **A one-home refactor BLINDS the gate that keyed on the value's literal shape — and the fix is to key on the CENTRALIZER, not to widen the shape** (SEC.25, 2026-07-28). 24. **A machine-derivable attribute stands in for the human-only one that actually decides** (SEC.25, 2026-07-28). 27. 🔴 **A gate whose bypass is CHEAP and whose miss is SILENT is aimed at the wrong population — it has NEGATIVE expected value, not merely low** (SEC.25 Ф1, 2026-07-28, killed at design stage before a line was written). What they share is SimpleCov's cached resultset — the dotfile SimpleCov keeps under the coverage output directory — which **every** rspec writes, because `COVERAGE=0` disables the GATE and not the report. (Spelling that artifact's path here would itself trip `claude_prose_path_refs`, since it is gitignored and absent until a run produces it — shape #29's teaching-citation-becomes-a-claim, met while writing this very item.) So a correct argument about one resource licensed a collision on another. ⚠️ Diagnostic signature worth carrying, since the symptom reads as «I broke coverage» rather than «something else ran»: `0 failures` together with `EXIT=2` and *every* group at 0.0 % — a genuine floor breach moves ONE group by tenths. Remedy is deleting that cached resultset and re-running the suite alone. Sibling of #43/#44 (two stances of one gate) with the axis moved one level down: there the two stances both existed and diverged, here the second stance never instantiates the guard.

55. 🔴 **Before building a gate, look for the record that this class was ALREADY measured and the gate ALREADY refused — and look for it in the ARTEFACT's header, because that is where such a verdict tends to live** (TEST.12 axis D, 2026-08-12). I spent half an hour writing a Prism parser to size a class, then designed a narrow gate for it, and only afterwards found `scripts/spec_claim_audit.rb` — an existing instrument for exactly that class whose header already carried **both** conclusions I was re-deriving: a HARD gate here is impossible by construction (the matchers are individually appropriate; the defect is semantic), and a corpus-wide advisory report was *measured and rejected* because ~282 candidates at roughly half precision get read zero times. **Two things generalise.** (a) *A design verdict is not only a tracker item or a memory line* — the cheapest home for "we tried this and refused it" is the header of the tool that replaced it, and nobody greps headers. So before writing an instrument or a gate, `grep` `scripts/` and the neighbouring gates' headers for the class's vocabulary; the answer is often a paragraph away from where you were about to add a second opinion. (b) *Building a parallel instrument is itself a measurement substitution* — four independent parsers over one class returned four different numbers, each honest about a different FORM of assertion, and the tool's own header says the count may be taken from it alone precisely because that had already gone wrong three times. ⊕ The mirror worth keeping: the tool's declared ceilings are a shortcut to the class's real depth — its ceiling "two examples with byte-identical bodies are not sought" was, in this pass, a live instance found by hand.

57. 🔴 **A gate over DECLARATIONS makes the whole class look covered — while the oldest member is usually the one whose behaviour nothing has ever tested** (SEC.27, 2026-08-12). Closing a "nobody declared X" class, the natural instrument is a gate asserting the declaration EXISTS on every member; it goes green across the set and reads as "class closed". It is not: **"the declaration is present" and "the declaration works" are different claims**, and the gate is blind to the second BY CONSTRUCTION. The asymmetry that follows is the trap, and it is self-inflicted — you write behavioural pins for the members you just fixed, because they are in your hands, and the pre-existing member inherits nothing. Measured here: two newly-validated attachments got a pass/reject pair each, while `MaintenanceRecord#photos` — the oldest, and the one guarding the D-MRV evidence base — had **zero** behavioural pins after years, and a mutation proved it (weakening its validator reddened nothing until pins were written). **Reflex: after adding a declaration-gate, ask which member existed BEFORE the gate, and mutate ITS mechanism — that is where the untested behaviour lives.** ⊕ Sibling framing worth keeping: the axis is "new ⊥ old", not "A ⊥ B", so the usual fork-detector (memory `feedback_exhaustive_cross_ref_dig` B-1, "one branch has the guard, check the other") only fires if you read your own diff as one branch of the fork.

56. 🔴 **Deleting a REDUNDANT test is not the same act as deleting a dead branch, and it needs THREE independent measurements plus a fourth pass nobody's brief asks for** (TEST.12 axis D, 2026-08-12; 22 examples removed). A dead branch is settled by an invariant; a redundant example is settled by nothing — "it has a successor" is a claim, and the three cheap ways it goes wrong are disjoint. **(1) Verify the pairs MECHANICALLY**: for every deletion, the claimed successor must exist at its address AND assert something beyond a status code — otherwise you are trading one vacuum for another, and the pairing report reads identically either way. **(2) Zero-loss set-diff over the WHOLE corpus of examples**, not the touched files: before-set minus after-set must equal exactly the intended drops, and — the half that matters — **nothing may APPEAR**; that is the only cheap way to catch a neighbour clipped by an off-by-one range. **(3) Coverage before and after.** If it does not move by a single line, the deleted set covered nothing of its own, and that is a measurement rather than an argument; if it moves, you have found a path the pairing missed. ⚠️ **None of the three sees RESIDUE, and three different instruments found three different residues in one pass**: `rubocop` gave two now-empty `describe` blocks, an adversarial agent gave an orphaned `let!` fixture (invisible to lint because `RSpec/LetSetup` is disabled repo-wide), and only a human read found two survivors that needed a PIN rather than deletion. **So budget a fourth pass — lint the touched files, and give the DISAPPEARANCE frame to someone who is not you** (§the two-frame rule: the curator can hold completeness, never disappearance). 🔑 **And before any of it, ask whether the "layer" you are cutting is a layer at all.** Here `spec/integration/` turned out to be a DIRECTORY, not a tier — rspec-rails maps `spec/(requests|integration|api)` to one and the same `type: :request`, so those examples shared the middleware stack, the hooks and the tier of the very files that superseded them. That single fact predicted the zero coverage delta before it was measured. **Ask not "how is this layer different by intent" but "what does the framework DO with this directory".** ⊥ The SIBLING act — removing a dead code BRANCH, the one an invariant does settle — is a different discipline with a different home: memory `feedback_dead_code_refactor` (taxonomy + canon `04_06 §B.4`). Do not merge the two: what makes that one cheap is precisely the thing this one lacks.

58. 🔴 **A boot guard is usually blind to the very placeholder that exists to make it fail loudly — because `REQUIRED_SECRET_NOT_SET` is neither blank nor the sentinel, and a presence-shaped predicate reads it as a real value** (ARCH.60, 2026-08-14). Our deploy manifests carry that string ~105 times as a visible "fill this in" marker, and the convention works only for guards that happen to check something else too: the AR-encryption guard rejects it *by accident*, because it measures LENGTH and the placeholder is 24 chars against a floor of 32. A new mail-transport guard checking "non-blank ∧ not the scaffold default" therefore passed on a manifest whose every mail variable was still a placeholder — I shipped that predicate, then met it two edits later when adding the placeholder rows myself. **The fix is not to special-case the string** — that is a second home for a convention nobody would think to update — **it is to check the value's SHAPE**, which is what `Security::Web3NetworkGuard` already does one file over (its address-format check rejects the placeholder as a side effect, and its message says so out loud). An address needs `@`; a hostname cannot contain `_`. Shape-checking is strictly stronger: the same predicate also catches a mispaste, a truncation and a `changeme`. **Two reflexes.** (a) *When you write a presence-shaped guard, enumerate the values your own deploy surfaces will legitimately contain before real provisioning* — placeholder, empty string, the framework's default, the scaffold value — and check the predicate against each; three of those four look "set". (b) *Then make the MESSAGE distinguish them*: "unset" and "set to a placeholder" are different operator actions, and telling a deployer their variable is missing when it is present-but-unusable sends them to the wrong file. ⊕ Mirror worth carrying past guards: the same blindness afflicts any *validation* whose only question is presence — a `validates :x, presence: true` on a column a seed fills with a placeholder is green forever. ⚠️ And the guard's arrival creates obligations elsewhere — for the `ENV.fetch`-without-default shape `spec/deploy/env_fetch_declaration_spec.rb` (INF.12) already walks them, so check it before assuming a gap; what stays ungated is the guard-SHAPED boot dependency that is not an `ENV.fetch` (this item's own mail-guard case) and the per-PROCESS axis. A boot dependency must be walked across **every deploy surface** (Kamal clear+secret · secrets file · each deploy workflow · every Kamal role-AND-accessory env-block across BOTH `config/deploy.yml` and its `config/deploy.canopy.yml` override · the terraform variable + template map) **and every PROCESS that loads the environment** — here two of them, a web-only staging leg with no Sidekiq and a UDP daemon that boots all initializers, would have been newly un-bootable for a capability neither can exercise. Sibling of #54, which is the same question asked of a *bootstrap file* rather than of a *variable*.

59. 🔴 **A shrink-list exemption has TWO ways to die, and the obvious check catches only one — the other leaves an expired exemption actively PROTECTING the regression it was meant to track** (I18N.2, 2026-08-14). The gate had the right instinct: a curated list that only shrinks, with an example asserting no dead entry. But "dead" was computed as `pending - live_producers`, i.e. it fires when the *producer* disappears. The second death is the one the list exists for: the component **migrates and becomes clean**. Nothing noticed, because the entry still resolves to a live producer — so the row stayed green, and any `t()` re-added to that component would have passed, since being on the list is exactly what waives the check. **An exemption whose grounds expired is not decorative; it is a hole shaped like the original defect.** Fix is one example: for each exemption, re-derive its GROUNDS and fail if they no longer hold (`pending.select { |c| source(c).scan(/\bt\(/).none? }`). ⊕ This is #53 with the crucial difference stated: there the condition was a *future event* (`back:`) and unverifiable by construction, so the reader was the only check; here the condition is **mechanically re-derivable**, and leaving it to the eye had no justification — so the rule sharpens to: *when you write a carve-out, ask whether its grounds are computable, and if they are, gate them.* 🔴 **And mutation-verify such a gate in THREE directions, because the middle one is what proves it is not simply always-red:** defect + no exemption → RED · defect + exemption → **GREEN** (the exemption legitimately waives) · clean + exemption → RED. Skipping the middle probe would leave "the gate reds on my mutation" indistinguishable from "the gate reds on everything", which is how an over-broad gate gets weakened later instead of trusted. ⚠️ Note the tell that sent me looking: closing the last item on the list made the list EMPTY, and an empty curated list is the moment to ask what its checks now assert — several of them become vacuous, and one of them (this one) turned out to have been vacuous all along for a whole class of entry.

61. 🔴 **Чи є ПОРОЖНЯ МНОЖИНА для гейта провалом чи метою — вирішує ФОРМУ доказу його живості, і переплутати їх означає або вічнозелену декорацію, або гейт, що забороняє власний успіх** (UI.7, 2026-08-15). Дві протилежні конструкції, і в цьому репо вони стояли поруч. Гейт над **ВЛАСТИВІСТЮ** населення («кожна рукописна форма несе токен») мусить мати підмет: нуль форм = нуль перевірок, тож він потребує явного `has subjects`-прикладу — і той **чесно впав** у мить, коли остання рукописна форма зникла, надрукувавши «правило втратило підмет, зніми гейт». 63. 🔴 **«Прибрано/гейтовано на користь X» вимагає доказу, що X ПРАЦЮЄ — виміряного живим трактом, а не запланованого; найдорожча форма — зняти РОБОЧИЙ механізм тим самим комітом, на слово про наступника** (UI.2 + два ADR того ж шару, 2026-07-27…08-15; сам шар зрізано 2026-08-15 — урок пережив носія). 67. 🔴 **A gate that pins two of OUR OWN homes to each other proves AGREEMENT, never correctness — and it is structurally blind to both sides being wrong the same way** (UI.3, 2026-08-17). `design_token_existence_spec` held set-equality between `ApplicationComponent::CUSTOM_TEXT_SCALE` and the `--font-size-*` keys in `@theme`, mutation-verified in both directions, green for seven months. 86. **«Operational HOW at a canon address» is NOT decided by the SHAPE of the text — a numbered checklist looks like HOW and usually is not one. The discriminator is COUPLING TO LOCAL STATE: count how many sibling `§` of its OWN doc the section cites.** Measured 2026-08-22 on a five-member inventory of that class: **three of five were false, all for the same reason** — the census had classified by form. What the coupling count caught: a «Namespacing Convention» decision tree whose every leaf cites a local directory registry (`§6.1`…`§6.4`) and which opens with a state claim; a «Procedure for claiming an RTC register» whose checklist quotes the current bit availability and the budget's exhaustion state; a pair of «Ordering convention» sections that read like a copied generic rule and measured **14% word overlap** — they are the ontology of each individual doc, i.e. WHAT. **The rule: a recipe that would be TORN OFF the state it administers belongs where that state is; only a recipe with zero local anchors is portable.** Second question, and it is cheap: **does the domain skill already carry the REFLEX?** Twice the answer was yes — canon held the mechanism, the skill held the one-line reflex, and that split was already correct; a move would have made a third home. ⚠️ Bound the same pass bought: the coupling count itself undercounts, because a `§`-ref inside a bullet body is easy to miss with a naive scan — one «autonomous» section turned out coupled on a READ. So use the count to RANK candidates and the read to decide, never the other way round. Sibling one level up → #85 (measure what the doc IS before arguing where it goes).

87. **A mass rename breaks RANGES and HISTORICAL STATEMENTS, not refs — and neither is visible to any ref gate, because both stay syntactically valid.** A dangling ref is syntactically dead, so the ref family catches it. But `00_00`→`<last doc>` after a blind replace still names a LIVE doc, so it resolves, so every gate is green — only the MEANING moved, and this particular sentence is read by every agent in every prompt. Measured 2026-08-22 on the module-07 dissolution: **twelve sites in three dialects** — arrow (four AI-routing files, plus two more inside `CLAUDE.md` itself), dash (`README`), dots (the gate registry in `00_06`, `ssot-maintenance`, and `legal-business` — where it was not even a range but two homes glued into range shape). 🔴 **The mirror half is worse: `deep_archival.md` described a range that «used to stand here», and the sweep rewrote that very historical token — the sweep falsified the record of its own earlier defect.** Two reflexes: inventory not only `NN_NN` occurrences but the FORMS where a doc number is a BOUNDARY rather than an address; and exclude every «here previously stood» phrase from the sweep by construction. ⚠️ Perimeter trap that nearly hid one site: `grep --include='*.md'` cannot see an extensionless file, and `.cursorrules` is one — inventory the perimeter without an extension glob.

88. **An exemption justified by the word «forever» is a time bomb whose fuse is the next free-slot occupation — and the thing that defuses it is a lantern, never the promise.** A per-ref exemption in a gate read: «the doc was dissolved, so this ref is dead FOREVER — that is exactly why it makes a good fixture». On 2026-08-22 the number was re-occupied by a new page, and the justification became false in one commit: the address that used to point at nothing now points at a REAL doc with no such section, i.e. precisely the defect the gate exists to catch, suppressed by its own exemption. Nothing broke only because the stale-exempt lantern is HARD (`exit 1`) and fires the moment such a ref starts resolving. **Reflex: occupying any freed number re-verifies EVERY exemption argued from permanence** — grep the exemption tables for «forever»/«назавжди»/«dissolved» before you write the new page, and re-state each surviving reason in terms of what CHECKS it, not what you believe. ⊕ The same event raises the price of every BLANKET path exemption: a folder-wide skip that used to hide an empty address now hides a live defect at that address.

89. **The same detector pointed at two surfaces can measure OPPOSITE things — so «this gate works over there» is not evidence that it should be extended here.** Measured 2026-08-23 on the dated-chronicle detector. In the memory corpus it is a real signal: those files are RULE files, so a dated block is usually an INSTANCE that belongs in the file's `log_*` twin — and the gate still declares itself **a trigger to READ, never a verdict**, because a migration router («N rules moved to <home> (date)») is syntactically identical to a run report and no regex separates them. Run the identical three-costume count over canon: **389 dated blocks, 239 of them inside the tracker** — the sanctioned home, the structural mirror of `log_*` — and most of the remaining 150 are PROVENANCE: verdict dates, «measured on», «here previously stood». 🔑 **Canon docs are SPEC files, so a dated block there is usually the very grounds the rule exists to PRESERVE.** One instrument, two surfaces, inverted meaning — and nothing in the instrument itself announces the flip. **Reflex: before porting a gate to a new surface, ask what the flagged FORM usually MEANS there, and expect the dominant genre to be the legitimate one at least once.** ⊕ Sibling verdict the same day: a detector for «⚖️ verdict resting on a repo number with no re-measurement named» was rejected outright — 12% precision wide, ~40% at its narrowest, because the `N→M` shape is shared with TRL transitions. Both failures share one axis: **the discriminator was never the FORM, it was what the text is ABOUT** — and that is the thing a pattern cannot see.

90. **When the candidate class is SMALL, you can measure a gate's precision EXHAUSTIVELY before writing a line of it — and twice in two days that killed the gate for under an hour of work.** The corpus already carries the law that a carrier exists only where the discriminator has FORM (`feedback_rule_needs_a_carrier`, the seven-attempt table). What was missing is the cheap protocol that applies it: **enumerate every candidate the proposed gate would fire on, read them, and count how many are real.** Both 2026-08-22/23 proposals died there. (a) «a `⚖️` verdict resting on a repo-number must name its re-measurement» — the wide detector hit 8, exactly ONE real (12%); its narrowest form (`N→M`) hit 10 across all of `docs/**`, half of them **TRL transitions** (`3 → 4`), because the same syntax carries a maturity scale and a repo delta (~40%). (b) «every `spec/quality/` file must be cited» — the strict form (full backticked path) left 2 of 35, and one of those, `focus_ring_contrast_spec`, is **substantively described** in canon and merely cited by bare name, so the gate would have reddened on a correctly documented gate: **50% precision measured over the entire population, not a sample.** The loose form (bare name anywhere) left ZERO — vacuous, and unable to tell description from a line that names the file *as undocumented*. 🔑 **Both failed on one axis, and it is the axis to test first: the discriminator was never the FORM of the record, it was what the record is ABOUT** — and a pattern cannot see aboutness. ⊕ Corollary that saves the residual from being lost with the gate: when the measurement collapses a "class" to one or two instances, **fix the instances** — a single undocumented gate is cured by one registry row, and the row can carry what the gate would never have said (here: that this spec guards a half-fix where the healthy half hid the sick one, and an entire ID family, 201 citations, went unchecked). ⚠️ And name the price of refusing out loud, because a refusal has no red to remind anyone: what stays unprotected, and what would make you reconsider.

91. **Read a gate's DECLARED CEILING before you diagnose its false positives — the answer is often already in its own header, and re-deriving it by measurement costs real passes.** The corpus already treats a declared ceiling as the closing-sweep checklist (what the gate will not redden after your edit). The mirror is missing and it costs more: **when a gate's output looks wrong, the first read is its ceiling, not its code.** Measured 2026-08-23 on `memory_gate.sh --stale-state`. Its yield of ten looked like ~60% false positives, so I measured which of them carried a closure marker on the line versus inside the matcher's window, found the window narrower than the sentence, and proposed widening it — while the function's own footer already states that `MARKED` is matched inside a **280-char window**, that «on a disciplined journal a share of these is false BY CONSTRUCTION», and that a per-file exemption «was considered and REFUSED» because a blanket silently un-checks every other address in that file. Every conclusion I bought with measurement was sitting in the text the tool prints on every run. ⊕ Two corollaries the same pass bought. **(a)** My hypothesis was right for **three of ten**, so the honest fix was not to weaken the matcher but to place each closure marker where the matcher looks — the remedy the ceiling had already picked. **(b)** A stance comment saying a mode «cannot live in `--audit`» is a RECORDED VERDICT: I promoted the mode into the battery, then read the reason (the class spikes to dozens after any archival wave, and a permanently-red battery trains the reader to skim the one stance that must stay loud) and reverted byte-identically. **A yield of zero today is not the premise that verdict rests on** — it rests on the shape of the spike. Rebuilding what a measurement rejected is exactly what #90 forbids, and the guard against it is the same one line: read the declaration first.

92. **A gate can be ENABLED, correct and green while its INPUT FILE does not exist in this project — and that zero measures the instrument, not the tree.** Measured 2026-08-23 (OPS.33): `Rails/UniqueValidationWithoutIndex` and `Rails/DangerousColumnNames` read **only** the Ruby-format schema dump — the `.rb` one Rails writes under the default `schema_format`; this project runs `schema_format = :sql`, so that file has never existed here. The cops were live in an enabled department, the run exited 0, and they inspected nothing — while 19 uniqueness validators sat unexamined and the class had a recorded precedent in this very repo. The failure is not that the tool is weak: it is that «enabled» and «looking at something» are different properties, and only the first one is visible. Nothing distinguishes this green from a real one — the report has no place to say «input absent», because a missing file is indistinguishable from an empty one. **Reflex: for every gate you inherit or enable, ask not «is it on» but «what FILE does it read, and does that file exist HERE» — one `ls` per gate, and it is the cheapest audit in this document.** ⊕ The mirror direction is worth the same line: when a gate DOES have its input, ask whether that input is generated — a step that writes to a generated artifact is undone by its generator, silently and with no error (the re-squash step that edited the `schema_migrations` INSERT block inside the SQL dump survived a whole cycle that way).

93. **A tool disabled BY ITS OWN VENDOR carries a PREMISE about your framework — and the premise is a claim, not a fact, so it ages exactly like a declared ceiling.** `Rails/TransactionExitStatement` refuses to run on `TargetRailsVersion ≥ 7.2` because its source states «transactions were restored to their historical behavior». A runtime probe on 8.1.3.1 — with a control, because otherwise the result cannot be told from a broken probe — showed the opposite: a `return` out of `transaction do` COMMITS what was written, while `raise ActiveRecord::Rollback` in the same run rolls back. So the vendor's rationale silently converted a live hazard into a green check, on the money path. **Reflex: when a tool declines to run, read WHY it declines, and test that reason against your own runtime before accepting the silence — the rationale sits in the vendor's source, is written once, and is never re-measured against your version.** ⚠️ This is not «distrust your dependencies»: the cop is correct about the versions it was written for. The point is that a disabling PREMISE is inherited without review, whereas an enabling one gets exercised on every run.

94. **A gate keyed on a FORM is blind exactly where the form goes DYNAMIC — and that is where the dangerous writer lives, so its zero is an argument AGAINST building it.** Measured 2026-08-25 (SLASH-1, denormalized `active_trees_count` feeding the slashing trigger): the item asked for either a recount sweeper or a gate catching writers that bypass the model callbacks. The candidate scan found sixteen `update_all`/`update_columns`/`insert_all` sites and **zero** real ones — but the interesting half was WHY the gate still lost. A literal detector reads `update_all(status: :x)` fine; the one site that already writes to `trees` builds its SQL into a **local variable** first (`sql = [...]; update_all(sql)`), so the argument is unreadable statically. Every writer disciplined enough to be caught would be caught, and the one shape that can carry the defect — assembled SQL — is invisible **by construction**. So the gate would report health while the actual class walked past it, which is worse than no gate: it converts an open question into a false attestation. 🔑 **The reflex is a question, not a rule: before keying a gate on a form, ask whether the LANGUAGE lets a caller express the same thing dynamically — string interpolation, an assembled array, `send`, a constant lookup — and if it does, ask whether the dangerous author is more or less likely to use that form than the safe one.** Here the answer inverted the decision. ⊕ What replaced it is worth carrying separately, because it generalises: when the defect is a DRIFT between a cached value and its source, the cheap carrier is not a gate over the writers but a **reconciliation inside a pass that already walks the population** — zero new workers, zero new schedule, and it catches every writer including the ones no static form can name. ⚠️ Its own ceiling, declared: reconciliation detects drift AFTER it happens, so it is a thermometer, not a lock — legitimate only where the damage is bounded, and here it was: both drift directions are safe for MONEY (the burn size reads a live COUNT independently), so what leaks is visibility, not funds. Had the money path depended on the cached value, a thermometer would have been the wrong instrument. Sibling shapes: #90 (small class → measure precision exhaustively) and #82 (a level-detector leaves the transition unwatched).

95. **A DERIVATION written as prose in ONE canon line has nothing to go red with — so it survives every change to its own inputs, and the fix is not a constancy-gate on the number but a MODEL that recomputes the chain** [E.67, 2026-08-26]. `05_03` derives `MAX_SUPPLY = 1B SCC` from a chain — «10k GP = 1 SCC · 2k SCC = 1 tCO₂ → ≈20M tree-years (≈2M trees × 10 y.)» — and that chain lived in a single sentence, recomputed nowhere. A value-guard pinning `1_000_000_000` would have been useless: the literal is not what rots. What rots is the **relationship** — change `emission_threshold` from 10k to 50k and the sentence stays syntactically perfect and arithmetically false, because nothing links the two halves. **The discriminating form is a parametric model whose `--assert` REPRODUCES the derivation numerically** (here: 2M trees × 50 SCC/tree/yr must yield 10 years, tolerance ±0.5) — it reds when the constant and the reasoning diverge, in either direction, and it names which one moved.
    🔬 **When this shape applies:** the canon states a number AND the reasoning that produced it, in prose, and no artefact re-derives it. Cheap test — grep the canon for `⇒`/`→`/`≈` next to a constant, then ask «what would recompute this if an input moved». If the answer is «a human re-reading the sentence», the derivation is undefended.
    ⚠️ **Do NOT widen this into «gate every derivation».** The precondition is that the chain has ≥2 independently-mutable inputs living in DIFFERENT homes (here `MAX_SUPPLY` is a Solidity `constant`, `emission_threshold` a DAO parameter, `scc_per_tree_year` a bench-pending measurement) — a derivation whose inputs all sit in one file is already defended by reading that file. And the model must carry its own declared ceiling: this one outputs a RANGE (10 y. ⊥ 63 y. ⊥ 1.6 y.), because one input is calibration-pending, and a gate that hid that spread behind a single number would be asserting precision it does not have (sibling of «precision-in-the-anchor»).
    ⊕ **Free second and third invariants, because the model already holds the units:** the same `--assert` pins that the simulated quantity is in COINS not POINTS (the 10 000:1 axis that cost `ARCH.88`/`ARCH.95`), and that the shipped baseline burns EXACTLY zero (the positive-A gate of `SLASH-1`). Both are one line each once the state exists — a model built for one question defends three.

96. **A mutation that lands inside a `rescue StandardError` proves NOTHING — and the pin it "verified" can be measuring an empty set** [DOC-T.89, 2026-08-26]. The standard reflex is right: to trust a green pin, break the thing it claims to watch and demand RED. But the *form* of the break decides whether the reflex works at all. Injecting `raise "MUTATION"` into a method whose tail carries `rescue StandardError => e` is swallowed by that very rescue — the example stays green, and you conclude "the pin reaches this line" when it never got there. 🔬 **Choose a mutation that moves the OBSERVED quantity, not one that aborts the path:** for a counter pin, make the increment unconditional with a fixed non-zero value (`increment(by: 999.0)`); for a boolean guard, invert the condition (`if false`). Both change what the example asserts on, and neither is reachable by an error handler. ⊕ **The trigger to run this at all:** a pin is green *and* the branch it names is still listed uncovered — that pair is a contradiction, and the resolution is almost always "the example takes a different route to a TWIN of the code you meant". Here the service incremented the same metric in two places (`dispatch_archive_group` for the normal batch, `send_clean_batch` for the binary-search sub-batch); the example exercised the first, the coverage gap sat on the second, and the comment above it announced it pinned both. 🔴 **A tombstone that promises a pin is not a pin** — when a comment says "we pin these directly", grep that the example under it actually touches those lines, because the sentence outlives the code that once made it true.

97. **Ask what SHAPE your pin engine can extract before believing a canon mirror is gated — ours reads `NAME = value`, so every mirror that is not a constant assignment sits outside every gate BY CONSTRUCTION, and the tell is a doc that CERTIFIES ITSELF** [DOC-T.89, 2026-08-26]. `canonical_block_pins.yml` is the house answer to «this fact legitimately lives in BOTH code and a doc mirror»: hash the canonical block, force a re-pin when it moves. Its extractor is `^\s*NAME\s*=\s*(.+)$`. That is exact for constants and structurally blind to everything else — parameter lists, event ABIs, method bodies, YAML blocks copied out of a config. So a canon page can carry a hundred lines of restated source and be, in gate terms, unwatched; and nothing in the registry says so, because the registry lists what IS pinned, never what CANNOT be. Measured: E.60 added one parameter to four functions and two events across both tokens; the contracts and `subgraph.yaml` moved together, and `05_03`+`05_01` kept the old arity in **twenty** places for five weeks with every doc gate green. 🔴 **The sharpest tell is not the stale line — it is the SELF-CERTIFYING TABLE.** `05_03` holds a «Subgraph vs Контракт — Повна Матриця» whose entire job is to assert those two artifacts agree, and it printed ✅ against a signature that neither of them used. A table like that reads as *verification already performed*, so it does not merely fail to catch the drift — it actively spends the reader's suspicion. **Reflex, in this order: (1) for any canon page that restates code, name the gate that watches it, and if the answer is the pin engine, check that the restated thing is literally a `NAME = value`; (2) if it is not, look for a property of the restatement that is INVARIANT across every dialect the corpus uses to spell it — here arity, which all four spellings agree on and which is exactly what moved — and gate THAT rather than the text; (3) treat every ✅ column inside the doc as a claim needing its own gate, because a matrix that certifies agreement is the highest-trust, lowest-evidence artifact a canon page can contain.** ⚠️ And the reason this shape is not «just add another pin»: the pin engine COULD have been widened to parse signatures, and that would have been the expensive answer — a second parser, a second re-pin ritual, and a new way to be stale. A one-property gate over the whole corpus (44 candidates, 20 red, zero false positives after two discriminators) cost one script and needs no ritual at all. **When a mirror resists pinning, look for the invariant NUMBER before you build a better parser.**

98. 🔴 **Порахуй, скільки гейтів ЧИТАЮТЬ артефакт і скільки його ВИКОНУЮТЬ — бо на файлі, який ніхто не завантажує, зелена може бути вся батарея** [seeds, 2026-08-26]. `db/seeds.rb` падав `NameError` на девʼятому рядку **три доби** при повністю зеленому CI. 113. 🔴 **A mutation-proof is a claim about the SUBJECT it ran against, not a property of the gate's name — so retargeting the gate and keeping the marker turns the proof into a lie about the new subject** [OPS.37, 2026-08-29]. `scripts/deploy_secret_scan.rb` carried `# ✅ MUTATION-VERIFIED 2026-08-23, both invariants, isolated` — true of the SDL-era gate, which read four Akash manifests. Спільний tell — **екстракція завжди УСПІШНА**: помилки немає, є тихе перевизначення, тож мовчить і гейт, і перевірка перевірки. Лік у коді: поле беруть ПОЗИЦІЙНО, скоуп обмежують секцією (файловий скан домішує сусідні таблиці з іншим розкладом), а на кількість колонок ставлять гард, який мусить бути ПОМИЛКОЮ, ніколи мовчазним значенням — тобто регенератор доводить власну ІДЕМПОТЕНТНІСТЬ, прогін над своїм виходом є no-op. ⚠️ Асиметрія, що робить клас дорогим: чим ретельніша робота, тим більше в ній приладів, а форму даних міняє САМЕ ВОНА — і два з трьох інстансів були приладами ПЕРЕВІРКИ, тобто ламався шар, який мав ловити.
