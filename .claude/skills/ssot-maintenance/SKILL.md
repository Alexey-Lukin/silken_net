## Core principle

**Every fact has ONE canonical home (00_06 §2); everything else references it, never restates.** When a fact changes, edit it *only* at its home — references stay valid. A mirror must be labelled "значення тут — дзеркало SSOT, правити там". The linters below enforce *owner-only vocabulary* (e.g. RTC register availability words may appear only in 03_01).

## Workflow — hunt → automate → fix

The loop that stabilises the SSOT (repeat per drift class):

```
1. HUNT     Find a fact restated inconsistently across docs/code
            (same value, two numbers; same string, two spellings).
            Identify its canonical OWNER (00_06 §2).
2. AUTOMATE Write a precise, low-false-positive linter (recipe below)
            so the drift can never silently return.
3. FIX      Clean every off-home restatement → make it a reference.
            Re-run the gate until green; the gate now holds the line.
```

> Before editing any symbol the docs describe, honour the repo's blast-radius rule (CLAUDE.md §2): trace the symbol's callers first. Docs edits are low-risk, but value changes that mirror code are not.

### Deep-archiving a 00_07 item (cement code + SSOT + tracker together)

A heavier, specialised loop for *retiring* a tracker item. Walk **every** code/doc site of the ID — forward **and** inbound refs, **semantic terms** (service names, constants, opcodes), not just the ID, across **all** `00_01..07_03` + code + spec + `.github`. Verify each `✅` against real code + `git log` (don't trust prose-claims-done). Canonize what lives only in 00_07 prose **before** trimming (migrate-first); fix any drift found along the thread; then **cement-trim** (open residual stays) or **archive** (fully done → §🗄️ table). Follow the breadcrumbs (`[DOC.N]`/`[FW.N]` tags, Cross-ref lines, `00_06 §2` home-registry). Commit each ID separately. 🔴 **Founder disciplines (2026-06-09):** ONE edit at a time (verify between — no batching, even non-glue); **READ the FULL canon section — in EVERY doc the fact lives in — BEFORE collapsing/thinning** (a grep hit is NOT confirmation; esp. a Присуд/verdict — never delete un-canonized analysis; an "all clean, nothing found" sweep is a signal to dig deeper, not to stop). This is the one rule with **no gate behind it** — the zero-loss set-diff is itself grep-based, so a fact that is present-by-token but gutted-in-substance passes green; **orphan-ID sweep** (`comm -23` referenced-vs-00_07-homed → a resolved+cited fix with no `####`/table row needs a §🗄️ row); **re-audit already-cemented items** to the deeper standard. ## Add a new drift guard — *how this skill evolves*

This is the point: the skill stays small, but it lets you turn **any** newly-found drift class into a permanent gate. The defenses grow; the skill doesn't. Recipe, mirroring the existing `DocsLinter` methods:

1. **Pick the owner.** Which doc canonically owns this fact (00_06 §2)? Everything else must only reference it.
2. **Write a pure function** in `lib/docs_linter.rb` — `module_function`, takes `text` (or `basename, text`), returns an array of human-readable violation strings. No Rails, no I/O.
3. **Keep false positives near zero** (heuristic linters are noisy):
   - Unicode-letter boundaries `(?<!\p{L})…(?![\p{L}])` so `звільнило`/`зарезервовано:` don't match a `вільн`/`резерв` rule.
   - Skip table rows (`line.lstrip.start_with?("|")`) and ```` ``` ```` fenced code.
   - **Exempt the owner doc** — it's *allowed* to state the fact.
4. **Unit-test it** in `spec/lib/docs_linter_spec.rb`: a positive (catches the real drift), a clean pass, and the near-misses that must *not* trip. Run `bin/rspec spec/lib/docs_linter_spec.rb`. **Then mutation-verify** (break it → FAIL → revert). A symmetry / false-green-prone guard goes through a 2-agent review before it silences a class (`[[project_doc_t33_t34_seed]]`). Full craft → **§Guard-craft** below.
5. **Wire it into** `lib/tasks/docs.rake` `check_refs`: accumulate hits, print a report block, push a label into `failed` (advisory while you clean the existing drift → flip to **HARD** once it's at 0).
6. **Record it** in the `00_06 §3` guard table and the campaign memory — **not in this skill**. ⚠️ Scope of that duty, because the sentence below overstates it and the mismatch has already cost a detour: §3 registers **workflow steps** — `docs_check` steps (CHECK A) plus the curated out-of-`docs.yml` allow-list (CHECK A2) — and CHECK E is the reverse axis, so a row must name a command a workflow actually runs. An **invariant spec living in the RSpec suite** is therefore NOT a §3 row: its three siblings (`spec/security/no_raw_action_cable_spec.rb`, `spec/i18n/broadcast_payload_invariance_spec.rb`, the enum-parity specs) have none, and adding one risks tripping CHECK E. Such a gate's home is the **canon section it protects** (e.g. `04_04 §8.1`) plus its own spec header. Verify which kind you built by running `guard_registry_sync` — don't infer it from this sentence. For workflow-step gates the enforcement below does apply: `guard_registry_sync` (DOC-T.40) fails CI if a new gate has no §3 row, if a §3 row names a file that no longer exists, **or if a §3 row claims a command/workflow the CI never runs** (reverse axis E — write the §3 command column exactly as the workflow runs it, and mark non-CI rows `advisory`/`on-demand`). Cross-file / code-reading gates go in `scripts/*.rb`, not `lib/docs_linter.rb` (which is pure-doc text); wire the new script into `docs.yml` **and** confirm its inputs are inside the `changes` filter — a gate outside it is decorative. (For an *unambiguous* retired string with no legit current use, skip the bespoke linter: add it to `DocsLinter::DEPRECATED_TERMS` — the general "any retired token's return is blocked" net.)

> When the **standard itself** changes (skeleton, home registry), edit `00_06` (the home) — this skill's pointers stay valid by design.

## 🛡️ Guard-craft — a gate that actually catches

**This is the home of guard-craft.** `00_06 §3` is the *registry* (which guards exist), a script's own header is the home of *why that guard is shaped the way it is* (it rots together with the code, so it cannot drift), and this section is the *craft* — what to ask before, during and after writing one. Instances/demonstrations live in the session memories that found them.

### The question that matters

Not "is there a gate?" but **"WHAT DOES THIS GATE NOT SEE?"** A green gate is evidence only about the class it actually inspects. Two consequences worth internalising:

- **Guards skew away from money.** Pure-doc surfaces end up well fenced while the doc⟷code *value* surface is held together by hand. The cheapest real gap is a **mirror declared in a code comment** ("edit it THERE") with no pin — most money-path holes closed by adding a row to `canonical_block_pins.yml` without touching the engine. Grep for comment-declared mirrors and ask: does each have a pin?
- **Cite a gate only for the class it truly catches.** `model_doc_sync` exiting 0 says nothing about prose — it compares *class names*. A green run quoted as proof of something adjacent is a counterfeit coin.

### A freshly-written gate is the worst-tested code in the repo

Mutation-verify proves it catches the INTENDED — nothing about what it cannot see. Two failure shapes are worse than "blind to a class", and both have shipped here **in the same session the gate was born**:

- **Dead scope under a green label.** `Tracker::Dashboard.stale_machine_who` anchored on `\z` while `each_line` keeps the trailing `\n` → the match failed on EVERY line, the HARD check did not exist, and the run printed "clean". An empty scope is indistinguishable from success. **In any line-scanning linter use `\Z` (or `chomp`), never `\z`** — and write a positive spec *for every scope*, otherwise "zero violations" means "zero checks".
- **A term that is a substring of the project's most frequent noun.** `ROI` ⊂ **gyroid** made the public manifesto read as three violations. Ask both "what does this regex NOT match?" and **"what does it match that it shouldn't — judged on the real hits, not on the intent."**

**Precision is measured in hits and lives in the ANCHOR.** Anchoring on individual words (`required`, `deterministic` — among the most common words in this canon) yielded 19% precision: 16 hits, 3 real. Narrowing to a **collocation** (`required status check` / `required-чек` / `PR-гейт`), demanding a number adjacent to the anchor, and scrubbing `TRL`/`§`/doc-ids took it to 100%. **A noisy advisory is a disabled gate**, so triaging every hit by eye is not optional.

### Ways a gate cannot see its own surface

1. **Decorative** — its INPUT sits outside the workflow's `changes:` filter, so it only ever fires on somebody else's PR (the `bio_contract.rb` hole; `.claude/**` repeated it later on a different gate). Reflex: **input ⊆ trigger-filter?** `guard_registry_sync` CHECK D now enforces this for pinned sources and mirror trees — but it is scoped to those, not to every guard tree.
2. **A whole GENRE outside every linter's namespace** — "Стаття N" headings; `08_03` carried `§1.1–§1.5` pointing at subsections that never existed, green for years. A genre exempt **by design** (`manifest.md`) is where drift is densest.
3. **A noisy advisory** — functionally off. Fix by narrowing the scope to one unit of work and grouping output (one line per file, detail behind `--verbose`), and by **naming the ceiling in the script header**: a semantic gate must declare what it cannot see, or green reads as "not checked".
4. **Blind to its own prose.** `workflow_gate_perimeter` read the workflows and its own Ruby constant, so its header comment could contradict that constant ("all eight" on line 6 vs "flip-pending" on line 10) and live that way until a prose-check was added. A gate sees data; it does not see what it says about itself.
5. **It under-implements the contract it declares.** Worse than #4, because the prose is *right* and the code is a subset. `stale_machine_who` stated its contract as a UNION in three homes (rake comment, spec comment, §3 row) and implemented one direction — it caught meta OVERSTATING and was structurally blind to meta UNDERSTATING, the costlier half (the meta-line is the scan layer, so a pure-👤 meta over machine work reads as "nothing here for me"). **Reflex: read what the gate SAYS it enforces, then check each direction of that sentence separately.** A bidirectional word — *union*, *parity*, *symmetric*, *round-trip*, *1:1* — is a promise of ≥2 checks; count them. ⚠️ **And counting them is not enough — check each direction's DOMAIN too** (DOC-T.55, 2026-07-31). The tracker's WHO pair looked complete: one gate for understating, one for overstating, both shipped. But the overstate half reads literally `include?("🤖")`, so of the three executor glyphs it guards exactly one — a meta-line advertising a `⚖️` verdict nobody is waiting for passes green forever. I found it by walking into it: an item of mine carried a stale `⚖️` for a day while `tracker:check` said clean. So the question after "how many directions?" is **"over what SET does each direction range?"** — a check that covers one member of an enum reads, from its name and its green run, exactly like one that covers all of them. 🔴 **Inverted root, and the more expensive one: the CANON PROSE is the under-implementation, and a gate transcribed from it faithfully inherits the hole** (OPS.3 labeler, 2026-07-29). `00_05 §2.6` had carried the mitigation as "an `all:` wrapper is mandatory wherever negative globs appear" — true, load-bearing, and strictly weaker than the invariant: it blesses a negative sharing one `changed-files` with a positive (OR *inside* the AND-wrapper) and an `all:` holding the negative block alone, both of which stick the label to every PR. The gate that finally held was written from a *derived* rule (expand to a disjunction of conjunctions; every branch carrying a negative must carry a positive), not from the sentence. **Reflex: when translating a prose rule into a gate, first construct counter-examples AGAINST THE PROSE — if one passes the sentence and still exhibits the disease, the canon is the defect and must be tightened in the same commit.** A remediated bug whose fix is recorded as a *form* ("wrap it in `all:`") rather than a *property* is where this hides.

🔴 **Sharpest variant: the gate's own DATA contradicts its declared taxonomy, and nothing compares the two** (SEC.25 scope gate, found 2026-07-28 — one day after shipping it). The gate's header prescribes a proof FORM per class (`unscoped_interpolation` → set-equality pin); its registry then pointed that row at a cross-org-404 example running `as: :json`, which never renders the subscription at all. So the row was of the wrong form *from birth*, which is strictly worse than the ceiling the header honestly admits ("pins the example's NAME, not its provingness" — that one describes an example *hollowed out later*). The gate can only grep the example's name, so nothing can catch this but reading. **Reflex: for any gate whose registry declares a per-row proof KIND, re-read each row's proof and ask "is this actually of the kind the row claims?" — a registry is data, and data drifts from the prose above it exactly like a mirror does.** Corollary that made it costly: it was found only because a *different* stale-mirror sweep dragged me through that row; no sweep was looking for it.

6. **It compares a HOMOGENEOUS pair and is blind to the seam between LAYERS** (I18N.1, 2026-07-26). The most reassuring gates compare like with like — locale↔locale, doc↔doc, workflow↔workflow — and a green run gets read as "this whole surface is fine". `i18n-tasks missing` compares every locale to every other and is structurally incapable of noticing that the *model's enum* grew while the YAML stood still: a display enum reached 14 values while the formatter knew 9, green the whole way. The sibling shape is worse — the pair that **no** gate compares: broadcast producers vs `turbo_stream_from` subscribers both live in the repo, nobody compares them, and eight producers were shipping into streams with zero listeners. **Reflex: name the two sets a gate compares, then ask which OTHER set this artifact must agree with — and whether anything checks that pair.** The cross-layer gate is usually a cheap spec (`Model.enum.keys` vs the locale file), not a linter. Corollary for such a spec: check the **base** locale only — cost then does not grow with the catalogue, and a newly-added, still-untranslated locale does not turn it red.

7. **A config mask switches the gate OFF, and the comment above it justifies a DIFFERENT problem** (I18N.1, 2026-07-26). `ignore_inconsistent_interpolations: ['*']` meant the CI step `i18n-tasks check-consistent-interpolations` could never fail — a green line in every build, checking nothing. The comment above it explained the mask with "UK has pluralisation forms en does not need", which is about the set of **keys**, not about `%{}` **variables**: a true sentence excusing an unrelated setting, which is exactly why nobody re-read it. It let a real bug through — a locale value carrying literal `#id` where every other locale had `#%{id}`. **Two reflexes.** (a) For every ignore/exempt/skip entry in a gate's config, ask *what would fail if I deleted this line* — here the answer was "nothing", the corpus was already clean and the mask was pure cost. (b) Read the justification against the setting, not against the code: a plausible sentence is not evidence that it describes THIS knob. A `'*'`-shaped exemption is never a tuning — it is a disabled gate wearing a config's clothes.

8. **It checks EXISTENCE where the real defect is SCOPE** (UI.4, 2026-07-27). A gate that pairs producers with subscribers answers "is anyone listening?" — and reads as covering the whole surface. It is structurally blind to "listening is fine, the channel is too wide": `"global_events"` was a bare unscoped stream carrying insurance payouts, and the fix the existence-gate would have blessed (add a subscriber) was precisely the cross-tenant leak. Note the adjacent gate did not help — the repo's cross-tenant item covers REST/Pundit, not stream names, so at the time *both* gates were green on the hole. *(The scope axis got its own gate on 2026-07-28 — `spec/security/turbo_stream_scope_spec.rb`; the example stays as the demonstration of the CLASS, and the general point survives: a gate owning one axis over a pairing silently launders the others.)* **Reflex: for every gate that pairs A with B, ask whether the pairing can be CORRECT and still wrong — usually the second axis is scope, quantity, or ordering, and it needs its own check, not a wider first one.**

9. **A guard's own extraction regex silently under-collects, and the guard's ceiling section says nothing about it** (I18N.2, measured 2026-07-27). `broadcast_payload_invariance_spec` anchors on a multi-line call shape, so a single-line `broadcast_*_to(...)` does not exist for it — verified: 1 of 2 calls seen in one file. Harmless for *that* gate (the missed call carries no payload), which is exactly why it survived: **an extraction bug shows no symptom while the missed items happen to be innocent.** The bill arrives when the same machinery is reused for a gate where completeness is the point. Reflex: before reusing an extractor, measure it against a hand count on one real file; and prefer AST (`Ripper`) over regex the moment a second consumer appears.

🔴 **And when you do write that AST extractor, expect the blindness to live in IT rather than in the gate's logic — three separate holes surfaced in one, each only after the gate was already green** (SEC.25 scope gate, 2026-07-28). (a) A node kind that *looks* like a record is not one: `var_ref` covers both `@wallet` and a local holding a string, so the classifier marked an interpolated local as a record — i.e. it **over-stated** the site's safety, the worst direction for anything that dispatches obligations. Found by measuring the extractor against a hand count, not by reading it. (b) **Any name pattern is wrong in both directions**: `broadcast_\w*_to` missed the gem's non-`_to` forms (which broadcast to the record's *own* stream — a stream with no name and no registry row), while `broadcast_\w+` swept in the app's own private helpers sharing the prefix (more numerous than the gem calls themselves — and the exact tally proved unreproducible on any basis a year later, which is its own lesson about writing one down). The durable fix is to stop patterning: derive the set from the library at runtime (`Turbo::Streams::Broadcasts` ∪ `Turbo::Broadcastable`), which also survives a gem upgrade untouched. (c) **The argument-less call form is a different AST node** — `broadcast_refresh` with no parens is `:vcall`, not `:command`/`:method_add_arg` — so the walker was blind to precisely the most idiomatic spelling of the thing the gate forbade, and the mutation *landed green*. Reflex for any AST walker: enumerate the call shapes explicitly (`foo(a)` · `foo a` · `X.foo(a)` · `X.foo a` · `foo` · `X.foo`) and write a unit example per shape — the paren-less and receiver-less ones are the pair everyone forgets. **(d) A THIRD shape surfaced the next day, in the same walker, found the same way — by probing, not reading** (2026-07-28): when the *nested* call is paren-less (`f X.m a, b`), it swallows the argument list into itself, so the OUTER call's args node arrives as a **bare array of arg nodes** with no `:args_add_block` wrapper — the only shape the arg extractor recognised. Result: `:absent`, i.e. "this call has no first argument", on a call that visibly has one. Note the meta-pattern across all three: each hole was in the *shape of the surrounding syntax*, none was in the walker's logic, and every one of them was invisible to reading and instant under a probe that enumerates spellings. So the reflex is not "read the walker carefully" — it is **write the probe table first**. Corollary on coverage: when such a walker's defensive branches sit uncovered, the honest fix is usually **deletion, not tests** — collapsing five duplicated emit paths into one and dropping genuinely unreachable guards moved branch coverage 97.81% → 98.16%, because the branches were dead rather than untested.

10. **It announces its own failure LOUDLY — and exits 0** (I18N.1, 2026-07-27). `i18n-tasks missing` could not resolve relative keys in the mailer templates (`relative_roots` knew only `app/views/components`), printed `Cannot resolve relative key ".heading"` — and returned **success**. The surface went unscanned, the build stayed green, and the diagnosis sat in output nobody reads, precisely because the exit code says everything is fine. This is worse than the silent shapes above: those at least do not assert health. **Reflex: for any gate that can print ERROR/WARN, check whether that affects its exit code** — if not, grep its output in CI (as `check-normalized` already must) or treat the step as inert. Corollary: a gate's *coverage* can shrink without its *verdict* changing, so a green step proves nothing about what it actually looked at.

11. **The spec pins that the call HAPPENED, never where it POINTED** (UI.4, 2026-07-27). Every spec on the broadcast surface asserted `have_received(:broadcast_replace_to)` with no argument matcher — so a producer aiming at `actuator_card_{id}` while the component rendered `actuator_{id}` stayed green for months. The assertion was *true*; it simply never touched the only thing capable of being wrong. **Reflex: when a call's correctness lives in an ARGUMENT — a DOM id, a stream name, a queue, a target path — assert the argument (`hash_including(target: …)`), not the bare invocation.** Generalises past specs: where the failure mode is silent (nothing raises, nothing logs), "it ran" and "it worked" are different claims, and only the first is cheap to assert — so cheapness is exactly what makes the useless one attractive.

12. **The spec computes its expectation with the SAME broken transform as the code** (I18N.1, 2026-07-26). A mailer spec asserted the subject by calling `alert.alert_type.humanize` — exactly what the code did — so the assertion was a tautology that could never fail, and the fact that the label never went through the locale file stayed invisible. Sibling shape in the same sweep: a spec riding a *fabricated* enum value (`"Thermal Anomaly"`, not in the enum) exercised only the fail-open branch and never the production path. **Reflex: an expectation must be an INDEPENDENT statement of the wanted result — a literal, or a value fetched from the other side of the contract — never a re-run of the logic under test.** 🔴 **Sharpest sub-shape, and it recurred three times in one campaign: the spec does not merely fail to see the defect — it NAMES the defect as the intended behaviour.** Three specs called `manual_review` an "unknown/unrecognized status" and pinned the fallback style, i.e. they asserted that a double-spend guard renders invisible on the money path; a sidebar-badge spec stubbed the very scope whose absence was the cross-tenant leak and asserted the stub's own number; and two cache-invalidation specs wrote *and* read the same dead key the code deleted, so code and pin drifted together and the pair stayed self-consistently green. In all three the assertion was true, the name was plausible, and mutation was useless — the mutant matched the pin. Reflex: **when a spec's name contains a synonym for "unknown / default / fallback / legacy", open the value it is describing and ask whether that value is actually a documented state of the system** — if it is, the spec is cementing a bug, not covering one. And when a spec must change to accommodate a fix, treat it as a hypothesis about what it was really testing: 24 red specs were the *evidence* the migration worked, and two of them turned out to have been asserting the bug.

13. **«Closed» for one caller is not closed for the CLASS** (I18N.1, 2026-07-26). `alert_type` was recorded as done once the shared formatter resolved it — then three separate bypasses surfaced (`clusters/show` raw enum, `dashboard/event_row` raw value interpolated into a *translated* sentence, `alert_mailer` `.humanize`). The inverse case is worth the same alertness: sometimes the code drifted against a canon that was already right (`render_auth_page`'s `title:` default existed in code while `04_04 §1` had long documented the signature without it), so «doc is stale» is a hypothesis, not a default.

14. **It pairs A with B and never asks whether EITHER is reachable** (UI.4, 2026-07-27, found the day after the sweep that declared the surface clean). *(The tract itself was wired up later the same day — the example below is kept in the past tense as a demonstration of the CLASS, not as live state.)* A producer⟷subscriber check answers "do both ends exist"; it cannot answer "does anyone ever arrive at them". `"geospatial_matrix"` passed every pairwise test — producer present, subscriber present, target rendered inside that very subscriber — and is dead, because **no route renders the subscriber, and none ever did in the whole history of the repo**. Ask what would have to be TRUE for a passing pair to still be inert, and check that separately (here: `routes.rb` + controllers, not the component's own file).** Sibling reading for #8: existence, scope, and reachability are three axes over one pairing, and a gate that owns one silently launders the other two.

15. **It checks that a pairing EXISTS and cannot ask who OWNS the shape flowing through it** (UI.4, 2026-07-27, the same afternoon). The fourth axis after existence/reachability/scope, and the one that finally explains why the earlier three kept finding half-fixes. A stream+target pair has exactly one owner — the page that renders the target — and any gate that merely confirms "producer aims at a target that exists" will bless a producer pushing a fragment shaped for a *different* owner: here `EwsAlert` pushed a 6-column `<tr>` into both a real `<tbody>` and a compact `<div>` panel, so an updated row changed its own tag mid-page. **The trap for the fixer is sharper than the bug**: making the container a table would satisfy every structural check and still be wrong, because the two owners need different *verbs* — the digest panel must `remove` a resolved alert and backfill the next one, the worklist must `replace` it with a struck-through row, and a fixed HTML fragment cannot express two verbs at all. **Reflex: when one entity feeds two surfaces, stop asking "does the payload fit" and ask "whose shape is this, and does the other owner need a different OPERATION?" If yes, the payload must become a signal (`broadcast_refresh_*_to`) rather than markup** — which also happens to dissolve the locale problem, since each viewer then re-renders in their own request. Generalises past Turbo: any push-based channel that ships a rendered artifact to more than one consumer has this defect latent.

16. **The assertion runs in the one locale where the fix and the bug produce IDENTICAL output** (I18N.1, 2026-07-27). Specs default to the base locale, and in a base locale a label very often *equals its own token* (`confirmed: confirmed`, `active: active`). So `expect(html).to include("confirmed")` is green whether the component resolved the label through the locale file or printed the raw enum — the example cannot express the defect it was written for, and no mutation reveals this because the mutation changes nothing observable. **Reflex: an i18n assertion belongs in a NON-base locale, where the label and the token differ; and add the negative half (`not_to match(/>\s*active\s*</)`) so a regression to the raw value goes red.** Generalises past i18n to every identity-shaped transform: if `f(x) == x` for your fixture, the fixture proves nothing about `f`.

17. **The pinned CSS class exists elsewhere on the same page, so the example passes through a NEIGHBOUR** (I18N.1, 2026-07-27). A spec named "highlights failed command status with danger accent" asserted `text-status-danger-accent` — which is the hover/focus class of the card's OFF *button*, not the status. It would have stayed green with the status not rendered at all, and it survived a rewrite of the very code it claimed to cover. Worse, the obvious replacement repeated the mistake: `bg-red-900` is also used by that card's own `offline` LED. **Reflex: before pinning a class/id/string, `grep -c` it in the file under test — a pin is only a pin if it is UNIQUE to the element under test.** Sibling of #11 (assert the argument, not the invocation): here the assertion touched the right page but the wrong element, which is the same failure wearing different clothes.

18. **The session that hunts stale mirrors leaves its own** (UI.4/I18N.2, 2026-07-27). Two commit messages in one session boasted about «lists that lied» and «mirrors that outlived the fact» — and that same session left a registry row asserting a producer that no longer exists, plus an item tail in the present tense about defects it had closed 11 minutes earlier. Both survived **three** subsequent doc-commits that edited the very same files, one of them three lines away. **The mechanism is specific, not carelessness: you sweep the thing you are changing, and a registry row is not what you are changing — it is what DESCRIBES what you changed.** Reflex: after editing behaviour, grep the artifact for the *old* behaviour's vocabulary (`prepend`, the old target id, the old method name), not for the item you were working on. A gate cannot help here — `tracker:check` and `docs:check_refs` both stayed green, because the row is well-formed and every link resolves; only the CLAIM is false.

19. **The idempotency spec is vacuous because the first run removed the subject from the scan scope** (ARCH.58, 2026-07-27). A self-healing sweeper scans a *symptom* (`Actuator.active`) and then *cures* it. Two specs named "does not create a second STOP on the next pass" and "does not duplicate the alert on the next pass" both passed — and would have passed with **both dedup guards deleted**, because after pass 1 the actuator is `idle` and pass 2 never looks at it. The assertion was true; it simply never reached the code it named. Note how convincing the shape is: it reads exactly like a real idempotency test, it is the same shape used for sweepers that *don't* cure (where the subject persists and the test is genuine), and a mutation of the guard leaves it green — so mutation-testing alone does not expose it either; only asking *"which of my two runs actually enters the branch?"* does. **Reflex: for any worker that removes its own trigger condition, an idempotency spec must RE-CREATE the precondition between runs (`re_stick`), or it asserts nothing.** Generalises to every cure-the-symptom job — reconcilers, migrators, backfills, retry-drainers: the second invocation is a no-op by construction, which is precisely why it proves nothing about the guard you wrote for it.

20. **The fix silently invalidates the spec that guarded the thing it fixed** (ARCH.58, 2026-07-27, found by a *third* adversarial round aimed at the *fixes*). Round two found a real defect: a sweeper's recovery step burned its own predicate fuel before a fallible tail, so a crash could leave a row invisible forever. The fix — wrapping the step in a transaction — was correct, and it also moved every `after_commit` callback to *after* the whole set commits. One existing spec (`"STOP bypasses the readiness gate on a still-active actuator"`) had been meaningful precisely because the callback fired while the actuator was still active; post-fix it fires after the actuator is already idle, so the gate would pass **without the bypass** and the spec stopped killing its mutant — while keeping a name that describes a world that no longer exists. **The general shape: changing WHEN something runs retroactively changes what every timing-dependent assertion is actually testing, and nothing goes red to tell you.** Transaction boundaries, `after_commit`→`after_save`, moving work into or out of a job, adding a lock — all have this property. **Reflex: after any change to ordering/atomicity, re-run the mutation for the guards that live in that window — not the whole suite, which stays green by construction.** Corollary on review economics: the round aimed at the *fixes* yielded more than the round aimed at the original work, because fixes are written under time pressure, against a freshly-changed model, by someone who has stopped looking for new classes.

21. **A scoping fix has THREE halves — the query, the CACHE KEY, and whoever DELETES that key — and mutating only the query proves one of them** (SEC.16 sidebar badge, 2026-07-28; the third half bought separately on the Oracle forecast cache). The third is the quiet one: when tenant-isolation renamed the key, only the *reader* moved to the scoped name, while three invalidators kept deleting the pre-scope name — so after the very event the invalidation existed for, the stale value survived its full TTL. **A rename orphans its invalidators silently, and nothing goes red**: the deleters still run, still succeed, and still delete a key nobody writes. Reflex: after renaming any cache key, grep the OLD name and confirm every deleter moved with it; the fix is one home (a class method that both sides call) rather than three call sites agreeing by hand. A helper computed a tenant-scoped count under a **shared** cache key. Fixing the query alone still leaks: the first viewer to warm the cache serves their number to every other tenant for the TTL. The two halves are independent defects with independent mutations, and a fix verified by one mutation reads as fully verified. Reflex: **for any per-tenant (or per-user, per-locale, per-role) cached value, mutate the KEY as its own experiment** — and note the assertion that catches it must call the helper for tenant A *before* tenant B, since a key-collision defect is invisible unless something is already cached. Generalises to every memoization boundary: `Rails.cache`, `@ivar` on a long-lived object, an HTTP `Cache-Control` header, a CDN key, a Sidekiq-side memo. The sibling reading is #12: the spec that made this invisible for as long as it existed stubbed `EwsAlert.unresolved` and asserted the stub's own value, so the scope could not be expressed by the example at all.

22. **Premises that apply identically to both branches cannot rank the branches** (SEC.25 gate design, 2026-07-28). Five runtime-measured facts about a signed capability token (deterministic, transparent-but-unforgeable, verified without user context, no TTL, no connection identity) were all true — and every one of them held equally for both classes the gate was meant to distinguish. Building a *ranking* on them, and concluding the prescribed classifier was inverted, was therefore an invented bridge over correct measurements: the honest test was empirical (every leak the repo had actually shipped sat on one side) and structural (one side inherits an existing, separately-audited enforcement layer; the other inherits nothing). Reflex: **after measuring, ask which of your facts DISCRIMINATES — a premise shared by both options is background, not evidence.** Corollary about form: the classifier survived as a **dispatcher** (which proof obligation each site owes) rather than as the check itself, and in that role it immediately surfaced a money-path hole the replacement design would never have looked at. So when an item prescribes a "cheap first step", attacking it as if it claimed to be the whole gate is a strawman — read what the item says its own scope is before overriding it.

23. **A one-home refactor BLINDS the gate that keyed on the value's literal shape — and the fix is to key on the CENTRALIZER, not to widen the shape** (SEC.25, 2026-07-28). The scope gate classified a stream name by the AST shape of the literal (`scoped_string` = has an `_org_` token, `unscoped_interpolation` = doesn't). Moving name derivation into one home — the right fix for the real defect, 11 hand-written copies of 4 names across 2 layers — turns every one of those arguments into a method call, i.e. `:indirect`: **two distinct proof obligations collapse into one opaque class, and the gate stops being able to see a class CHANGE, the worst event on that axis.** Widening the shape-matcher is the trap (you cannot pattern-match "this string was built correctly"). The answer is that the *method name on the blessed receiver* becomes the class (`Name.org` → one obligation, `Name.gateway_ota` → another), which is strictly more robust than shape-matching and, as a bonus, immune to the call-shape blindnesses in #9. **Reflex: before centralizing any value a gate inspects, ask what that gate keys on — and move both in one commit.** The general form: any DRY refactor of a value under surveillance must relocate the surveillance to the new single point of truth, or it silently converts a specific check into a generic one.

🔴 **Sharper sub-shape, because the victim need not exist yet: a one-home refactor also blinds gates that are still only PLANNED, and there is nothing to notice it on** (SEC.25/UI.4, 2026-07-30). The tracker had carried, for weeks, "the producer⟷subscriber pair reduces to a set comparison — the AST extractor already exists, no new machinery". Measured before writing a line: after names moved into the home, `arg_pattern` is `nil` on **all 20 sites**, so the pair would have compared argument *classes*, not addresses. The shipped gate had compensated by keying on the method name; the unbuilt one had nothing to compensate with, and no red run could ever have told us — a plan cannot go green or red. **Reflex: when you centralize a value, also grep the BACKLOG for gates described against its old shape, and re-measure their premise before implementing them.** Corollary that decided this case: the honest test of a proposed symmetric check is *"list the shipped defects and name the SHAPE each had"* — here 7 of 12 were "the producer addresses the stream opaquely" (a method parameter, a `||` chain, bare `self`), i.e. an axis of FORM, and only 1 was "two sets diverged". A pair-gate is attractive because it is symmetric and easy to describe, not because defects take that shape.

24. **A machine-derivable attribute stands in for the human-only one that actually decides** (SEC.25, 2026-07-28). The gate derives a name's CLASS from its shape, and prescribes the proof FORM from the class. But the form that is actually required follows from the **page's cardinality**: a single-record page whose stream name interpolates that record's own attribute is safe transitively (the org-scoped `find` runs before format dispatch), while a page looping over a collection needs set-equality, because there the defect looks like an *extra* stream rather than a missing own one. Cardinality is not visible to any extractor — so the taxonomy had silently conflated two cases under one class. **Reflex: for every derived classification a gate makes, name the thing that REALLY determines the required proof, and check whether the derivation can see it. If it cannot, the class must be a DECLARATION in the registry with the reason written next to it — never an inference.** Sibling of #8: three axes over one pairing, and a machine can only see the ones it can parse.

25. **A new example can be vacuous because the method under test is STUBBED elsewhere in its own file — and the neighbouring example's odd-looking setup line is the tell** (SEC.25, 2026-07-28). I added an example calling `alert.send(:broadcast_alert_update)` and asserted the resulting broadcast; it reported "received: 0 times" while a runtime probe showed every precondition healthy. Cause: the spec file stubs that method globally, so `send` hit the stub and executed nothing. The sibling example three lines above carried `allow_any_instance_of(described_class).to receive(:broadcast_alert_update).and_call_original` — which I had read as ceremony. It was the precondition. **Reflex: before writing an example that invokes a method directly, grep the file for that method's name in `allow`/`expect ... to receive` — and treat any `and_call_original` in a neighbour as a warning sign, not boilerplate.** The dangerous direction is the *silent* one: had my assertion been a negative (`not_to have_received`), the stub would have made it pass forever, and nothing — not mutation, not coverage — would have said so. Sibling of #19: both are examples that never reach the code they name.

26. **Citing the wrong precedents is the same failure as inventing a mechanism, one level up: the EVIDENCE is borrowed rather than the reasoning** (SEC.25, 2026-07-28). Justifying a one-home refactor, I wrote into five separate homes that it removes "the class this repo caught three times". All three catches were real, all three were the *adjacent* axis (target DOM ids and record-form streams); the surface I had just centralized had **zero** shipped precedents. Nothing in the sentence was invented — the bugs happened, the duplication was real — yet the bridge between them was false, and it made a defensible change look battle-proven. Two consequences worth internalising: the honest justification is usually narrower and still sufficient (here: blast radius — losing the tenant token is a *leak*, which none of the cited bugs could cause), and **the cited-but-unfixed axis is a finding in itself** — those five hand-written target ids were still there, un-homed and un-gated, precisely because attention went to the surface that had no precedent. **Reflex: when you reach for "this class has bitten us before", open each incident and check it is the same MECHANISM, not the same feeling.**

27. 🔴 **A gate whose bypass is CHEAP and whose miss is SILENT is aimed at the wrong population — it has NEGATIVE expected value, not merely low** (SEC.25 Ф1, 2026-07-28, killed at design stage before a line was written). The plan was subscribe-time authorization in an owned ActionCable channel. Two measurements ended it. (a) **The client picks which channel class handles its subscription** — `Subscriptions#add` constantizes `id_options[:channel]` from client JSON, checking only descent from `Channel::Base`, while the signature covers the stream *name* alone; the stream-source element even keeps `channel` in `observedAttributes` and re-subscribes itself. So the adversary edits one attribute and lands on the unguarded default, and the gate polices only people who were never the threat. (b) **Its `reject` is invisible and irreversible** — `reject()` calls `forget(subscription)`, so the client never re-sends it, and no `rejected` callback exists. Hence the *only* population it can actually affect is legitimate viewers whose case the resolver fails to map — and that was not an edge case, since four of five org-resolution chains end in NULLABLE columns. **Two reflexes.** First, for any fail-closed control, name **who it fires on** and **who can step around it**; if those are different people, the control is theatre with a victim. Second, "fail-closed" is only safe when failure is *loud* — a silent fail-closed is an outage scheduled for later, and the honest comparison is against the hole it bounds, not against zero. Sibling of §Mutation-verify's "measure the mitigation's own failure mode": here the mitigation's failure mode was strictly worse than the leak it addressed, and the form that survived (abandon the address — rotate an epoch inside the name) is immune to both halves because it needs no per-subscriber verdict at all.

**Two traps specific to writing the second half** (both shipped, both caught by adversarial review the same day — the session's real yield):
- **Your exemption may rest on a premise your own code refutes.** The reverse-axis guard exempted three-executor items as "physically unsatisfiable in two slots" — while the `⚖️ ⊂ 👤` line three lines below collapsed the triple onto a legal pair. The exemption silenced the gate on ~12% of the corpus, including three instances of the exact pathology it was written for: **the fix legalised the disease it diagnosed.** Before writing `next if …`, construct the case you are excusing and run it.
- **Match on the LEADING token, never `include?` over the line.** A residual tagged `👤` may *cite* closed machine work in prose ("§5.3 вже 🤖-verified"); an `include?` scan reads that as open 🤖 and the "fix" writes a phantom claim into the meta-line — manufacturing the very drift the sibling gate guards. Both gates carried the defect, so they blinded each other and both stayed green. Anchor first, then count.

28. 🔴 **The subject runs BEFORE the layer you would compare it against — so its own spec is structurally incapable of going red** (SEC.29, 2026-08-01). `Rack::Attack` sits in the middleware stack *ahead of the router*, so `rack_attack_spec` gets its 429 even for a path that no longer exists. Every one of its examples is therefore honest about the counter and silent about the target: a throttle rule can drift off a live route, off a verb, or off half its own declared surface, and the suite stays green forever. Two real drifts were sitting there — a `post?` check on a route registered as PATCH (the only step that actually *changes* a password), and an `==` path compare that missed `/auth/m2m_token/refresh`, i.e. the rule covered half of what its own comment says it protects. **Reflex: for any component that executes before the thing it references, its own spec cannot be the gate — you need a second spec that asks the OTHER layer** (here: `recognize_path` against the router). And name the axis precisely: one example proves the PATH is alive, a different one proves the RULE fires on it; the first stayed green through both defects.

    🔴 **And the gate I wrote for exactly this failed at exactly this — it compared the registry to the ROUTER and never to the RULE.** Its `verbs:` column was hand-written prose that nothing verified, so on the founding defect (path alive, rule reading the wrong verb) it would have been green, and one registry row was *already* lying about its rule on the day it was born. The fix is to call the subject directly — `Rack::Attack.throttles[name].block.call(request)` — which turns the column from a declaration into a measurement, and the founding-class mutation now goes red. ⚠️ The probe itself needed measuring first: the block returns `request.ip` as its discriminator, so a `Rack::MockRequest` without `REMOTE_ADDR` reads as "matches nothing" for *every* rule — a probe that is false-green in both directions. **Reflex: when a registry declares a property of some other artifact, ask what compares the two — and if the answer is "a human wrote it down", the gate is documentation with a test-suite's reputation.**

    🔴 **And it came back a third time, one layer deeper: the gate's own DEFAULT silently narrowed the very axis the registry left open** (ARCH.77, 2026-08-01, caught by an adversarial pass — not by the suite). The registry says `verbs: nil` meaning *"this rule does not discriminate on verb, so check them all"*; the example generator read `(config[:verbs] || %w[GET])` and checked **GET alone**. Consequence: of the five paths under the one rule that spans both routing circuits, the two POST-only ones produced **zero examples** — so deleting the load-bearing `(?:/api/v1)?` group from the rule's regex left the entire suite green (mutation-verified). Worse, the registry comment three lines above asserted the opposite in prose ("both addresses listed explicitly … no example would have gone red otherwise"), i.e. the gate shipped with a **written promise its own default made empty**. The fix is to derive the verbs from the router (`recognize_path` per candidate verb) rather than from a literal default, which turned 40 examples into 42 — and the two new ones are exactly the missing POSTs. **Reflex: `nil` in a registry means "unspecified", and every `||` that fills it is a policy decision — read each default and ask which member of the set it silently drops.     Two corollaries earned the same day. **(a) The form of the fix can be impossible for reasons that have nothing to do with the fix.** The obvious repair — derive the paths from `Rails.application.routes.url_helpers` into one home — cannot run in an initializer: `load_config_initializers` is an Engine-group initializer and routes are drawn in `set_routes_reloader_hook` (Finisher), while the lazy route set is enabled only under `Rails.env.local?`. Check the framework's load order before promising a "single home". **(b) A curated registry needs a completeness check, or it becomes the blindness it was written to cure**: pair the registry with `expect(Rack::Attack.throttles.keys).to match_array(REGISTRY.keys)` so a newly added rule cannot enter the codebase unwatched. 29. 🔴 **Mass deletion leaves SEMANTIC tails that every link-checker blesses — the ID still resolves, so the gate stays green while the prose lies** (`08_03` module dissolution, 2026-07-23…24). Deleting whole sections or files is the operation `docs:check_refs` is weakest against, because it validates *references* and never the sentences built around them. Four shapes, all shipped, none gate-visible: **(a) range prose** — `§9–§15` survives the deletion of `§13–§15`, since the auto-ToC rewrites headings and never touches a sentence; **(b) vocabulary orphan** — a term whose *definition* lived only in the deleted home (`WP1–WP9`, defined in `07_03 §7`) stays in use elsewhere with nothing defining it; **(c) archive node** — archiving an ID with N inbound refs leaves every "do X for [ID]" semantically stale even though the archive row resolves, so a high-inbound ID (one carried 10) means N rewrites, not one; **(d) bare `§X` outside a code span** — `file_section_dangling_refs` is digit-led (`NN_NN §X`) by construction, so a naked `(North-Star §0.1)` orphaned by deleting `§0` is invisible to it. **Reflex: after any mass delete, grep the four things the ID-checkers cannot see — range prose, the deleted home's defined VOCABULARY, every inbound of each archived ID, and bare `§X` — through three lenses (gate + agents + advisory scripts), because each is blind where the others look.**

    **Mechanics of a full dissolution.** Merge + delete must be **one atomic commit** (destination doc, sweep, deletion, heading renumber and indices together); a redirect **stub is not safe**, because `08_01 §2` will not resolve against a thin stub that has no `§2`. Sweep scripts must be **§-scoped** — an unscoped unlink caught a legitimate link in a different section, and the tell was the dry-run count (8 where 7 were expected), so always dry-run with a count expectation. The perimeter extends past `docs/`: an adversarial pass *after* the commit still found a legend range, a half-swept archive row, and an orphaned GitHub label (`.github/labels.yml` sits outside the docs sweep entirely, and its `description` carries a 100-char CI limit that fails the label-sync job). JSON caches store Unicode escapes (`\u…`), so a literal `gsub` misses them.

    🔴 **And the payoff nobody budgets for: a mass delete is the best DRIFT DETECTOR available.** Walking every inbound ref — which nothing else forces you to do — exposes long-standing quiet drift no gate can see, because each individual reference is well-formed: two inbound refs pointed at the wrong person entirely, two others cited a section of an expanded registry instead of the row that actually owned the fact. **Reflex: budget the inbound walk as an audit, not as cleanup — the deletion is the excuse, the drift is the yield.**

### Design rules

- **Self-consistency, not hardcode** — derive interdependent numbers from one parameter.
- **Context-anchor, never a bare number** — the same value is legitimate against different owners (provenance-mix at meV).
- **Pin an invariant, not a growing counter.** "8 Lorenz constants" is mathematics; "9 economic ones" grows, so the gate flags honest additions and gets switched off. 🔴 **The mirror case bites harder, because the gate then punishes an IMPROVEMENT** (SEC.25, 2026-07-28): a `producers.size >= 12` liveness canary went red the moment a duplicated broadcast was extracted into one method — 12 calls became 11, and the gate reported "extractor blinded" about a pure dedup. Lowering the number just re-arms the trap. The stable form for "is the extractor still looking at the right tree" is **coverage of a curated FILE set**: immune to how many calls live inside each file, still a tripwire in both directions, and it names what to do when a file legitimately leaves (remove the row in the same commit). General rule: a canary must count something the work is not allowed to change, and *call sites* are exactly what refactoring changes.
- **Two sets with an element MIGRATING between them → compare each separately, never their union** (GOV.2: a migration leaves the union unchanged, so a union-check is blind exactly on its own class).
- **A pin is one-directional** — `canonical_block_drift` hashes only `source:`; `mirrors:` is prose, so editing a mirror does not move the gate. Ceiling recorded in `00_06 §3`.
- **The gate form prescribed inside a tracker item is itself revisable** — do not implement a bad shape because an item named it.

### Mutation-verify: the pitfalls

- `git checkout` also reverts an UNCOMMITTED fix → mutate with a reverse `Edit`, not a checkout.
- **A money-path constant is its own hazard**: editing `GAMMA` tripped the permission classifier, and rightly — an interrupted session would have left the tree broken. Make the pin engine a **pure function** and mutate **in memory**.
- A mutation that fails to apply, or breaks syntax, proves **nothing** — check that it landed (and that the file still parses) before reading the result.
- 🔴 **A mutation can land, parse, AND mean something other than what you wrote — so "it landed" is not the check; "what does it evaluate to" is** (SEC.25 Ф3, 2026-07-29). To prove a stream name's epoch suffix was load-bearing I neutered it as `#{'' && epoch}` — and in Ruby the empty string is **truthy**, so the expression returned `epoch` and the name went from `..._org_5_e1` to `..._org_51`. The epoch was still in the name; only the separator died. Seven examples went red (they pin the literal), the one end-to-end example that pins the *mechanism* stayed green, and the obvious reading — "that pin is vacuous" — was exactly backwards: the pin was fine, the mutation was. Note why the usual safeguards all passed: the file changed, `ruby -c` was OK, and the suite went red. **Reflex: for any mutation more clever than deleting a term, print or reason out the mutated VALUE once** (`..._org_51` would have shown it instantly), and prefer the dumbest possible mutation — drop the term entirely rather than short-circuit it. Sibling of the fixture-collision bullet below: there the mutation was semantically right and the data made it a no-op; here the data was fine and the mutation was wrong.
- 🔴 **A mutation can be semantically RIGHT and still prove the opposite, because the object under it is memoized — and the failure direction is FALSE-POSITIVE, i.e. "the lever works"** (SEC.25, 2026-07-30). To show that rotating `Turbo.signed_stream_verifier_key` invalidates every issued stream name, I reassigned the key in-process and re-verified a name: it still verified, which reads as "rotation does nothing". Cause: `Turbo.signed_stream_verifier` is `@signed_stream_verifier ||=`, so the verifier was built once and the new key never reached it. The honest measurement is **two separate processes**, and it returned `nil` as designed. Note which way this cuts — had I been *confirming* rather than *doubting*, the same experiment would have "proved" the lever fine while it was inert. **Reflex: for anything read through a memo, a cache, a connection pool, a class-level `||=`, or a config frozen at boot, mutate by starting a NEW process — never by assignment.** Sibling of the bullet above: there the mutation was wrong and the data fine; here the mutation was fine and the *object* stale.
- 🔴 **A mutation that LANDS can still be a no-op, because the fixtures make the wrong value equal the right one** (SEC.25, 2026-07-27). To prove a request-spec really pinned *whose* organization, I swapped `current_user.organization` → `Organization.first` — and the suite stayed green. Not because the pin was weak in shape, but because the spec's own `let` ordering created the user's org **first**, so the two expressions were literally the same record. A single-subject spec cannot distinguish "the right one" from "the first one", "the only one", or "the last created one"; the fix is a **second subject that must get a different answer** (two users in two orgs), after which the same mutation goes red. **Reflex: when the thing under test is a SELECTION, the mutation must be to a plausible WRONG selection — and the fixture has to make wrong ≠ right.** Corollary: a mutation surviving is a claim about the spec, so investigate it; treating green-under-mutation as "close enough" is how a pin that pins nothing gets committed with a comment saying it pins something.
- 🔴 **The mirror of "a spec that cannot fail": a pin constructed so it can never PASS — and it looks like a real regression** (SEC.25, 2026-07-31). A fresh cross-tenant pin asserted `not_to include(foreign_wallet.crypto_public_address.to_s)`. That record's address is `nil`, `nil.to_s` is `""`, and `include("")` is true for every string — so the example failed on a correctly-behaving app, and the obvious reading ("the fix is missing") was exactly backwards. Note the shape: the emptiness came from the *fixture path*, not the assertion — the wallet is built by a `Tree` callback rather than the factory, so the attribute the pin keyed on was never populated. **Reflex: any negative assertion on a value read off a record must first prove that value is non-blank** — `expect(x).to be_present` before `not_to include(x)` — and when a brand-new pin goes red, suspect the pin before the code, because a pin has never been mutation-verified yet while the code usually has.
- **Verify by EXIT CODE after every batch**, never by `| tail` (a cut-off FAILED header reads green).

### Hardening checklist

`tolerance = 1 display digit, NOT 0.5` · `encoding=utf-8` · `findall == 1` ambiguity guard · coverage gaps · **a guard's CI job must be import-free stdlib** (a bare runner without numpy breaks CI in a way the author never sees locally; lib-importing guards belong in the conda job) · **propagation twins** — pinning only `SUMMARY` leaves stale twins when the path-filter never fires for them.

### Odds and ends that earned their line

A guard does not pin its own reason for existing · a golden test that validates DEFAULTS cements an off-spec number · a curated map is a tripwire (a dead entry must go RED) · science surfaces need a real guard, not `stan_audit` (symbols vs numbers — prove ingestion) · an honesty-pass that comes back POSITIVE is a preventive guard · **a skill mirror rots more quietly than canon → sweep the skills in every closing pass** · the best sort of mutation-proof is **a gate that catches its own author** (`DOC-T.15` line-refs and the vertical-list linter both bit the person writing them).

## Gotchas (hard-won)

- **Subset `bin/rspec` runs trip the SimpleCov coverage gate** ("Models 0% < 90%" / `minimum_coverage`). That's an **artifact** of a partial resultset, not a real failure. The linter/ToC specs are pure units (`spec_helper`, no Rails/DB) — run them gate-free with `COVERAGE=0 bin/rspec spec/lib/docs_*_spec.rb`; for app-coverage truth run the full `bin/rspec` (`[[feedback_local_verify]]`).
- **`db/structure.sql`**: never stage drive-by Postgres-version line diffs — restore from HEAD (`[[feedback_structure_sql]]`).
- **No volatile counts in prose** (test/line tallies drift every commit). Reference the source or generate it (`[[feedback_no_volatile_counts]]`).
- **`wiki:sync` needs SSH access** to the `*.wiki.git` repo; **always dry-run first**; read its "unresolved links" — they're often stale source links worth fixing. **Run it PLAIN** — never prepend `/usr/bin` to PATH (shadows the rvm ruby shim → system Ruby 2.6 → bundler crash); a `Gem::Resolver…GemParser` trace can also be a SentinelOne-eaten shim (`[[project_rvm_env_repair]]`).
- **A missing closing ` ``` ` fence silently desyncs EVERY fence-aware guard** (the `in_fence` toggle runs in ~9 `DocsLinter` methods) + truncates the ToC — one unclosed fence disables them all at once. **Now HARD-gated**: `DocsLinter.unbalanced_code_fences` (DOC-T.45, 2026-07-18) counts fences by the SAME `line.start_with?` predicate the guards use, so `docs:check_refs` aborts on an odd count (reporting the opening line) — a mirror gate, self-consistent with what it protects.
- **A freshly-written guard can be pure decoration, and a green baseline HIDES it** — the `\z`-vs-`\Z` dead-scope class (DOC-T.52). Full account, with the other blindness shapes, in **§Guard-craft** above; it is the reason recipe step 4 is not optional.
- **Homoglyph / mixed-script drift** — a Cyrillic letter hiding inside a Latin word (`geniпin`-class) passes every ASCII gate. Detector = a perl per-letter-run scan flagging any `\p{L}+` run that carries Latin+Cyrillic TOGETHER; run it after chemistry-name work (ligand / enzyme names are the usual carriers).
- **`.c` firmware comments stay Ukrainian + the file's poetic house style** (`[[feedback_comment_style]]`).
- **zsh**: `status` is read-only; quote globs (`[[feedback_zsh_bash_gotchas]]`).
- **Required-check caveat**: if `ci.yml` jobs are *required* status checks, also mark `docs.yml`'s gate required — else a docs-only PR (which skips `ci.yml`) could merge without the gate enforced.
