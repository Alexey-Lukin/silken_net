1. **Shared peripheral, per-operation reconfig: restore the baseline — and make sure a baseline EXISTS.** Named instance: Queen MUST call `Restore_ECB_Mode()` after every CBC operation, else subsequent LoRa decrypts silently fail (wrong KeySize + wrong key in CRYP). The class is wider than CRYP — it has bitten in **three different shapes**, and the breakage always lands on the NEXT user of the peripheral, never on the caller who reconfigured. Check all three whenever a peripheral has more than one caller (CRYP · Radio · SPI1 · ADC · DMA):
   - **(a) configured, never returned** — the original SEC.8/FW.16 ECB↔CBC, plus CCM width-units (`MX_CRYP_Restore_From_CCM` puts the width-units back to WORD and re-runs `MX_CRYP_Init` — DataType 32B + ambient key; gotcha 7.1). CRYP-specific home: `03_05 §7`.
   - **(b) nothing to restore TO** — ✅ **closed 2026-09-11 [FW.61]**, and the shape is worth keeping because it is the one a restore-reflex cannot reach. Baseline LoRa modulation used to be set by **no call at all**, so the peripheral carried whatever the last writer left. `RadioInit` is not a baseline: it programs timers/IRQ and `SUBGRF_SetTxParams(RFO_LP, 0, …)` — the **low-power PA at 0 dBm** — while SF/BW/CR/preamble/CRC stay unwritten, and `SubgRf.RxContinuous` stays `false`, which silently turns the Queen's always-on listener into RX-single. **A driver default is not a baseline; only an explicit call is.** The doc home of the NUMBERS is `03_05 §2.1` (`00_06 §2.3` registry); the compiler's declared MIRROR is `firmware/common/lora_phy.h` (pure profile) + `lora_phy_apply.h` (`Lora_Phy_Apply_Sync_Word` · `Lora_Phy_Apply_Tx/Rx` — the single seam both firmwares and `make -C firmware/test lora_phy` call). ⚠️ The two setters share ONE pair of driver structs, but TX-before-RX is a convention; the ONE load-bearing order is `Lora_Phy_Apply_Sync_Word()` FIRST (boot and after the LoRaWAN detour) — it calls SetModem inside and restores what the detour left in the register (why → the header of `lora_phy_apply.h`). `RadioSend` rewrites payload length per frame.
   - **(c) a partial restore reads as a complete one** — ✅ **closed by construction in the same pass, and that is the point**: the panic-TX restore used to re-set ONE of six `SetTxConfig` arguments (preamble) and pass a private `LORA_PANIC_*` quartet for the rest, correct only because that quartet happened to equal canon. Those defines are gone; PANIC now differs from baseline in exactly one argument, because there is only one place the other twelve are written. **Whenever you see a "restore" that names fewer arguments than the call it undoes, the fix is not to widen the restore but to remove the second copy of the defaults.** ⊕ **2026-09-24 the seam grew a second variable argument, and it is a different kind** (⚖️ FW.61): TX power became a per-ROLE constant (`LORA_PHY_TX_POWER_DBM_SOLDIER` 14 ⊥ `_QUEEN` 10 — the Queen's ERP ceiling with her 5-dBi antenna), passed like `rx_continuous`. 🔴 Both constants are `int8_t`, so a Queen call site handed the Soldier's constant compiles clean: the `_Static_assert` in `lora_phy.h` judges the VALUE of `_QUEEN`, never WHICH constant a call site picks, and the host pin judges the seam's form, not `main.c` (declared blindness (2) of FW.61). A new `Lora_Phy_Apply_Tx` caller — read its role off the file it sits in, and grep `TX_POWER_DBM_` in the diff before you push.
1b. **Queen re-resolves the CoAP server IP after N≥3 consecutive flush-fails, so an A-record flip is picked up without an IWDG reboot** (FW.58 host-half, vilize 07-11) — flow + RAM table → `03_02 §4` (`Coap_Reresolve_Due`, `sim7070_coap.h`). ⚠️ Two counters, never merge them: `coap_consec_fail` (streak, resets on any `send_success`, drives the re-resolve) ⊥ `g_coap_fail_count` (lifetime health odometer, never reset); the DNS-fail path `return`s before the streak. Silicon-confirm = RUNBOOK §5.5 (👤 bench). There is no runtime backend-switch command — failover is the A-record flip only.
1c. **Retransmit is UPLINK-only — the downlink poll has none, so a lost 2.05 is recovered only by the `cmd=` echo cursor, never by a CoAP retry (FW.63).** `Flush_Cache_To_Rails` increments `coap_mid` ONCE and retries the same PDU inside `for (retry < COAP_MAX_RETRIES)` — a genuine same-MID CON retransmit. `Queen_Poll_Downlink` does the opposite: `coap_mid++` on **every** attempt and `return`s on an empty reply, and `Sim7070_Udp_Fetch` is a one-shot `CAOPEN→CASEND→CADATAIND→CARECV→CACLOSE` with no internal retry. So a lost 2.05 on the downlink poll is **never re-requested** at the CoAP layer; the order survives only because the `cmd=` echo re-serves it (below). Rails' `CoapGate::REPLY_CACHE` is real but only dedups a *duplicated datagram*. ⚠️ **No retransmit does not make the MID cache safe:** `coap_mid` lives in the Queen's RAM and the cache slot has no TTL, so after a reboot the same number arrives carrying a DIFFERENT question. Serving the cache there answers someone else's poll and silently swallows the live pending command. Today `CoapGate::REPLY_CACHE` is keyed on a request FINGERPRINT (route + query): match → `poll_duplicate`, mismatch → `poll_mid_collision` + fresh derivation. The transferable half: **a cache keyed on a counter that its writer resets is keyed on nothing** — ask what zeroes the key, not just what increments it. Two reflexes: (a) **never generalise one CoAP tract's reliability onto the other** — that is exactly how the false claim entered three docs and two code comments; (b) the OTA leg shows the correct shape — `g_ota_fetch_next_ch` does not advance until the chunk is handled, so a lost chunk is simply re-requested; CMD's equivalent cursor is the `cmd=<token>` echo (below). ⚠️ **CMD's cursor is the echo:** Rails does only `dispatch!` at build time; `acknowledge!` waits for `observe_delivered_command!` to see a `cmd=<token>` echo from Queen (`g_last_acked_cmd_token`, mirroring `fw=`) on a later poll, so a lost 2.05 now re-serves the same envelope instead of losing the order — `Cmd_Dedup_Check` makes the redelivery safe. Design-justification (why echo over blind re-delivery or a documented open-loop) → `03_02 §4а`; state and chronicle → `00_07` FW.63. ⚠️ **And the echoed token is the LAST colon-field, never «the 3rd colon» (FW.60, 2026-09-10):** an `ACTION:value` payload shifted the old window onto ACTUATOR_ID, so the echo never matched `idempotency_token` and an EXECUTED command died by TTL as `failed` — the dedup hash stayed self-consistent, which is exactly why nothing noticed. Locator = pure header `firmware/queen/cmd_token.h` (host-pinned, mutation-verified); Rails forbids a colon in ACTION (`ActuatorCommand::ALLOWED_PAYLOAD_FORMAT`), so both ends agree by construction — do not reintroduce a colon-counting parser.
2. **RTC registers are nearly all spoken-for — but allocated ≠ optimally packed** — DR0..DR19 allocated except **DR7, freed by FW.54** (DID is now deterministic `f(UID)` recomputed on boot via `did_derive.h` — `03_01 §7`; spend DR7 only via the `03_01 §2.2` procedure). After the FW.2 freeze-contract even DR15 is reserved (CCM Frame Counter, dormant until `FW2_CCM_ENABLED` flips at bench). For new persisted state: **first** check `03_01 §2.3.2` reclamation (under-utilized DRs → freeable without Flash: DR2 holds a 1-bit flag, DR14/DR19 pack) **before** paying Flash-KV (`03_01 §2.3`) wear. RAM-state inventory + key→field map = `03_01 §2.3.1`. Canonical register map (bit-fields + magic markers) = `03_01 §2` — never restate the allocation in code comments, reference it.
3. **`Load_AES_Key()` must run BEFORE `MX_CRYP_Init()` — reversed, CRYP silently uses a zeroed key.** Both files follow this order but it's easy to break during refactoring.
4. **Cold-TX deferral: at low temperature the Soldier skips TX entirely, so never assume every wake cycle emits a packet** — the FW.10 winter ESR guard against brownout (its Vcap half is degenerate in the field — gotcha 9).
5. **StatusByte layout is post-FW.29 — `[PanicFlag:1 | Status:2 | GrowthPoints:5]`, and status 3 means vm_error, never tamper** — packet byte 10 = `[PanicFlag:1 (bit7) | Status:2 (bits6..5) | GrowthPoints:5 (bits4..0)]`; firmware packs `(status << 5) | growth_points`, backend unpacks `(byte & 0x1F) * 2`. `Status` now has 4 values (0 homeostasis / 1 stress / 2 anomaly / 3 **vm_error** — [SLASH-1 P0, 2026-07-05] status=3 is written ONLY by `BIO_STATUS_VM_ERROR`; mruby `pack_status_byte` returns 0..2; physical tamper rides PANIC_FLAG, NOT the status bits — backend side → #10). Normal frames force bit7=0 (`lora_payload[10] &= ~PANIC_FLAG_BIT`); panic frames set it. Canon: `03_04 §4.4` Status-byte + `03_01 §8`.
6. **Lorenz state on boot is a warm continuation from DR16–18 only when DR19 holds the magic AND all three values are finite, otherwise a cold start derived from `K_seed`** — table + the MUST-write invariant (DR16–18 + DR19 after every cycle) → `03_04 §2.1`; layout → `03_01 §2`. Non-obvious here: the cold-start math is One-Home `firmware/common/lorenz_seed.h` (FW.30, byte-parity with backend `SeedDerivation`); `epoch_day` prefers beacon UTC (`soldier_unix_ts`, FW.20); the RTC default after VBAT loss = 10957 = backend `FIRMWARE_RTC_DEFAULT_EPOCH_DAY`.
7. **CCM is gated, ECB is live — WL CCM API is TWO-PHASE, and the CCM era is TWO-KEY** — the FW.2 AES-128-CCM path (30B wire-rev2.1, 8B MIC, DR15 FC) is fully integrated behind `FW2_CCM_ENABLED 0` (Soldier Phase-4 + panic TX; Queen = blind courier — cleartext-DID demux, NO decrypt, air+1 records via `firmware/queen/rx_route.h`). The shipping build is **AES-128-ECB transitional**. Traps: (1) `HAL_CRYPEx_AESCCM_Encrypt/Decrypt` DO NOT EXIST in WL-HAL (F4/F7/L4 API) — the real flow is `Init.B0` (`Build_CCM_B0`) + `HAL_CRYP_Encrypt/Decrypt` (Size in BYTES) + `HAL_CRYPEx_AESCCM_GenerateAuthTAG` + caller-side `Fw2_Ccm_Tag_Equal`; after CCM restore width-units to WORD (`MX_CRYP_Restore_From_CCM`). (2) In the 14B CCM plaintext (rev2.1) `status_byte` is offset 6, offset 10 is `diag`, offsets 12..13 are `ema_delta_t_s` («wire = GP input» contract, E.63 (г)) — never read CCM payload through legacy 16B offsets. (3) **Key-scoping (FW.2 (в), 2026-07-03)**: Soldier's ambient `hcryp` = **KEYB cluster control-plane** (`bcast_key`, page 125, `Load_Broadcast_Key` fail-open fallback→KEYL); session `aes_key` (KEYL) lives ONLY inside the CCM scope — `MX_CRYP_Init_CCM` sets `pKey` EXPLICITLY, Restore returns KEYB (a sticky session key would MIC-fail every frame on Rails). Queen's single LoRa key = the KEYB **value** (her code unchanged). FW.17 ratchet rotates session only. 8. **`HAL_GetTick()` is frozen in STOP2 — a tick delta measures active time only, never wall time, so use wall-seconds** — SysTick stops during `EnterSTOP2Mode`, so a tick delta measures only active-time, NOT wall-time. Host mocks have a monotonic tick → they hide this. **FW.49 S1 host-half is shipped**: `delta_t_seconds` (the *primary* bio-signal) runs on wall-seconds. ⚠️ The timebase is SPLIT across two files on purpose, and the header is the half that must stay pure: `firmware/common/wall_time.h` carries the HAL-free arithmetic (`Silken_Wall_Delta_Seconds` · `Silken_Wall_Elapsed_Seconds` · `Silken_Wall_Is_Utc` · `Silken_Civil_From_Unix`) so it compiles into the firmware AND the host tests, while the HAL half — `Wall_Seconds_Now`, which reads the RTC calendar and is ≡0 on silicon until the clock is set — lives in `firmware/soldier/main.c`. ⛔ Do not add a HAL call to the header: that seam is exactly what makes «host-half is shipped» mean anything. (`Wall_Seconds_Now`, RTC-calendar timebase, cold-start/backwards/epoch-jump guards → **сентинел `DELTA_T_UNKNOWN_S`**; wire `dT:2` saturates @0xFFFF). ⚠️ On silicon `Wall_Seconds_Now` returns 0 (honest refusal → сентинел → GP=0) until the LSE/RTC clock-tree bench bring-up — `00_07 FW.49`. ⚠️ Absent is the CLOCK-TREE, not the symbol: `MX_RTC_Init` is declared, called and stubbed across files (`git grep -n MX_RTC_Init -- firmware ':!firmware/extern'`) — its body is empty, so a grep for the symbol finds it and proves nothing; FW.27-B re-request counts silent wakeups instead of ticks (STOP2-immune by design). Still: never trust a raw tick delta as wall-seconds. Canon `03_01 §1.4`/`§1.10`. 🔴 **Fallback = SENTINEL, never a value** (ARCH.102): `DELTA_T_UNKNOWN_S = 0` branches BEFORE the formula on both mirrors (`bio_contract.rb#pack_status_byte` ⊥ `Attractor.expected_homeostasis_gp`) → `status 0, GP 0`, and the EMA is not fed on it — at 0 (and at the old «neutral» 60 s) `m` clamps to 1.0 → GP 31 = the maximum, so every placeholder value lands on over-mint. Why and when → the header of `bio_contract.rb` + `03_04 §4.3` + `00_07` E.63. **Reflex, wider than this site: push a fallback constant through the WHOLE chain — a «neutral» input is regularly the output's extreme; take «not measured» out of the value space.** ⚠️ `vcap` stays on nominal 3300 on purpose (BQ25570 regulates the rail) — two absences, two answers. 🔴 **Коли пишеш тіло `MX_RTC_Init` на бенчі, жоден гейт помилки в ньому не впіймає** (чому — `00_07` FW.49: `HAL_OK` зі сміттєвим, але ненульовим часом годує `metabolic_health()` і мінт). **Верифікація тіла — приладом на бенчі, ніколи зеленим CI.**
9. **`vcap_voltage` is honest mV of VDDA, NOT the EDLC Vcap — the rail says nothing about stored energy, so all four thresholds on it are degenerate** — post-FW.50 the raw-counts-as-mV bug is fixed: `vcap_voltage = Adc_Vdda_Mv(...)` (factory VREFINT-cal, `firmware/common/adc_convert.h`, host-tested) → ≈3300 mV while the buck lives. But VREFINT sees **VDDA behind the buck**, and BQ25570 regulates that rail to 3.3 V from VSTOR ≥ 3.4 V up to the cap's 5.5 (`02_03 §7`) — so the rail carries **no information about stored energy at all**, by design of the power tree. Until a real Vcap divider + separate ADC channel lands (hardware residual, `00_07 FW.50`), **every threshold on this rail is degenerate: FOUR constants over FIVE comparison sites** (`git grep -nE '(vcap_voltage|vcap_mv) *[<>]=? *[A-Za-z_]' -- firmware/soldier firmware/common firmware/queen`) — know all of them before touching any:
   - `VCAP_LISTEN_THRESHOLD = 2800` → always OPEN (3300 > 2800): the RX-listen window is effectively ungated, AND (CCM-gated, dormant) the FC-hiwater Flash-advance energy gate always passes.
   - `FAUNA_VCAP_MIN_MV = 4500` → always CLOSED. Deliberate honesty guard, tripwire-tested. **Don't "fix" it down.**
   - `CAD_PANIC_PREAMBLE_VCAP_MIN_MV = 4500` (`cad_sniff.h`) → mirror of fauna; panic preamble always falls back to the default 8 symbols, never the extended "last scream".
   - `COLD_TX_DEFER_VCAP_MV = 4000` (`tx_defer.h`) → always TRUE, so `Should_Defer_TX` collapses to `temp < −15°C` alone. [ARCH.99] The "cold but well-charged tree still transmits" clause is unreachable; direction is safe (silence, not damage) and panic frames bypass the predicate entirely.

   🔴 **The transferable lesson is about how the fourth stayed hidden for months, and it generalises past firmware.** Three of the four *declared* their degeneracy (canon FW.50 named two, `cad_sniff.h`'s own header named the third) — and the fourth's carrier asserted **the opposite** («обидві умови несучі — кон'юнкція, не диз'юнкція»). So any search keyed on the declaration (grep «fail-closed», «свідомо», «проксі») returns exactly the three that were already safe and is blind **by construction** to the only dangerous one. **Enumerate a class by its SHARED INPUT — grep the rail (`vcap_mv`), the column, the variable — never by the name of the thing or by the words its honest instances happen to use.** Sibling instance one domain over: `backend` #10, where the device-liveness bypasses never mention the predicate's name, so you grep `last_seen_at` instead. ⚠️ And do not read the host suite as evidence about the field: `test_soldier_logic` feeds vcap 4000/4001/5000 and genuinely *discriminates* — the function is correct, it is the **input** that cannot exist. Canon `03_01 §1.4` (FW.50 note — the list) + `§1.8а`; verdict A ratified 2026-08-13 (`00_07` archive, ARCH.99); the open fork is the live Vcap channel → `00_07` FW.50 ⚖️.
10. **`BIO_STATUS_VM_ERROR = 0x60`, not 0xFF — it must survive the panic-bit mask (`& ~PANIC_FLAG_BIT`) as status 3 with zero growth points.** Backend decodes status=3 as `vm_error` (honest software-fault → `firmware_fault` ops-alert, [SLASH-1 P0] — NOT tamper/vandalism); `emission_eligible_growth_points` zeroes gp for anomaly/vm_error (defense-in-depth). A wire byte with status=anomaly/vm_error must NEVER mint.
11. **OTA wire has two layers with different headers — LoRa Queen→Soldier and CoAP Rails→Queen — and a length is never guessed from padding** — LoRa Queen→Soldier: `[0x99][idx:2][total:2][bytecode:11]` (5B header). CoAP Rails→Queen: `[0x99][idx:2][total:2][len:2][bytecode:len][crc16:2]` — explicit `len` (NOT length-guessing from CBC padding — that bug truncated every chunk) + CRC16 verified via `firmware/common/silken_crc.h`. The assembled stream Soldier CRC32-checks = `bytecode + zero-pad + CRC32`, LoRa-MTU(11)-aligned. Built by `OtaPackagerService`. Canon `03_02 §5`.
12. **cppcheck version-skew: a green local lint proves NOTHING about CI** — CI runs cppcheck **2.13**, the local `silken_lint` conda env has **2.21**; the two classify diagnostics differently (2.13 gated `constParameterCallback` that 2.21 let pass → false-green local, red CI). Related trap: suppress-ids MIGRATE with usage — taking a callback's address flips `constParameterPointer`→`constParameterCallback`, silently unmatching an existing inline suppress. Also: deleting a header cppcheck couldn't resolve OPENS a deeper analysis path — expect previously-hidden pre-existing findings (2 shadowVariable surfaced when the radio.h stub died); fix them properly (rename), don't suppress.
13. **Enabling compile-coverage of a gated block = wire ALL its board-freeze deps FIRST; only the ARM `hal_check_ccm` lane sees the gated branch, so build it locally (`firmware/.toolchain/`, gotcha 7.4) before pushing, or each miss is a separate red CI push.** THREE parts, miss any → red main: (a) the in-file `#define GATE 0` MUST be `#ifndef`-wrapped so CMake's `-DGATE=1` sticks — a bare `#define` clobbers the `-D` (macro-redefined = warning-not-error, in-file wins → block stays dead = a silent no-op guard; the exact ARCH.34 bug, re-hit on ARCH.35); (b) board pin-macros stubbed in `queen_hal_check.c` **before** its `#include "../queen/main.c"` (macros must precede use); (c) every HAL module the block calls enabled in `firmware/hal_glue/stm32wlxx_hal_conf.h` — ARCH.35 W25Q32 SPI → uncomment `HAL_SPI_MODULE_ENABLED` (mirror of how ARCH.34's block needs the already-enabled `HAL_FLASH`; compile-only OBJECT lib = header decl suffices, no link). **Grep the block's FULL external-symbol set** (`sed -n 'A,Bp' main.c | grep -oE 'HAL_[A-Za-z]+|[A-Z][a-zA-Z]+_HandleTypeDef|<pin-macros>'`) and wire each BEFORE the first push — a review that flags one missing dep can miss a second (it flagged `W25Q32_CS`, not the SPI-HAL module). The macro-redefinition + gate arithmetic ARE host-verifiable (`cc -DGATE=1 -E`), even though the block itself isn't.
14. **The audio window is guarded BEFORE the HAL, and the vendored HAL is the reason** [ARCH.102, 2026-09-09]: `HAL_ADC_Start_DMA` dereferences `hadc->DMA_Handle` before any check (three XferCallback assignments in vendored `stm32wlxx_hal_adc.c`), so an unlinked DMA is not `HAL_ERROR` but a NULL write → HardFault — the missing piece was the LINK (`MX_DMA_Init` + `__HAL_LINKDMA`), not a timeout. `firmware/common/audio_dma.h` is the One-Home for the predicates (`Audio_Dma_Peripherals_Ready` · `AUDIO_DMA_TIMEOUT_MS 250` · `AUDIO_DMA_IDLE/DONE/ERROR`): all three ways of not measuring land in `AUDIO_DMA_IDLE`, so inference never runs on a fabricated buffer (the `DELTA_T_UNKNOWN_S` discipline of gotcha 8). ⚠️ The vectors (`DMA1_Channel1_IRQHandler` · `EXTI0_IRQHandler`) live in `main.c` — there is no `stm32wlxx_it.c` — and before 2026-09-09 they did not exist, so both callbacks were dead code (`vibration_detected` could never become 1 on silicon). ⚠️ Host/compile level only: on today's silicon the gate stays CLOSED (`MX_ADC_Init`/`MX_TIM2_Init` bodies empty until the FW.46 board-freeze); the post-ARCH.102 pipeline is `03_01 §1.5` + `03_03 §2.2`. ⛔ A second acoustic counter's slot comes from the `03_01 §2` DR0 row (`[10]` = the SEC.21 canary bit), never from a comment — gotcha 2: reference the map, never restate it; incident → `00_07` ARCH.102.
