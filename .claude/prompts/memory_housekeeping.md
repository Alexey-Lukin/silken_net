# Промт: Memory Housekeeping (догляд за персистентною пам'яттю)

> **Як використовувати:** встав цей файл (або «виконай `.claude/prompts/memory_housekeeping.md`») коли власник просить упорядкувати / почистити / структурувати персистентну пам'ять (`…/memory/MEMORY.md` + `*.md`). Це **дім** методу; skill `memory-maintenance` лише посилається сюди. Спілкуйся українською. Канонічний **формат** пам'яті (frontmatter, типи user/feedback/project/reference, Why/How-to-apply, `[[name]]`-лінки, один факт = один файл) живе в системному промті — тут його НЕ дублюємо, лише застосовуємо.

---

## 🎯 Місія

Тримати пам'ять **чистою, структурованою й без дублів** — але **БЕЗ АМНЕЗІЇ**. Індекс має бути тонким (гачки), деталь — у файлах; відкриті дії — у трекері (`00_07`), а не лише в пам'яті. Покращувати, а не видаляти цінне.

**Дух роботи (цитати власника, 2026-06-13):**
- «живе цінне не удаляти, краще якісно таке покращити.»
- «повиносити ще сміття з памяті, але акуратно, спокійно і впевнено, **нам не треба амнезії**.»
- «Мені головне щоб **не удалилось те що треба**.»
- «все що ми знаходимо по дорозі що треба робити, **то не губи**.»
- «якщо було щось в памяті що ще **робити, перевіряти** … і його **нема в 00_07** — то краще туди занести.»
- «поструктурувати, повидаляти дуплікацію … **глибоко** досліди, проаналізуй як краще. Дуже уважно.»

> ⚠️ **Залізне правило конфлікту:** коли «прибрати сміття» свариться з «не загубити потрібне» — **перемагає збереження**. Сумніваєшся → лишай. Звітуй чесно, а не вигадуй видалення.

## 🔢 Порядок (по кроках, не поспішаючи)

### 1. Інвентаризація + цілісність (ПЕРЕД будь-якими змінами)
- Список усіх файлів: розмір(байти)/рядки/тип. Знайди **викиди** (один файл у рази більший — кандидат на внутрішнє тоншання, але див. крок 4).
- **1:1 index↔files:** кожен `- [..](file.md)` у `MEMORY.md` → існуючий файл; кожен файл (крім `MEMORY.md`) → має рядок в індексі. **Жодного broken-pointer чи orphan.**
  ```bash
  # health-gate — exit 0 = healthy. Run BEFORE (baseline) + AFTER (zero-loss proof).
  fail=0
  for fn in $(grep -oE '\]\(\w+\.md\)' MEMORY.md|tr -d ']()'); do [ -f "$fn" ]||{ echo "BROKEN:$fn"; fail=1; }; done
  for f in *.md; do [ "$f" = MEMORY.md ]&&continue; grep -q "($f)" MEMORY.md||{ echo "ORPHAN:$f"; fail=1; }; done
  for l in $(grep -rhoE '\[\[[a-z0-9_]+\]\]' *.md|tr -d '[]'|sort -u); do [ -f "$l.md" ]||{ echo "DANGLING:[[$l]]"; fail=1; }; done  # струни резолвяться
  for f in *.md; do [ "$f" = MEMORY.md ]&&continue; { grep -q '^name:' "$f"&&grep -q 'type:' "$f"; }||{ echo "FORMAT:$f"; fail=1; }; done
  exit $fail   # 209-vs-0: ненульовий = зламана струна / формат / integrity
  ```

### 2. Індекс = ТІЛЬКИ гачки
- `MEMORY.md` — один рядок на пам'ять: `- [Title](file.md) — короткий гачок`. Деталь живе у **файлі**.
- Якщо гачок розрісся у стіну тексту (історія/деталь) — це сміття В ІНДЕКСІ. **Перед** тоншанням **переконайся**, що ця деталь реально є у файлі (grep по ключових токенах/раундах), і лише тоді обріж гачок до 1-2 речень + «деталі у файлі». (Прецедент: гачок 7861→786 символів після перевірки, що R6-R12 у файлі.)

### 3. Структура по типу (reorder VERBATIM, нуль-втрата)
- Згрупуй `MEMORY.md`: `## 👤 User` / `## 🛠 Feedback` / `## 📚 Reference` / `## 📦 Project`. Велику секцію (>~15) під-групуй (`### …`).
- Роби **скриптом-reorder** (рядки переставляються байт-у-байт + заголовки), НЕ переписуй гачки руками. Класифікуй за префіксом імені файлу (`user_`/`feedback_`/`reference_`/`project_`).
- **Доведи нуль-втрату:** `diff <(grep '^- \[' BACKUP|sort) <(grep '^- \[' MEMORY.md|sort)` → `IDENTICAL`.

### 4. Прибрати сміття — але verify-before-delete (no amnesia)
- **Сміття** = справді мертве: дубльована-в-індексі деталь, стейл-статус, що вже resolved, editorial-шум. **НЕ сміття** = уроки, рішення, відкриті айтеми, «чому», `[[links]]`, наукова провенанс.
- Тест на видалення: *чи спричинить втрата амнезію (зникне потрібний факт/урок/рішення/відкритий пункт)?* ТАК → лишай. НІ → можна прибрати.
- **Великий історичний файл (campaign-history тощо) — це дім-деталей за дизайном.** Його вага — норма (він поглинає деталь, щоб індекс був тонкий). НЕ потрошити без явної згоди власника; уроки вплетені в механіку — різати ризиковано. Запропонуй конкретну стару секцію на стиснення, не гати весь запис.

### 5. Дублікація (рідкісна)
- Реальний дубль зазвичай = **index-vs-file** (крок 2); memories лінкують `[[name]]`, не повторюють. Два РІЗНІ факти однієї категорії — **не дубль**. Глибше → family 4 (router).

### 6. Action-items → 00_07 (щоб пережили будь-яке тоншання)
- Пройди проєктні пам'яті на відкриті **to-do / to-check / follow-up / pending / residual / awaiting**.
- Для кожного: чи є воно в `00_07`? (`grep` по темі/ID). Багато вже там (напр. IP→UNI.3, partner→UNI.*, reliability→E.*).
- **Якщо НЕ в 00_07** — додай туди коректним item'ом (правильна §-секція за канон-домом; `section-home` guard вимагає, щоб meta-ref модуля = секція). Потім **встав у пам'ять рядок `Tracked in 00_07: <ID>`** — щоб видно було, що не загубиться.
- Зовнішні треди (партнери/нейминг/рішення) теж лічаться як action-items.

### 7. Стейл-гачки
- Звір гачок з файлом, онови розійдені (перенумеровані ID, зроблені задачі) → mirror-факти гниють, decay-typing family 5.

### 8. Безпека
- Механіка правок (span-replace унікальним маркером, `cp`-backup, glue-guard, set-diff) → family 2. **Пам'ять поза git** (`~/.claude/…`) — немає `git revert`, backup = єдина safety-net.

## 🧠 Durable-уроки

> **Auto-consolidate — метод застосовується до себе.** Уроки живуть у 6 іменованих family нижче (стабільний каркас). Новий урок → **влий рядком у відповідну family**, НЕ приклеюй окремий date-stamped абзац (саме так секція колись розрослась у стіну, яку довелось рефакторити). Нова family — лише якщо принцип не лягає в жодну (тримай ≤~7). Family переросла ~6 рядків → стисни її тим самим методом. «Коли вивчено» → git, не текст.

**Дух:** чистка добре-доглянутої памʼяті = де-bloat + структура + стейл-фікси, **НЕ масове видалення** (той самий «не вигадуй переноси», що в SSOT). Скорочуй **ТОЧКОВО, не пропорційно**: 0 у щільному (guards/принципи), багато — де вода. Сумніваєшся → лишай (перемагає збереження).

### 1 · Verify-before-delete = READ, не grep
- Деталь мусить жити в **ДОСТУПНОМУ домі** (файл / канон / `00_07` / інша памʼять / код) ПЕРШ ніж зрізати її з індексу/гачка. ⚠️ **git-історія — НЕ дім** (founder: «в гіт рідко дивляться») — «воно є в git» саме по собі НЕ виправдовує видалення потрібного. [[feedback_verify_canon_before_delete]]
- **grep = FALSE-negative-машина** на unicode (β/ρ, кирилиця) + markdown (`**bold**`-між-слів, `` `backtick` ``, «лапки», case `Same`≠`same`) + `\|`-ERE-alternations → присутність lessons/«чому» підтверджуй **READ-ом** (файл малий = дім факту), grep лише перше наближення (кусало ≥4× за кампанію, включно з самим curator'ом під час крос-файл-скану).
- Обрізати дубль-**СТАТУС** (список, що 100% у файлі) безпечно; чіпаєш lessons/«чому» — READ.
- Verify **АКТУАЛЬНИЙ стан** цілі, не памʼять «що нібито зробив» (`wc -w` викрив блоки, які я вважав done).
- **ID-родини в `00_07` = РЕЄСТР визначень** (канон реферить по ID) → видалити дефініцію = dangling-ref + `tracker:check` FAIL (спіймано гейтом → restore). [[reference_deep_archival_prompt]]
- **No-volatile:** гачок не тримає дрейфливі лічильники. [[feedback_no_volatile_counts]]

### 2 · Merge зберігає / Compress — окрема операція
- **«merge+dedup» ≠ «скоротити»** (founder спиняв мене серед merge): зливаючи N блоків — КОНТЕНТ кожного *verbatim*, схлопуй лише СТРУКТУРУ (N headers → 1 + теги) + прибирай *справжній* дубль (recurring-урок → одна «shared» нота + `→`-pointer). Компресія = окрема операція з окремою вказівкою.
- **Гейт на МОМЕНТ запису, не лише на прибирання:** anti-wall правило (SKILL/prompt) інвокується на «почисти» — ПІСЛЯ накопичення; стіна ж муриться в кінці сесії (append=O(1) vs consolidate=O(n) → append виграє щоразу). Лік (shipped): преамбула `MEMORY.md` з write-time тригером «пишеш date-stamped абзац? STOP → знайди family», що читається ЩОСЕСІЇ. [[feedback_memory_curation_autonomy]]
- **🔴 Рефактор без порога-на-ФАЙЛ = тимчасовий; хвороба мутує під БУКВУ правила.** Той самий `feedback_vilize_sweep_method` за 18 год після рефактора відріс 35→53 kB (15 Edit-ів, **жодного мінуса**): «влий рядком» працювало, «стисни family» не спрацювало ЖОДНОГО разу — убили date-stamp, і абзац вдягнув дефіс, звучись «рядком»; дотиснули «≤8 рядків» — рядки роздулись удвічі. Тож поріг став на **файлі** (≤~40 kB): консолідація товстить рядок ЗА ВИЗНАЧЕННЯМ, тому «≤N B на рядок» суперечило б «влий у наявний». **Діагностика рецидиву = jsonl-археологія** (`Dir["*.jsonl"]` → `tool_use` Write/Edit по file_path: `Write` = повний розмір, сума `new_string−old_string` після нього мусить збігтися з поточним — збіг доводить, що НІЧОГО не віднімали). [[feedback_no_volatile_counts]]
- **🔴 Family-рефактор чужого метод-файлу = окрема операція** (прецедент 2026-07-16: `feedback_vilize_sweep_method` 53→35 kB, 17 date-stamped абзаців → 7 families). Date-stamped-абзацна форма = **жанрова хвороба**, не властивість цього промта: ≥5 абзаців «§XX-ітерація (дата, `hash`)» = рефактор назрів. **Порядок обов'язковий:** (1) уроки витягує агент-ЧИТАЧ (не grep) → (2) перевір, які **не мають другого дому** — per-section файл може НЕ мати абзацу в методі взагалі (§03b/§05 не мали → 5 money-path-уроків жили в одному екземплярі) → (3) **розшир `Related` ПЕРШ** (тут виявляються односторонні `in`-only струни) → (4) лише тоді ріж. Зникає: `§XX`-заголовки · голі інвентарі (`00_07` = live SSOT) · мантра-лічильники (`stan_audit §XX = 0` ×8) · хеші-прикраси · мертві `NEXT = §XX` (після замкнення циклу = **дезінформація**, не сміття). Лишається: демонстрації пасток (навіть із датою), «чому», founder-рішення, рецепти. **Дім↔метод двосторонні:** дім може слати В метод по уроки → метод тримає ПРАВИЛА, доми ІНСТАНСИ; зріз абзацу наосліп = амнезія в обидва боки → READ дім, питай «дім тримає правило чи лише фікс?».
- **Прозова цитата в `[[дужках]]` = фальшива струна:** «деталь → git + `[[memory]]`» граф читає як лінк, і вона «резолвиться» лише через **case-insensitive macOS** (`memory.md`→`MEMORY.md`) — на Linux dangling. Health-gate кроку 1 це пропускає (`[ -f ]` case-insensitive) → додай `ls | grep -ix`. Цитуючи анти-патерн, НЕ бери термін у `[[…]]`.
- **Big-file механіка:** (a) cross-cutting-уроки → READ `§Durable` ПЕРШ (anti-amnesia); (b) Ruby span-replace межами по **УНІКАЛЬНОМУ маркері** (НЕ `[[link]]`/спільний токен — presence-guard інакше abort-не на не-той-span, і саме це рятує) + `cp`-backup + set-diff guard-імен; (c) **leading-`\n` glue-bug** на row-removal (same-file Edits — ПО ОДНОМУ, ніколи паралельно; `replace_all`-cousin: хіт усередині `[...](...)` → таргетований одиночний Edit) → boundary-grep (`rg '\|\|'`) ПІСЛЯ кожної структурної правки (спіймав злиття `01_03).### Iter-4`) → [[feedback_parallel_edit_glue]]; (d) format-residue (orphan `^>$`, no-blank-before-`#`) → scan наприкінці.

### 3 · Founder-signal + калібрування «не-інформації»
- **founder «ще є сміття» ПІСЛЯ твого «mostly clean» = ВАЛІДНИЙ сигнал**, не похибка (його «все ідеально = підозріло», обернене на тебе) — не захищай попередній прохід, шукай ІНШИЙ зріз. [[feedback_memory_curation_autonomy]]
- **«Не-інформація» калібруй на РЕАЛЬНИХ зразках з файлу** (абстрактне питання марне; multiselect зі зразками-рядками — влучний): клас = мета-наратив про мій процес (`didn't trust ✅`, `instinct WRONG`) · одноразові tooling-трюки · routine finding-переліки, чий дім деінде (`00_07`/canon) · повторні мантри + голі metrics. **Принцип + «чому» + founder-рішення + open-items = ІНФОРМАЦІЯ**, лишай.
- **Date/shipped/session = шум ЗАЗВИЧАЙ, АЛЕ демонстрація-багу/пастки = DURABLE** (`||`-glue parallel-edit, `c275120` bad-commit, `/ready` force_ssl — несуть техзнання; видалити = амнезія): прибирай дату/shipped-*обгортку*, демонстрацію ЛИШАЙ; дату-В-ПРИКЛАДІ (напр. `# fix (2026-06-06)`) роби generic (`(YYYY-MM-DD)`). «Поняття сесії» (S6..S24) = каркас-не-інформація → merge у тематичний виклад.
- **Zero-loss контракт:** links + guards + open-items + unique-lessons + safety = ТВЕРДЕ (set-diff vs backup = 0 lost); routine-ID-приклади можна прорідити, якщо дім доступний — але **ДЕКЛАРУЙ** прибране, не тихо.

### 4 · Memory = ROUTER (type-routing), не дублікат
- **Роль:** абсолютний контекст збирається ЗАНОВО щозадачі (memory→skills→canon→code) → «сміття» = все, що Claude однаково перечитає з canon/code; memory тримає лише стан / open-work / крос-домен-пастки / уроки / вказівники. [[feedback_task_execution_workflow]]
- **Type-route КОЖЕН шматок:** operational-*how* (генератори/CLI/код-список) → domain **SKILL** · shipped-*what* + заморожені рішення → **CANON** (+`00_07` ID) · live-state + крос-домен-уроки/«чому» → **memory**.
- **skill-gap-fill:** делегуєш «дім → skill X» → ВІДКРИЙ X, переконайся що РЕАЛЬНО містить (picogk/in-silico/ml мали прогалини після делегування) — інакше dangling pointer; донеси в skill ПЕРШ.
- **Стоншує НЕ фанатично:** operational-recap (picogk −66%) >> insight/decision-dense (sec_cluster/ip_posture/gaia = mostly-KEEP); decision/«чому»/open-стан = лишай.
- **Elevate крос-домен мета-урок в ОДИН дім** ([[feedback_computational_honesty_engine]]), усі вказують. **Routing-audit:** кожен project-файл МУСИТЬ маршрутизувати (canon / `00_07` / code / skill / `[[link]]`).
- **Двошаровість router'а (різні органи, різні закони):** `MEMORY.md` = **scan-шар** (glyph-стан ✅🔄🔴 + routing-теги для ОКА; товстий гачок ОК, якщо тег ≠ деталь файлу — оптимізуй на швидкий scan, не повноту) · файли + `[[струни]]` = **resonance-шар** (recall через мережу — струна = провідник, `in=0` вузол «провисає»; типізуй навантаженням `⊥`/`sibling`/`causal`/`kin`). Не дублюй resonance у scan і навпаки; `⊥` (свідома архітектурна жертва) — найцінніший, найрідкісніший клас: познач її ТАМ, де вона вже в прозі, + застереження «не полагоди» (optimistic-mint⟂custodial-trust; lopsided-defense). **Навігаційні ролі (корелюють з типом):** ⚓ **якорі** = `feedback`/`reference` (high-**inbound** — принципи, native-стабільні → орієнтуйся ПО НИХ, коли загубився) · 🗼 **маяки** = `project` (high-**outbound** — ведуть до роботи, але стан-світло частково `mirror`-гниюче → verify-target). Tensegrity/маяк-якір замір → §Systemic.

### 5 · Systemic — дивись з висоти (патерни, невидимі file-by-file)
- **broken-link = КЛАС:** dash-form `[[ssot-campaign-history]]` → underscore filename-slug; `grep -oE '\[\[[a-z0-9]+-[a-z0-9-]+\]\]'` corpus-wide → map (target-exists-guard) → re-sweep до 0.
- **🔴 ORPHANED-ГАЧОК = третій клас, health-gate СЛІПИЙ:** гачок цитує факт, який **МІГРУВАВ** з цільового файлу (auto-consolidate вилив урок у метод-дім), а роутинг лишився на старому. Лінк не dangling, файл існує → integrity-гейт зелений, а читач іде в **порожнє місце**. Лік: для КОЖНОЇ фактичної клаузи гачка — grep її ключового токена в цільовому файлі (0 hits = або мігрував, або вигаданий). Спіймано: «close-review зловив CI-break» (`vilize_01b` = 0, живе у `feedback_vilize_sweep_method` F4/F7) · «BQ-guard-straw-man» (`vilize_02a` = 0, живе F6). **Підвид-перлина: гачок цитує ЗАКРЕСЛЕНИЙ текст власного файлу** — файл сам себе виправив (`~~vilize-NEXT = §01a~~ → цикл замкнено`), індекс лишився на до-закресленій версії.
- **Volatile-лічильник у гачку не «дрейфливий» — він УЖЕ неправдивий:** «15 merged» проти `gh pr list` = **14 merged + 1 closed-superseded**. Емпірика > правило: перевір число ЖИВИМ джерелом, і воно саме доведе, чому лічильникам не місце в індексі ([[feedback_no_volatile_counts]]).
- **stale-drift = decay-typing (mirror-факти розпадаються, native — ні):** факт або **ДЗЕРКАЛИТЬ** canon/code/`00_07` (verdict/стан/`file:line`/«shipped X» — **HIGH decay**, гниє щойно source рухається @shipping → verify-vs-source ПЕРШ ніж стверджувати; closing-sweep-ціль [[feedback_task_execution_workflow]]) або **NATIVE** (урок / `⊥`-жертва / cross-domain-trap / founder-«чому» — **LOW decay**, memory Є дім, стабільне). reconcile vs canon = ТОЧКОВО на mirrors (не гати всі факти; спіймано e61/slashing-stale, manifest-overclaims). **Профіль чистки project-файлу ~ його STAGE-гліф:** ✅-journal (deploy/vilize_00 — завершена кампанія) хворіє ФОРМОЮ, не змістом (commit-хеші · «N-agent review» framing · мета-мантри = дублі дім-метод-файлу `vilize_sweep` F4/F6) → агресивний −50% де-cruft безпечний; 🔄-ledger (e61 — жива черга) звіряй NEXT/статус-мітки проти `00_07` ПЕРШ — **stale-NEXT = найгостріший mirror-decay: жене на ЗРОБЛЕНЕ** (ARCH.61 сидів «швидкий старт», а вже §🗄️), named-open усі зберегти, стискай консервативно. `⊥`-інваріанти = найстабільніший native-клас. system-reminder «N days old» = ГРУБИЙ проксі — тип точніший за час.
- **Standardize:** `name:` = filename-slug (= форма `[[link]]`); description = тісний one-line hook (тригери, без дат/інцидентів); кожен `[[link]]` резолвиться.
- **Frontmatter:** `node_type`/`originSessionId` = **HARNESS-managed** (re-stamp миттєвий на БУДЬ-який запис — file-watcher на `memory/*.md`; Bash-обхід більше не працює) → **НЕ стрипати**; format-guard = `name`+`description`+`metadata.type` присутні.
- **Tensegrity / recall-струни:** inbound-`[[link]]` = **recall-провідник** — вузол з `in=0` «провисає» (знайдеться лише прямим scan, не резонує через мережу). Пас: зміряй граф (`for f; grep -l [[slug]]` → inbound-count) → isolated (`in=0∧out=0`) = випав, напів-звислі (`in=0`) = провисли → напни recall-струну до **значущих** `in=0` (dormant/done лишай). Струна має нести навантаження в прозі (`sibling`/`causal`/`kin`/`⊥`), не бути декором; не вигадуй струну без семантики. **Generated maps як лінзи** (`⊥`-жертви · hub-колони · провислі · decay-клас) = **native**, завжди свіжі (grep обчислює з source, не гниє) — АЛЕ map-grep САМ жертва false-negative: наївний `⊥[^*]*⟂` проґавив **4 з 8** на `**bold**`/дужках-між → **verify map-патерн READ-ом** (карта бреше авторитетніше за спогад, бо виглядає точною).
