# HW.56 — the Soldier's schematic, written by code (power deck first)

The node's schematic is generated by `build_schematic.rb`, the same way `tools/pcb/*` generate boards: the agent writes and checks it without a window, the human opens the same file in KiCad. Ruling, tools and their limit (no vendor model of the power path) — [`02_01 §7`](../../../docs/02_01_Hardware_Architecture_and_BOM.md); state and open legs — [`00_07`](../../../docs/00_07_Action_Plan_Tracker.md) HW.56.

## What is here

| File | Role |
|---|---|
| `build_schematic.rb` | the source — generates everything below (AGPL-3.0-or-later, like all tooling); its header says where every number comes from and what the schematic does NOT prove |
| `soldier_power.kicad_sch` | the schematic (KiCad 10) — ⛔ do not edit it by hand: edit the generator and rebuild |
| `silkennet.kicad_sym` | the project symbol library: symbols corrected against their datasheets (today the BQ25570 — two pin types per SLUSBH2G) |
| `sym-lib-table` | the project library table — stock libraries through `${KICAD10_SYMBOL_DIR}`, ours through `${KIPRJMOD}`, so the schematic does not depend on the user's global table |
| `soldier_power.kicad_pro` | a minimal project file, so KiCad opens the folder as a project |

The design outputs are hardware design and fall under **CERN-OHL-S-2.0** by the zone map in [`/NOTICE`](../../../NOTICE); KiCad's S-expressions have no comment syntax, so they carry no per-file tag.

## Rebuild and check

```bash
ruby tools/pcb/soldier_schematic/build_schematic.rb           # regenerate + ERC + PDF + SPICE netlist into out/
ruby tools/pcb/soldier_schematic/build_schematic.rb --check   # the same, and red if the committed files lag the generator
```

Any Ruby works (no bundle); KiCad 10 is looked up in `~/Applications/KiCad`, or through `KICAD_CLI` and `KICAD_SYMBOL_DIR`. The run is red on any ERC violation (all severities), on a failed PDF or netlist export, on a capacitor value written with a bare `F` (SPICE reads it as femto), and on any pin whose net in KiCad's own exported netlist differs from the net the generator intended. That last check is what makes drawing safe: the generator keeps the intended connections (pin → net) apart from the drawing (wires, labels, ground symbols), so a wire that touches the wrong pin, or a label renamed to another existing net — which ERC cannot see, since no label is left dangling — turns the run red with the pins named. The drawing form (ground symbols, dividers as wired ladders, parallel capacitors on a shared rail, IC pins as stub + label) is a delegated ruling in [`02_01 §7`](../../../docs/02_01_Hardware_Architecture_and_BOM.md). `out/` is ignored by git — it is rebuilt.

The divider resistors are not typed into the generator: it reads them from the table in [`02_03 §5`](../../../docs/02_03_BQ25570_MPPT_Nano_Power.md) with the same parser `tools/firmware/bq25570_dividers.rb --check-canon` uses to judge that table, so the schematic cannot drift from the canon. Part numbers are not copied either: each part's `BOM` field points to its position in [`02_01 §3.1`](../../../docs/02_01_Hardware_Architecture_and_BOM.md).

## Opening it in KiCad

Open `soldier_power.kicad_pro` from the main KiCad window and start the Schematic Editor from there. After a rebuild, use File ▸ Revert to see the new version. Do not save over the file from KiCad: the next rebuild overwrites it.
