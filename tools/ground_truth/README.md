# Ground-truth: чужі емпіричні дані про справжні дерева

Інструментарій ноги [`00_07`](../../docs/00_07_Action_Plan_Tracker.md) **E.64** — звести відкритий
UA-набір санітарного стану лісів у придатний артефакт. Наукові межі й підстава, чому цей
шлях узагалі легітимний, канонізовані в
[`05_05 §8.5`](../../docs/05_05_Slashing_and_Risk_Policy.md) — тут лише інструмент.

```bash
python3 tools/ground_truth/fetch.py        # транспорт → raw/ + raw/manifest.json
python3 tools/ground_truth/build_slice.py  # санітизація + зріз → cherkasy_sanitary.csv
```

**Джерело.** `data.gov.ua`, набір «Перелік заходів з поліпшення санітарного стану лісів»
(Держлісагентство, **CC BY 4.0**), поквартально з 2024-Q1. Список ресурсів не хардкодиться —
береться з CKAN `package_show`, тож новий квартал приїжджає сам.

## ⛔ Чим цей артефакт НЕ є

Найдорожча помилка тут — не технічна, а адресна, і вона вже стояла записаною в трекері.

- **Це не вхід для `SilkenNet::LorenzValidationService`.** Той сервіс — чиста функція над
  `Array<Hash>` з ключами `stress_index` · `ground_truth_decline` · `z_value` · `sap_flow`;
  жодного з цих полів у наборі немає **за побудовою**, бо він описує таксацію виділу й
  призначений захід. Дописати сервісу read-шлях заради цього означало б зламати його
  оголошену чистоту, щоб напис став правдивим.
- **Це не per-tree ground truth.** Зерно рядка — **виділ** (десятки-сотні дерев), а
  призначення санітарної рубки є адміністративним рішенням, не фізіологічною смертю.
- **Це не панель.** Набір є реєстром **новопризначених** заходів: нормалізованим ключем
  лише ~6 % координат зустрічаються більш ніж в одному кварталі публікації, тож ряду по
  одному виділу не існує — динаміки з нього не дістати, лише зріз.
- **Прив'язки до наших координат у ньому немає.** Адреса рядка — `область → лісництво →
  квартал → виділ`; географічних координат немає взагалі. Вигадати їх = фабрикація.

**Чим воно Є:** стенд-рівневий baseline і зовнішня перевірка правдоподібності — сторонній
лейбл занепаду на наш власний ліс, здобутий без 👤 і без партнера, тобто рівно та
«невідбирана» вісь, якої вимагає критерій місії
([`00_01 §1.1`](../../docs/00_01_Vision_Mission_and_Roadmap.md)).

## Що робить санітизація

Кожен крок лишає слід у колонці `repaired` — відновлене значення мусить бути відрізнюваним
від виміряного.

| Крок | Дефект джерела | Дія |
|---|---|---|
| кодування | UTF-8, прочитаний як cp1251 і збережений знову | зворотне перекодування, лише якщо результат менш мохібейний |
| дублі | портал опублікував `2024-Q3` побайтовою копією `2024-Q1` | дедуп за **SHA-256 файлу**, не за міткою кварталу |
| Excel «число → дата» | `22.6` збережено як `22.Чер` | однозначне відновлення `день.місяць` → `день.номер` |
| Excel «дата → серійник» | `45421` | епоха 1899-12-30 → ISO |
| назви підприємств | та сама одиниця має 3+ написань | нормалізація ключа; оригінал лишається в `enterprise_raw` |

⚠️ **Excel-псування систематичне, а не випадкове:** постраждали лише значення з дробовою
частиною 1..12 (їх Excel прийняв за дати), решта неушкоджені. Відновлення повертає число,
але зміщення в тому, ЯКІ рядки постраждали, лишається властивістю джерела.

## Похідні колонки — це НАШІ твердження

`pine_share` · `cut_share` · `severity_ordinal` · `reason_biotic|abiotic|fire|unclassified`
обчислюються нами, а не читаються з джерела; джерельні поля лишаються поруч у тому ж рядку.
Класифікатор причин виведено з частотного розбору самих даних — перша редакція, написана
«зі знання домену», лишала 5.9 % рядків нерозкласифікованими, і всі вони виявились
біотичними, тобто бідність словника читалась як властивість джерела.

**Звірка з каноном** (соснові виділи Черкащини, `pine_share ≥ 8`): біотичний 95.1 % ·
абіотичний 14.0 % · пожежа 0.6 % · нерозкласифікованих 0.0 % — збігається з числами
[`05_05 §8.5`](../../docs/05_05_Slashing_and_Risk_Policy.md), отриманими незалежним
класифікатором. По ВСІЙ області частки інші (97.2 / 7.8 / 0.3), тому звіт друкує обидві
популяції: без цього різниця множин читалась би як дрейф.

## Середовище

🔴 **TLS тут іде крізь корпоративну інспекцію (Zscaler)** — сертифікат `data.gov.ua`
підписаний `Zscaler Intermediate Root CA`, чий корінь лежить у Keychain, але не в `certifi`.
Тому `fetch.py` бере **системне** сховище через `truststore`; без нього і дефолтний контекст,
і явний `certifi` падають `CERTIFICATE_VERIFY_FAILED`. ⚠️ Прочитати це як «портал
недоступний» означало б винести вердикт про чужий сервіс із поведінки власного
інтерпретатора — саме такою помилкою був діагноз «HTTP 429», що коштував попередньому
проходу 52 хвилини (справжньою причиною там був Cloudflare-челендж на не-браузерний
`User-Agent`).
